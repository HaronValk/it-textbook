# Групповые политики углублённо: порядок применения, фильтрация, WMI, Item-level targeting, loopback

## 1. Введение (зачем это нужно в реальной работе)

Заявка в поддержку: «Пользователь: ivanov / ВМ WIN11-CL01 / Что написал: "После перезагрузки не открывается панель управления — пишет, что заблокировано администратором. У Петровой на WIN10-CL02 всё открывается. Мне срочно настроить принтер, закрытие месяца!" / Срочность: высокая».

Дальше ты открываешь консоль, видишь десяток политик, половина из них «вроде бы должна применяться», и понимаешь: без понимания порядка применения GPO ты будешь гадать. На L1 ты умел создать GPO и перезагрузить машину. На L2 от тебя ждут другого: по `gpresult` понять, какая именно политика победила, почему соседняя не применилась, и не сломать при этом полсотни рабочих мест.

Групповые политики — это 80% всех «загадочных» изменений в домене: пропал диск, закрылась панель, не ставится программа, принтер не тот. Почти всегда причина одна из пяти: неверный порядок/уровень привязки, конфликт с Block Inheritance, слишком узкая или слишком широкая security filtering, кривой WMI-фильтр, либо loopback, про который забыли. После этой главы ты будешь уметь читать RSoP-отчёт как бухгалтер баланс, осознанно выбирать инструмент фильтрации (группа → OU → WMI → ILT) и объяснять коллеге, почему «политика не работает» — это не «глючит домен», а конкретная причина с конкретным именем.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

GPO живёт в двух местах. Первое — объект в AD (`CN=Policies,CN=System,DC=corp,DC=vektor,DC=lab`): там версия, GUID, список client-side extensions. Второе — папка в SYSVOL: `\\corp.vektor.lab\SYSVOL\corp.vektor.lab\Policies\{GUID}\` с `GPT.INI`, подпапками `Machine` и `User` и файлами ADMX/ADML на уровне домена (`\\corp.vektor.lab\SYSVOL\corp.vektor.lab\Policies\PolicyDefinitions`).

Клиент получает список политик по LDAP (389/636), файлы тянет по SMB (445), аутентификация — Kerberos (88, урок 20). Применяет всё служба **gpsvc** («Клиент групповой политики») через **CSE** — client-side extensions, отдельные модули под каждый тип настроек (реестр, безопасность, firewall, Preferences, scripts). Порт «групповой политики» не нужен — она ездит на чужих протоколах, и это первое, что стоит запомнить.

```text
Путь GPO: от контроллера домена до рабочего стола

[Загрузка компьютера]
  gpsvc ──LDAP──► DC01: «какие GPO положены этому компьютеру?»
        ──SMB───► \\corp.vektor.lab\SYSVOL\...\Machine
        ├─ отсев 1: ссылка выключена / пустой GPO
        ├─ отсев 2: security filtering (нет Read + Apply Group Policy)
        ├─ отсев 3: WMI-фильтр не сошёлся (проверяется НА КЛИЕНТЕ)
        └─ применение CSE: реестр, безопасность, firewall, скрипты
[Экран входа]
  gpsvc ──► список GPO для пользователя: Local → Site → Domain → OU(родитель) → OU(ребёнок)
        ├─ Loopback? → user-часть берём с компьютера (Replace) или смешиваем (Merge)
        └─ для каждого элемента Preferences → Item-level targeting
[Рабочий стол]
  Фон: 90 мин ± 30 мин рандома (на DC — 5 мин), настройки безопасности — раз в 16 ч
```

**Порядок применения (LSDOU):** Local → Site → Domain → OU, от родительского OU к дочернему. Побеждает то, что применено позже. Внутри одного контейнера при нескольких привязках действует **Link Order**: порядок 1 — высший приоритет, применяется последним. Дальше два усилителя: **Block Inheritance** на OU отрезает всё, что пришло сверху, а **Enforced** (бывший No Override) на ссылке пробивает Block Inheritance и перебивает дочерние OU. Важная деталь для интервью и для жизни: настройки смешиваются **по каждому параметру отдельно** — один GPO может победить по одному пункту и проиграть по другому.

**Три разных фильтра — не путать:**

| Инструмент | Что фильтрует | Где вычисляется | Гранулярность |
|---|---|---|---|
| Security filtering (ACL объекта GPO) | весь GPO | на DC при чтении списка | пользователь/компьютер/группа |
| WMI filter | весь GPO, максимум один на GPO | на клиенте, через WMI | любой WQL-запрос |
| Item-level targeting (ILT) | один элемент Preferences | на клиенте | ОС, группа, IP, OU, реестр, WMI, LDAP |

WMI-фильтр — это WQL-запрос, например: «только Windows 11» (`BuildNumber >= '22000'`). Фильтр выполняется на клиенте, а не на DC, поэтому стоит секунды на каждую политику и может вести себя по-разному у разных пользователей одного компьютера `[ПРОВЕРИТЬ контекст выполнения для user-настроек]`. ILT — надстройка над Preferences: у каждого элемента (ярлык, файл, реестр, принтер) на вкладке Common можно задать условие; условия комбинируются через AND/OR и item-level collections.

**Loopback processing** — единственная настройка, которая меняет саму логику: она лежит в Computer Configuration → Administrative Templates → System → Group Policy → «Configure user Group Policy loopback processing mode». В режиме **Replace** пользовательские настройки из GPO пользователя не применяются вообще, вместо них берутся user-настройки GPO, привязанных к OU компьютера. В режиме **Merge** сначала применяются настройки пользователя, потом поверх — настройки с компьютера. Цена Replace: личные диски, folder redirection и прочие пользовательские удобства исчезают у всех, кто сядет за эту машину.

## 3. Аналогия из жизни

Представь бизнес-центр, где сидит компания «Вектор». Правила висят на дверях. Правила конкретного кабинета (Local) — самые слабые: их легко отменить приказом сверху. Правила бизнес-центра (Site), затем приказы компании (Domain), затем приказы отдела (OU, от главного к вложенному) — каждый следующий слой главнее предыдущего. Если в одной папке лежат два приказа по одному вопросу, действует тот, у кого номер меньше (Link Order 1). Отдел может повесить табличку «приказы сверху не принимаем» (Block Inheritance), но приказ с грифом «отмене не подлежит» (Enforced) всё равно залетит в кабинет. Фейс-контроль на входе пускает только по списку (security filtering), охранник дополнительно проверяет марку ноутбука (WMI-фильтр), а в столовой на каждом блюде табличка «только для бухгалтерии» (ILT). Loopback — это переговорная: в ней действуют правила переговорной, а не твои личные привычки.

Аналогия ломается на конфликтах: в реальности приказы не «смешиваются по абзацам», а групповые политики именно так и работают — один GPO побеждает по одному параметру и проигрывает по другому.

## 4. Практика и команды

**1. Ручной запуск обработки.**
```powershell
gpupdate /force /target:user
gpupdate /force /target:computer /boot
```
`/force` — переприменить все настройки, даже если версия GPO не менялась; `/target` — только пользователь или только компьютер; `/boot` и `/logoff` — перезагрузка/выход сразу после обработки (нужно для Software Installation и Folder Redirection). `/sync` работает только вместе с `/force` и делает обработку при следующем входе синхронной. Вывод: `Computer Policy update has completed successfully.`

**2. Быстрая сводка RSoP на клиенте.**
```powershell
gpresult /r /scope:user
```
Показывает, в каких группах пользователь, какие GPO применились, какие отфильтрованы и почему (`Denied (Security)`, `Denied (WMI Filter)`, `Denied (Not applied — empty)`). Это первая команда при любом «политика не работает».

**3. Полный отчёт с победителями.**
```powershell
gpresult /h C:\Temp\rsop.html /f
```
`/h` — HTML-отчёт, `/f` — перезаписать файл. В отчёте смотри три блока: «Group Policy Objects» (применённые/отфильтрованные), «Settings» (по каждому параметру указан **Winning GPO** — вот он, ответ на «кто это сделал») и «Group Policy Infrastructure» (время обработки, версии GPO). `/v` — подробный текстовый вывод, `/z` — суперподробный.

**4. RSoP через PowerShell (то же, но скриптуемо).**
```powershell
Get-GPResultantSetOfPolicy -ReportType Html -Path C:\Temp\rsop2.html -Computer WIN10-CL02 -User 'VEKTOR\sidorov'
```
Работает с машины, где установлен RSAT/GroupPolicy module и есть права администратора на цели. Удобно, когда пользователь за другим концом офиса.

**5. Инвентаризация GPO на DC01.**
```powershell
Get-GPO -All | Sort-Object ModificationTime -Descending |
  Select-Object DisplayName, GpoStatus, UserVersionNumber, ComputerVersionNumber, ModificationTime
```
`GpoStatus` покажет, не отключён ли GPO целиком или его половина (`UserSettingsDisabled`). Разные версии user/computer на разных DC — сигнал, что SYSVOL ещё не реплицировался (см. урок 17).

**6. Кто наследует и где забор.**
```powershell
Get-GPInheritance -Target 'OU=Склад,OU=Company,DC=corp,DC=vektor,DC=lab' |
  Select-Object -ExpandProperty InheritedGpoLinks |
  Format-Table DisplayName, Order, Enabled, Enforced, IsBlocked
```
Видно `Order`, `Enabled`, `Enforced` и флаг `InheritanceBlocked` у самого контейнера. Это главный инструмент разбора «почему прилетело/не прилетело сверху».

**7. Управление привязками.**
```powershell
New-GPLink -Name 'GPO-Baseline-User' -Target 'OU=Company,DC=corp,DC=vektor,DC=lab' -LinkEnabled Yes -Order 1
Set-GPLink -Name 'GPO-Baseline-User' -Target 'OU=Company,DC=corp,DC=vektor,DC=lab' -Enforced Yes
Set-GPInheritance -Target 'OU=Склад,OU=Company,DC=corp,DC=vektor,DC=lab' -IsBlocked Yes
Remove-GPLink -Name 'GPO-Buh-Panel-Strict' -Target 'OU=Бухгалтерия,OU=Company,DC=corp,DC=vektor,DC=lab'
```
`-Enforced Yes|No`, `-IsBlocked Yes|No`, `-Order <int>`. Привычка: сначала `Get-GPInheritance`, потом изменение, потом снова `Get-GPInheritance` — иначе не заметишь, что включил Enforced «на минутку» и забыл.

**8. Security filtering из консоли.**
```powershell
Set-GPPermission -Name 'GPO-Sklad-Regedit' -TargetName 'Authenticated Users' -TargetType Group -PermissionLevel GpoNone
Set-GPPermission -Name 'GPO-Sklad-Regedit' -TargetName 'Domain Computers' -TargetType Group -PermissionLevel GpoRead
Set-GPPermission -Name 'GPO-Sklad-Regedit' -TargetName 'GG-Sklad' -TargetType Group -PermissionLevel GpoApply
Get-GPPermission -Name 'GPO-Sklad-Regedit' -All | Format-Table Trustee, Permission
```
`GpoApply` = Read + Apply Group Policy, `GpoRead` = только чтение, `GpoNone` = удалить запись. Не используй `-Replace` на живой GPO: снесёшь все права разом.

**9. WMI-фильтр: сначала проверь запрос, потом создавай.**
```powershell
Get-CimInstance -Query "SELECT Caption, Version, BuildNumber, ProductType FROM Win32_OperatingSystem"
New-GPWmiFilter -Name 'WMI-Win11-Only' -Expression "SELECT * FROM Win32_OperatingSystem WHERE BuildNumber >= '22000'" -Description 'Только Windows 11'
Get-GPWmiFilter | Format-Table Name, Expression
```
`ProductType = 1` — рабочая станция, `2` — контроллер домена, `3` — сервер. Сравнение `BuildNumber` строковое, для пятизначных номеров это работает. Привязка фильтра к GPO в GPMC: Scope → WMI Filter (в PowerShell — свойство `WmiFilter` объекта GPO `[ПРОВЕРИТЬ]`).

**10. Item-level targeting — глазами пользователя.**
```powershell
whoami /groups | Select-String 'GG-Buh'
gpresult /h C:\Temp\rsop-ilt.html
```
ILT-условие «User in group» проверяется по фактическому членству в момент обработки. Если проверяешь под админом (`adm.student`), он не в `GG-Buh` — и элемент «не применится», хотя всё настроено верно.

**11. Журнал обработки политик.**
```powershell
Get-WinEvent -LogName 'Microsoft-Windows-GroupPolicy/Operational' -MaxEvents 30 |
  Format-Table TimeCreated, Id, LevelDisplayName, Message -Wrap
```
Успешная обработка — событие 1500, ошибки — 1503 и серия 7xxx `[ПРОВЕРИТЬ точные номера]`. История применённых GPO лежит в `C:\ProgramData\Microsoft\Group Policy\History` (компьютер) и `%LOCALAPPDATA%\Microsoft\Group Policy\History` (пользователь) — папки с GUID.

**12. Проверка SYSVOL и GUI-инструменты.**
```powershell
Test-Path '\\corp.vektor.lab\SYSVOL\corp.vektor.lab\Policies'
```
Если путь не открывается — политики не применятся вообще, и это проблема репликации/прав (урок 17). GUI: `gpmc.msc` (Group Policy Management), `rsop.msc` (в новых сборках может отсутствовать — тогда только `gpresult /h`), мастера **Group Policy Results** и **Group Policy Modeling** в GPMC.

## 5. Лабораторная работа (пошаговый сценарий на виртуалке)

### Предусловия
Готовый стенд L2: DC01 (10.10.10.10, AD DS + DNS + DHCP), FS01 (10.10.10.20, папка `\\FS01\Obshchee`), WIN11-CL01 (в домене, рабочее место ivanov), WIN10-CL02 (в домене, рабочее место petrova). Пользователи `ivanov` (OU `Бухгалтерия`, группа `GG-Buh`), `petrova` (OU `HR`, `GG-HR`), `sidorov` (OU `Склад`, `GG-Sklad`). Компьютерные учётки — в OU `Компьютеры`. Все работы ведём под `VEKTOR\adm.student`, пароль стенда `Lab#2026-vektor`. Сидим на DC01 с `gpmc.msc` и модулем GroupPolicy; на клиентах — PowerShell от администратора.

### Снапшот
В VMware Workstation на каждой затрагиваемой ВМ: VM → Snapshot → Take Snapshot, имя `before-l2-021`. Через `vmrun` (пути подставь свои):
```bash
vmrun snapshot "C:\VMs\DC01\DC01.vmx" before-l2-021
vmrun snapshot "C:\VMs\WIN11-CL01\WIN11-CL01.vmx" before-l2-021
vmrun snapshot "C:\VMs\WIN10-CL02\WIN10-CL02.vmx" before-l2-021
```

### Шаги

1. **DC01, инвентаризация.** `Get-GPO -All | ft DisplayName,GpoStatus` и `Get-GPInheritance -Target 'DC=corp,DC=vektor,DC=lab'`. Ожидаемо: видны Default Domain Policy/Default Domain Controllers Policy и структура OU. Запомни, что уже привязано — дальше добавляем только своё.

2. **DC01, базовая политика.** `New-GPO -Name 'GPO-Baseline-User'`, затем `New-GPLink -Name 'GPO-Baseline-User' -Target 'OU=Company,DC=corp,DC=vektor,DC=lab' -Order 1`. В `gpmc.msc` → Edit → User Configuration → Policies → Administrative Templates → **Control Panel** → «Prohibit access to Control Panel and PC settings» = **Enabled**. Ожидаемо: настройка сохранена, версия GPO выросла.

3. **WIN11-CL01, проверка.** Вход как `VEKTOR\ivanov` → `gpupdate /force`, затем попытка открыть «Параметры»/панель управления. Ожидаемо: сообщение о блокировке политикой. `gpresult /r` — `GPO-Baseline-User` в списке применённых.

4. **DC01, исключение для бухгалтерии.** `New-GPO -Name 'GPO-Buh-Panel'`, привязка к `OU=Бухгалтерия,OU=Company,DC=corp,DC=vektor,DC=lab`. Та же настройка = **Disabled**. Ожидаемо: у GPO два состояния одного параметра на разных уровнях — классический конфликт.

5. **WIN11-CL01, конфликт разрешён.** `gpupdate /force` под `ivanov`, открыть панель управления. Ожидаемо: открывается — дочерний OU применён позже. `gpresult /h C:\Temp\rsop.html`: у параметра Winning GPO = `GPO-Buh-Panel`, оба GPO в списке применённых.

6. **DC01 + WIN11-CL01, Link Order.** Создай `GPO-Buh-Panel-Strict` с тем же параметром = **Enabled**, привяжи к `OU=Бухгалтерия` с `-Order 1`, а `GPO-Buh-Panel` переведи в `-Order 2` (`Set-GPLink ... -Order 2`). На клиенте `gpupdate /force`: панель снова блокируется — побеждает порядок 1. Верни `GPO-Buh-Panel` на `-Order 1`, у `GPO-Buh-Panel-Strict` сделай `Remove-GPLink` и `Set-GPO -Name 'GPO-Buh-Panel-Strict' -GpoStatus AllSettingsDisabled`. Ожидаемо: панель снова открывается.

7. **DC01 + WIN11-CL01, Block Inheritance.** `Set-GPInheritance -Target 'OU=Склад,OU=Company,DC=corp,DC=vektor,DC=lab' -IsBlocked Yes`. Вход на WIN11-CL01 как `VEKTOR\sidorov` → `gpupdate /force`. Ожидаемо: панель управления открывается, `GPO-Baseline-User` в отчёте `gpresult /r` отсутствует, а `Get-GPInheritance` показывает `InheritanceBlocked: True`.

8. **DC01, Enforced.** `New-GPO -Name 'GPO-NoRecycle'`, привязка к `OU=Company` с `-Enforced Yes`; в Edit → User Configuration → Administrative Templates → **Desktop** → «Remove Recycle Bin icon from desktop» = Enabled. На WIN11-CL01 под `sidorov`: `gpupdate /force`. Ожидаемо: корзина исчезла, хотя наследование заблокировано; панель управления по-прежнему открывается (у `GPO-Baseline-User` Enforced нет).

9. **DC01, security filtering.** `New-GPO -Name 'GPO-Sklad-Regedit'`, привязка к `OU=Склад` (Order 1), настройка User Configuration → System → «Prevent access to registry editing tools» = Enabled. Затем три команды `Set-GPPermission` из раздела 4: убрать `Authenticated Users`, добавить `Domain Computers` = `GpoRead`, `GG-Sklad` = `GpoApply`. Проверь: под `sidorov` на WIN11-CL01 `regedit` блокируется, под `ivanov` — открывается. В `gpresult /r` у ivanov GPO будет в блоке «filtered out: Denied (Security)».

10. **DC01 + клиенты, WMI-фильтр.** `New-GPWmiFilter -Name 'WMI-Win11-Only' -Expression "SELECT * FROM Win32_OperatingSystem WHERE BuildNumber >= '22000'"`. Создай `GPO-Win11-Autoplay`, привяжи к `OU=Company`, настройка Computer Configuration → Administrative Templates → Windows Components → AutoPlay Policies → «Turn off Autoplay» = Enabled, в Scope прикрепи WMI-фильтр. На WIN11-CL01 `gpresult /r /scope:computer` — GPO применён; на WIN10-CL02 `gpresult /h` — «Denied (WMI Filter)». Дополнительно проверь сам запрос через `Get-CimInstance -Query` на обеих машинах.

11. **DC01 + клиенты, Item-level targeting.** Создай `GPO-Prefs-Shortcut`, привяжи к `OU=Company`. Edit → User Configuration → Preferences → Windows Settings → Shortcuts → New Shortcut: Target `\\FS01\Obshchee`, Location Desktop. Вкладка **Common** → Item-level targeting → New Item → Security Group → `VEKTOR\GG-Buh`. Проверка: `ivanov` на WIN11-CL01 видит ярлык, `petrova` на WIN10-CL02 — нет; если `petrova` сядет за WIN11-CL01, ярлыка тоже не будет (условие про пользователя).

12. **DC01 + WIN10-CL02, loopback.** Создай `GPO-Loopback-Restricted`, привяжи к `OU=Компьютеры,DC=corp,DC=vektor,DC=lab`, security filtering оставь только `WIN10-CL02$` с `GpoApply`. Внутри: Computer Configuration → Administrative Templates → System → Group Policy → «Configure user Group Policy loopback processing mode» = Enabled, Mode **Replace**; плюс User Configuration → Control Panel → тот же запрет = Enabled. Вход на WIN10-CL02 как `sidorov` → `gpupdate /force`: панель управления блокируется, хотя в его OU наследование заблокировано. Переключи Mode на **Merge** и сравни `gpresult /h`: в Merge в user-части видны и его собственные GPO, и политика с компьютера.

13. **Сбор доказательств.** Сохрани `gpresult /h` с обеих клиентских машин в `\\FS01\Obshchee\rsop\` (создай папку через `New-Item`), обнови `stand-log.md`.

## 6. Ошибки новичков и безопасность

1. **Удалить `Authenticated Users` из Security Filtering и фильтровать только по пользователям.** → Компьютерная часть GPO и фоновая обработка пользовательских настроек перестают работать: у машины нет прав читать политику. → Оставляй `Authenticated Users` с `GpoRead` и убирай только `Apply`, либо добавляй `Domain Computers` = `GpoRead`.
2. **Свалить всё в Default Domain Policy.** → Один неудачный эксперимент ломает весь домен, откатить точечно нельзя. → Отдельная GPO под каждую задачу, внятное имя, короткое описание.
3. **Ставить WMI-фильтр на каждый GPO «для точности».** → Каждый фильтр — WQL-запрос на клиенте при каждой обработке, вход растягивается на десятки секунд. → Сначала OU и группы, WMI — только когда без него никак.
4. **Путать Block Inheritance и Enforced.** → Включённый «на минутку» Enforced перебивает все дочерние OU и месяцам живёт незамеченным. → Правило: Enforced — только для домена/сайта и только осознанно, с записью в `stand-log.md`.
5. **Ждать мгновенного применения.** → Фон — 90 ± 30 минут, безопасность — раз в 16 часов, часть настроек требует повторного входа или перезагрузки. → `gpupdate /force` (+`/logoff`, `/boot`), при проблемах — `gpresult /h`.
6. **Включить loopback Replace на общем терминале «чтобы всё было одинаково».** → У всех пользователей пропадают личные диски, folder redirection и прочие user-настройки. → Replace только для киосков, начинать с Merge, документировать исключения.
7. **Тестировать политику под `adm.student`.** → У админа другой набор групп и другой контекст, ILT-условия и security filtering сработают иначе. → Тест под реальным пользователем (`ivanov`, `petrova`, `sidorov`).
8. **Проверять «на глаз» и не сохранять доказательства.** → Спор с коллегой или пользователем «ничего не менялось» проигран. → Всегда `gpresult /h` в файл, отчёт в папку на FS01.

**Безопасность.** Не отключай через GPO брандмауэр, Defender и контроль учётных записей «чтобы заработало» — в боевой среде это мгновенно превращается в инцидент. Не храни пароли в Group Policy Preferences (Drive Maps, Local Users and Groups): они лежали в SYSVOL в виде `cpassword` и были закрыты обновлением MS14-025 — для локальных админов есть LAPS (урок 23). Не давай `GpoApply` группам вроде `Domain Users` на политики с логон-скриптами от SYSTEM. И помни: ссылка на GPO с `Enforced` — это политический инструмент, а не технический; в нормальной компании изменения привязок проходят через согласование.

## 7. Вопросы на собеседовании

**1. В каком порядке применяются групповые политики и что победит при конфликте?**
Ответ: Local → Site → Domain → OU (от родительского к дочернему), побеждает применённое позже. Внутри контейнера — Link Order: номер 1 главнее, применяется последним. Block Inheritance отрезает наследование, но Enforced на верхней ссылке его пробивает и перебивает дочерние OU. Конфликт разрешается по каждому параметру отдельно.
*Что хочет услышать интервьюер:* LSDOU, link order, Enforced поверх Block Inheritance, «по каждому параметру отдельно».
*Красный флаг:* «побеждает та политика, которая новее» или путаница в том, что 1 — это высший приоритет.

**2. Чем security filtering отличается от WMI-фильтра и Item-level targeting? Когда что применять?**
Ответ: security filtering — ACL на объекте GPO, фильтрует весь GPO по пользователю/компьютеру/группе, проверяется на DC при формировании списка. WMI-фильтр — один на GPO, WQL-запрос, выполняется на клиенте, подходит для условий по железу/ОС/версии. ILT — условие на отдельный элемент Preferences (ярлык, реестр, принтер), комбинируется через AND/OR. Приоритет выбора: OU и группы → ILT → WMI (как самый дорогой).
*Что хочет услышать интервьюер:* понимание гранулярности и стоимости каждого механизма.
*Красный флаг:* «WMI-фильтров на одном GPO можно повесить несколько» или «ILT фильтрует всю политику».

**3. Что такое loopback processing и чем Replace отличается от Merge?**
Ответ: настройка Computer Configuration → System → Group Policy, меняет источник пользовательских настроек на компьютере. Replace — user-настройки из GPO пользователя игнорируются, берутся только user-настройки GPO, привязанных к OU компьютера. Merge — сначала настройки пользователя, потом поверх настройки с компьютера. Типовой кейс — киоски, терминалы, общие рабочие места, где нужен одинаковый интерфейс.
*Что хочет услышать интервьюер:* что loopback — про user-настройки, привязанные к компьютеру, и что Replace может снести личные удобства.
*Красный флаг:* «loopback влияет на компьютерные настройки» или незнание разницы между режимами.

**4. Пользователь говорит «политика не применяется». Как диагностируешь?**
Ответ: `gpresult /r` и `gpresult /h` (применённые, отфильтрованные, Winning GPO) → `Get-GPInheritance` (ссылка выключена, Enforced, Block Inheritance, Order) → `Get-GPPermission` (права Apply/Read, компьютерная учётка) → WMI-фильтр и ILT-условия → журнал `Microsoft-Windows-GroupPolicy/Operational` → доступность SYSVOL и репликация между DC01/DC02 → доверие к домену/сеть (медленный канал, сайт и подсеть). Отдельно проверяю, тот ли пользователь и та ли машина в OU.
*Что хочет услышать интервьюер:* методичный порядок «от отчёта к инфраструктуре», а не «перезагрузите ещё раз».
*Красный флаг:* сразу лезть пересоздавать GPO или включать Enforced «чтобы точно применилось».

**5. Почему WMI-фильтры считаются медленными и чем их заменить?**
Ответ: запрос выполняется на клиенте при каждой обработке для каждого GPO с фильтром, время входа растёт; поведение зависит от WMI-сервиса и прав. Альтернативы: отдельные OU под группы машин, security filtering по группам компьютеров, ILT для элементов Preferences, разные GPO для разных ОС. WMI оставить для случаев, где без него никак (например, ноутбуки vs десктопы через `Win32_Battery`).
*Что хочет услышать интервьюер:* что инструмент выбирается по стоимости, а не «нравится».
*Красный флаг:* «WMI-фильтры бесплатны по производительности».
