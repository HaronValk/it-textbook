# Защита от вредоносного ПО: Kaspersky Security Center, Dr.Web, Defender for Endpoint — централизованное управление

## 1. Введение (зачем это нужно в реальной работе)

Тикет в очереди: «Пользователь: ivanov / ВМ: WIN11-CL01 / Что написал: "После обеда ноутбук стал тормозить, в трее красный значок, написано «Защита отключена». И ещё какая-то таблица перестала открываться — антивирус её удалил, а это отчёт за квартал!" / Срочность: высокая».

Вот это — типовая реальность L2. Не «поставь антивирус на один компьютер», а «у меня 50 машин, на одной защита выключилась, на другой ложное срабатывание съело рабочий файл, а на третьей вообще не обновлялись базы месяц назад». По одной машине с бубном бегать нельзя — нужен централизованный сервер управления: он раздаёт настройки, ключи, обновления, задания на проверку и собирает события со всех станций в одно место.

После этой главы ты должен уметь: понимать архитектуру «сервер управления — агент — модуль защиты»; разворачивать политику на все машины и запрещать пользователю её менять; ставить и разбирать задачи проверки и обновления; отличать ложное срабатывание от реального заражения; читать журналы антивируса в Windows Event Log и в консоли KSC; понимать, что такое Defender for Endpoint и почему он в РФ 2026 — особый случай; и знать, где в этой картине Linux-машины стенда (UBU01, ASTRA01).

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Корпоративный антивирус — это всегда **три слоя**, а не одна программа:

```text
        +-------------------------------------------------------+
        |  СЕРВЕР УПРАВЛЕНИЯ (KSC / Dr.Web Server / MDE cloud)  |
        |  - хранит политики, задачи, ключи лицензий            |
        |  - собирает события, статусы, отчёты                  |
        |  - раздаёт обновления баз (или ссылается на вендора)  |
        +--------------------------+----------------------------+
                                   |  агент -> сервер
                                   |  KSC: TCP 13000
                                   |  Dr.Web: TCP 2193 [ПРОВЕРИТЬ]
                                   |  MDE: HTTPS 443 в облако MS
        +--------------------------v----------------------------+
        |  АГЕНТ на рабочей станции (klnagent / Dr.Web Agent)   |
        |  - связь с сервером, приём политик и задач            |
        |  - сам ничего не лечит, только исполняет              |
        +--------------------------+----------------------------+
                                   |
        +--------------------------v----------------------------+
        |  МОДУЛЬ ЗАЩИТЫ (Kaspersky Endpoint Security, Dr.Web    |
        |  Desktop Security Suite, Defender Antivirus)          |
        |  файловый/веб/почтовый антивирус, HIPS, контроль       |
        |  устройств, сетевой экран, EDR-сенсор                 |
        +-------------------------------------------------------+
```

Ключевые понятия, которые надо знать наизусть:

- **Файловый антивирус (on-access scanner)** — перехватывает обращения к файлам через драйвер-фильтр файловой системы. Сравнивает с **сигнатурами** (база хешей/байтовых шаблонов), прогоняет через **эвристику** (подозрительные признаки в коде) и **репутационные сервисы** (Kaspersky Security Network, Dr.Web Cloud).
- **Базовый набор сигнатур (base)** — то, что обновляется каждые несколько часов. Если базы старые — свежий вирус не поймается, даже если «антивирус стоит».
- **HIPS / контроль программ** — правила «какой процесс что может» (лезть в автозагрузку, писать в System32). Это уже поведенческий слой, а не сигнатуры.
- **EDR** (Endpoint Detection and Response) — запись событий на конечной точке (запуск процессов, сетевые соединения, изменения реестра) и возможность реагировать: изолировать хост от сети, собрать пакет для расследования. Kaspersky EDR, Dr.Web (частично через «Ревизор»), Microsoft Defender for Endpoint.
- **Политика (policy)** — централизованный набор настроек, привязанный к группе устройств. Внутри настроек есть «замок»: заблокированная настройка не может быть изменена локально ни пользователем, ни админом на месте.
- **Задача (task)** — централизованное действие по расписанию: обновление баз, полная/быстрая проверка, установка ПО, инвентаризация, смена ключа.
- **Tamper Protection / самозащита** — запрет останавливать службы антивируса и править его настройки даже локальному администратору.
- **Passive mode / регистрация в Windows Security Center** — Windows с 8-й версии разрешает только один активный антивирус. Сторонний антивирус регистрируется в WSC, а встроенный Defender автоматически уходит в пассивный режим. Отсюда классическая путаница: «в Безопасности Windows написано, что защита выключена» — а на самом деле работает KES.

Порты и сеть, которые пригодятся: KSC — TCP 13000 (агент → сервер) `[ПРОВЕРИТЬ актуальный порт в вашей версии]`, веб-консоль KSC — обычно 8080 `[ПРОВЕРИТЬ]`; push-установка агента идёт по SMB/RPC (445, 135) и админским шарам; обновление баз — исходящий 443 к серверам вендора (или к своему серверу обновлений); MDE — исходящий 443 к облаку Microsoft.

Сравнение трёх продуктов, чтобы не путаться:

| | Kaspersky Security Center | Dr.Web Enterprise Security Suite | Microsoft Defender for Endpoint |
|---|---|---|---|
| Сервер | свой (Windows Server + SQL) | свой (Dr.Web Server) | облако Microsoft |
| Агент | Network Agent (klnagent) | Dr.Web Agent | встроен в Windows 10/11 |
| Консоль | MMC-консоль и Web Console | Dr.Web Control Center `[ПРОВЕРИТЬ название в вашей версии]` | security.microsoft.com |
| РФ 2026 | есть, в реестре отечественного ПО | есть, в реестре отечественного ПО | новых продаж в РФ нет, только демо/учебно |
| Linux-станции | KES for Linux | Dr.Web для Linux | практически нет |

## 3. Аналогия из жизни

Представь бизнес-центр. На каждом входе стоит **постовой** (файловый антивирус): смотрит в список разыскиваемых (сигнатуры) и в лица (эвристика). Есть **внутренний регламент охраны** — что досматривать, кого пускать, где хранить ключи (это политика). Есть **начальник охраны** в кабинете: он пишет регламент сразу для всех постов, выдаёт им новые списки раз в час (задача обновления), собирает рапорты и раз в неделю устраивает учебную тревогу (задача проверки). Если постовой ушёл покурить и не сдал смену — начальник это видит и звонит, а не узнаёт об этом из новостей. И отдельно есть **система видеонаблюдения** — она ничего не запрещает, но пишет, кто куда шёл, чтобы потом разобраться (это EDR). Аналогия ломается в одном: постовой не ошибается, а антивирус ошибается регулярно — и ложное срабатывание по рабочему файлу бухгалтера это не «вирус», а дефект списка разыскиваемых.

## 4. Практика и команды

**1. `Get-MpComputerStatus` — состояние Defender на машине.** С этого начинается любая диагностика «антивирус не работает».

```powershell
Get-MpComputerStatus | Format-List AMServiceEnabled,AntivirusEnabled,RealTimeProtectionEnabled,AntivirusSignatureVersion,AntivirusSignatureLastUpdated,QuickScanEndTime,AMRunningMode
```
`AMServiceEnabled` — жива ли служба WinDefend. `AntivirusEnabled` — включён ли антивирус как активный. `RealTimeProtectionEnabled` — работает ли защита в реальном времени. `AntivirusSignatureVersion/LastUpdated` — свежесть баз. `AMRunningMode` показывает `Normal`, `Passive Mode` и т.п. `[ПРОВЕРИТЬ наличие поля в вашей сборке]`. Смотреть в первую очередь на дату баз: если она месячной давности — машина фактически без защиты.

**2. `Get-MpPreference` — что настроено и какие исключения.**

```powershell
Get-MpPreference | Select-Object DisableRealtimeMonitoring,ExclusionPath,ExclusionProcess,ScanScheduleDay,SignatureUpdateInterval
```
`ExclusionPath`/`ExclusionProcess` — папки и процессы, которые антивирус не проверяет. Это самое опасное место в корпоративной сети: люди «чтобы быстрее работало» добавляют туда `C:\` целиком. `DisableRealtimeMonitoring` = `True` — красный флаг, разбирайся немедленно.

**3. Изменение настроек и исключений.**

```powershell
Set-MpPreference -DisableRealtimeMonitoring $false
Add-MpPreference -ExclusionPath "D:\1C_Bases" -ExclusionProcess "1cv8.exe"
```
Исключения для 1С — типовой сценарий в РФ: базы и рабочие каталоги кластера исключают, чтобы сканер не блокировал файловые блокировки. Правильно — исключать **каталоги баз и каталог временных файлов**, а не процесс `1cv8.exe` целиком: исключённый процесс антивирус не проверяет вообще, и через него можно провести загрузчик.

**4. Обновление баз вручную.**

```powershell
Update-MpSignature
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -SignatureUpdate
```
Первое — командлет, второе — встроенная утилита `MpCmdRun.exe`. Если обновление падает с ошибкой — почти всегда виноват прокси или отсутствие выхода на 443. Проверка: `Test-NetConnection download.windowsupdate.com -Port 443`.

**5. Запуск проверки.**

```powershell
Start-MpScan -ScanType QuickScan
Start-MpScan -ScanType FullScan -ScanPath "D:\Share"
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Scan -ScanType 2
```
`-ScanType 1` — быстрая, `2` — полная (в `MpCmdRun`). На сервере полную проверку в рабочее время не запускают никогда — только по расписанию в окно обслуживания.

**6. Что нашлось и что с этим сделали.**

```powershell
Get-MpThreatDetection | Sort-Object InitialDetectionTime -Descending | Select-Object -First 10
Get-MpThreat | Format-List ThreatName,Resources,ActionSuccess,IsActive
Remove-MpThreat -ThreatID <ID>
```
`Get-MpThreatDetection` — журнал обнаружений с путями. `IsActive = True` — угроза не обезврежена, надо реагировать. `Remove-MpThreat` удаляет/чистит по ID.

**7. Журнал Defender в Event Log — доказательная база.**

```powershell
Get-WinEvent -LogName "Microsoft-Windows-Windows Defender/Operational" -MaxEvents 30 |
  Where-Object Id -in 1116,1117,5001,5007 | Format-Table TimeCreated,Id,Message -Wrap
```
1116 — обнаружен вредоносный объект, 1117 — принято действие, 5001 — отключена защита в реальном времени, 5007 — изменена конфигурация. Именно эти ID просят при разборе инцидента (и они же нужны на уроке 75 про SIEM).

**8. Проверка применения групповых политик.**

```cmd
gpupdate /force
gpresult /r /scope:computer
rsop.msc
```
`gpresult /r` покажет, какие GPO применились к компьютеру. Если политика Defender не приехала — ищи конфликт: две GPO с разными значениями, побеждает та, что ниже по приоритету в OU.

**9. Где в GUI настроить Defender централизованно.** На DC01: `Диспетчер серверов → Средства → Управление групповой политикой → corp.vektor.lab → Компьютеры → Политики → создать GPO → Изменить → Конфигурация компьютера → Политики → Административные шаблоны → Компоненты Windows → Антивирусная программа Microsoft Defender`. Внутри — разделы «Защита в режиме реального времени», «Проверка», «Исключения». Это бесплатный и полностью легальный способ централизованно управлять Defender без облака.

**10. Проверка связи Network Agent с сервером KSC.**

```cmd
"C:\Program Files (x86)\Kaspersky Lab\NetworkAgent\klnagchk.exe"
Test-NetConnection 10.10.10.11 -Port 13000
```
`klnagchk` показывает параметры подключения агента (адрес сервера, порт, использование SSL) и тестирует соединение с сервером `[ПРОВЕРИТЬ точный набор ключей для вашей версии]`. Если агент «на связи» по логам, но устройство в консоли не появляется — смотри срок действия сертификата сервера и время на клиенте (расхождение часов ломает TLS).

**11. KES из командной строки (локальная проверка без консоли).**

```cmd
"C:\Program Files (x86)\Kaspersky Lab\Kaspersky Endpoint Security for Windows\avp.com" UPDATE
"C:\Program Files (x86)\Kaspersky Lab\Kaspersky Endpoint Security for Windows\avp.com" SCAN C:\Temp
```
`avp.com` — консольный интерфейс KES for Windows: `UPDATE` запускает обновление баз, `SCAN <путь>` — проверку `[ПРОВЕРИТЬ синтаксис для вашей версии KES — в 11/12 он менялся]`. Удобно для скриптов и для проверки «а сам модуль вообще жив».

**12. Linux-станция: ClamAV как бесплатный обязательный минимум.**

```bash
sudo apt update && sudo apt install -y clamav clamav-daemon
sudo systemctl stop clamav-freshclam
sudo freshclam
sudo systemctl start clamav-freshclam
clamscan -r -i /home --log=/tmp/clamav-scan.log
sudo systemctl status clamav-daemon
clamdscan /home
```
`-r` — рекурсивно, `-i` — печатать только заражённое, `--log` — писать лог. `clamdscan` работает через демон и в разы быстрее (база уже загружена в память). ClamAV — сигнатурный сканер без EDR и без централизованного управления уровня KSC; в РФ 2026 на Linux-парке обычно ставят Kaspersky Endpoint Security for Linux (CLI `kesl-control`) или Dr.Web для Linux `[ПРОВЕРИТЬ точные ключи CLI]`, а ClamAV держат как вторую линию и для проверки файловых хранилищ.

**13. KSC: где что лежит в консоли.** Web Console: раздел «Устройства» → «Группы устройств» → группа `Company\Компьютеры` → вкладки «Политики», «Задачи», «Устройства»; раздел «Мониторинг и отчёты» → «Отчёты» (например, «Отчёт о защите», «Отчёт о вирусах») `[ПРОВЕРИТЬ названия отчётов в вашей версии]`. Политика создаётся кнопкой «Добавить политику» → выбрать приложение KES for Windows → настроить → обязательно включить замки на ключевых узлах («Файловый антивирус», «Обновление», «Самозащита»).

### Шаги

1. **DC01.** Создай GPO `SEC-Defender-Baseline` и привяжи её к OU `Company\Компьютеры`. Путь: `Конфигурация компьютера → Политики → Административные шаблоны → Компоненты Windows → Антивирусная программа Microsoft Defender → Защита в режиме реального времени`. Включи «Отключить защиту в режиме реального времени» = **Отключено** (то есть защита включена), «Отключить мониторинг поведения» = Отключено. Ожидаемо: политика сохранена и привязана.
2. **DC01.** В том же GPO: `Антивирусная программа Microsoft Defender → Проверка` → включи «Указать день недели для запуска проверки» и «Указать время суток для быстрой проверки» (например, среда, 13:00). Ожидаемо: расписание задано централизованно, локально его не поменять.
3. **WIN11-CL01.** `gpupdate /force`, затем `gpresult /r /scope:computer`. Ожидаемо: в списке применённых политик есть `SEC-Defender-Baseline`.
4. **WIN11-CL01.** `Get-MpPreference | Select ScanScheduleDay,ScanScheduleQuickScanTime,DisableRealtimeMonitoring`. Ожидаемо: значения совпадают с GPO — значит, централизованное управление реально работает, а не «в консоли красиво».
5. **WIN11-CL01.** Скачай с официального сайта `eicar.org` тестовый файл `eicar.com` (это безвредная строка-«пустышка», стандартный тест антивирусов, не вирус) и попробуй сохранить его в `C:\Temp`. Ожидаемо: Defender блокирует запись/сразу удаляет файл, в трее уведомление.
6. **WIN11-CL01.** `Get-MpThreatDetection | Select ThreatName,Resources,InitialDetectionTime`. Ожидаемо: запись с именем вроде `EICAR_Test_File` и путём файла. Проверь Event ID 1116 в журнале Defender (команда из п.4.7).
7. **DC02.** Установи Kaspersky Security Center (Административный сервер + Web Console) с пробной лицензией. Создай группу администрирования `Company\Компьютеры\Клиенты`. Ожидаемо: консоль открывается, группа видна, сервер слушает 13000 (`netstat -ano | findstr 13000`).
8. **DC02.** В KSC: «Пакеты установки» → добавить пакет Kaspersky Endpoint Security for Windows; «Задачи» → «Установка приложения» → цель WIN11-CL01 → запустить. Ожидаемо: на WIN11-CL01 появляется Network Agent, устройство переезжает в консоль со статусом «ОК».
9. **DC02.** Создай политику `POL-KES-Clients` для KES: включи файловый антивирус, включи самозащиту, поставь замки, запрети пользователю отключать защиту и менять настройки. Ожидаемо: политика в статусе «Применена» на WIN11-CL01 (в свойствах устройства видно применённую политику).

### Сломай и почини

**Заявка:** «Пользователь: ivanov / ВМ: WIN11-CL01 / Что написал: "Утром включил компьютер — в трее красный значок, антивирус пишет, что защита отключена и базы не обновляются. Вчера всё работало." / Срочность: высокая».

**Как воспроизвести поломку.** На DC02 в KSC открой свойства сервера → «Лицензирование» и удали ключ (или замени на заведомо просроченный). Дождись синхронизации агента (5–15 минут) или перезапусти WIN11-CL01. KES теряет лицензию → защита в реальном времени останавливается, а Defender при этом остаётся в пассивном режиме, потому что сторонний антивирус всё ещё зарегистрирован в Windows Security Center. Машина остаётся **без работающей защиты вообще** — это самая частая реальная авария в парке на 50+ машин.

**Диагностика по шагам (именно в этом порядке):**

1. На WIN11-CL01: `Get-MpComputerStatus | Select AMRunningMode,RealTimeProtectionEnabled` — видим пассивный режим Defender. Значит, Defender «думает», что защиту обеспечивает кто-то другой. Ловушка закрыта, идём дальше.
2. Смотрим KES: `Get-Service | Where-Object Name -like "*avp*"` и в трее статус лицензии. Или `avp.com STATUS` `[ПРОВЕРИТЬ синтаксис]`. Видим «лицензия отсутствует/истекла».
3. В KSC: «Устройства» → WIN11-CL01 → «Обнаруженные события»/отчёт о защите. Видим событие «Защита отключена: нет действующей лицензии» и дату.
4. `klnagchk.exe` на WIN11-CL01 — агент на связи с сервером, значит проблема не в сети, а именно в лицензии.
5. Смотрим срок действия ключа в KSC («Лицензирование»): если ключ просрочен — это не «глюк», это плановая задача админа, которая проспана.

**Решение:** добавить рабочий ключ на сервер KSC (или активировать пробный заново), назначить задачу «Смена ключа» на группу `Клиенты`, дождаться применения, проверить `Get-MpComputerStatus` (Defender снова в пассивном режиме, а KES — активен и защищает) и статус устройства в KSC = «ОК». Отдельно — завести напоминание за 30 дней до истечения лицензии. Если ключа нет вообще и не будет — временно вывести KES из системы, чтобы Defender вышел из пассивного режима: **хоть какая-то** защита лучше, чем две выключенные.

**Ответ пользователю:** «Иван, добрый день. Причина — истёк лицензионный ключ антивируса на сервере управления, из-за этого защита на твоём компьютере отключилась. Ключ уже обновил, защита работает, базы обновляются. Перезагружать ничего не нужно, но если увидишь красный значок снова — сразу напиши. Приношу извинения за неудобства».

**Закрытие заявки:** категория «Информационная безопасность → Антивирус → Лицензирование», решение — «просроченный ключ, обновлён, добавлен контроль сроков», в описании — ID событий и скриншот статуса «ОК».

## 6. Ошибки новичков и безопасность

1. **«Поставил антивирус — значит защищён».** → На машине с базами месячной давности и выключенной защитой в реальном времени антивирус есть только в «Установка и удаление программ». → Правильно: контроль свежести баз и статуса защиты — ежедневный отчёт, а не факт установки.
2. **Широкие исключения «чтобы 1С не тормозила».** → Исключение `C:\` или процесса целиком = дыра, через которую пройдёт любой загрузчик. → Правильно: точечные каталоги баз, конкретные типы файлов, обязательный комментарий «зачем» и дата пересмотра.
3. **Политика без замков.** → Пользователь сам отключает защиту, «потому что тормозит», а ты узнаёшь об этом через месяц. → Правильно: ключевые узлы политики блокируются, локальное изменение запрещено; отключение — только по заявке с обоснованием.
4. **Проверка всего диска в разгар рабочего дня.** → Сервер с 1С встаёт, файловые шары задыхаются, прилетает вторая заявка. → Правильно: полная проверка только в окно обслуживания, быстрая — по расписанию, нагрузка ограничивается настройками сканера.
5. **Удалил заражённый файл вместе с «уликами».** → Разбор инцидента невозможен: непонятно, как пришло и куда ещё пришло. → Правильно: сначала карантин и выгрузка события, потом лечение; при подозрении на серьёзное — изоляция хоста и передача ИБ (урок 79).
6. **Игнорирование ложных срабатываний.** → Пользователи сами удаляют антивирус, лишь бы работало. → Правильно: ложное срабатывание — тикет с категорией «false positive», восстановление файла из карантина, исключение по хешу/пути, при массовости — обращение вендору.
7. **Сервер антивируса без резервной копии и без обновления.** → Упал KSC — на руках 50 машин без управления и без политик. → Правильно: бэкап базы KSC, документированная процедура восстановления, отдельный сервер (не на DC).

**Безопасность.** В боевой среде нельзя: ставить сервер управления антивирусом на контроллер домена; давать L1-специалисту право менять политики без согласования; отключать самозащиту антивируса «для теста» на рабочей машине; хранить ключи лицензий в общей папке `\\FS01\Obshchee` (они там лежат в открытом виде и их утащат); запускать «тестовые» файлы сомнительного происхождения вместо официального EICAR; и главное — отключать защиту «на время» и забывать включить. На стенде учебный пароль `Lab#2026-vektor` используется только потому, что это стенд: в реальной работе пароли не переиспользуют и не пишут в тикетах.

## 7. Вопросы на собеседовании

**1. «У вас 50 машин. Как вы централизованно управляете антивирусом?»**
Ответ: сервер управления (KSC / Dr.Web Server / облако MDE) + агент на каждой станции + модуль защиты. На сервере — политики по группам устройств с замками на ключевых настройках, задачи обновления и проверки по расписанию, единая лицензия и отчёты. Машины без агента или с устаревшими базами видны в отчёте, по ним идёт отдельная работа.
*Что хочет услышать интервьюер:* что ты мыслишь группами устройств и политиками, а не «хожу по машинам руками». *Красный флаг:* «я ставлю антивирус на каждый ПК и настраиваю локально».

**2. «Пользователь говорит, что антивирус отключён. Ваши действия?»**
Ответ: сначала факты, потом выводы. Смотрю состояние модуля (служба, реальный статус, свежесть баз, лицензия), событие в журнале (1116/1117/5001/5007 для Defender), статус устройства в консоли управления. Проверяю три частые причины: истёкшая лицензия, локальное отключение пользователем (значит, политика без замка), конфликт двух антивирусов (Defender в пассивном режиме). Отдельно — не путать «красный значок в трее» с обязательным уведомлением WSC.
*Что хочет услышать:* порядок диагностики, а не «переустановлю». *Красный флаг:* «перезагружу и посмотрю».

**3. «Почему Defender может быть отключён, если он встроен в Windows?»**
Ответ: Windows разрешает один активный антивирус. При установке стороннего продукта Defender регистрируется как пассивный (`AMRunningMode = Passive Mode`) и не защищает. Если сторонний антивирус сломался или потерял лицензию, получается «дыра»: один в пассивном режиме, второй не работает. Поэтому при отказе от стороннего антивируса его надо корректно удалить, чтобы Defender вернулся в активный режим.
*Что хочет услышать:* понимание механизма WSC и passive mode. *Красный флаг:* «Defender вообще всегда отключён, он же бесплатный».

**4. «Чем Kaspersky Security Center отличается от Kaspersky Endpoint Security?»**
Ответ: KSC — сервер управления (политики, задачи, отчёты, лицензии), KES — сам модуль защиты на конечной точке. KSC ничего не проверяет, KES не хранит общих настроек. Между ними — Network Agent, который держит связь (TCP 13000) и передаёт политики и задачи.
*Что хочет услышать:* чёткое разделение «консоль/сервер» и «агент/продукт». *Красный флаг:* путаница в названиях, «это одно и то же».

**5. «Что вы сделаете при обнаружении вируса на рабочей станции?»**
Ответ: не «удалю файл и закрою тикет». Фиксирую событие (ID, путь, имя угрозы, время), при активной угрозе изолирую хост от сети (в KSC/MDE — отдельное действие), выясняю источник и масштаб (по отчётам — есть ли то же на других машинах), файл в карантин, при подозрении на серьёзный инцидент — передача ИБ по регламенту (урок 79). Лечение — только после фиксации. В завершение — проверка, что базы и политика на всех машинах актуальны.
*Что хочет услышать:* порядок «зафиксировать → изолировать → оценить масштаб → передать», а не геройство в одиночку. *Красный флаг:* «сразу удалю и никому не скажу».
