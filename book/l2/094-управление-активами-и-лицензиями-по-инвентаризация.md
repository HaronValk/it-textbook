## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Система инвентаризации — это три слоя плюс потребители данных.

```text
   Источники данных                      Сервер сбора                 Потребители
 ┌──────────────────────┐          ┌───────────────────────────┐
 │ WIN11-CL01           │          │ UBU01  10.10.10.30        │
 │ служба GLPI Agent    │──HTTP───▶│ Apache :80/443            │
 │ сбор раз в сутки     │  POST    │  ├─ GLPI 10 (веб + REST)  │
 └──────────────────────┘  JSON    │  └─ MariaDB               │
 ┌──────────────────────┐  /XML    │      активы, ПО, лицензии │   ┌──────────────────┐
 │ UBU01 / ASTRA01      │─────────▶│      история, привязки    │──▶│ Отчёты, аудит    │
 │ glpi-agent (cron)    │          └─────────────┬─────────────┘   │ Заявки Helpdesk  │
 └──────────────────────┘                        │                 │ CMDB, Ansible    │
 ┌──────────────────────┐                        ▼                 └──────────────────┘
 │ DC01, FS01, DC02     │─────────▶   Алерты: «лицензия истекает»,
 │ GLPI Agent           │             «превышено число мест»,
 └──────────────────────┘             «нет данных 7 дней»
```

**Слой 1 — агент.** Небольшая служба на машине. Раз в сутки (или по расписанию) собирает: имя хоста, BIOS-UUID, серийный номер, модель, CPU, объём RAM и дисков, версию ОС, список установленного ПО с версиями и датами установки, сетевые адаптеры и MAC, иногда — учётные записи. На Windows данные берутся из WMI/CIM, реестра (ветки `Uninstall`), файловой системы; на Linux — из `dpkg`/`rpm`, `/proc`, `/sys`, `dmidecode`.

**Слой 2 — транспорт.** Обычный HTTP/HTTPS (уровень 7 модели OSI, порты 80/443). Агент делает один POST на endpoint сервера и получает в ответ «принято». GLPI Agent отправляет данные в формате JSON на `http://сервер/front/inventory.php`, OCS Inventory NG использует свой XML-протокол на `http://сервер/ocsinventory` `[ПРОВЕРИТЬ формат OCS]`. Никаких входящих портов на клиенте открывать не нужно — агент сам стучится наружу, поэтому инвентаризация дружит с NAT и файрволами.

**Слой 3 — сервер и БД.** Принимает пакет, нормализует (приводит названия «Microsoft Office LTSC Professional Plus 2021» и «Microsoft Office LTSC Professional Plus 2021 - ru-ru» к одной записи), складывает в MariaDB. В GLPI модель данных такая:

- **Computer** (актив) — уникален по имени/серийному номеру, у него есть «Последняя инвентаризация»;
- **Software** — справочник программ (название);
- **SoftwareVersion** — версия, привязанная к Software;
- **License** — купленная лицензия: тип, количество мест, дата покупки, срок действия, поставщик, стоимость;
- связи: Computer ↔ SoftwareVersion (что установлено), License ↔ Computer (где использовано).

Отсюда появляется **Compliance** — сравнение «мест в лицензии» и «числа установок». Если мест 10, а установок 12, GLPI подсвечивает превышение.

**Agent-less инвентаризация.** Есть и второй путь: сервер сам сканирует подсеть (WMI по учётке домена для Windows, SSH для Linux, SNMP для сетевого оборудования). В GLPI это делается через «обнаружение сети» и требует доменной учётной записи с правами чтения WMI `[ПРОВЕРИТЬ точное меню]`. Минус: работает только когда машина включена и доступна, а список ПО по WMI неполный и медленный. Поэтому в реальной работе агент — основной способ.

**GLPI vs OCS.** OCS Inventory NG — отдельный проект со своим сервером; GLPI — ITSM-система (заявки, активы, лицензии, контракты), куда данные инвентаризации приходят. Исторически для связи использовали FusionInventory, который влился в GLPI, и теперь штатный агент называется **GLPI Agent**. OCS жив отдельно и умеет синхронизироваться с GLPI через плагин `[ПРОВЕРИТЬ «OCS-NG plugin for GLPI»]`. В учебном стенде ставим GLPI + GLPI Agent — один сервер вместо двух.

**Типы лицензий, которые надо различать:**

| Тип | Что это | Пример в стенде |
|-----|---------|-----------------|
| Бессрочная (perpetual) | купил один раз, версия зафиксирована | Windows Server 2022 (на стенде — Evaluation) |
| Подписка | платишь за период, по окончании не работает | Microsoft 365, антивирус |
| OEM | привязана к железу, не переносится | Windows на ноутбуке из магазина |
| CAL | клиентская лицензия на доступ **к серверу** | Windows Server CAL, RDS CAL |
| По местам / по пользователям | считается либо установка, либо человек | 1С, КриптоПро CSP |
| Свободная (GPL/MIT/Apache) | бесплатна, но с условиями | Apache, MariaDB, GLPI |

Отдельно запомните: **Freeware ≠ можно ставить в компании**. WinRAR, AnyDesk, TeamViewer бесплатны только для личной или некоммерческой使用; для компании «Вектор» это платно. Такие установки — классическая находка при аудите.

## 3. Аналогия из жизни

Представьте библиотеку. Есть каталог, где на каждую книгу заведена карточка: автор, название, год, инвентарный номер и сколько физических экземпляров куплено. Есть формуляры читателей: кто какую книгу держит. Раз в месяц библиотекарь проходит по полкам и сверяет: на полке 9 экземпляров «Войны и мира», в каталоге 10 — значит, один на руках, ищем формуляр.

Инвентаризация ПО — это сверка полок с каталогом. Агент — библиотекарь, который обходит машины и переписывает корешки. GLPI — картотека. Лицензия — это чек на покупку: если куплено 10 экземпляров, а на полках стоит 12, вы не вправе держать лишние два, даже если они «сами появились».

Аналогия перестаёт работать на копировании: книгу украсть и размножить незаметно нельзя, а программу — можно, причём копия никуда не «исчезает с полки» и стоит столько же, сколько оригинал.

## 4. Практика и команды

### 4.1. Почему `Win32_Product` — путь в ад

```powershell
Get-CimInstance -ClassName Win32_Product | Select-Object Name, Version
```

Класс `Win32_Product` на самом деле запускает переустановку MSI-конфигурации для каждого пакета: медленно, генерирует события `MsiInstaller` 1035 и иногда ломает приложения. В работе не используйте. Показываю, чтобы вы узнали команду и не повторили её на боевой машине.

### 4.2. Правильный список ПО через реестр

```powershell
$paths = @(
  'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*'
)
Get-ItemProperty $paths -ErrorAction SilentlyContinue |
  Where-Object { $_.DisplayName } |
  Select-Object DisplayName, DisplayVersion, Publisher, InstallDate |
  Sort-Object DisplayName
```

Разбираем: три ветки — 64-битные программы, 32-битные (в `WOW6432Node`) и установленные «только для меня». `Where-Object { $_.DisplayName }` отсекает служебные записи-обновления без имени. `DisplayDate` в формате `YYYYMMDD`.

Типичный вывод:

```text
DisplayName                          DisplayVersion  Publisher           InstallDate
-----------                          --------------  ---------         -----------
7-Zip 23.01 (x64)                    23.01           Igor Pavlov       20260114
Google Chrome                        131.0.6778.86   Google LLC        20260109
```

Смотрим: наличие подозрительного `Publisher`, дубли одного продукта разных версий (признак обновления или двух установок), пустой `InstallDate`.

### 4.3. Инвентаризация железа и ОС одним запросом

```powershell
$cs = Get-CimInstance Win32_ComputerSystem
$os = Get-CimInstance Win32_OperatingSystem
$bios = Get-CimInstance Win32_BIOS
[pscustomobject]@{
  Host        = $cs.Name
  Domain      = $cs.Domain
  Model       = $cs.Model
  RAM_GB      = [math]::Round($cs.TotalPhysicalMemory/1GB)
  OS          = $os.Caption
  OSVersion   = $os.Version
  Serial      = $bios.SerialNumber
  BIOS_UUID   = (Get-CimInstance Win32_ComputerSystemProduct).UUID
}
```

`BIOS_UUID` — самое стабильное поле: по нему GLPI склеивает активы, даже если машину переименовали. Имя хоста и IP — плохие ключи: их меняют.

### 4.4. Статус лицензии Windows

```cmd
cscript //nologo C:\Windows\System32\slmgr.vbs /dlv
```

`/dlv` — подробная информация: канал (`Retail`, `Volume:MAK`, `OEM:DM`), частичный ключ продукта, остаток активаций и дней. То же через PowerShell:

```powershell
Get-CimInstance SoftwareLicensingProduct -Filter "Name like 'Windows%'" |
  Where-Object PartialProductKey |
  Select-Object Name, LicenseStatus, PartialProductKey
```

`LicenseStatus = 1` означает «лицензирована». Канал `Volume:MAK` с остатком активаций `0` — сигнал, что пора закупать.

### 4.5. Статус лицензии Office

```cmd
cscript //nologo "C:\Program Files\Microsoft Office\Office16\OSPP.VBS" /dstatus
```

Путь `Office16` используется для Office 2016/2019/2021 `[ПРОВЕРИТЬ для LTSC 2024]`. Вывод содержит последние 5 символов ключа и `LICENSE STATUS: ---LICENSED---`. На машине без активации увидите `---NOTIFICATIONS---` или `---UNLICENSED---`.

### 4.6. Массовый сбор в CSV по списку машин

```powershell
$computers = 'WIN11-CL01','WIN10-CL02','FS01','DC01'
$all = foreach ($c in $computers) {
  Invoke-Command -ComputerName $c -ScriptBlock {
    Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
                     'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
      Where-Object DisplayName |
      Select-Object @{n='Computer';e={$env:COMPUTERNAME}}, DisplayName, DisplayVersion, Publisher
  }
}
$all | Export-Csv C:\Temp\software-inventory.csv -NoTypeInformation -Encoding UTF8
```

`Invoke-Command` работает по WinRM (порт 5985/5986) и требует прав локального администратора на целевых машинах. Это быстрый способ «снять слепок» до развёртывания агента. В продакшене так делать на 50 машин каждый день — плохая идея: держите агента.

### 4.7. Linux: список пакетов

```bash
# Debian / Ubuntu / Astra
dpkg-query -W -f='${Package}\t${Version}\n' | sort

# RHEL / AlmaLinux / РЕД ОС
rpm -qa --qf '%{NAME}\t%{VERSION}-%{RELEASE}\n' | sort
```

`-W` — показать пакеты, `-f` — формат вывода. На Ubuntu дополнительно `snap list` и `flatpak list`, если используются. Смотреть: пакеты с версией `unknown`/`local` — обычно поставлены из `.deb` вручную и часто не учтены.

### 4.8. Linux: железо и серийник

```bash
sudo dmidecode -s system-serial-number
sudo dmidecode -s system-uuid
hostnamectl
lscpu | head -n 15
free -h
lsblk -o NAME,SIZE,TYPE,FSTYPE
```

`dmidecode` читает SMBIOS и требует root. `system-uuid` — тот же ключ, что `BIOS_UUID` в Windows; именно по нему GLPI склеивает машину после переустановки ОС.

### 4.9. Ручной прогон агента GLPI на Linux

```bash
sudo systemctl status glpi-agent
sudo glpi-agent --server http://10.10.10.30/front/inventory.php --force --debug
```

`--force` — игнорировать расписание и отправить данные сейчас, `--debug` — подробный лог в консоль (видно, какие модули собрались и что ответил сервер). Конфиг обычно лежит в `/etc/glpi-agent/conf.d/` `[ПРОВЕРИТЬ путь для вашей версии]`.

### 4.10. Ручной прогон агента OCS (для сравнения)

```bash
sudo apt install ocsinventory-agent
sudo ocsinventory-agent --server http://10.10.10.30/ocsinventory
```

Конфигурация — `/etc/ocsinventory/ocsinventory-agent.cfg` `[ПРОВЕРИТЬ]`. Вывод заканчивается строкой вида `Inventory sent successfully` `[ПРОВЕРИТЬ формулировку]`.

### 4.11. GLPI REST API: вытащить список компьютеров

```bash
# 1) получаем сессию (App-Token создаётся в Setup → General → API)
curl -s -X GET "http://10.10.10.30/apirest.php/initSession" \
  -H "App-Token: <APP_TOKEN>" \
  -H "Authorization: user_token <USER_TOKEN>"

# 2) с полученным session_token запрашиваем активы
curl -s -X GET "http://10.10.10.30/apirest.php/Computer?expand_dropdowns=true" \
  -H "App-Token: <APP_TOKEN>" \
  -H "Session-Token: <SESSION_TOKEN>"
```

API — то, чем вы будете связывать GLPI с Zabbix и Ansible: например, генерировать inventory-файл для плейбуков (урок 86) прямо из GLPI.

### 4.12. Быстрая проверка «есть ли программа на машине»

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -like '*AnyDesk*' |
  Select-Object DisplayName, DisplayVersion, InstallDate, Publisher
```

Именно так вы за 10 секунд ответите на половину заявки №4471.

### Шаги

1. **UBU01.** Обновляем систему и ставим LAMP-стек:
   ```bash
   sudo apt update && sudo apt upgrade -y
   sudo apt install -y apache2 mariadb-server \
     php php-mysql php-mbstring php-curl php-gd php-xml php-intl \
     php-zip php-bz2 php-ldap php-apcu php-cli libapache2-mod-php
   ```
   Ожидаемо: `apache2` и `mariadb` запущены, `systemctl status apache2` — `active (running)`.
   Замечание по РФ: если зеркала Ubuntu недоступны, используйте локальное зеркало или официальный образ с ubuntu.com — GLPI полностью открытый, ограничений на использование в коммерции нет.

2. **UBU01.** Создаём базу:
   ```bash
   sudo mariadb
   ```
   ```sql
   CREATE DATABASE glpi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'glpi'@'localhost' IDENTIFIED BY 'Lab#2026-vektor';
   GRANT ALL PRIVILEGES ON glpi.* TO 'glpi'@'localhost';
   FLUSH PRIVILEGES;
   EXIT;
   ```
   Пароль — учебный со стенда. В продакшене он был бы другим и хранился в менеджере секретов.

3. **UBU01.** Скачиваем GLPI (актуальная ветка 10.0.x) и раскладываем:
   ```bash
   cd /tmp
   wget https://github.com/glpi-project/glpi/releases/download/10.0.16/glpi-10.0.16.tgz   # [ПРОВЕРИТЬ актуальный номер]
   sudo tar -xzf glpi-10.0.16.tgz -C /var/www/html/
   sudo chown -R www-data:www-data /var/www/html/glpi
   ```
   Ожидаемо: появился каталог `/var/www/html/glpi` с `index.php`.

4. **UBU01.** Настраиваем Apache:
   ```bash
   sudo a2enmod rewrite
   sudo sed -i 's/AllowOverride None/AllowOverride All/' /etc/apache2/apache2.conf
   sudo systemctl restart apache2
   ```
   Ожидаемо: `http://10.10.10.30/glpi` открывает установщик.
   Если PHP 8.3 из Ubuntu 24.04 несовместим с вашей версией GLPI, поставьте поддерживаемую версию PHP `[ПРОВЕРИТЬ матрицу совместимости GLPI ↔ PHP 8.3 на glpi-project.org]`.

5. **UBU01 (браузер с хоста или WIN11-CL01).** Проходим установщик: язык → проверка расширений (все зелёные) → параметры БД (`localhost`, `glpi`, пароль из шага 2, база `glpi`) → установка. Ожидаемо: экран «Установка завершена», предложение удалить `install/`.

6. **UBU01.** Убираем установщик и заходим:
   ```bash
   sudo rm -rf /var/www/html/glpi/install
   ```
   Вход: `glpi` / `glpi`. Сразу меняем пароль (Профиль → Пароль) и создаём сущность «Вектор» (Администрирование → Сущности).

7. **UBU01.** Ставим агент и регистрируем сам сервер в инвентаре:
   ```bash
   sudo apt install -y glpi-agent       # [ПРОВЕРИТЬ наличие пакета в репозитории GLPI-проекта]
   sudo glpi-agent --server http://10.10.10.30/front/inventory.php --force
   ```
   Ожидаемо: в GLPI → Активы → Компьютеры появилась запись `UBU01` со статусом последней инвентаризации «только что».

8. **WIN11-CL01.** Скачиваем MSI-агент со страницы релизов GLPI Agent и ставим:
   ```cmd
   msiexec /i GLPI-Agent-1.xx-x64.msi /qn SERVER=http://10.10.10.30/front/inventory.php RUNNOW=1
   ```
   `[ПРОВЕРИТЬ имена свойств SERVER и RUNNOW и актуальную версию MSI]`. Альтернатива — раскатка через Ansible из урока 86 или GPO.

9. **WIN11-CL01.** Проверяем, что служба жива и инвентаризация ушла:

## 6. Ошибки новичков и безопасность

1. **`Win32_Product` как инструмент инвентаризации** → запускает переустановку MSI, тормозит, ломает приложения → только реестр или `CIM Win32Reg_AddRemovePrograms` `[ПРОВЕРИТЬ доступность класса]`.
2. **«Установлено» = «лицензировано»** → 12 копий, 10 лицензий, штраф по итогам аудита → лицензия должна быть привязана к активам в системе, а сверка — регулярной.
3. **Ключ склейки актива — имя хоста или IP** → после переименования или DHCP-переезда появляются дубликаты → используйте BIOS-UUID/`system-uuid`.
4. **Ручной Excel** → устаревает за месяц, никто не ведёт → инвентаризация только автоматическая, процесс обновления — раз в сутки.
5. **Забытые даты окончания подписок** → антивирус или 1С «встали» в самый неподходящий момент → в лицензии обязательно поле срока и уведомление за 30/14/7 дней.
6. **Бесплатные программы без проверки условий** → AnyDesk, TeamViewer, WinRAR в коммерческой компании требуют платной лицензии → вводите белый список ПО и политику «что вне списка — заявка в ИТ».
7. **Увольнение без списания актива** → ноутбук и лицензии висят на уволенном сотруднике, отчёт врёт → чек-лист оффбординга с обязательным закрытием актива.
8. **Агент без ограничения прав** → агент с доменной админской учёткой на всех машинах = один взлом и весь домен ваш → отдельная служебная учётка с минимальными правами.

### Безопасность

- GLPI — это готовая карта вашей сети: имена, версии ОС, открытые сервисы. Никогда не выставляйте его в интернет; в компании — только внутренний сегмент, HTTPS, доступ по группам AD через LDAP `[ПРОВЕРИТЬ настройку LDAP-синхронизации]`.
- Учебный стенд работает по HTTP — данные идут открытым текстом. В боевой среде только HTTPS с валидным сертификатом (в РФ — часто от внутреннего УЦ или от КриптоПро-совместимого решения).
- API-токены и пароли БД не храните в вики, в git и в общих папках вроде `\\FS01\Obshchee` — только в менеджере секретов.
- Не давайте инвентаризационному агенту прав администратора домена. Ему достаточно локальных прав на чтение WMI и реестра.
- Тот факт, что «данные о ПО не персональные», не отменяет 152-ФЗ: если в инвентаре есть связка «сотрудник → устройство → программы», это уже обрабатываемые данные, нужен режим ограниченного доступа.

## 7. Вопросы на собеседовании

**1. Чем инвентаризация активов отличается от CMDB и зачем нужны обе?**

Ответ: инвентаризация отвечает на вопрос «что у нас есть» — автоматический снимок железа и ПО с машин. CMDB отвечает на вопрос «как это связано и от чего зависит» — какие сервисы стоят на каком сервере, кто владелец, что упадёт, если выключить FS01. CMDB без инвентаризации быстро устаревает, потому что её наполняют руками; инвентаризация без CMDB бесполезна для оценки влияния инцидентов. Правильная связка: агенты наполняют технический слой, а в CMDB эти данные подтверждаются владельцами сервисов и участвуют в change-management.

*Что хочет услышать интервьюер:* понимание разницы между «списком железа» и «моделью зависимостей», плюс опыт связывания их автоматически.
*Красный флаг:* «CMDB — это тот же Excel, только в системе» или «нам хватает отчёта из AD».

**2. Как вы построите инвентаризацию ПО в компании на 200 рабочих мест?**

Ответ: ставлю GLPI на отдельный сервер, разворачиваю GLPI Agent на все машины централизованно (GPO для Windows-парка, Ansible/SSH для Linux), настраиваю ежедневный сбор и мониторинг «нет данных N дней». Дальше — нормализация справочника ПО и белый/чёрный списки. Лицензии завожу по факту закупок с датами и местами, привязываю к активам, включаю уведомления о превышении и истечении. Отчётность отдаю через отчёты GLPI или REST API по расписанию. Процесс закрепляю регламентом: новое ПО — через заявку, оффбординг — через списание актива.

*Что хочет услышать интервьюер:* что вы мыслите процессом, а не разовой установкой, и что автоматизация развёртывания у вас уже отработана.
*Красный флаг:* «пройдусь по машинам вручную и соберу в таблицу».

**3. Что такое вендорский лицензионный аудит и как к нему готовиться?**

Ответ: вендор (обычно Microsoft через партнёра, реже 1С, КриптоПро) запрашивает подтверждение легальности: количество лицензий по типам, число установок, редакции. Готовиться нужно заранее: держать в системе актуальный инвентарь, хранить подтверждающие документы (договоры, сертификаты, ключи), знать разницу между «куплено» и «установлено», учитывать CAL и мультилицензирование. Если обнаружено расхождение — легализовать (докупить) до подачи отчёта и зафиксировать план. Скрывать бесполезно: аудит по факту сверяет ваши же данные.

*Что хочет услышать интервьюер:* понимание, что аудит — это работа с документами и цифрами, а не «спрятать лишнее».
*Красный флаг:* «мы просто не отвечаем на письма вендора».

**4. Как считаются лицензии на Windows Server, и почему CAL — отдельная история?**

Ответ: сам Windows Server лицензируется по редакциям (Standard, Datacenter) и по ядрам/процессорам, а доступ пользователей и устройств к службам сервера требует клиентских лицензий CAL — отдельно на пользователя или на устройство. Для терминального доступа нужны RDS CAL, для виртуализации — свои правила редакций `[ПРОВЕРИТЬ актуальные условия у Microsoft]`. Поэтому на 50 сотрудников нельзя «просто купить один сервер»: нужен сервер + пул CAL, а если есть 1С-сервер и терминалы — ещё и лицензии 1С и RDS.

*Что хочет услышать интервьюер:* что вы не путаете серверную лицензию с клиентской.
*Красный флаг:* «CAL — это когда много пользователей», без понимания схемы подсчёта.

**5. Как вы поймёте, что в компании используется нелегальное ПО, и что сделаете?**

Ответ: сверяю отчёт «установлено» с реестром закупок: программы без лицензии, превышение числа мест, «серые» версии (бесплатные редакции, установленные в коммерческой среде), портативные сборки. Дальше — не «удалить и забыть», а заявка владельцу процесса: либо легализуем (докупка), либо удаляем с заменой на свободный аналог. Фиксирую решение в системе, чтобы при следующей сверке не было сюрпризов.

*Что хочет услышать интервьюер:* аккуратность и понимание, что это комплаенс-процесс, а не охота на ведьм.
*Красный флаг:* «сразу удаляю всё, что не в списке, без предупреждения».
