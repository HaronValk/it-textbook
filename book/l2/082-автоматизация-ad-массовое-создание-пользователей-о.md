# Автоматизация AD: массовое создание пользователей, отчёты, аудит неактивных учёток

## 1. Введение (зачем это нужно в реальной работе)

Понедельник, 9:12. В тикете — заявка от Петровой (HR, ВМ WIN10-CL02):

> «Здравствуйте! С этой недели выходят 5 новых кладовщиков, скидываю список. Нужно создать им учётки, доступ к `\\FS01\Obshchee` и чтобы в понедельник все работали. Ещё просьба: подготовьте отчёт — сколько у нас учёток, которые не заходили полгода, и кого можно блокировать. И на будущее: каждый месяц нужен такой список».

Дальше сценарий знакомый любому админу: если делать это руками через «Active Directory Users and Computers» (ADUC), пять человек — это 30 минут кликов, а если сотрудников 50 и один уволился, а другой вышел из декрета — начинается путаница. Через полгода никто не помнит, кто заводил учётку `temp_ivan_2` и зачем.

В L1 вы уже сдавали заявки на создание пользователей. На L2 вы должны уметь делать это пачкой, воспроизводимо и с журналом. После этой главы вы будете уметь:

- завести 50 учёток из CSV-файла одним запуском скрипта, с предварительной «сухой» проверкой;
- сделать скрипт **идемпотентным** — который можно запускать повторно без дублей и ошибок;
- строить отчёты по учётным записям в CSV, который нормально открывается в Excel у бухгалтера;
- находить неактивные, «никогда не входившие» и отключённые учётки — и понимать, почему `LastLogon` не равен `LastLogonDate`;
- проверять по журналу безопасности, кто и когда создавал/отключал учётки;
- удалять учётки безопасно (или не удалять вообще).

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Active Directory — это база данных (`NTDS.dit` на контроллере домена) плюс набор служб доступа к ней. Каждый объект — пользователь, группа, компьютер, OU — это запись с набором **атрибутов**. `SamAccountName`, `UserPrincipalName`, `Department`, `lastLogonTimestamp` — всё это атрибуты. «Создать пользователя» = создать объект класса `user` в контейнере (OU) и заполнить атрибуты.

Как PowerShell с этим общается:

```text
┌──────────────────────────┐        ┌────────────────────────────────────┐
│ DC01 (10.10.10.10)       │        │ Ваша сессия PowerShell             │
│  AD DS + DNS + DHCP      │        │  Import-Module ActiveDirectory     │
│  ┌────────────────────┐  │  LDAP  │  New-ADUser   ──┐                 │
│  │ NTDS.dit           │◀─┼───────▶│  Get-ADUser   ──┤                 │
│  │  OU=Company        │  │ 389/636│  Search-ADAccount┘                 │
│  │   ├─ Бухгалтерия   │  │        └────────────────────────────────────┘
│  │   ├─ HR            │  │
│  │   ├─ Склад  ◀──────┼──┼── создаём здесь
│  │   └─ IT            │  │
│  └────────────────────┘  │
│  DNS:53  Kerberos:88     │
│  SMB:445 RPC:135+dynamic │
└──────────┬───────────────┘
           │ репликация (если в стенде уже поднят DC02 10.10.10.11)
           ▼
      DC02 (10.10.10.11)
```

Порты и уровни, которые надо помнить наизусть:

| Что | Порт | Уровень |
|---|---|---|
| LDAP (запросы, изменения) | TCP 389 | L7 |
| LDAPS (шифрованный LDAP, используется по умолчанию современными средствами) | TCP 636 | L7 |
| Global Catalog | TCP 3268 / 3269 | L7 |
| Kerberos (аутентификация) | TCP/UDP 88 | L7 |
| DNS (поиск контроллера домена) | TCP/UDP 53 | L7 |
| SMB (доступ к `\\FS01\...`) | TCP 445 | L7 |
| RPC (часть операций ADUC, репликация) | TCP 135 + динамические | L4–L7 |

Ключевая идея для автоматизации: PowerShell-командлеты `*-AD*` — это **тонкая обёртка над LDAP**. Поэтому ошибки выглядят как LDAP-ошибки («directory object not found», «constraint violation»), а ограничения — как ограничения каталога (уникальность `SamAccountName` и `UserPrincipalName` в масштабе домена/леса).

Второй важный момент — **репликация**. В домене несколько контроллеров, и при записи на DC01 объект появится на DC02 не мгновенно. Отсюда классическая боль с атрибутами входа:

- `lastLogon` — точное время последнего входа **на конкретном контроллере**. Не реплицируется. Опросив один DC, вы увидите только входы через него.
- `lastLogonTimestamp` — реплицируемый атрибут, но обновляется **не при каждом входе**, а примерно раз в 14 дней (с рандомизацией, чтобы не было шторма репликации). Точность — «плюс-минус две недели».
- `LastLogonDate` — не атрибут AD вообще. Это свойство, которое командлеты AD **вычисляют** из `lastLogonTimestamp` и отдают как дату.

Практический вывод: для «отключить тех, кто не заходил 90 дней» `lastLogonTimestamp` подходит идеально (погрешность 14 дней на фоне 90 — ерунда). Для «когда сотрудник заходил в последний раз» — не подходит, нужен опрос всех DC по `lastLogon`.

## 3. Аналогия из жизни

AD — это гигантский паспортный стол с картотекой. Каждый ящик картотеки — OU (`Company → Склад`), в ящике лежат карточки людей, у карточки есть поля: фамилия, логин, отдел, отметка о последнем визите. `LDAP` — это язык, на котором вы разговариваете с регистратором: «дай мне все карточки из ящика Склад, у которых в поле “отключён” стоит галочка». Скрипт — это ваш помощник, который один раз заучил фразу и теперь повторяет её сто раз без ошибок и без перекуров.

А `lastLogon` и `lastLogonTimestamp` — это два разных журнала посещений: один вахтёр ведёт на каждом входе лично, но только на своём посту (и если человек зашёл через другой вход, этот вахтёр ничего не знает), а второй — общий журнал, куда запись переносится раз в две недели, зато он есть у всех постов сразу.

Где аналогия ломается: карточку из паспортного стола нельзя «удалить с возможностью восстановления за 180 дней», а в AD это штатная функция (AD Recycle Bin), и именно она спасает от последствий неудачного скрипта.

## 4. Практика и команды

Ниже — рабочий набор L2-админа. Всё выполняется на DC01 (или с машины с установленным RSAT, см. урок 81).

**1. Подготовка сессии и кодировки.** Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI — кириллица в OU (`OU=Склад`) превратится в мусор. Сохраняйте скрипты в UTF-8 **с BOM** и правьте вывод консоли:

```powershell
Import-Module ActiveDirectory
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
```

**2. Проверить CSV до запуска.** Правило «сначала посмотри, что импортируешь»:

```powershell
$rows = Import-Csv -Path 'C:\Scripts\AD\new-users.csv' -Encoding UTF8
$rows | Format-Table SamAccountName, FirstName, LastName, OU -AutoSize
$rows.Count
```

Смотрим: количество строк совпадает с ожидаемым, нет `$null` в `SamAccountName`, нет лишних пробелов. Если файл сохранял Excel в русской локали — разделитель будет `;`, тогда нужен `-Delimiter ';'` или `-UseCulture` (берёт разделитель из региональных настроек).

**3. Создать одного пользователя «начерно» — с `-WhatIf`.** `-WhatIf` есть у всех командлетов, меняющих AD; он показывает, что было бы сделано, и ничего не меняет:

```powershell
New-ADUser -Name "Тест Тестов" -SamAccountName test.tt -UserPrincipalName test.tt@corp.vektor.lab `
  -Path "OU=Склад,OU=Company,DC=corp,DC=vektor,DC=lab" -Enabled $true -WhatIf
```

Ключи: `-Path` — DN контейнера (не «путь в проводнике»), `-Enabled $true` — иначе учётка создастся отключённой (по умолчанию `New-ADUser` создаёт **disabled**-учётку).

**4. Создание с хэш-таблицей параметров (splatting).** Читабельнее и позволяет собирать параметры динамически:

```powershell
$p = @{
    Name                  = 'Морозов Дмитрий'
    GivenName             = 'Дмитрий'
    Surname               = 'Морозов'
    SamAccountName        = 'morozov'
    UserPrincipalName     = 'morozov@corp.vektor.lab'
    Path                  = 'OU=Склад,OU=Company,DC=corp,DC=vektor,DC=lab'
    Department            = 'Склад'
    Title                 = 'Кладовщик'
    AccountPassword       = (ConvertTo-SecureString 'Lab#2026-vektor' -AsPlainText -Force)
    Enabled               = $true
    ChangePasswordAtLogon = $true
}
New-ADUser @p
```

`-ChangePasswordAtLogon $true` — обязательный элемент нормальной работы: временный пароль должен быть сменён при первом входе. `-PasswordNeverExpires` мы **не** ставим (об этом в разделе 6).

**5. Идемпотентность: проверка «а он уже есть?»** Перед созданием — поиск по `SamAccountName`:

```powershell
$sam = 'morozov'
if (Get-ADUser -Filter "SamAccountName -eq '$sam'" -ErrorAction SilentlyContinue) {
    "уже существует — пропускаем"
} else {
    "создаём"
}
```

Обратите внимание: в `-Filter` подставляется строка, а не `{скриптблок}` — так переменная гарантированно раскрывается. `-ErrorAction SilentlyContinue` нужен, потому что `Get-ADUser` при отсутствии объекта кидает ошибку.

**6. Массовая выдача групп.** Группа из CSV, вложенность не важна — `Add-ADGroupMember` умеет принимать массив:

```powershell
Add-ADGroupMember -Identity 'GG-Sklad' -Members 'morozov'
Get-ADGroupMember -Identity 'GG-Sklad' -Recursive |
    Select-Object SamAccountName, objectClass
```

`-Recursive` раскрывает вложенные группы — без него вы увидите только прямых членов.

**7. Домашняя папка — это два действия, а не одно.** Атрибуты `-HomeDirectory`/`-HomeDrive` только пишут поля в AD; папку и права создаёте вы:

```powershell
New-Item -Path "\\FS01\Obshchee\Users\morozov" -ItemType Directory -Force
icacls "\\FS01\Obshchee\Users\morozov" /grant "VEKTOR\morozov:(OI)(CI)M"
Set-ADUser -Identity morozov -HomeDirectory "\\FS01\Obshchee\Users\morozov" -HomeDrive 'H:'
```

`(OI)(CI)M` — наследование на объекты и контейнеры, право Modify. В норме NTFS-права ставят на FS01 по локальному пути `D:\...`, а не по UNC — так меньше сюрпризов с правами на шару.

**8. Отчёт по всем пользователям в CSV для Excel.**

```powershell
Get-ADUser -Filter * -SearchBase "OU=Company,DC=corp,DC=vektor,DC=lab" `
  -Properties LastLogonDate, PasswordLastSet, Created, Description |
  Select-Object SamAccountName, Name, Enabled, Department, Title,
                LastLogonDate, PasswordLastSet, Created, Description |
  Sort-Object LastLogonDate |
  Export-Csv -Path 'C:\Scripts\AD\reports\users.csv' -NoTypeInformation -Encoding UTF8 -Delimiter ';'
```

`-Properties` обязателен: по умолчанию `Get-ADUser` отдаёт урезанный набор полей. `-NoTypeInformation` убирает первую строку `#TYPE`. `-Delimiter ';'` — чтобы русский Excel открыл файл без «мастера импорта».

**9. Найти неактивные учётки.**

```powershell
$cut = (Get-Date).AddDays(-90)
Search-ADAccount -AccountInactive -TimeSpan (New-TimeSpan -Days 90) -UsersOnly |
    Select-Object Name, SamAccountName, LastLogonDate, DistinguishedName
```

`Search-ADAccount` умеет ещё `-AccountDisabled`, `-PasswordNeverExpires`, `-LockedOut`, `-AccountExpired`. Важная деталь: `-AccountInactive` считает по `lastLogonTimestamp`, и учётки, **которые ни разу не входили**, в этот список по опыту часто не попадают — проверьте на стенде и доберите отдельным запросом:

```powershell
Get-ADUser -Filter * -Properties LastLogonDate |
    Where-Object { $null -eq $_.LastLogonDate -and $_.Enabled } |
    Select-Object SamAccountName, Created
```

**10. Точная дата входа — со всех контроллеров.** Только для одной-двух учёток, иначе долго:

```powershell
Get-ADDomainController -Filter * | ForEach-Object {
    Get-ADUser -Identity ivanov -Server $_.HostName -Properties lastLogon |
        Select-Object @{n='DC';e={$_.Server ?? $_.DistinguishedName}}, SamAccountName,
                      @{n='lastLogon';e={[datetime]::FromFileTime($_.lastLogon)}}
}
```

`lastLogon` хранится как `FILETIME` (число 100-нс интервалов с 1601 года) — поэтому `FromFileTime`.

**11. Мёртвые компьютерные учётки** — их забывают чаще, чем пользовательские:

```powershell
Get-ADComputer -Filter * -Properties LastLogonDate |
    Where-Object { $_.LastLogonDate -lt (Get-Date).AddDays(-90) } |
    Select-Object Name, LastLogonDate, DistinguishedName
```

**12. Аудит: кто создавал и отключал учётки.** Нужна включённая политика «Audit User Account Management» (она входит в Default Domain Controllers Policy по умолчанию на Server 2022 `[ПРОВЕРИТЬ на своём стенде]`):

```powershell
Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4720, 4722, 4725, 4726, 4728
    StartTime = (Get-Date).AddDays(-30)
} -MaxEvents 200 | Select-Object TimeCreated, Id, Message
```

ID: 4720 создание, 4722 включение, 4725 отключение, 4726 удаление, 4728 добавление в глобальную группу.

**13. Не удалять, а отключать и перемещать.**

```powershell
Disable-ADAccount -Identity morozov
Move-ADObject -Identity (Get-ADUser morozov).DistinguishedName `
  -TargetPath "OU=Disabled,OU=Company,DC=corp,DC=vektor,DC=lab"
```

А если удалили — спасает корзина AD (включается один раз на лес):

```powershell
Enable-ADOptionalFeature -Identity 'Recycle Bin Feature' `
  -Scope ForestOrConfigurationSet -Target corp.vektor.lab
Get-ADObject -Filter 'isDeleted -eq $true -and objectClass -eq "user"' `
  -IncludeDeletedObjects -Properties LastKnownParent
```

4. **DC01.** Сохранить скрипт `C:\Scripts\AD\New-VektorUsers.ps1` **в кодировке UTF-8 с BOM**:
   ```powershell
   [CmdletBinding(SupportsShouldProcess = $true)]
   param(
       [Parameter(Mandatory)][string]$CsvPath,
       [string]$LogDir = 'C:\Scripts\AD\logs'
   )
   Import-Module ActiveDirectory -ErrorAction Stop
   Start-Transcript -Path (Join-Path $LogDir ("create-users-{0}.log" -f (Get-Date -Format 'yyyyMMdd-HHmmss'))) | Out-Null

   $pwd  = ConvertTo-SecureString 'Lab#2026-vektor' -AsPlainText -Force
   $rows = Import-Csv -Path $CsvPath -Encoding UTF8
   $ok = 0; $skip = 0; $fail = 0

   foreach ($r in $rows) {
       $sam = $r.SamAccountName.Trim()
       try {
           if (Get-ADUser -Filter "SamAccountName -eq '$sam'" -ErrorAction SilentlyContinue) {
               Write-Host "SKIP $sam — уже существует"; $skip++; continue
           }
           $params = @{
               Name                  = "$($r.FirstName) $($r.LastName)"
               GivenName             = $r.FirstName
               Surname               = $r.LastName
               DisplayName           = "$($r.FirstName) $($r.LastName)"
               SamAccountName        = $sam
               UserPrincipalName     = "$sam@corp.vektor.lab"
               Path                  = $r.OU
               Department            = $r.Department
               Title                 = $r.Title
               AccountPassword       = $pwd
               Enabled               = $true
               ChangePasswordAtLogon = $true
               Description           = "Создан скриптом $(Get-Date -Format 'yyyy-MM-dd')"
           }
           if ($PSCmdlet.ShouldProcess($sam, 'Создание учётной записи')) {
               New-ADUser @params -ErrorAction Stop
               if ($r.Group) { Add-ADGroupMember -Identity $r.Group -Members $sam -ErrorAction Stop }
               Write-Host "OK   $sam"; $ok++
           }
       }
       catch {
           Write-Warning "FAIL $sam : $($_.Exception.Message)"; $fail++
       }
   }
   Write-Host "Итого: создано $ok, пропущено $skip, ошибок $fail"
   Stop-Transcript | Out-Null
   ```

## 6. Ошибки новичков и безопасность

1. **Сразу удалять (`Remove-ADUser`) вместо отключения.** → Учётки `sidorov` больше нет, а вместе с ней потеряны членство в группах, права на файлы и история. → Сначала `Disable-ADAccount`, потом перемещение в `OU=Disabled`, удаление — через 30–90 дней по регламенту и только после проверки, что объект не используется сервисами.
2. **Запускать массовый скрипт без `-WhatIf`.** → Пятьдесят учёток с опечаткой в DN или в отделе, и разбираться с этим вручную. → Всегда: `-WhatIf` → прогон на 1–2 строках → полный прогон → проверка отчётом.
3. **Неидемпотентный скрипт.** → Повторный запуск «на всякий случай» сыпет ошибками `The specified account already exists`, а при других сценариях — плодит дубли `ivanov2`, `ivanov_new`. → Проверка существования перед созданием (шаг 5 раздела 4).
4. **Пароль в открытом виде в CSV/скрипте.** → Утечка через общую папку, Git или почту. → Пароль генерируется в момент создания, передаётся по защищённому каналу, учётка требует смены при первом входе (подробно — урок 76).
5. **Верить `LastLogonDate` как точному времени.** → «Он не заходил с марта» — а на самом деле заходил вчера через другой контроллер домена. → Для отключения — да, для разговора с сотрудником — опрос всех DC по `lastLogon`.
6. **`Search-ADAccount -AccountInactive` как единственный источник.** → Учётки, которые не входили **никогда**, могут не попасть в список и останутся висеть живыми. → Дополнительный запрос по `LastLogonDate -eq $null`.
7. **CSV без `-Encoding` и без `-Delimiter`.** → В Excel «кракозябры» или весь файл в одной колонке; бухгалтерия возвращает отчёт со словами «у вас файл битый». → `-Encoding UTF8 -Delimiter ';' -NoTypeInformation`.
8. **Нет лога и транскрипта.** → Через месяц невозможно ответить на вопрос «кто создал эту учётку и когда». → `Start-Transcript` + запись в `stand-log.md` (а в проде — ещё и заявка в системах учёта изменений).

### Безопасность
- CSV со списком сотрудников (ФИО, должность, отдел) — это **персональные данные** (152-ФЗ, урок 78). Хранить их в `\\FS01\Obshchee` «чтобы все видели» нельзя: только отдельная папка с правами администраторов и HR.
- Массовые операции выполняются **отдельной учётной записью** с правами только на нужные OU, а не от `adm.student`/Domain Admin с вашего рабочего места. В идеале — JEA (Just Enough Administration) или делегирование прав на OU.
- Включите AD Recycle Bin **до** того, как она понадобится, и проверьте tombstone lifetime (по умолчанию 180 дней в современных лесах `[ПРОВЕРИТЬ в вашей версии]`).
- Любое массовое изменение в боевой среде — через согласование (change management), в окно работ, с предварительной резервной копией состояния системы контроллера домена.
- Аудит учётных записей безinclude политики аудита бессмысленен: сначала включаем «Audit User Account Management», потом строим отчёты по 4720/4725/4726.

## 7. Вопросы на собеседовании

**1. «Как вы создадите 150 учётных записей за один раз?»**
Ответ: готовлю CSV (логин, ФИО, отдел, OU, группа), проверяю импорт, пишу скрипт с `Import-Csv` + `New-ADUser` через splatting, с проверкой существования (`Get-ADUser -Filter "SamAccountName -eq '...'"`), `try/catch` на каждую строку, `Start-Transcript` в лог и обязательным `-WhatIf` перед боевым прогоном. Пароли — временные, с `ChangePasswordAtLogon = $true`, передача по защищённому каналу. После — сверка отчётом и запись о работах.
*Что хочет услышать интервьюер:* идемпотентность, логирование, dry-run, обработка частичных ошибок.
*Красный флаг:* «напишу цикл и запущу» — без проверки данных, без логов, без плана отката.

**2. «Чем `lastLogon` отличается от `lastLogonTimestamp` и что такое `LastLogonDate`?»**
Ответ: `lastLogon` — точное время входа, но обновляется только на том контроллере, который аутентифицировал пользователя, и не реплицируется. `lastLogonTimestamp` — реплицируемый атрибут, обновляется не чаще примерно раза в 14 дней, поэтому даёт погрешность до двух недель. `LastLogonDate` — вычисляемое свойство командлетов PowerShell (дата из `lastLogonTimestamp`), в самом каталоге такого атрибута нет. Для аудита «не заходил 90 дней» хватает `lastLogonTimestamp`; для точной даты — опрос всех DC по `lastLogon` и перевод из FILETIME.
*Что хочет услышать интервьюер:* понимание репликации и того, что «один DC — не истина».
*Красный флаг:* «LastLogonDate — это атрибут AD» или «lastLogon реплицируется».

**3. «Как найти неактивные учётки и что с ними делать дальше?»**
Ответ: `Search-ADAccount -AccountInactive -TimeSpan 90 -UsersOnly`, плюс отдельно учётки, которые ни разу не входили (`LastLogonDate -eq $null`), плюс `-AccountDisabled` и `-PasswordNeverExpires`. Дальше — не удаление, а процесс: отчёт согласуется с руководителями отделов, учётка отключается, перемещается в `OU=Disabled`, снимается с групп, дальше карантин 30–90 дней и только потом удаление. Исключения — сервисные учётки и учётки в длительном отпуске/декрете: их надо явно вынести в отдельный список, иначе отключите работающий сервис.
*Что хочет услышать интервьюер:* процесс, а не одна команда; понимание рисков и исключений.
*Красный флаг:* «найду и сразу удалю всё старше 90 дней».

**4. «Скрипт массово создал учётки не в том OU и с неверными отделами. Ваши действия?»**
Ответ: останавливаю дальнейшие запуски, фиксирую список затронутых объектов (по времени создания: `-Properties Created` + фильтр), оцениваю масштаб. Если объектов немного — исправляю атрибуты `Set-ADUser` и перемещаю `Move-ADObject` в правильный OU; если удаляли лишнее — восстанавливаю из AD Recycle Bin (`Get-ADObject -Filter 'isDeleted -eq $true' -IncludeDeletedObjects` + `Restore-ADObject`). Правлю скрипт (валидация DN и названий OU до создания), прогоняю на тестовом OU, оформляю постмортем: что сломалось, почему проверки не поймали, что меняем в процессе.
*Что хочет услышать интервьюер:* хладнокровие, знание Recycle Bin, работа с корневой причиной, а не «переделаю руками».
*Красный флаг:* «откачу весь контроллер домена из снапшота» без оговорок про USN rollback.

**5. «Как вы поймёте, что учётку создал не тот, кто должен был?»**
Ответ: по журналу Security на контроллерах домена — события 4720 (создан), 4725 (отключён), 4726 (удалён), 4728/4732 (добавлен в группу), с полями Subject (кто действовал) и Target (над кем). Плюс `Created`/`CreatedBy` в атрибутах объекта (`CreatedBy` требует `-Properties` `[ПРОВЕРИТЬ доступность в вашей версии схемы]`) и сверка с заявками в системе учёта. Если события аудита не включены — увидим только факт наличия объекта, поэтому политика аудита включается до инцидента, а логи с DC собираются в SIEM (урок 75).
*Что хочет услышать интервьюер:* знание конкретных Event ID и понимание, что без включённого аудита расследования не будет.
*Красный флаг:* «посмотрю `whenCreated`» как единственный ответ.
