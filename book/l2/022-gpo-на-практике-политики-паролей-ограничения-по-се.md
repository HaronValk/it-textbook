# GPO на практике: политики паролей, ограничения ПО, сетевые диски, принтеры, шаблоны ADMX

## 1. Введение (зачем это нужно в реальной работе)

Утро понедельника, в поддержку прилетают два тикета подряд.

**Тикет #4412** — Иван Иванов (`ivanov`), ВМ `WIN11-CL01`: «Добрый день! После обеда пропал диск H: с бухгалтерскими папками, диск U: на месте. У Марии Петровой на её компьютере всё открывается. Ещё у неё сам поставился сетевой принтер, а у меня нет».

**Тикет #4413** — Мария Петрова (`petrova`), ВМ `WIN10-CL02`: «Не могу поменять пароль на новый — система пишет, что пароль не соответствует требованиям политики. И ещё: запустила программу-клиент банка со склада, а она не открывается, пишет про ограничения».

Оба тикета — это одна тема. Групповые политики (Group Policy, GPO) — главный инструмент, которым админ в домене Windows управляет сотней настроек сразу на всех машинах: пароли, диски, принтеры, запрет ПО, обновления. В L1 вы в основном «смотрели, применилась ли политика». В L2 вы их создаёте, ломаете и чините.

После этой главы вы должны уметь: настраивать парольную и блокировочную политику домена там, где она реально работает; раздавать сетевые диски и принтеры через GPO и понимать, почему у одного пользователя они есть, а у другого нет; блокировать запуск нежелательного ПО; разворачивать центральное хранилище шаблонов ADMX и объяснять, зачем оно нужно; диагностировать неприменение политик по логам и gpresult.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

GPO — это объект в каталоге AD (класс `groupPolicyContainer`), а его содержимое физически лежит в общей папке SYSVOL на контроллерах домена. Клиент при загрузке и при входе пользователя читает SYSVOL по SMB (порт **445**), находит там файлы настроек и применяет их. Адрес GPO клиент узнаёт из AD по LDAP (**389**), а доступ к SYSVOL аутентифицируется Kerberos (**88**) — тема урока 20.

Внутри одного GPO две независимые половины: **Computer Configuration** и **User Configuration**. Компьютерная часть применяется при загрузке ВМ и в фоне (по умолчанию каждые 90 минут ± случайные 0–30 минут; на контроллерах домена — каждые 5 минут), пользовательская — при интерактивном входе и тоже в фоне. Настройки хранятся в `registry.pol` — это двоичный файл, который клиентская служба (CSE, client-side extension) «вкручивает» в реестр.

```
DC01 (10.10.10.10)
└── \\corp.vektor.lab\SYSVOL\corp.vektor.lab\
    └── Policies\
        ├── {31B2F340-...}\          <- GUID конкретного GPO
        │   ├── Machine\registry.pol     <- Computer Configuration
        │   ├── User\registry.pol        <- User Configuration
        │   └── Machine\Preferences\...  <- GPP: диски, принтеры, задачи
        └── Definition\                  <- ЦЕНТРАЛЬНОЕ ХРАНИЛИЩЕ ADMX
            ├── *.admx                   <- описания настроек (язык-нейтральные)
            └── ru-RU\*.adml             <- тексты на русском
```

Ключевое разделение, которое путают 80% новичков: **Policies vs Preferences**.

- **Policies** (раздел `Policies`, бывшие Administrative Templates + Security Settings) — «настоящие» политики. Пока GPO применяется, настройка держится; перестал применяться — настройка снимается и возвращается в «Не задано». Пользователь не может её изменить.
- **Preferences** (GPP, раздел `Preferences`) — расширение, появившееся в Windows Server 2008. Это не «политика», а автоматизированное действие: «создай диск», «создай принтер», «создай локального пользователя». Оно **татуируется**: если GPO убрать, созданный диск или принтер сам не исчезнет. Отсюда половина заявок «а почему у меня до сих пор эта хрень?».

Где что лежит в GPMC (Group Policy Management Console, `gpmc.msc`):

| Задача | Путь в редакторе GPO | Тип |
|---|---|---|
| Парольная политика | Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies → Password Policy | Policy |
| Блокировка учётки | ... → Account Policies → Account Lockout Policy | Policy |
| Сетевые диски | User Configuration → Preferences → Windows Settings → Drive Maps | GPP |
| Принтеры (по пользователю) | User Configuration → Preferences → Control Panel Settings → Printers | GPP |
| Принтеры (по компьютеру) | Computer Configuration → Policies → Windows Settings → Deployed Printers | Policy |
| Ограничение ПО | Computer Configuration → Policies → Windows Settings → Security Settings → Software Restriction Policies | Policy |
| AppLocker | ... → Security Settings → Application Control Policies → AppLocker | Policy |

Два важных нюанса про пароли. Первый: **настройки Account Policies действуют на доменные учётные записи, только если GPO прилинкован к корню домена** (`corp.vektor.lab`). Если прилинковать к OU — политика подействует лишь на *локальные* учётки компьютеров в этой OU. Доменная учётка живёт в каталоге, а не в OU с компьютерами. Второй: если на корне домена несколько GPO с Account Policies, побеждает одна — та, у которой выше приоритет по Link Order. Поэтому классика — держать пароли в `Default Domain Policy` и ничего другого туда не писать. Разные пароли для разных групп — это Fine-Grained Password Policy, урок 23.

Десктопные ограничения ПО бывают двух видов: **SRP** (Software Restriction Policies) — старый механизм, работающий на всех редакциях, и **AppLocker** — новый, но требующий Windows Enterprise/Education. На стенте у нас Enterprise-сборки, но в реальном офисе с Windows 11 Pro AppLocker не заработает — это ограничение лицензии, и об этом надо помнить.

**ADMX** — это XML-файлы, описывающие, какие настройки существуют и как они ложатся в реестр. Без ADMX оснастка не знает о существовании настройки. По умолчанию GPMC читает шаблоны из локальной папки `C:\Windows\PolicyDefinitions` того компьютера, где вы её запустили, — это плохо: у вас шаблоны Windows 11, у коллеги Windows 10, и вы видите разные настройки. Решение — **Central Store**: одна копия шаблонов в SYSVOL, которую читают все.

## 3. Аналогия из жизни

Представьте завод. GPO — это приказы директора, которые хранятся в канцелярии (SYSVOL). Приказ про пропускной режим (парольная политика) действует на всех, кто проходит через главную проходную домена, — и подействует, только если его вывесили именно на главной проходной, а не в цеху. Список запрещённых предметов на входе — это SRP. Разнарядка «кому какой инструмент и какой станок» — это GPP: мастер каждое утро обходит рабочих и выдаёт заново, а не прибивает к стене. И наконец, **бланки приказов** — это ADMX: пока в канцелярии нет типографского бланка «приказ о запрете съёмных носителей», директор физически не может такой приказ написать, даже если очень хочет.

Аналогия ломается в одном: приказ, прибитый к стене (настоящая Policy), при отмене снимают вместе с гвоздём, а вот выданную разнарядку (Preference) рабочий оставляет себе навсегда, даже если мастер про неё забыл.

## 4. Практика и команды

Все команды — из PowerShell на **DC01** под `VEKTOR\adm.student`, если не сказано иное.

**1. Посмотреть действующую парольную политику домена**
```powershell
Get-ADDefaultDomainPasswordPolicy
net accounts /domain
```
`Get-ADDefaultDomainPasswordPolicy` (модуль ActiveDirectory) показывает объект политики из AD; `net accounts /domain` — то же глазами утилиты. Смотрим `MinPasswordLength`, `ComplexityEnabled`, `LockoutThreshold`, `LockoutDuration`, `MaxPasswordAge`.
```
MinPasswordLength            : 7
ComplexityEnabled            : True
LockoutThreshold             : 0
MaxPasswordAge               : 42.00:00:00
```
`LockoutThreshold : 0` — блокировки нет вообще, подбор пароля не ограничен. Это первое, что проверяют на аудите.

**2. Выгрузить политику безопасности в файл**
```powershell
secedit /export /cfg C:\Temp\secpol.inf
```
`/cfg` — куда писать. Файл в формате INF, ищите секцию `[System Access]`: `MinimumPasswordLength`, `LockoutBadCount`, `PasswordComplexity`. Удобно для сравнения «до/после» и для диффа между серверами. На контроллере домена доменная политика — это и есть его локальная политика.

**3. Принудительно применить политики**
```powershell
gpupdate /force
gpupdate /force /target:user
gpupdate /force /target:computer /sync
```
`/force` — переприменить всё, даже неизменившееся. `/target` — только пользовательскую или только компьютерную часть. `/sync` — применить синхронно, не отпуская приглашение (нужно, когда делаете `gpresult` сразу после). `/boot` и `/logoff` — перезагрузка/выход после применения.

**4. Что реально применилось**
```powershell
gpresult /r /scope:computer
gpresult /h C:\Temp\gpo-WIN11-CL01.html /f
```
`/r` — краткий отчёт, `/scope` — только computer или только user, `/h` — HTML-отчёт (его можно приложить к заявке), `/f` — перезаписать файл. В `/r` смотрите блок «Объекты групповой политики, которые были применены» и, главное, «Объекты групповой политики, которые НЕ были применены» — там указана причина (Filtering: Not Applied — Security, Not Applied — WMI, Not Applied — Empty). Именно здесь чаще всего находится ответ на «политика не работает».

**5. Инвентаризация GPO в домене**
```powershell
Get-GPO -All | Select-Object DisplayName, GpoStatus, ModificationTime, Owner |
    Sort-Object ModificationTime -Descending
```
`GpoStatus` покажет `AllSettingsEnabled` / `ComputerSettingsDisabled` / `UserSettingsDisabled` — так находят GPO, у которых случайно выключена нужная половина.

**6. Полный отчёт по одному GPO**
```powershell
Get-GPOReport -Name "USR-Drive-Maps" -ReportType Html -Path C:\Temp\drives.html
```
`-ReportType Xml` — для машинной обработки и диффов, `Html` — для чтения. Незаменимо при разборе «кто изменил»: сравниваете XML-выгрузки за разные даты.

**7. Создать GPO и прилинковать к OU**
```powershell
New-GPO -Name "USR-Drive-Maps" -Comment "Диски U: и H: для пользователей"
New-GPLink -Name "USR-Drive-Maps" -Target "OU=Company,DC=corp,DC=vektor,DC=lab" -LinkEnabled Yes
```
`-Comment` — обязательная привычка, через полгода вы не вспомните, зачем это создали. Дальше настройки добавляются в редакторе (`gpmc.msc` → правой кнопкой по GPO → Изменить).

**8. Кто кого перекрывает**
```powershell
Get-GPInheritance -Target "OU=Company,DC=corp,DC=vektor,DC=lab"
```
Показывает цепочку прилинкованных GPO и `InheritanceBlocked`. Помните из урока 21: порядок применения — локальная политика → сайт → домен → OU (сверху вниз), внутри одного контейнера — по возрастанию Link Order. Здесь же видно, что реально победит.

**9. Бэкап и восстановление GPO**
```powershell
Backup-GPO -All -Path \\FS01\Obshchee\IT\GPO-Backup -Comment "перед изменением парольной политики"
Restore-GPO -Name "USR-Drive-Maps" -Path \\FS01\Obshchee\IT\GPO-Backup
```
`-All` — бэкапить всё; выгрузка делается в папку, внутри создаются подпапки с GUID. `Restore-GPO` восстанавливает из папки; если бэкапов несколько, добавляют `-BackupId` (GUID виден в `Get-GPOBackup -Path ...`). Это единственный цивилизованный способ откатить GPO, кроме снапшота.

**10. Проверка сетевых дисков на клиенте**
```powershell
net use
Get-SmbMapping
net use H: /delete
```
`net use` показывает буквы, UNC-пути и статус (`OK`, `Unavailable`, `Disconnected`). `Get-SmbMapping` — то же в PowerShell-объектах. `net use H: /delete` — снять зависшее подключение (частая причина «диск не мапится, буква занята»).

**11. Проверка принтеров на клиенте и сервере**
```powershell
Get-Printer | Select-Object Name, DriverName, PortName, Shared
Get-Printer -ComputerName FS01
Get-PrinterDriver -ComputerName FS01
Add-Printer -ConnectionName \\FS01\Vektor-Lab
```
`Get-Printer` — список очередей, `-ComputerName` — на удалённом сервере, `Get-PrinterDriver` — какие драйверы реально установлены (после PrintNightmare это критично). `Add-Printer -ConnectionName` подключает общий принтер вручную — так вы быстро проверяете, проблема в GPO или в самом принтере.

**12. Проверить наличие центрального хранилища ADMX**
```powershell
Get-ChildItem "\\corp.vektor.lab\SYSVOL\corp.vektor.lab\Policies\Definition\*.admx" | Measure-Object
Get-ChildItem "\\corp.vektor.lab\SYSVOL\corp.vektor.lab\Policies\Definition\ru-RU\*.adml" | Measure-Object
```
Если обе команды возвращают ноль — Central Store нет. В GPMC признак успеха: в редакторе GPO на разделе Administrative Templates внизу подпись «Policy definitions (ADMX files) retrieved from the central store».

**13. Лог групповой политики**
```powershell
Get-WinEvent -LogName "Microsoft-Windows-GroupPolicy/Operational" -MaxEvents 30 |
    Select-Object TimeCreated, Id, Message
```
Общий журнал применения GPO. Ошибки обработки настроек предпочтений (GPP) чаще попадают в журнал `Application` с источником вида «Group Policy Drive Maps» и кодом 4098 [ПРОВЕРИТЬ точный источник для вашей сборки].

Нужны: **DC01** (10.10.10.10, AD DS + DNS + DHCP, вход `VEKTOR\adm.student`), **FS01** (10.10.10.20, файловый сервер и сервер печати, папки `\\FS01\Obshchee` и `\\FS01\Buh`), **WIN11-CL01** (`ivanov`, член `GG-Buh`), **WIN10-CL02** (`petrova`, член `GG-HR`). ### Шаги

1. **DC01, зафиксировать «до».** В PowerShell выполните `Get-ADDefaultDomainPasswordPolicy` и `secedit /export /cfg C:\Temp\secpol-before.inf`. Ожидаемо: минимальная длина 7, сложность включена, `LockoutThreshold : 0`.

2. **DC01, парольная политика.** `gpmc.msc` → `corp.vektor.lab` → правой кнопкой по **Default Domain Policy** → Изменить → Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies. Настройте:

```text
Password Policy
  Enforce password history ................. 12
  Maximum password age ..................... 60
  Minimum password length .................. 10
  Password must meet complexity ........... Enabled
  Store passwords using reversible encryption ... Disabled
Account Lockout Policy
  Account lockout threshold ................ 5
  Account lockout duration ................. 15
  Reset account lockout counter after ...... 15
```

Ожидаемо: настройки сохранены, предупреждений нет. Почему сюда, а не в новый GPO: парольная политика домена должна быть ровно в одном месте, а `Default Domain Policy` — штатное место для неё; всё остальное из этого GPO давно пора вынести (см. раздел 6).

3. **DC01, применить и проверить.** `gpupdate /force`, затем `net accounts /domain`. Ожидаемо: `Minimum password length: 10`, `Lockout threshold: 5`. Пароль стенда `Lab#2026-vektor` (15 символов) проходит, никого не ломаем.

4. **DC01, GPO для дисков.** `New-GPO -Name "USR-Drive-Maps" -Comment "Диски U: и H:"` и прилинкуйте к `OU=Company,DC=corp,DC=vektor,DC=lab`. В GPMC: правой кнопкой по GPO → **GPO Status → Computer configuration settings disabled**. Затем Изменить → User Configuration → Preferences → Windows Settings → **Drive Maps** → New → Mapped Drive:

```text
General:  Action = Update,  Location = \\FS01\Obshchee,  Drive Letter = U,
          Label as = Obshchee,  Reconnect = включён
Common:   Item-level targeting → New Item → Security Group → VEKTOR\GG-Buh  (только для второго диска)
```
Второй элемент: `Action = Update`, `\\FS01\Buh`, буква `H:`, `Reconnect` включён, ILT по группе `GG-Buh`. Ожидаемо: в списке два элемента, у второго в колонке Targeting стоит `Y`.

5. **DC01, GPO для принтеров.** `New-GPO -Name "CMP-Printers"` → прилинковать к `OU=Компьютеры,DC=corp,DC=vektor,DC=lab`. Ожидаемо: GPO создан, в нём пока пусто.

6. **FS01, привязать принтер к GPO.** `printmanagement.msc` → Print Servers → FS01 → Printers → правой кнопкой по `Vektor-Lab` → **Deploy with Group Policy** → Browse → выбрать `CMP-Printers` → галочка на нужной архитектуре (x64) → Add → OK. Ожидаемо: «The operation completed successfully», в `Get-GPOReport -Name "CMP-Printers" -ReportType Xml -Path C:\Temp\p.xml` появилась запись в Deployed Printers.

7. **DC01, ограничение ПО.** `New-GPO -Name "SEC-AppControl"` → линк на `OU=Компьютеры`. Изменить → Computer Configuration → Policies → Windows Settings → Security Settings → **Software Restriction Policies** → правой кнопкой → New Software Restriction Policies. Затем: `Security Levels` оставить `Unrestricted` по умолчанию (важно — иначе заблокируете всё). `Additional Rules` → New Path Rule: Path = `C:\Tools\*.exe`, Security level = **Disallowed**. Ожидаемо: правило видно в списке.

8. **WIN11-CL01, подготовить тестовую папку.** В PowerShell от администратора: `New-Item -ItemType Directory C:\Tools -Force; Copy-Item C:\Windows\System32\notepad.exe C:\Tools\note.exe`. Запустите `C:\Tools\note.exe` — пока открывается. Ожидаемо: блокнот стартует.

9. **WIN11-CL01, применить и проверить.** `gpupdate /force`, выход и вход `ivanov`. Проверьте: в «Проводнике» появились `U:` (`Obshchee`) и `H:` (`Buh`); в «Устройства и принтеры» появился `Vektor-Lab` на FS01; запуск `C:\Tools\note.exe` даёт окно «Запуск этой программы запрещён политикой ограничения программ». Ожидаемо: все три эффекта.

10. **WIN10-CL02, проверить, что ILT держит.** Вход `petrova` → `gpupdate /force`, выход/вход. Ожидаемо: `U:` есть, `H:` **нет** (Петрова не в `GG-Buh`), принтер есть, `C:\Tools\note.exe` заблокирован. Если `H:` появился — ищите ошибку в ILT (пункт 4).

12. **DC01, Central Store.** Скопируйте папку `C:\Windows\PolicyDefinitions` с любой Windows 11 (можно с WIN11-CL01) на DC01, затем:
```powershell

New-Item -ItemType Directory -Path $cs -Force
Copy-Item "C:\Temp\PolicyDefinitions\*.admx" $cs
New-Item -ItemType Directory -Path "$cs\ru-RU" -Force
```

## 6. Ошибки новичков и безопасность

1. **Парольная политика в GPO, прилинкованном к OU с пользователями.** → На доменные учётки она не действует вообще, а вы уверены, что «настроили». → Парольная политика домена — только линк на корень `corp.vektor.lab`.
2. **Сваливать всё в `Default Domain Policy`.** → Один неосторожный клик ломает вход всему домену, а истории изменений нет. → В `Default Domain Policy` держим только Account Policies и Kerberos Policy, всё остальное — отдельными GPO.
3. **`Action = Create` для дисков.** → Диск создаётся один раз и больше не обновляется при смене пути на FS01. → Для своих управляемых дисков используйте `Update`; `Replace` — когда нужно полностью пересоздать; `Delete` — только осознанно.
4. **Забыть `Reconnect` в Drive Maps.** → После перезагрузки диск «пропадает». → Всегда проверяйте галочку `Reconnect`.
5. **SRP с default level `Disallowed` и пустым списком правил.** → Машина не может запустить вообще ничего, включая `explorer.exe`, и вы теряете удалённый доступ. → Сначала `Unrestricted` + точечные запреты; на боевой среде — сначала режим «только аудит» (для AppLocker) и пилотная группа.
6. **ADMX разложены в `C:\Windows\PolicyDefinitions` на DC.** → Каждый админ видит свой набор настроек, версии расходятся, часть политик «исчезает». → Единственный правильный путь — Central Store в SYSVOL.
7. **Скопировать `.admx` без `.adml`.** → В оснастке вместо текста настройки — «не удалось найти описание» и пустые поля. → Копируйте `.admx` в корень `Definition`, а `.adml` — в `Definition\ru-RU`.
8. **Хранить пароли в Group Policy Preferences.** → Уязвимость MS14-025: `cpassword` расшифровывается тривиально, патч просто запретил создавать такие элементы. → Пароли в GPP — никогда; для локальных админов — LAPS (урок 23).

### Безопасность

Никогда не отключайте фильтрацию и не раздавайте права на редактирование GPO «всем админам»: изменение GPO — это выполнение кода от `SYSTEM` на всех машинах домена сразу. Права на `Default Domain Policy` — только у узкой группы. Любое ограничение ПО сначала обкатывайте на одной OU и одной ВМ, а не на всём домене. И помните про PrintNightmare (CVE-2021-34527): после патчей установка драйверов принтера обычным пользователем запрещена, поэтому раздача принтеров через GPP от имени пользователя часто требует UAC, а через Deployed Printers (машинный контекст) — работает. Проверяйте политики `Point and Print Restrictions` и `Limits print driver installation to Administrators` [ПРОВЕРИТЬ точное имя во вашей сборке] — на боевой среде они должны быть настроены осознанно, а не «по умолчанию».

## 7. Вопросы на собеседовании

**Вопрос 1. Где в домене задаётся парольная политика и почему нельзя просто прилинковать GPO к OU с пользователями?**
Ответ: Account Policies — это настройки безопасности, которые для доменных учётных записей применяются только из GPO, прилинкованного к корню домена. Доменная учётка хранится в каталоге AD, её пароль проверяет контроллер домена, применяя политику домена. GPO на OU влияет только на локальные учётки компьютеров в этой OU. Если на корне несколько GPO с Account Policies, работает один — с высшим приоритетом по Link Order. Разные пароли для разных групп — только Fine-Grained Password Policy через `ADSI Edit` или `Get-ADFineGrainedPasswordPolicy`.
*Что хочет услышать:* чёткое «только на корень домена» и понимание, что FGPSO существует отдельно.
*Красный флаг:* «прилинкую к OU Бухгалтерия и бухгалтерам сделаю пароль длиннее».

**Вопрос 2. Чем настройки в разделе Policies отличаются от Preferences?**
Ответ: Policies — это настоящие политики: пока GPO применяется, значение держится в реестре и защищено от пользователя; когда GPO перестаёт применяться, настройка снимается. Preferences (GPP) — автоматизированные действия: создать диск, принтер, задачу, локального пользователя. Они «татуируются» в системе и после удаления GPO остаются, если не задан режим «применять один раз» или обратное действие. Плюс GPP поддерживает Item-Level Targeting, а политики — нет (там фильтрация, WMI и loopback, см. урок 21).
*Что хочет услышать:* разницу в поведении при отмене GPO и упоминание ILT.
*Красный флаг:* «это одно и то же, просто в разных папках».

**Вопрос 3. Как запретить запуск нежелательной программы, если у пользователей нет прав администратора? SRP или AppLocker?**
Ответ: Пользователи и так не могут менять `Program Files`, но могут запустить `.exe` из своей папки — значит нужен контроль по пути/хэшу/издателю. SRP умеет path rules, hash rules, certificate rules и работает на всех редакциях, включая Pro; в документации Microsoft он помечен как устаревший для Windows 10/11, но работает. AppLocker гибче (правила по издателю, DLL-правила, режим аудита, событийный журнал), но требует Enterprise/Education — на Pro не заработает, это лицензионное ограничение. В обоих случаях сначала режим аудита, потом пилотная OU, потом раскатка.
*Что хочет услышать:* знание лицензионного ограничения AppLocker и того, что раскатывать надо постепенно.
*Красный флаг:* «поставлю AppLocker на Windows 11 Pro» или «заблокирую всё и добавлю исключения».

**Вопрос 4. Пользователь пишет, что у него не появился сетевой диск. Ваши действия?**
Ответ: Сначала `net use` / `Get-SmbMapping` — диск вообще не создан или создан, но недоступен (это разные ветки). Потом `gpresult /r /scope:user` — применён ли GPO и нет ли в блоке «Not Applied» причины (фильтрация безопасности, WMI-фильтр, пустая половина GPO). Затем смотрим сам GPO через `Get-GPOReport`: Action (`Create`/`Update`/`Delete`), права на шару, Item-Level Targeting и членство в группе. Дальше — журнал Application на ошибки расширения Drive Maps. Проверяем, что клиент видит DC и SYSVOL по SMB.
*Что хочет услышать:* порядок «клиент → факт применения → содержимое GPO → права/ILT».
*Красный флаг:* сразу «перезапущу gpupdate /force пять раз» без сбора данных.

**Вопрос 5. Что такое Central Store и зачем он нужен?**
Ответ: Это папка `\\<домен>\SYSVOL\<домен>\Policies\Definition` в SYSVOL, куда один раз кладут `.admx` (язык-нейтральные описания настроек) и `.adml` в подпапку языка (`ru-RU`). Все GPMC в домене начинают читать шаблоны оттуда, а не из локального `C:\Windows\PolicyDefinitions`. Это даёт единый набор настроек для всех админов, отсутствие рассинхрона версий и возможность добавлять сторонние ADMX (Office, Chrome, 1С [ПРОВЕРИТЬ наличие ADMX у вашей версии 1С]). Шаблоны надо брать с самой новой ОС в парке — старые клиенты просто игнорируют незнакомые настройки.
*Что хочет услышать:* путь, состав (admx + adml) и проблему, которую решает.
*Красный флаг:* «ADMX надо ставить на каждый компьютер через GPO».
