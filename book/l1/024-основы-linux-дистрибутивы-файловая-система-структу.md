## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Что такое Linux.** Строго говоря, Linux — это ядро (kernel). Всё остальное — программы вокруг него: оболочка (shell), утилиты, библиотеки, менеджер пакетов. Вместе это называется «дистрибутив». Ядро одно, дистрибутивов — сотни.

**Из чего состоит дистрибутив:**

```text
+---------------------------------------------------+
|  Прикладное ПО: nginx, ssh, bash, coreutils       |
+---------------------------------------------------+
|  Менеджер пакетов: apt (deb) / dnf (rpm) / apk    |
+---------------------------------------------------+
|  Системные библиотеки: glibc, systemd, openssl    |
+---------------------------------------------------+
|  Ядро Linux (kernel)                              |
+---------------------------------------------------+
|  Аппаратура (или виртуалка VMware)                |
+---------------------------------------------------+
```

**Семейства дистрибутивов** (важно для L1, потому что команды отличаются):

| Семейство | Пакеты | Примеры | Где встречается в РФ |
|-----------|--------|---------|----------------------|
| Debian | `.deb`, `apt` | Debian, Ubuntu, Astra Linux, РЕД ОС | серверы, рабочие места госсектора |
| Red Hat | `.rpm`, `dnf`/`yum` | RHEL, CentOS Stream, AlmaLinux, Rocky, ALT | корпоративные серверы, ALT в школах/госсекторе |
| SUSE | `.rpm`, `zypper` | openSUSE, SLES | реже, но встречается |
| Arch | `.pkg.tar.zst`, `pacman` | Arch, Manjaro | почти не в бизнесе |

На нашем стенде UBU01 — Ubuntu Server 24.04 (семейство Debian, пакеты `apt`). В уроке 30 появится ASTRA01 — тоже Debian-семейство, но со своими особенностями. Debian в стенд не входит, только для сравнения в тексте.

**Файловая система.** В Linux нет дисков `C:`, `D:`. Есть одно дерево, корень — `/`. Любой диск, раздел, сетевая папка «монтируется» (подключается) в точку этого дерева. Даже флешка становится папкой, например `/media/adm.student/USB`.

**Стандарт FHS — где что лежит.** Это не «рекомендация», а де-факто закон: любой админ и любой скрипт ожидают, что конфиги в `/etc`, логи в `/var/log`, а не наоборот.

```text
/                       корень
├── bin -> usr/bin      базовые команды (ls, cp, cat)
├── sbin -> usr/sbin    команды админа (mount, ip)
├── boot                ядро и загрузчик
├── dev                 устройства (диски, терминалы)
├── etc                 КОНФИГИ (текстовые файлы)
├── home                домашние папки пользователей
│   └── adm.student
├── lib, lib64          библиотеки
├── media, mnt          временные точки монтирования
├── opt                 стороннее ПО (не из пакетов)
├── proc, sys           виртуальные ФС ядра (в памяти)
├── root                домашняя папка root
├── run                 runtime-данные служб (в памяти)
├── srv                 данные сервисов (веб, ftp)
├── tmp                 временные файлы, чистится
├── usr                 программы и их данные
│   ├── bin, sbin
│   ├── lib
│   └── share           документация, man
└── var                 ИЗМЕНЯЕМЫЕ данные
    ├── log             логи
    ├── lib             состояние служб (БД, кэши)
    ├── spool           очереди (печать, почта)
    └── www             веб-контент (на Debian/Ubuntu)
```

Запомни три кита: **`/etc` — настройки, `/var` — меняется, `/home` — пользователи.** 90% вопросов L1 закрываются этим правилом.

**Права и владельцы.** У каждого файла есть владелец (user), группа (group) и три набора прав: для владельца, для группы, для остальных. Права бывают `r` (чтение), `w` (запись), `x` (выполнение). Подробно — в уроке 25, здесь достаточно узнавать вывод `ls -l`.

**Порты и протоколы** (пригодятся позже, но упомянуть надо): SSH — TCP/22, HTTP — TCP/80, HTTPS — TCP/443. На UBU01 сейчас работает только SSH.

## 3. Аналогия из жизни

Представь большой офисный центр. Корень `/` — это адрес здания. `/etc` — щиток с электрикой и документацией: там лежат инструкции, как всё настроено, но сами сотрудники там не сидят. `/home` — кабинеты сотрудников, у каждого свой, с личными вещами. `/var/log` — журнал охраны на входе: туда пишется, кто вошёл, кто вышел, что сломалось. `/usr/bin` — склад инструментов: молотки, отвёртки, все ими пользуются, но никто не хранит их у себя в кабинете. `/tmp` — стол в переговорной: положил, поработал, ушёл, уборщица выбросит. `/opt` — арендованное помещение под чужую фирму: она сама решает, что там внутри.

Аналогия ломается на одном: в реальном здании нельзя «приделать» новый этаж к существующему, а в Linux можно — это называется монтирование, и диск `/dev/sdb1` может внезапно оказаться папкой `/data`.

## 4. Практика и команды

Все команды — на UBU01 под `adm.student`. Часть требует `sudo` (пароль `Lab#2026-vektor`).

**1. Где я и кто я.**

```bash
pwd
whoami
id
```

`pwd` — print working directory, показывает текущий каталог. `whoami` — под кем я. `id` — uid, gid и группы. Пример вывода:

```text
adm.student@ubu01:~$ pwd
/home/adm.student
adm.student@ubu01:~$ whoami
adm.student
adm.student@ubu01:~$ id
uid=1000(adm.student) gid=1000(adm.student) groups=1000(adm.student),27(sudo)
```

Смотрим: я в домашней папке, я в группе `sudo` — значит, могу выполнять команды от root через `sudo`.

**2. Что в корне.**

```bash
ls -la /
```

`-l` — длинный формат, `-a` — включая скрытые (начинаются с точки). Примерно:

```text
drwxr-xr-x   19 root root  4096 ... bin -> usr/bin
drwxr-xr-x    4 root root  4096 ... boot
drwxr-xr-x   95 root root  4096 ... etc
drwxr-xr-x    3 root root  4096 ... home
drwx------    5 root root  4096 ... root
drwxrwxrwt   12 root root  4096 ... tmp
drwxr-xr-x   14 root root  4096 ... usr
drwxr-xr-x   13 root root  4096 ... var
```

Стрелка `->` — симлинк (символическая ссылка). `bin -> usr/bin` значит, что `/bin` — это ссылка на `/usr/bin`, так сделано в современных Ubuntu.

**3. Дерево каталогов.**

```bash
tree -L 1 /
```

`-L 1` — глубина один уровень. Если `tree` не установлен (по умолчанию в Ubuntu Server его нет), поставь позже в уроке 27 через `sudo apt install tree` или используй `ls /`. Здесь просто запомни команду.

**4. Где лежит программа.**

```bash
which ls
which ssh
type cd
```

`which` ищет исполняемый файл в `$PATH`. Примерно:

```text
/usr/bin/ls
/usr/bin/ssh
cd is a shell builtin
```

`cd` — встроенная команда оболочки, файла на диске нет. Это нормально.

**5. Что за файл.**

```bash
file /etc/hostname
file /bin/ls
```

`file` определяет тип по содержимому, а не по расширению (в Linux расширения почти ничего не значат). Примерно:

```text
/etc/hostname: ASCII text
/bin/ls: ELF 64-bit LSB pie executable, x86-64, ...
```

**6. Конфиги — в `/etc`.**

```bash
ls /etc | head -20
cat /etc/hostname
cat /etc/os-release
```

`head -20` — первые 20 строк. `/etc/os-release` — универсальный файл, где любой дистрибутив пишет своё имя и версию. Примерно:

```text
PRETTY_NAME="Ubuntu 24.04 LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
```

Это первое, что смотрят при заявке «у меня Linux, не знаю какой».

**7. Логи — в `/var/log`.**

```bash
ls -l /var/log
sudo tail -n 20 /var/log/syslog
```

`tail -n 20` — последние 20 строк. `syslog` — основной системный журнал в Ubuntu. Читать его без `sudo` обычно нельзя — файл принадлежит группе `adm` или `syslog`. Подробно про чтение логов — урок 28.

**8. Свободное место.**

```bash
df -h
du -sh /var/log
```

`df -h` — сколько занято на каждом смонтированном разделе, `-h` — human-readable (в гигабайтах, а не в блоках). `du -sh` — сколько занимает конкретная папка. Примерно:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        24G  4.1G   19G  18% /
/dev/sda1       1.1G  6.2M  1.1G   1% /boot/efi
```

Если `/` заполнен на 100% — типичная авария, из-за которой не стартуют службы. `du -sh /var/log/*` покажет, кто виноват.

**9. Домашняя папка и скрытые файлы.**

```bash
ls -la ~
```

`~` — сокращение для `/home/adm.student`. Скрытые файлы (`.bashrc`, `.ssh`, `.profile`) — это настройки пользователя, они начинаются с точки.

**10. Точки монтирования.**

```bash
mount | grep '^/dev'
findmnt /
```

`mount` без аргументов показывает всё, что смонтировано. `findmnt` — современнее и читаемее. Примерно:

```text
/        /dev/sda2  ext4  rw,relatime
/boot/efi /dev/sda1 vfat  rw,...
```

**11. Справка.**

```bash
man ls
ls --help
man 5 passwd
```

`man` — встроенная документация. `man 5 passwd` — раздел 5 (форматы файлов), а не раздел 1 (команды). Разделы man: 1 — команды, 5 — форматы файлов, 8 — админские команды. Выход из `man` — клавиша `q`.

**12. Поиск файла по имени.**

```bash
find /etc -name 'ssh*' 2>/dev/null
```

`find` ищет по дереву, `-name` — по шаблону, `2>/dev/null` — выбросить ошибки «permission denied» в мусор. Примерно:

```text
/etc/ssh
/etc/ssh/ssh_config
/etc/ssh/sshd_config
```

**13. Через GUI (для сравнения).** На Ubuntu Server графики нет. На десктопных Ubuntu/Astra файловый менеджер — «Файлы» (Nautilus), корень открывается через `Other Locations → Computer`. На Windows аналог — «Этот компьютер», но там диски, а здесь одно дерево.


1. Проверь права и владельца:

    ```bash
    ls -l /var/log/syslog
    ```

2. Проверь, в каких группах ты:

    ```bash
    id
    ```

    Ожидаемо: `adm` в списке нет.

3. Убедись, что дело именно в правах, а не в отсутствии файла:

    ```bash
    ls -l /var/log | grep syslog
    ```

    Файл есть, но читать нельзя.

- Прочитать через `sudo` (правильно для разовой диагностики):

    ```bash

    ```

- Добавить `adm.student` в группу `adm` (правильно, если человеку это нужно постоянно):

    ```bash
    sudo usermod -aG adm adm.student
    ```

    После этого нужно **перелогиниться** (выйти из SSH и зайти снова), иначе группа не подхватится. Проверить: `id` покажет `adm`.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** искать диски `C:`, `D:` в Linux.
   **К чему приводит:** путаница, попытки «найти диск» вместо монтирования.
   **Как правильно:** одно дерево от `/`, всё остальное — точки монтирования (`df -h`, `findmnt`).

2. **Ошибка:** хранить данные в `/tmp`.
   **К чему приводит:** файлы исчезают после перезагрузки или через несколько дней (systemd-tmpfiles чистит).
   **Как правильно:** данные — в `/home`, `/srv`, `/opt` или на отдельном смонтированном разделе.

3. **Ошибка:** править конфиги в `/etc` без бэкапа.
   **К чему приводит:** сломанная служба, не стартует SSH или сеть.
   **Как правильно:** `cp file file.bak` перед правкой, а лучше — через `sudoedit` и с записью в журнал изменений.

4. **Ошибка:** работать под `root` постоянно.
   **К чему приводит:** одна опечатка в `rm -rf` — и нет системы.
   **Как правильно:** обычный пользователь + `sudo` на конкретные команды. На стенде `adm.student` уже в группе `sudo`.

5. **Ошибка:** считать, что расширение `.exe` или `.txt` что-то значит.
   **К чему приводит:** неверные ожидания, «файл не запускается».
   **Как правильно:** `file имя` — определяет тип по содержимому; `chmod +x` — делает файл исполняемым.

6. **Ошибка:** путать `/etc` и `/var`.
   **К чему приводит:** логи ищут в `/etc`, конфиги — в `/var/log`, ничего не находят.
   **Как правильно:** `/etc` — статика (настройки), `/var` — динамика (логи, БД, кэши).

7. **Ошибка:** игнорировать `df -h` при «сервер тормозит».
   **К чему приводит:** не замечают, что `/` заполнен на 100%, и лечат не то.
   **Как правильно:** при любой «сервер не отвечает» — первым делом `df -h` и `du -sh /var/log/*`.

8. **Ошибка:** ставить пакеты «наугад» без понимания семейства.
   **К чему приводит:** `apt` на RHEL или `dnf` на Ubuntu — команда не найдена.
   **Как правильно:** сначала `cat /etc/os-release`, потом выбирать `apt` или `dnf`.

### Безопасность

- **Не отключай SSH-пароль и не давай `root` логиниться по SSH** «чтобы удобнее» — это прямой путь к взлому. На стенде это учебно, в бою — инцидент ИБ.
- **Не давай `chmod 777`** на файлы и папки «чтобы работало». Это открывает запись всем, включая веб-процессы, и превращается в уязвимость.
- **Не храни пароли в открытом виде** в `/home` или `/etc`. На стенде пароль `Lab#2026-vektor` — учебный, в реальной среде так нельзя.
- **Не запускай `rm -rf /` и подобное** даже «для проверки». На стенде это сломает ВМ, в бою — уволит.
- **Помни про 152-ФЗ:** если на Linux-сервере лежат персональные данные (например, выгрузки бухгалтерии), доступ к `/home` и `/var` должен быть ограничен и логироваться.

## 7. Вопросы на собеседовании

**Вопрос 1. Чем отличаются дистрибутивы Linux?**
Как спросят: «Ubuntu и CentOS — в чём разница для админа?»
Ответ: «Ядро одно, различия — в менеджере пакетов, версиях библиотек и политике обновлений. Ubuntu и Debian используют `apt` и `.deb`, RHEL/CentOS/Alma/Rocky — `dnf` и `.rpm`. В РФ ещё важны Astra Linux и РЕД ОС (Debian-семейство) и ALT (RPM). Для L1 главное — быстро определить семейство через `cat /etc/os-release` и не путать команды».
Что хочет услышать: понимание, что «Linux» — это не одна ОС, и умение адаптироваться.
Красный флаг: «Linux — это Ubuntu, остальное не Linux».

**Вопрос 2. Где в Linux лежат конфиги, логи и данные приложения?**
Как спросят: «Куда смотреть, если служба не работает?»
Ответ: «Конфиги — `/etc`, логи — `/var/log`, изменяемые данные служб — `/var/lib`, стороннее ПО — `/opt`, данные веб-сервера на Debian/Ubuntu — `/var/www`. Домашние папки пользователей — `/home`. Это стандарт FHS, любой админ и скрипт на него рассчитывают».
Что хочет услышать: знание FHS на уровне рефлекса.
Красный флаг: «Логи в `/etc`» или «не знаю, где логи».

**Вопрос 3. Что такое точка монтирования?**
Как спросят: «Почему в Linux нет диска D:?»
Ответ: «В Linux одно дерево от корня `/`. Любой диск, раздел или сетевую папку подключают в точку этого дерева — это и есть точка монтирования. Смотреть текущие — `df -h` или `findmnt`. Флешка, например, монтируется в `/media/<user>/<label>`».
Что хочет услышать: понимание модели «одно дерево».
Красный флаг: «Диски ищут в `/dev` и работают с ними напрямую как с файлами».

**Вопрос 4. Сервер «тормозит», с чего начнёшь на Linux?**
Как спросят: «Пользователь говорит, что сервер не отвечает. Твои первые команды?»
Ответ: «Сначала `df -h` — не заполнен ли корень. Потом `free -h` — память, `uptime` — нагрузка, `systemctl status <служба>` — жива ли служба, `tail /var/log/syslog` — что пишет система. Если `/` на 100% — ищу виновника через `du -sh /var/log/*` и чищу старые логи».
Что хочет услышать: алгоритм, а не «перезагружу».
Красный флаг: «Сразу перезагружу сервер».

**Вопрос 5. Чем `sudo` отличается от входа под `root`?**
Как спросят: «Почему не работают под root постоянно?»
Ответ: «`sudo` даёт выполнить конкретную команду от root, при этом действия логируются в `/var/log/auth.log`, и обычный пользователь не может случайно снести систему. Постоянная работа под root — это отсутствие аудита и один `rm -rf` от катастрофы. В бою root-логин по SSH обычно запрещён».
Что хочет услышать: понимание модели безопасности.
Красный флаг: «Работаю только под root, так удобнее».
