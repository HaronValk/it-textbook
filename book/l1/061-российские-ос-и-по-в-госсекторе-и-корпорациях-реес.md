## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

### Что такое реестр отечественного ПО

**Реестр российского программного обеспечения** — это официальный список ПО, которое признано российским (по критериям правообладания, суммы отчислений в РФ и т. д.). Ведёт его Минцифры, публикует на портале `reestr.digital.gov.ru`. Запись в реестре — это юридический факт, а не техническая характеристика: софт может быть в реестре, но плохо работать, и наоборот.

Зачем это L1: в госструктурах и госкомпаниях закупка ПО вне реестра часто запрещена или требует обоснования. Когда пользователь просит «поставьте мне Photoshop», ответ может быть не «нет бюджета», а «этого нет в реестре, использовать нельзя». L1 должен уметь проверить: есть ли программа в реестре, и если нет — предложить аналог из реестра.

### Импортозамещение: три уровня

Импортозамещение идёт не одной волной, а тремя:

1. **ОС** — Astra Linux, РЕД ОС, ALT, Rosa, ОС «Альт Образование» и т. д.
2. **Офисный пакет** — Р7-Офис, МойОфис, LibreOffice (не в реестре как российский, но свободный).
3. **Прикладное ПО** — 1С, КриптоПро CSP, браузеры (Яндекс Браузер, Atom), почта, ЭДО, ВКС.

Плюс отдельно — **доверенные ПАК** (программно-аппаратные комплексы) и **сертифицированные ФСТЭК** версии ОС для работы с гостайной.

### Где это живёт в архитектуре

```text
┌──────────────────────────────────────────────────────────────┐
│ Пользователь (сотрудник «Вектора»)                           │
├──────────────────────────────────────────────────────────────┤
│ Прикладной слой: 1С, Р7-Офис, КриптоПро, браузер, ЭДО       │
├──────────────────────────────────────────────────────────────┤
│ ОС: Windows 10/11  ИЛИ  Astra Linux / РЕД ОС / ALT           │
├──────────────────────────────────────────────────────────────┤
│ Инфраструктура: AD (Windows) или Samba/FreeIPA (Linux)       │
├──────────────────────────────────────────────────────────────┤
│ Железо / виртуализация (VMware, Proxmox, Hyper-V)            │
└──────────────────────────────────────────────────────────────┘
```

Ключевой момент для L1: **прикладной слой зависит от ОС**. 1С есть под Windows и под Linux, но установщики разные. КриптоПро CSP — тоже под обе платформы, но плагин для браузера отдельный. Р7-Офис — под обе. А вот, скажем, Microsoft Office под Linux нет вообще, поэтому на Astra Linux его физически не поставить.

### Типовые протоколы и порты, которые всплывают при миграции

- **SMB (445/tcp)** — общие папки. Astra Linux умеет монтировать `\\FS01\Obshchee` через `cifs-utils`, но путь и учётка должны быть в формате домена.
- **LDAP (389/tcp) и LDAPS (636/tcp)** — вход Linux в AD. На стенде это делается на уроке 50 (SSSD/realmd или Samba) [ПРОВЕРИТЬ в твоей версии].
- **Kerberos (88/tcp)** — часть аутентификации в AD.
- **RDP (3389/tcp)** — с Linux на Windows через `xfreerdp` или `remmina`.
- **CUPS (631/tcp)** — печать на Linux.

### Реестр vs «сертифицированная версия»

Отдельно запомни: **«в реестре» ≠ «сертифицировано ФСТЭК»**. Astra Linux есть в двух вариантах: обычная (в реестре) и «Astra Linux Special Edition» с сертификатом ФСТЭК для работы с гостайной. Для L1 это значит: если пользователь в защищённом контуре, ставить туда «обычную» Astra нельзя, даже если она в реестре.

## 3. Аналогия из жизни

Представь, что ты переезжаешь в другую страну. У тебя есть любимая кофемашина (Microsoft Office), но в новой стране розетки другие (Linux). Ты можешь купить переходник (Wine, PlayOnLinux) — иногда работает, иногда искрит. Можешь купить местную кофемашину (Р7-Офис, LibreOffice) — она варит кофе, но кнопки расположены иначе, и любимый сорт капсул (макросы VBA, шаблоны `.docm`) может не подойти. А можешь держать обе кофемашины на кухне (dual-boot или Windows-VM на Linux) — но это две розетки, два места и объяснение каждому гостю, какая для чего.

Аналогия ломается в одном: кофемашина не обязана быть «в реестре», а софт в госсекторе — обязан, и это юридическое требование, а не вопрос удобства.

## 4. Практика и команды

### 4.1. Проверить, что за ОС перед тобой (Linux)

```bash
cat /etc/os-release
```

Ключи: без ключей, читает файл. Смотрим поля `NAME`, `VERSION`, `ID`, `PRETTY_NAME`. На Astra Linux будет `ID=astra`, на Ubuntu — `ID=ubuntu`, на РЕД ОС — `ID=redos` [ПРОВЕРИТЬ точное значение для твоей версии].

Пример вывода (примерно):

```text
NAME="Astra Linux (Orel)"
VERSION="2.12"
ID=astra
PRETTY_NAME="Astra Linux (Orel) 2.12"
```

### 4.2. Узнать версию ядра и архитектуру

```bash
uname -a
```

Смотрим: ядро, архитектура (`x86_64`), хостнейм. Полезно, когда пользователь говорит «у меня Linux», а надо понять, 32 или 64 бита и какое ядро — от этого зависит, какой пакет качать.

### 4.3. Проверить, установлен ли офисный пакет (Linux)

```bash
dpkg -l | grep -Ei 'r7|myoffice|libreoffice'
```

`dpkg -l` — список установленных пакетов в Debian-семействе (Astra, Ubuntu). `grep -Ei` — регистронезависимый поиск по нескольким словам. Если пусто — пакета нет.

### 4.4. Установить LibreOffice на Ubuntu/Astra (если разрешено политикой)

```bash
sudo apt update
sudo apt install -y libreoffice
```

`-y` — не спрашивать подтверждения. На Astra Linux репозитории могут быть свои, и `apt update` иногда ругается на недоступность зеркал [ПРОВЕРИТЬ в твоей версии]. В рабочей среде установку ПО вне утверждённого списка надо согласовывать.

### 4.5. Посмотреть, чем открывается файл `.odt` в Windows

В PowerShell на WIN10-CL02:

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Classes\.odt' -ErrorAction SilentlyContinue
```

Смотрим значение `(default)` — это ProgID, например `LibreOffice.WriterDocument.1` или `R7Office.Document`. Если ключа нет — Windows не знает, чем открывать `.odt`, и пользователь видит «чем открыть?».

### 4.6. Проверить установленный офис в Windows

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*',
                 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -match 'Office|Libre|Р7|R7|МойОфис' |
  Select-Object DisplayName, DisplayVersion
```

`Get-ItemProperty` читает ключи реестра, `Where-Object` фильтрует по имени, `Select-Object` оставляет нужные поля. Так L1 за минуту видит, что реально стоит на машине.

### 4.7. Проверить, есть ли программа в реестре отечественного ПО

Через браузер на WIN11-CL01: открыть `reestr.digital.gov.ru`, в поиске ввести название («Р7-Офис», «Astra Linux», «КриптоПро CSP»). Смотрим: класс ПО, правообладатель, дата включения. Скриншот — в заявку.

### 4.8. Смонтировать общую папку с FS01 на Linux (Astra/Ubuntu)

```bash
sudo apt install -y cifs-utils
sudo mkdir -p /mnt/obshchee
sudo mount -t cifs //10.10.10.20/Obshchee /mnt/obshchee -o username=ivanov,domain=VEKTOR
```

`-t cifs` — тип файловой системы SMB/CIFS, `-o` — опции монтирования. Пароль спросит интерактивно. На стенде FS01 появится только в уроке 46, поэтому до него команду выполнять не на чем — это справочный пример.

### 4.9. Посмотреть, какие процессы запущены (что реально работает)

```bash
ps aux | grep -Ei 'r7|libre|1c'
```

`ps aux` — все процессы, `grep` — фильтр. Так видно, запущен ли офис вообще, или пользователь кликает по ярлыку, а процесс падает.

### 4.10. Проверить сетевую доступность сервера обновлений/лицензий

```bash
ping -c 4 10.10.10.10
```

`-c 4` — четыре пакета и выход. На стенде ICMP разрешён на всех ВМ, ответ будет. В рабочей среде сервер лицензий 1С или сервер обновлений может не отвечать на ping — тогда проверяем порт через `nc -zv 10.10.10.10 1540` (порт сервера 1С, [ПРОВЕРИТЬ]).

## 6. Ошибки новичков и безопасность

1. **Ошибка:** «В реестре — значит, можно ставить куда угодно».
   **К чему приводит:** установка несертифицированной версии в защищённый контур, нарушение требований ФСТЭК/регулятора.
   **Как правильно:** проверять не только наличие в реестре, но и класс ПО и наличие сертификата, если контур защищённый.

2. **Ошибка:** «Astra Linux — это как Ubuntu, разницы нет».
   **К чему приводит:** команды `apt` работают, но репозитории, пути и версии пакетов отличаются; инструкция с Ubuntu ломается на Astra.
   **Как правильно:** всегда начинать с `cat /etc/os-release` и сверять с документацией именно этого дистрибутива.

3. **Ошибка:** «Поставлю LibreOffice вместо Р7-Офис, раз оба открывают `.odt`».
   **К чему приводит:** в госструктуре LibreOffice может быть не в реестре как российский, и его использование вне утверждённого списка — нарушение.
   **Как правильно:** уточнять у ИБ/закупок, что разрешено; LibreOffice — только если политика компании это допускает.

4. **Ошибка:** «Пользователь просит Microsoft Office на Astra Linux — поставлю через Wine».
   **К чему приводит:** нестабильная работа, потеря данных, неработающие макросы, и всё это — вне поддержки.
   **Как правильно:** объяснить пользователю, что MS Office под Linux официально не поддерживается, предложить Р7-Офис/МойОфис/LibreOffice.

5. **Ошибка:** «Скопирую файл `.docm` с макросами на Linux-машину, открою в LibreOffice».
   **К чему приводит:** макросы VBA не работают или работают частично, документ портится.
   **Как правильно:** предупредить пользователя, что макросы — зона риска при миграции; сложные документы открывать на Windows-машине.

6. **Ошибка:** «Пропишу в заявке „поставил Р7-Офис“, не проверив, что он реально запускается».
   **К чему приводит:** пользователь возвращается с той же проблемой, доверие к поддержке падает.
   **Как правильно:** после установки всегда запускать программу и открывать тестовый файл.

7. **Ошибка:** «Скачаю дистрибутив с первого сайта в поиске».
   **К чему приводит:** риск пиратской сборки или вредоносного файла.
   **Как правильно:** качать только с официального сайта правообладателя или из корпоративного каталога ПО.

### Безопасность

- **Нельзя** ставить ПО вне утверждённого списка в госструктуре — это нарушение регламента, а иногда и законодательства.
- **Нельзя** использовать пиратские сборки «русских ОС» и «крякнутый» офис — только официальные дистрибутивы (evaluation, свободные, учебные).
- **Нельзя** отключать SELinux/AppArmor на Astra/Ubuntu «чтобы работало» — это снижает защиту; если что-то не работает, ищи причину, а не отключай защиту.
- **Нельзя** передавать учётные данные от реестра/порталов по открытым каналам — только через корпоративные.
- На стенде пароль `Lab#2026-vektor` — учебный; в реальной среде такие пароли недопустимы.

## 7. Вопросы на собеседовании

**Вопрос 1. Что такое реестр отечественного ПО и зачем он нужен?**

Как спросят: «Сталкивались с реестром российского ПО? Что это вообще?»

Ответ: «Это официальный список программ, признанных российскими, его ведёт Минцифры на портале `reestr.digital.gov.ru`. В госструктурах и госкомпаниях закупка ПО вне реестра часто запрещена или требует обоснования. На стенде я проверял наличие Astra Linux и Р7-Офис в реестре — обе там есть. Для L1 это значит: когда пользователь просит поставить программу, надо проверить, есть ли она в реестре, и если нет — предложить аналог оттуда».

Что хочет услышать интервьюер: понимание, что реестр — юридический инструмент, а не технический, и что L1 умеет его проверить.

Красный флаг: «Реестр — это где программы скачивают» (путаница с магазином приложений).

**Вопрос 2. Чем Astra Linux отличается от Ubuntu для L1?**

Как спросят: «Работали с Astra Linux? Чем она отличается от обычного Linux?»

Ответ: «Оба Debian-семейства, команды `apt`/`dpkg` работают одинаково. Отличия: свои репозитории, свой набор пакетов, свой путь к конфигам в некоторых местах, и главное — у Astra есть сертифицированная версия Special Edition для защищённых контуров. На стенде у меня ASTRA01 и UBU01 рядом, я сравнивал `cat /etc/os-release` — `ID=astra` и `ID=ubuntu`. Для L1 правило простое: всегда начинать с `cat /etc/os-release` и не тащить инструкцию с Ubuntu на Astra без проверки».

Что хочет услышать: понимание, что «Linux — это не одна ОС», и привычка проверять дистрибутив.

Красный флаг: «Linux — он и есть Linux, разницы нет».

**Вопрос 3. Пользователь просит Microsoft Office на Astra Linux. Что делать?**

Как спросят: «Приходит заявка: „поставьте мне Word на Linux“. Ваши действия?»

Ответ: «Объясню, что Microsoft Office под Linux официально не поддерживается, и предложу аналоги из реестра — Р7-Офис, МойОфис или LibreOffice, если политика компании его допускает. Уточню, какие форматы нужны: если `.docx` — все три открывают. Если нужны макросы VBA — предупрежу, что они могут не работать, и предложу открывать такие файлы на Windows-машине. Если пользователь настаивает — эскалирую на L2/руководителя, потому что это вопрос политики, а не техники».

Что хочет услышать: умение объяснить ограничение и предложить альтернативу, а не молча ставить Wine.

Красный флаг: «Поставлю через Wine, будет работать» (не будет стабильно).

**Вопрос 4. Какие типовые сложности возникают при миграции на отечественное ПО?**

Как спросят: «С какими проблемами сталкиваются при переходе на российский софт?»

Ответ: «Первое — форматы файлов: `.odt` в Windows без ассоциации не открывается, `.docm` с макросами на Linux работает частично. Второе — привычки пользователей: кнопки в Р7-Офис расположены иначе, люди жалуются, что „всё не так“. Третье — совместимость с периферией: некоторые принтеры и сканеры под Linux требуют отдельных драйверов. Четвёртое — доступ к общим папкам: на Linux монтирование SMB через `cifs-utils` требует правильного формата учётки и домена. Пятое — обновления: репозитории могут быть недоступны из РФ, нужны зеркала. На стенде я воспроизводил первую проблему — `.odt` не открывался на WIN10-CL02, лечится восстановлением ассоциации».

Что хочет услышать: конкретика, а не общие слова; понимание, что миграция — это не только «поставить другую ОС».

Красный флаг: «Миграция — это просто переустановить ОС».

**Вопрос 5. Что такое сертифицированная версия ОС и почему это важно?**

Как спросят: «Чем отличается Astra Linux обычная от Special Edition?»

Ответ: «Special Edition — версия с сертификатом ФСТЭК, её можно использовать в защищённых контурах и для работы с гостайной. Обычная Astra в реестре есть, но для защищённого контура её недостаточно. Для L1 это значит: прежде чем ставить ОС в защищённый контур, надо уточнить у ИБ, какая именно версия сертифицирована и разрешена. На стенде у меня обычная Astra Linux CE — для учебных задач хватает, но в реальной работе с гостайной это было бы нарушением».

Что хочет услышать: понимание разницы «в реестре» и «сертифицировано», готовность уточнять у ИБ.

Красный флаг: «Сертификат — это формальность, главное чтобы работало».
