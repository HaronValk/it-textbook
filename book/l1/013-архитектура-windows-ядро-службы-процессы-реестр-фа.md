## 2. Теория «под капотом»

### Два режима: пользовательский и ядерный

Процессор x86-64 имеет несколько уровней привилегий («колец», rings). Windows использует два: Ring 3 — пользовательский режим (`user mode`), и Ring 0 — ядерный (`kernel mode`).

- В **user mode** живут все обычные программы и службы. Они не могут напрямую лезть в память друг друга, к железу, к чужим процессам. Хочешь диск — попроси ядро через системный вызов.
- В **kernel mode** живут само ядро и драйверы. Здесь вся память общая, ошибка стоит BSOD (синего экрана) — ядро упало, вся система упала.

```
┌──────────────────── User mode (Ring 3) ────────────────────┐
│  Программы: excel.exe, 1c.exe, powershell.exe, mmc.exe      │
│  Службы: services.exe (диспетчер служб) → svchost.exe       │
│  Библиотеки: kernel32.dll, advapi32.dll, ntdll.dll          │
│  ntdll.dll = граница: дальше вызов уходит в ядро (syscall)  │
├─────────────────── Kernel mode (Ring 0) ───────────────────┤
│  Ядро + планировщик: ntoskrnl.exe                           │
│  Менеджеры: памяти, процессов, ввода-вывода, объектов,       │
│  кэша, безопасности (SRM), конфигурации (реестр)            │
│  win32k.sys (графика), драйверы *.sys, HAL: hal.dll         │
├─────────────────────────────────────────────────────────────┤
│  Железо: CPU, RAM, диск, сеть                               │
└─────────────────────────────────────────────────────────────┘
```

**Почему это важно для L1:** когда зависает программа — это user mode, лечится убийством процесса. Когда синий экран — это kernel mode, лечится драйвером, обновлением или откатом (это урок 21).

### Процессы, потоки, службы

- **Процесс** — запущенная программа со своей изолированной памятью. У процесса есть PID (идентификатор), владелец, набор открытых «хэндлов» (дескрипторов) — файлов, ключей реестра, сетевых сокетов.
- **Поток** (thread) — единица работы внутри процесса. Один процесс может иметь десятки потоков.
- **Служба** (service) — это тоже процесс, но запущенный не пользователем, а Диспетчером служб (`services.exe`) и работающий без интерактивного рабочего стола. Служба может стартовать до входа пользователя и работать, когда никто не залогинен.

Ключевой момент: начиная с Windows Vista действует **изоляция сеанса 0** (Session 0 Isolation). Службы работают в сеансе 0, пользователь — в сеансе 1 и выше. Поэтому служба не может показать тебе окошко на рабочем столе, и это правильно с точки зрения безопасности.

Многие службы для экономии памяти живут «пачками» внутри одного общего процесса `svchost.exe`. Отсюда и «почему их так много» — это не вирус, а групповая упаковка.

Базовые системные процессы, которые ты увидишь всегда:

| Процесс | Что делает | Можно ли убить |
|---|---|---|
| `System` (PID 4) | ядро и драйверы | нет, критично |
| `smss.exe` | Session Manager, запускает сеансы | нет, критично |
| `csrss.exe` | подсистема Win32, консоль | нет → BSOD |
| `wininit.exe` | инициализация сеанса 0 | нет, критично |
| `services.exe` | Диспетчер служб (SCM) | нет, критично |
| `lsass.exe` | проверка подлинности, учётки | нет → перезагрузка |
| `svchost.exe` | контейнер для служб | смотря что внутри |
| `explorer.exe` | рабочий стол, Проводник | да, перезапустится |

### Реестр

Реестр — это единая иерархическая база настроек Windows: вместо сотен разбросанных `.ini`-файлов (как в старых Windows) настройки лежат в одном дереве. Реестр — это не файл, а база, которую держит в памяти менеджер конфигурации ядра. На диск она сохраняется «ульями» (hives).

Пять основных веток:

| Ветка | Что внутри | Файл на диске |
|---|---|---|
| `HKEY_LOCAL_MACHINE` (HKLM) | настройки всей машины | `C:\Windows\System32\config\` → `SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY` |
| `HKEY_CURRENT_USER` (HKCU) | настройки текущего пользователя | `C:\Users\<имя>\NTUSER.DAT` |
| `HKEY_USERS` (HKU) | все профили; `HKU\.DEFAULT` — профиль системы | `NTUSER.DAT` каждого профиля |
| `HKEY_CLASSES_ROOT` (HKCR) | сопоставления типов файлов | виртуальная: склейка `HKLM\SOFTWARE\Classes` + `HKCU\Software\Classes` |
| `HKEY_CURRENT_CONFIG` (HKCC) | текущий профиль оборудования | виртуальная, в памяти |

Важно: `HKLM\SAM` и `HKLM\SECURITY` доступны только системе — обычный админ увидит «Отказано в доступе». Это норма, а не поломка.

### NTFS

NTFS (New Technology File System) — файловая система по умолчанию для дисков Windows. Что она даёт сверх простой FAT32:

- **Права доступа (ACL)** на каждый файл и папку — списки контроля доступа, а не только «только чтение» как атрибут.
- **Журнал транзакций** (`$LogFile`) — после внезапного выключения система восстанавливает целостность, а не теряет всё.
- **MFT** (Master File Table) — таблица, где хранятся метаданные о каждом файле: имя, размер, права, время, где лежат данные.
- **Большие объёмы и файлы**: FAT32 не умеет файлы больше 4 ГБ, NTFS умеет (ограничение — размер тома) `[ПРОВЕРИТЬ точные лимиты для конкретной версии]`.
- **Альтернативные потоки данных (ADS)** — в один файл можно записать несколько потоков. Именно на этом построены метки «скачано из интернета» (`Zone.Identifier`).
- **Сжатие, шифрование (EFS), квоты, жёсткие ссылки и junction-точки**.

Права NTFS работают **локально и по сети**. А «общий доступ к папке» (шара, SMB) — это отдельный слой разрешений: итоговый доступ = пересечение прав шары и прав NTFS, причём берётся самое строгое. Это подробно в уроке 17, здесь просто запомни, что слоёв два.

Сетевые порты, которые встретятся: **TCP 135** (RPC, через него управляют службами и реестром удалённо), **TCP 445** (SMB — общие папки), **TCP 5985/5986** (WinRM — удалённый PowerShell).

## 3. Аналогия из жизни

Представь большой офисный центр. На крыше и в подвале — инженерные системы: электрика, вентиляция, водопровод. Туда пускают только сертифицированных инженеров, и если они что-то сломают, встанет всё здание целиком. Это **kernel mode**. Внутри здания — съёмные офисы компаний. Каждый офис заперт своим ключом, чужой сотрудник туда не зайдёт, а если в одном офисе уронили шкаф — соседи этого даже не заметят. Это **user mode**, а каждая фирма — **процесс**.

Часть арендаторов уходит домой в шесть, а часть работает круглосуточно: охрана, уборка, серверная. Их не видно на общем плане этажа, но они работают всегда и без них здание не функционирует. Это **службы**.

В подвале стоит одна общая картотека на всё здание: в ней записано, на каком этаже какой замок, какие правила пропуска, какой температурный режим. Каждый может попросить выписку, но правки — только через коменданта и с журналом. Это **реестр**.

А сам склад здания — это огромное помещение со стеллажами, пронумерованными ячейками, журналом приёмки-выдачи и турникетом на каждом стеллаже: у каждого сотрудника свой пропуск, и он определяет, какие именно ячейки ему открыты. Это **NTFS**.

Где аналогия ломается: офисы физически разделены стенами, а процессы в памяти разделены только виртуальной адресацией — которую настраивает ядро. И «инженеры» из подвала не находятся в отдельном помещении: они работают на том же процессоре, просто с другим уровнем привилегий.

## 4. Практика и команды

> На русской версии Windows заголовки вывода и названия встроенных групп будут на русском («Имя образа», «ВСТРОЕННЫЕ\Администраторы»). Значения — те же. Ниже примеры на английском для читаемости.

### 1. Версия и сборка ОС

```cmd
winver
systeminfo | findstr /B /C:"OS Name" /C:"OS Version" /C:"System Type"
```

`systeminfo` выдаёт длинную простыню: версию, сборку, объём RAM, список обновлений, домен. `findstr` фильтрует нужные строки. Смотреть: `OS Name` (редакция — на стенде должно быть `Windows 11 Enterprise Evaluation`), `OS Version` (номер сборки).

### 2. Список процессов (CMD)

```cmd
tasklist
tasklist /v /fi "imagename eq svchost.exe"
tasklist /svc /fi "pid eq 1120"
tasklist /fo csv > C:\L1-Lab\processes.csv
```

- `/v` — подробный вид: добавляет имя пользователя, заголовок окна, время CPU.
- `/fi` — фильтр: по имени образа (`eq`, `ne`) или по PID.
- `/svc` — показать, какие службы живут внутри процесса. Главный ключ для `svchost.exe`.
- `/fo` — формат вывода: `table`, `list`, `csv`.

Типичный фрагмент `/v`: колонки `Image Name`, `PID`, `Session Name`, `Session#`, `Mem Usage`, `Status`, `User Name`, `CPU Time`, `Window Title`. Смотреть на `Mem Usage` и `User Name` — если «непонятный» процесс висит под конкретным пользователем, это, скорее всего, его программа.

### 3. Процессы в PowerShell — с сортировкой

```powershell
Get-Process | Sort-Object WS -Descending | Select-Object -First 10 Name, Id, WS, CPU
```

`WS` (Working Set) — сколько физической памяти процесс держит сейчас, в байтах. `CPU` — суммарное процессорное время в секундах с момента старта (не проценты!). Именно поэтому процесс со «страшными» 5000 секундами CPU может быть безобидным — он просто давно работает.

### 4. Командная строка процесса — кто его запустил

```powershell
Get-CimInstance Win32_Process -Filter "Name = 'powershell.exe'" |
    Select-Object ProcessId, ParentProcessId, Name, CommandLine
```

`CommandLine` показывает, с какими аргументами запущен процесс, `ParentProcessId` — кто родитель. В нормальной работе это первое, что смотрят при подозрении на «майнер» или скрипт-вредитель.

### 5. Убить процесс

```cmd
taskkill /PID 4321 /F
taskkill /IM notepad.exe /F
```

```powershell
Stop-Process -Id 4321 -Force
```

`/F` — принудительно, без вопроса «сохранить данные?». Несохранённые данные пользователя при этом теряются. `/T` в `taskkill` убивает ещё и дочерние процессы.

### 6. Службы: GUI и консоль

GUI: `Win+R` → `services.msc`. Столбцы: «Имя», «Описание», «Состояние», «Тип запуска». Двойной клик по службе → вкладка «Зависимости» (что нужно ей и кому нужна она) и вкладка «Восстановление» (что делать при падении).

```cmd
sc.exe query Spooler
sc.exe qc Spooler
net start Spooler
net stop Spooler
```

> **Ловушка:** в PowerShell `sc` — это алиас `Set-Content`, а не утилита служб. Всегда пиши `sc.exe`.

`sc.exe qc` (query config) выдаёт: `START_TYPE` (`2 AUTO_START`, `3 DEMAND_START` — то есть вручную, `4 DISABLED`), `BINARY_PATH_NAME` (путь к exe), `SERVICE_START_NAME` (под какой учёткой работает), `DEPENDENCIES`.

```powershell
Get-Service | Where-Object Status -eq 'Running' | Sort-Object DisplayName
Get-Service -Name Spooler | Select-Object Name, Status, StartType
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
    Select-Object Name, State, StartMode, StartName, PathName
```

### 7. Реестр: чтение из консоли

```cmd
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion" /v ProductName
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion" /v CurrentBuild
reg query "HKLM\SYSTEM\CurrentControlSet\Services\Spooler" /v Start
```

Вывод:
```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion
    ProductName    REG_SZ    Windows 11 Enterprise Evaluation
```

`REG_SZ` — строковое значение, `REG_DWORD` — число. Вторая команда показывает, что настройки служб тоже лежат в реестре: `Start` = `0x2` — авто, `0x3` — вручную, `0x4` — отключена. Это ровно то же, что ты видишь в `services.msc`.

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object ProductName, DisplayVersion, CurrentBuild
```

В PowerShell реестр — это «диск»: `HKLM:` и `HKCU:`, по ним ходят как по папкам (`Get-ChildItem HKLM:\SOFTWARE`).

### 8. Файловая система: что за том

```cmd
fsutil fsinfo volumeinfo C:
fsutil fsinfo ntfsinfo C:
```

`volumeinfo` покажет `File System Name : NTFS`, метку и серийный номер. `ntfsinfo` — размер кластера (`Bytes Per Cluster`, обычно 4096), расположение и размер MFT. Кластер — минимальная порция, которую FS выделяет файлу: файл в 1 байт займёт 4 КБ на диске.

### 9. Права NTFS

```cmd
icacls C:\L1-Lab
mkdir C:\L1-Lab
icacls C:\L1-Lab /grant "VEKTOR\ivanov:(OI)(CI)M"
```

Вывод `icacls`:
```
C:\L1-Lab BUILTIN\Administrators:(OI)(CI)(F)
          NT AUTHORITY\SYSTEM:(OI)(CI)(F)
          BUILTIN\Users:(OI)(CI)(RX)
```
`(OI)` — наследуется объектами (файлами), `(CI)` — контейнерами (папками), `(F)` — полный доступ, `(M)` — изменение, `(RX)` — чтение и выполнение. То есть «Пользователи» получают чтение на папку и на всё, что внутри.

### 10. Linux для сравнения (UBU01)

```bash
ps aux --sort=-%cpu | head -6
systemctl status ssh --no-pager
df -hT
ls -l /home
```

`ps aux` — аналог `tasklist`, `systemctl` — аналог `services.msc`, `df -hT` — аналог `fsutil fsinfo volumeinfo`. Обрати внимание: в Linux права `-rwxr-x---` — это те же ACL в компактной форме. Ощущение «это одно и то же, просто разными словами» — правильное.

3. **WIN11-CL01, GUI.** `Win+R` → `resmon` (Монитор ресурсов). Вкладка «ЦП» → раскрой «Связанные дескрипторы».
   **Ожидаемо:** видно, какие процессы реально жрут CPU прямо сейчас, с именами файлов, которые они открыли. Это самый быстрый инструмент для «тормозит».

   **Ожидаемо:** список процессов и, во второй команде, — какие службы сидят в каждом `svchost.exe`. Найди свой самый «толстый» процесс по памяти.

   **Ожидаемо:** топ-5 по памяти. Сравни с тем, что видел в диспетчере — цифры должны примерно совпадать.

6. **WIN11-CL01, GUI.** `Win+R` → `services.msc`. Найди службу `Print Spooler` (Диспетчер печати). Открой её свойства → вкладка «Зависимости».
   **Ожидаемо:** видно, что от неё зависит печать; на вкладке «Восстановление» — реакция на сбои. Ничего не меняй.

7. **WIN11-CL01, CMD/PowerShell.** Выполни:
   ```cmd
   sc.exe qc Spooler
   ```

## 6. Ошибки новичков и безопасность

1. **Убивать процессы «на всякий случай», особенно `svchost.exe`, `csrss.exe`, `wininit.exe`.**
   → К чему приводит: BSOD, принудительный выход из системы, потеря несохранённых данных у пользователя. Убийство `csrss.exe` гарантированно валит систему.
   → Как правильно: сначала понять, что за процесс (`Get-CimInstance Win32_Process` → `CommandLine`), и только потом принимать решение. Системные процессы не трогаем — если проблема в них, нужна перезагрузка или разбор драйверов.

2. **Писать `sc` в PowerShell вместо `sc.exe`.**
   → К чему приводит: `sc` — алиас `Set-Content`. Команда `sc query Spooler` молча создаст или перезапишет файл с именем `query`, а не покажет службу. Новичок в панике: «команда не работает».
   → Как правильно: всегда `sc.exe query Spooler`.

3. **Править реестр без экспорта ветки и без точки восстановления.**
   → К чему приводит: система не загружается, «синий экран» на старте, переустановка. Реестр — не текстовый файл, отменить «Ctrl+Z» нельзя.
   → Как правильно: перед любой правкой — `Файл → Экспорт` нужной ветки, плюс `rstrui` / точка восстановления. Это тема урока 16, но правило действует с первого дня.

4. **Отключать службы «для ускорения» пачкой.**
   → К чему приводит: перестаёт работать печать (`Spooler`), сеть (`Dnscache`, `Dhcp`), обновления (`wuauserv`), вход в домен. Пользователь не поймёт, что случилось, а ты не вспомнишь, что менял месяц назад.
   → Как правильно: менять только ту службу, которая относится к проблеме; ставить `Manual`, а не `Disabled`; фиксировать в `stand-log.md`.

5. **Путать «права NTFS» и «общий доступ».**
   → К чему приводит: «я же дал доступ на шару, почему не открывается?» — потому что NTFS-права запрещают. Или наоборот: дали Everyone на шару, а внутри NTFS режет.
   → Как правильно: помнить, что слоёв два и итог — самый строгий. Сначала NTFS, потом шара. Подробно в уроке 17.

6. **Считать, что «реестр можно почистить» сторонними чистилками.**
   → К чему приводит: «оптимизаторы» ломают привязки COM-объектов, после чего отваливается 1С, Office или КриптоПро. Выигрыш в скорости — нулевой.
   → Как правильно: реестр не чистить. Проблемы производительности ищутся в процессах, дисках и драйверах.

7. **Работать всё время под локальным администратором и с отключённым UAC.**
   → К чему приводит: любая запущенная программа (и любой макрос в документе от контрагента) получает полные права. Это главный вектор заражения в офисах.
   → Как правильно: обычная учётка для работы, повышение — точечно через UAC. На стенде `adm.student` — учебная учётка, в бою так нельзя.

8. **Игнорировать `explorer.exe` после перезапуска — и удивляться, почему пропал рабочий стол.**
   → К чему приводит: паника «я всё сломал» и лишняя перезагрузка.
   → Как правильно: `explorer.exe` перезапускается штатно: Диспетчер задач → Файл → Запустить новую задачу → `explorer.exe`. Данные не теряются.

### Безопасность

В боевой среде **нельзя**:

- **Отключать Microsoft Defender и брандмауэр** «чтобы работало быстрее/чтобы открылось». Это не ускорение, а дыра: сетевой червь вида WannaCry ходит именно по открытому SMB (445).
- **Давать `Everyone — Full Control`** на папки. Один такой ресурс — и через месяц никто не знает, кто и что там наворотил. Права выдаются группам (`GG-Buh`, `GG-HR`), а не «всем».
- **Хранить пароли в реестре, в скриптах или в планировщике задач** в открытом виде. Реестр читается любым администратором, а часто и обычным пользователем.
- **Выкладывать дампы и экспорты реестра (`HKLM\SAM`, `SECURITY`) в чаты и на форумы.** Там хэши паролей.
- **Запускать «чистильщики реестра» и «активаторы»** с торрентов — это классический канал доставки троянов. Только легальные evaluation/лицензионные версии.

На стенде мы сознательно делаем просто: единый учебный пароль `Lab#2026-vektor`, отключение части проверок при экспериментах. В реальной работе пароль у каждого свой, а любое ослабление безопасности согласуется и фиксируется.

## 7. Вопросы на собеседовании

### Вопрос 1. Чем служба отличается от обычного процесса?

**Ответ:** Служба — это тоже процесс, но запускается он не пользователем, а Диспетчером служб (`services.exe`), работает в сеансе 0 (изоляция сеанса 0 с Vista), не имеет интерактивного окна и может стартовать до входа пользователя в систему. У службы есть тип запуска (авто / вручную / отключена), учётная запись, под которой она работает, и настройки восстановления при сбое. Многие службы упакованы по нескольким в один `svchost.exe` для экономии памяти.

**Что хочет услышать интервьюер:** что ты понимаешь «безлюдный» характер службы, знаешь `services.msc` и `sc.exe qc`, и не путаешь службу с приложением.

**Красный флаг:** «служба — это программа в трее» или «службы — это драйверы».

---

### Вопрос 2. Что такое реестр? Назови основные ветки и где он лежит на диске.

**Ответ:** Реестр — иерархическая база настроек Windows, которую держит в памяти менеджер конфигурации ядра и сохраняет на диск в виде ульев. Основные ветки: `HKLM` (настройки машины), `HKCU` (текущий пользователь), `HKU` (все профили), `HKCR` (ассоциации типов файлов, виртуальная склейка), `HKCC` (текущий профиль оборудования, в памяти). Файлы: `C:\Windows\System32\config\SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, а пользовательские — `C:\Users\<имя>\NTUSER.DAT`. Ветки `SAM` и `SECURITY` доступны только системе.

**Что хочет услышать интервьюер:** что ты знаешь разницу между `HKLM` и `HKCU` (частая причина «настройка не применилась ко всем») и понимаешь, что реестр — не файл, а база.

**Красный флаг:** «реестр — это папка с настройками» или «HKCR — отдельный файл».

---

### Вопрос 3. Чем NTFS лучше FAT32 и что она даёт?

**Ответ:** NTFS даёт права доступа ACL на каждый файл и папку, журнал транзакций (`$LogFile`) для восстановления после сбоя, таблицу MFT с метаданными, поддержку файлов больше 4 ГБ (у FAT32 это жёсткий лимит), альтернативные потоки данных (ADS), сжатие, шифрование EFS, квоты и жёсткие ссылки. FAT32 — простая файловая система без прав, годится для флешек, но не для рабочих дисков.

**Что хочет услышать интервьюер:** что для тебя NTFS — это прежде всего **права**, а не «просто формат диска».

**Красный флаг:** «NTFS быстрее» без единого слова о правах и журнале.

---

### Вопрос 4. Пользователь пишет: «Компьютер тормозит». Твои действия?

**Ответ:** Уточняю у пользователя, когда началось и что менялось (обновление, установка программы). Дальше по шагам: Диспетчер задач → «Производительность», смотрю, что в потолке — CPU, память, диск или сеть. Затем «Подробности», сортировка по загрузке, нахожу процесс-лидер, проверяю через `Get-CimInstance Win32_Process` его командную строку и родителя. Если это системный процесс — не убиваю, проверяю драйверы и журналы. Если пользовательский — выясняю, что за программа, проверяю автозагрузку и планировщик. Параллельно смотрю свободное место на `C:` и состояние диска по SMART.

**Что хочет услышать интервьюер:** структурный подход и понимание, что «тормозит» — это не диагноз, а симптом, который надо разложить на CPU / RAM / диск / сеть.

**Красный флаг:** «перезагружу» или «почищу реестр» как первые действия.

---

### Вопрос 5. Зачем Windows разделяет user mode и kernel mode?

**Ответ:** Для надёжности и безопасности. В user mode каждая программа изолирована в своём адресном пространстве: падение одной не роняет систему, а вредоносный код не может напрямую лезть в память другой программы или в железо. В kernel mode работают ядро и драйверы, у которых полный доступ; ошибка там означает BSOD. Программа обращается к системе через системные вызовы (`ntdll.dll` → ядро), которые проверяются на корректность.

**Что хочет услышать интервьюер:** понимание, почему синий экран — это всегда про ядро/драйверы, а зависшее приложение — про user mode.

**Красный флаг:** «kernel mode нужен для скорости» без упоминания изоляции и привилегий.
