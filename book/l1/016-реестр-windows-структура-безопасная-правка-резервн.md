## 2. Теория «под капотом»

**Реестр (Registry)** — это иерархическая база данных настроек Windows. В ней хранится всё: параметры оборудования, настройки пользователей, ассоциации файлов, установленные программы, политики безопасности, службы. Программы читают и пишут туда постоянно. В отличие от старых `.ini`-файлов, реестр — единое централизованное хранилище с чёткой структурой.

### Структура: кусты, ключи, значения

Реестр состоит из **кустов** (hives) — корневых разделов. Их пять основных:

```text
HKEY_LOCAL_MACHINE  (HKLM)  — настройки компьютера, общие для всех пользователей
  ├─ HARDWARE      — данные о железе (создаётся при загрузке, не сохраняется)
  ├─ SAM           — база учётных записей (защищена)
  ├─ SECURITY      — политики безопасности (защищена)
  ├─ SOFTWARE      — настройки установленного ПО
  └─ SYSTEM        — настройки самой ОС, драйверы, службы

HKEY_CURRENT_USER   (HKCU)  — настройки текущего пользователя
  └─ ... (это ссылка на ветку внутри HKEY_USERS)

HKEY_USERS          (HKU)   — настройки всех пользователей системы
HKEY_CLASSES_ROOT   (HKCR)  — ассоциации файлов и COM-объекты (слияние HKLM\SOFTWARE\Classes и HKCU\Software\Classes)
HKEY_CURRENT_CONFIG (HKCC)  — текущий профиль оборудования (ссылка на HKLM\SYSTEM\CurrentControlSet\Hardware Profiles\Current)
```

Внутри куста — **ключи** (keys, как папки) и **значения** (values, как файлы). У каждого значения есть имя, тип и данные. Основные типы:

| Тип | Что хранит | Пример |
|-----|-----------|--------|
| `REG_SZ` | строка | путь к программе |
| `REG_EXPAND_SZ` | строка с переменными | `%SystemRoot%\system32` |
| `REG_DWORD` | 32-битное число | `1` = включено, `0` = выключено |
| `REG_QWORD` | 64-битное число | редко, счётчики |
| `REG_BINARY` | двоичные данные | параметры оборудования |
| `REG_MULTI_SZ` | список строк | несколько путей |

Полный путь к значению выглядит так: `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` — это ключ автозагрузки, а внутри значения с именами программ и путями к ним.

### Где реестр физически лежит

На диске реестр — это набор файлов в `C:\Windows\System32\config\` (для HKLM) и в профилях пользователей `C:\Users\<имя>\NTUSER.DAT` (для HKCU). Файлы `SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, `DEFAULT` — это и есть кусты. Их нельзя просто скопировать «на всякий случай» при работающей системе — они заблокированы. Именно поэтому для бэкапа используют `reg export` или «Экспорт» в `regedit`.

### Как это работает в общей картине

```text
Программа/служба/драйвер
        │
        ▼
  Win32 API (RegOpenKey, RegQueryValue...)
        │
        ▼
  Менеджер реестра (ядро Windows)
        │
        ▼
  Файлы кустов на диске (SYSTEM, SOFTWARE, NTUSER.DAT...)
        │
        ▼
  Кэш в оперативной памяти (для скорости)
```

Когда ты правишь реестр — меняется и кэш в памяти, и файл на диске (с задержкой). Некоторые изменения вступают в силу сразу, некоторые — после перезапуска программы или системы. Это важно: «я поправил, а не работает» часто значит «нужен перезапуск службы/проводника/системы».

## 3. Аналогия из жизни

Реестр — это **архивная картотека в большой конторе**. Кусты — это шкафы (HKLM — общий шкаф организации, HKCU — личный шкаф сотрудника). Ключи — это папки внутри шкафа, вложенные друг в друга по темам («Оборудование», «Программы», «Пользователи»). Значения — это карточки в папках, где написано конкретное: «принтер по умолчанию — HP», «обои — синие», «программа запускается при старте — да».

Хочешь поменять настройку — идёшь по адресу (путь ключа), достаёшь карточку (значение), переписываешь (меняешь данные). Если перепутал папку и переписал не ту карточку — сломается не то, что хотел. Если выдернул карточку совсем (удалил значение) — программа может не найти настройку и упасть или взять значение по умолчанию. А если сжёг папку целиком — потеряешь всё, что в ней было.

Аналогия перестаёт работать в одном: в картотеке можно порвать бумажку и никто не заметит, а в реестре удаление одного ключа может уронить загрузку системы.

## 4. Практика и команды

Все команды выполняем на **WIN11-CL01** (Windows 11) под локальной учёткой `ivanov` или `adm.student`. `regedit` и `reg.exe` есть в любой Windows из коробки.

### 4.1. Открыть редактор реестра (GUI)

Меню «Пуск» → набрать `regedit` → Enter → подтвердить UAC. Или `Win+R` → `regedit` → Enter.

Слева — дерево кустов и ключей, справа — значения выбранного ключа. Адресная строка сверху — путь. Это основной инструмент L1 для просмотра и точечной правки.

### 4.2. Посмотреть ключ автозагрузки

```powershell
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
```

`reg query` — прочитать ключ. Вывод примерно такой:

```text
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
    SecurityHealth    REG_EXPAND_SZ    %windir%\system32\SecurityHealthSystray.exe
    VMware User Agent REG_SZ           "C:\Program Files\VMware\VMware Tools\vmtoolsd.exe" -n vmusr
```

Смотрим: имя значения, тип, путь. Если видишь подозрительное имя с путём в `C:\Users\...\AppData\Local\Temp\` — это красный флаг (возможно, вредонос). В L1 такие находки эскалируют в ИБ, а не удаляют молча.

### 4.3. Прочитать одно значение

```powershell
reg query "HKCU\Control Panel\Desktop" /v Wallpaper
```

`/v` — конкретное значение по имени. Вывод:

```text
HKEY_CURRENT_USER\Control Panel\Desktop
    Wallpaper    REG_SZ    C:\Users\ivanov\AppData\Roaming\Microsoft\Windows\Themes\TranscodedWallpaper
```

Если значение не существует — `reg query` вернёт ошибку «Не удалось найти указанный раздел реестра или значение». Это нормальный результат, не баг.

### 4.4. Экспорт ветки в файл (резервная копия)

```powershell
reg export "HKCU\Software\Microsoft\Office" "C:\Lab\vektor\backup-office.reg" /y
```

`reg export` — сохранить ветку в `.reg`-файл. `/y` — перезаписать без вопроса. Файл `.reg` — это текстовый файл со структурой ключей и значений, его можно открыть блокнотом и посмотреть глазами. **Это твой главный инструмент бэкапа перед правкой.**

Правило: перед любой правкой — `reg export` той ветки, которую трогаешь. Не всей системы, а именно её.

### 4.5. Импорт ветки обратно (восстановление)

```powershell
reg import "C:\Lab\vektor\backup-office.reg"
```

`reg import` — применить `.reg`-файл. Восстанавливает ключи и значения из файла. Если ключ уже есть — перезапишет значения; если нет — создаст. **Важно:** `reg import` не удаляет то, чего нет в файле. То есть если ты после бэкапа создал новый ключ, импорт его не уберёт. Для полного отката ветки нужно сначала удалить её, потом импортировать — но это уже опасно, и в L1 так не делают без понимания.

### 4.6. Добавить или изменить значение

```powershell
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced" /v HideFileExt /t REG_DWORD /d 0 /f
```

`reg add` — создать/изменить значение. Ключи:
- `/v` — имя значения
- `/t` — тип (`REG_DWORD`, `REG_SZ`, `REG_EXPAND_SZ`, `REG_BINARY`)
- `/d` — данные
- `/f` — без подтверждения

Эта команда включает показ расширений файлов в проводнике (`HideFileExt = 0`). Полезная типовая настройка, которую L1 делает пользователям, чтобы они видели `.exe`, `.pdf` и не путали.

### 4.7. Удалить значение

```powershell
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced" /v HideFileExt /f
```

`reg delete` с `/v` — удалить конкретное значение. Без `/v` — удалить весь ключ (осторожно!). `/f` — без подтверждения. После удаления значение вернётся к поведению по умолчанию.

### 4.8. Экспорт целого куста (полный бэкап)

```powershell
reg export "HKLM\SOFTWARE" "C:\Lab\vektor\backup-hklm-software.reg" /y
```

Полный бэкап `HKLM\SOFTWARE` — это сотни мегабайт и долго. В L1 так делают редко, обычно перед крупными изменениями (установка драйверов, обновление). Для точечной правки хватает бэкапа конкретной ветки.

### 4.9. Сравнить состояние до и после

```powershell
reg query "HKLM\SYSTEM\CurrentControlSet\Services\Spooler" /v Start
```

`Start` — тип запуска службы: `0` boot, `1` system, `2` auto, `3` manual, `4` disabled. Полезно, когда «принтер не работает»: проверяем, не отключена ли служба диспетчера печати. Это типичная заявка L1.

### 4.10. Через GUI: экспорт и импорт в regedit

В `regedit`: правый клик по ключу → «Экспорт» → выбрать путь и имя `.reg` → «Сохранить». Импорт: «Файл» → «Импорт» → выбрать `.reg`. То же самое, что `reg export`/`reg import`, только мышкой. Для L1 это часто удобнее, потому что видно, что именно экспортируешь.

## 6. Ошибки новичков и безопасность

1. **Править реестр без бэкапа.** → Одна неверная правка — и программа не запускается, а откатить нечем. → Всегда `reg export` той ветки, которую трогаешь, перед правкой.

2. **Удалять ключи «на всякий случай».** → Удаление `HKLM\SYSTEM\CurrentControlSet\Services\...` может уронить загрузку. → Удаляй только то, в чём уверен; сомневаешься — эскалируй в L2.

3. **Путать HKLM и HKCU.** → Правка в HKLM меняет всех пользователей, в HKCU — только текущего. → Спроси себя: «это настройка компьютера или пользователя?» — и выбирай куст.

4. **Импортировать `.reg` из интернета.** → Файл может содержать вредоносные правки (отключение Defender, автозапуск). → Импортируй только свои бэкапы или проверенные файлы; открывай `.reg` блокнотом перед импортом.

5. **Забыть про перезапуск.** → Правка есть, а поведение не изменилось. → Перезапусти программу, службу или `explorer.exe`; для системных — перезагрузка.

6. **Править реестр другого пользователя без загрузки его куста.** → В `regedit` не видно `HKCU` другого юзера. → Загрузи его `NTUSER.DAT` через «Файл» → «Загрузить куст» (это уже L2-навык, в L1 — эскалация).

7. **Считать, что `reg import` удаляет лишнее.** → Импорт только добавляет/перезаписывает, но не удаляет. → Для полного отката ветки — сначала удалить её, потом импортировать (опасно, только с бэкапом).

8. **Игнорировать права.** → `reg add` в HKLM без админа вернёт «Отказано в доступе». → Запускай PowerShell «от имени администратора» для правок HKLM.

### Безопасность

В боевой среде **нельзя**:
- править реестр на продакшн-машине без согласования и бэкапа;
- импортировать `.reg`-файлы из непроверенных источников (типичный вектор атаки);
- отключать через реестр Defender, UAC, брандмауэр «чтобы работало» — это дыра в безопасности;
- хранить бэкапы реестра с паролями/ключами в общих папках.

Правило L1: реестр — инструмент диагностики и точечной правки, а не «место, где можно всё сломать и починить». Сомневаешься — не трогай, эскалируй.

## 7. Вопросы на собеседовании

**Вопрос 1. Что такое реестр Windows и зачем он нужен?**
Как спросят: «Объясни, что такое реестр, простыми словами».
Ответ: «Реестр — это иерархическая база настроек Windows. В ней хранятся параметры системы, оборудования, программ и пользователей. Состоит из кустов (HKLM — настройки компьютера, HKCU — текущего пользователя, HKCR — ассоциации файлов и т.д.), внутри — ключи и значения с типами REG_SZ, REG_DWORD и другими. Программы читают и пишут туда через Win32 API».
Что хочет услышать: понимание структуры (кусты/ключи/значения) и что это не «страшная магия», а обычная база.
Красный флаг: «реестр — это папка с настройками» без понимания разницы HKLM/HKCU.

**Вопрос 2. Как безопасно править реестр?**
Как спросят: «Пользователю нужно поменять настройку через реестр. Твои действия?»
Ответ: «Сначала уточняю, что именно меняем и зачем. Делаю бэкап нужной ветки через `reg export` или «Экспорт» в regedit. Правлю точечно — одно значение, а не весь ключ. Проверяю результат, при необходимости перезапускаю программу или explorer. Если что-то пошло не так — `reg import` из бэкапа. Всё фиксирую в заявке».
Что хочет услышать: дисциплина «бэкап → правка → проверка → откат при необходимости».
Красный флаг: «Открываю regedit и правлю» без упоминания бэкапа.

**Вопрос 3. Чем отличается HKLM от HKCU?**
Как спросят: «Где хранятся настройки пользователя, а где — компьютера?»
Ответ: «HKLM — настройки компьютера, общие для всех пользователей (службы, драйверы, установленное ПО). HKCU — настройки текущего пользователя (обои, ассоциации файлов, настройки программ для него). HKCU — это ссылка на ветку внутри HKU для текущего юзера. Правка в HKLM влияет на всех, в HKCU — только на одного».
Что хочет услышать: понимание области действия правки.
Красный флаг: «Это одно и то же».

**Вопрос 4. Пользователь говорит, что не открываются PDF. Как диагностируешь через реестр?**
Как спросят: «С чего начнёшь?»
Ответ: «Спрошу, когда началось и что делали. Проверю ассоциацию: `reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.pdf\UserChoice"`. Если ключа нет или он битый — ассоциация сломана. Восстановлю из бэкапа (`reg import`) или через «Параметры → Приложения по умолчанию». Проверю, что файл открывается. Если не помогает — проверю, установлена ли программа для PDF».
Что хочет услышать: конкретный путь в реестре и понимание, что есть штатный GUI-способ.
Красный флаг: «Удалю все ключи, связанные с PDF» — это ломает больше, чем чинит.

**Вопрос 5. Что будет, если удалить ключ HKLM\SYSTEM\CurrentControlSet\Services\Spooler?**
Как спросят: «Можно ли так сделать?»
Ответ: «Нельзя. Это ключ службы диспетчера печати. Удаление приведёт к тому, что служба перестанет существовать, принтеры не будут работать, а восстановить можно только из бэкапа реестра или точки восстановления. В L1 такие правки не делают — если служба сломана, её переустанавливают через `sc` или восстановление системы, а не удаляют ключ».
Что хочет услышать: понимание последствий и границ компетенции L1.
Красный флаг: «Удалю и посмотрю, что будет».
