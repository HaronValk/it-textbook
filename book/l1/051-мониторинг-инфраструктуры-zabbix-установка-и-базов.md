# Мониторинг инфраструктуры: Zabbix — установка и базовая настройка в лаборатории

## 1. Введение (зачем это нужно в реальной работе)

Понедельник, 9:12. Заявка в поддержку «Вектора»:

> **Пользователь:** Мария Петрова (HR), ВМ WIN10-CL02
> **Что написала:** «Не могу зайти на общую папку `\\FS01\HR`, пишет "недоступен". У меня отчёт через час, помогите срочно!»
> **Срочность:** Высокая

Ты открываешь консоль и понимаешь: чтобы ответить «сервер жив или лёг», надо сходить на FS01, посмотреть, работает ли служба, отвечает ли сервер по сети, не забит ли диск. А если таких серверов десять и заявок утром двадцать? Бегать по каждой машине руками — это и есть та работа, которую мониторинг забирает у тебя.

Мониторинг — это система, которая сама, круглосуточно, раз в минуту, стучится на каждый сервер и клиент и записывает: жив ли он, сколько у него процессора, памяти, места на диске, работают ли нужные службы. Когда что-то выходит за порог — она шлёт уведомление. В реальной работе L1 первым видит эти уведомления и по ним открывает заявки, а не наоборот.

Zabbix — один из самых распространённых бесплатных инструментов мониторинга в России: открытый исходный код, ставится на Linux, умеет следить и за Windows, и за Linux, и за сетевым оборудованием. После этой главы ты сможешь: поставить Zabbix-сервер на UBU01, добавить в него узлы сети (DC01 и WIN11-CL01), настроить простой триггер «мало места на диске» и прочитать по мониторингу, что происходит с сервером, когда приходит заявка вроде заявки Марии.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Zabbix состоит из трёх частей, которые надо держать в голове.

**Zabbix server** — мозг. Это служба на Linux-машине, которая по расписанию опрашивает узлы, хранит историю и решает, когда сработал триггер. У нас он будет на UBU01.

**Zabbix agent** — маленькая служба, которую ставят на каждую наблюдаемую машину (Windows или Linux). Агент слушает порт **10050/TCP** и отдаёт серверу метрики: загрузку CPU, память, свободное место, состояние служб. Сервер стучится к агенту, а не наоборот — это важно для брандмауэров.

**Zabbix frontend** — веб-интерфейс (PHP + веб-сервер), через который ты настраиваешь всё мышкой в браузере. Он ходит к серверу и к базе данных.

Плюс **база данных** (у нас MariaDB) — там лежат конфигурация, история метрик и события.

Схема стенда после этого урока:

```text
        браузер на хосте (Windows)
                 |
                 | http://10.10.10.30/zabbix   (порт 80)
                 v
   +-----------------------------+
   |  UBU01  10.10.10.30         |
   |  Apache + PHP (frontend)    |
   |  zabbix-server  <----------+--- опрос агентов по 10050/TCP
   |  MariaDB                    |
   +-----------------------------+
            |                    |
            | 10050/TCP          | 10050/TCP
            v                    v
   +-----------------+   +------------------+
   | DC01            |   | WIN11-CL01       |
   | 10.10.10.10     |   | 10.10.10.51      |
   | Zabbix agent    |   | Zabbix agent     |
   +-----------------+   +------------------+
```

Ключевые понятия, которые тебе нужны на уровне L1:

- **Host (узел)** — одна наблюдаемая машина в Zabbix, у неё есть имя и адрес.
- **Item (элемент данных)** — конкретная метрика: «свободно байт на диске C:», «загрузка CPU за 5 минут». У каждого элемента свой интервал опроса.
- **Trigger (триггер)** — правило «когда метрика хуже порога, поднимай проблему». Например: свободно меньше 10% на диске → проблема.
- **Problem (проблема)** — событие, которое триггер поднял. Пока условие держится — проблема открыта; когда метрика вернулась в норму — закрывается.
- **Template (шаблон)** — набор готовых элементов и триггеров, который ты привязываешь к узлу, чтобы не настраивать всё вручную. Для Windows есть готовый шаблон `Windows by Zabbix agent`, для Linux — `Linux by Zabbix agent`.

Порты, которые надо помнить: **10051/TCP** — сервер Zabbix (для активных проверок и обмена между сервером и прокси), **10050/TCP** — агент, **80/TCP** — веб-интерфейс. На стенде мы работаем только с 10050 и 80.

## 3. Аналогия из жизни

Представь диспетчерскую в большом бизнес-центре. На каждом этаже стоит датчик дыма и температуры (это **агент**), все датчики по проводам подключены к пульту охраны (это **сервер**). На пульте сидит оператор и смотрит на табло: если в каком-то помещении температура выше нормы — на табло загорается красная лампочка с номером помещения (это **триггер** и **проблема**). А ещё есть журнал, где записано, какая температура была в каждом помещении вчера в 15:00 (это **история метрик**). Ты, как L1, — тот, кто первым видит красную лампочку и идёт разбираться.

Аналогия ломается в одном: датчик дыма просто сообщает «дым есть/нет», а Zabbix-агент умеет отдавать сотни разных метрик по запросу, и сервер сам решает, что и как часто спрашивать.

## 4. Практика и команды

Все команды ниже — на UBU01 под `adm.student` (там, где нужен root — через `sudo`). Пароль стенда `Lab#2026-vektor`.

**1. Проверить, что машина готова и интернет есть (UBU01).**

```bash
ip -br a
ping -c 3 10.10.10.2
```

`ip -br a` — краткий список интерфейсов и адресов; ждём `ens33 ... 10.10.10.30/24`. `ping` до шлюза 10.10.10.2 проверяет, что NAT-сеть работает. Если пинг не идёт — дальше нет смысла ставить пакеты.

**2. Обновить список пакетов и поставить нужное (UBU01).**

```bash
sudo apt update
sudo apt install -y apache2 mariadb-server php php-mysql php-gd php-xml php-bcmath php-mbstring php-ldap zabbix-server-mysql zabbix-frontend-php zabbix-apache-conf zabbix-sql-scripts zabbix-agent
```

`apt update` обновляет список доступных пакетов из репозиториев. `apt install` ставит веб-сервер Apache, базу MariaDB, PHP с модулями, которые требует frontend Zabbix, сам сервер, frontend, скрипты для создания схемы БД и агент (агент на самом сервере тоже полезен — сервер мониторит сам себя). Пакеты `zabbix-*` в стандартном репозитории Ubuntu 24.04 есть, но версия может быть старой — `[ПРОВЕРИТЬ]`, какая именно в твоём зеркале. Если хочешь свежую — есть официальный репозиторий Zabbix, но это отдельная настройка, для лаборатории хватит стандартного.

**3. Создать базу и пользователя БД (UBU01).**

```bash
sudo mysql -uroot
```

Внутри консоли MariaDB:

```sql
CREATE DATABASE zabbix CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
CREATE USER 'zabbix'@'localhost' IDENTIFIED BY 'Lab#2026-vektor';
GRANT ALL PRIVILEGES ON zabbix.* TO 'zabbix'@'localhost';
SET GLOBAL log_bin_trust_function_creators = 1;
QUIT;
```

`CREATE DATABASE` создаёт пустую базу. `CREATE USER` и `GRANT` дают Zabbix-серверу доступ к ней. `log_bin_trust_function_creators = 1` нужен, чтобы импорт схемы не упал на создании функций — это требование Zabbix `[ПРОВЕРИТЬ для твоей версии]`. Пароль `Lab#2026-vektor` — учебный, в бою так нельзя.

**4. Импортировать схему БД (UBU01).**

```bash
zcat /usr/share/zabbix-sql-scripts/mysql/server.sql.gz | mysql -uzabbix -p zabbix
```

`zcat` распаковывает gzip-файл на лету, `mysql` заливает SQL в базу `zabbix` от пользователя `zabbix`. Спросит пароль — введи `Lab#2026-vektor`. Импорт идёт 1–3 минуты, это нормально. Путь к файлу может отличаться в зависимости от версии пакета — `[ПРОВЕРИТЬ]` через `dpkg -L zabbix-sql-scripts | grep server.sql`.

**5. Указать пароль БД серверу Zabbix (UBU01).**

```bash
sudo nano /etc/zabbix/zabbix_server.conf
```

Найти строку `# DBPassword=` и заменить на:

```text
DBPassword=Lab#2026-vektor
```

Сохранить (Ctrl+O, Enter, Ctrl+X). Без этого сервер не подключится к базе и не запустится.

**6. Запустить службы и включить автозапуск (UBU01).**

```bash
sudo systemctl restart zabbix-server zabbix-agent apache2
sudo systemctl enable zabbix-server zabbix-agent apache2
sudo systemctl status zabbix-server --no-pager
```

`restart` перезапускает, `enable` включает автозапуск при загрузке. В `status` ищи строку `Active: active (running)`. Если `failed` — смотри `journalctl -u zabbix-server -n 50 --no-pager`, там будет причина (чаще всего — неверный пароль БД или не импортирована схема).

**7. Открыть веб-интерфейс (браузер на хосте).**

В браузере на хосте: `http://10.10.10.30/zabbix`. Пройдёт мастер настройки: проверка требований → подключение к БД (Database host `localhost`, Database name `zabbix`, User `zabbix`, Password `Lab#2026-vektor`) → имя сервера (оставь `Zabbix server`) → финиш. После — вход: логин `Admin`, пароль `zabbix` (это дефолт Zabbix, смени его сразу в Profile → Change password).

**8. Установить агент на Windows (WIN11-CL01 и DC01).**

Скачай MSI-установщик Zabbix agent с официального сайта Zabbix (раздел Download, версия должна совпадать с сервером `[ПРОВЕРИТЬ]`). Запусти, в мастере укажи:
- Host name: `WIN11-CL01` (или `DC01`)
- Zabbix server IP/DNS: `10.10.10.30`
- Server or Proxy for active checks: `10.10.10.30`
- Listen port: `10050`

Установка создаст службу `Zabbix Agent`. Проверь в PowerShell:

```powershell
Get-Service 'Zabbix Agent'
Get-NetTCPConnection -LocalPort 10050 -State Listen
```

Первая команда должна показать `Running`, вторая — что порт 10050 слушается. Если служба не запускается — смотри Event Viewer → Windows Logs → Application.

**9. Разрешить порт 10050 в брандмауэре Windows (WIN11-CL01, DC01).**

```powershell
New-NetFirewallRule -DisplayName 'Zabbix agent 10050' -Direction Inbound -Protocol TCP -LocalPort 10050 -Action Allow -Profile Domain,Private
```

`New-NetFirewallRule` создаёт правило. `-Direction Inbound` — входящий трафик, `-LocalPort 10050` — порт агента, `-Profile Domain,Private` — только для доменного и частного профиля (публичный не трогаем, это правильная практика). На стенде до L1 №44 клиенты ещё в рабочей группе, поэтому профиль будет `Private` — это нормально.

**10. Проверить, что сервер видит агента (UBU01).**

```bash
zabbix_get -s 10.10.10.51 -k agent.ping
```

`zabbix_get` — утилита с сервера, которая спрашивает у агента конкретный ключ. `agent.ping` возвращает `1`, если агент жив. Если пусто или ошибка — либо агент не запущен, либо брандмауэр, либо неверный адрес. Аналогично проверь DC01: `zabbix_get -s 10.10.10.10 -k agent.ping`.

### Сломай и почини

**Заявка:**

> **Пользователь:** Иван Иванов (бухгалтерия), ВМ WIN11-CL01
> **Что написал:** «Zabbix перестал показывать мой компьютер — в интерфейсе он серый, метрики не обновляются с утра. У соседей (DC01) всё зелёное.»
> **Срочность:** Средняя

**Как воспроизвести поломку.** На WIN11-CL01 в PowerShell от администратора:

```powershell
Stop-Service 'Zabbix Agent'
Set-Service 'Zabbix Agent' -StartupType Disabled
```

Служба остановлена и отключена от автозапуска. Через 2–3 минуты в Zabbix хост `WIN11-CL01` станет `Unavailable` (серый `ZBX`), метрики перестанут обновляться. DC01 при этом остаётся зелёным — это совпадает с текстом заявки.

**Диагностика по шагам.**

1. На UBU01: `zabbix_get -s 10.10.10.51 -k agent.ping` → пусто или ошибка `connection refused` / `timeout`. Значит, проблема на стороне клиента, а не сервера.
2. На UBU01: `ping -c 3 10.10.10.51` → пинг идёт. Значит, сеть и брандмауэр в порядке (ICMP разрешён), проблема в службе.
3. На WIN11-CL01: `Get-Service 'Zabbix Agent'` → `Stopped`, `StartType: Disabled`. Причина найдена.
4. Проверь журнал: Event Viewer → Windows Logs → Application → источник `Zabbix Agent` — там будет запись об остановке службы (кто и когда). Если остановил не ты — это повод эскалировать в L2 (возможно, кто-то «оптимизировал» автозапуск).

**Решение.** На WIN11-CL01 в PowerShell от администратора:

```powershell
Set-Service 'Zabbix Agent' -StartupType Automatic
Start-Service 'Zabbix Agent'
Get-Service 'Zabbix Agent'
```

Ожидаемо: `Status: Running`, `StartType: Automatic`. Через 1–2 минуты в Zabbix хост снова зелёный, метрики пошли.

**Ответ пользователю.** «Иван, добрый день. Проблема была в том, что на вашем компьютере остановилась служба Zabbix Agent — та, что отправляет данные мониторинга. Я её запустил и включил автозапуск, сейчас всё отображается. Если повторится — напишите, разберёмся, что её останавливает.»

**Закрытие заявки.** Категория: «Мониторинг / агент», решение: «Служба Zabbix Agent была остановлена и отключена от автозапуска; запущена, автозапуск восстановлен». Время: 10–15 минут.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** оставить дефолтный пароль `Admin`/`zabbix`. **К чему приводит:** любой, кто дотянется до веб-интерфейса, получит полный контроль над мониторингом. **Как правильно:** сменить пароль сразу после первого входа, как в шаге 7.

2. **Ошибка:** открыть порт 10050 на все профили брандмауэра (`-Profile Any`). **К чему приводит:** агент доступен из любой сети, включая публичные Wi-Fi. **Как правильно:** `-Profile Domain,Private`, как в разделе 4.

3. **Ошибка:** запустить `zabbix-server` до импорта схемы БД. **К чему приводит:** служба падает с `cannot connect to database` или `table 'hosts' doesn't exist`. **Как правильно:** сначала БД и импорт, потом конфиг и запуск.

4. **Ошибка:** забыть `log_bin_trust_function_creators = 1` перед импортом. **К чему приводит:** импорт падает на создании функций. **Как правильно:** выставить до импорта, как в разделе 4.

5. **Ошибка:** поставить агент с версией, отличной от сервера. **К чему приводит:** часть метрик не приходит, в логах агента ошибки протокола. **Как правильно:** версии сервера и агента должны совпадать (или агент не старше сервера на мажорную версию) `[ПРОВЕРИТЬ для твоей версии]`.

6. **Ошибка:** настраивать всё вручную на каждом хосте, без шаблонов. **К чему приводит:** десятки элементов, которые забываешь обновлять. **Как правильно:** привязывать шаблон `Windows by Zabbix agent` / `Linux by Zabbix agent`.

7. **Ошибка:** игнорировать `Monitoring → Problems` и смотреть только `Latest data`. **К чему приводит:** пропускаешь реальные проблемы. **Как правильно:** `Problems` — первое, что открываешь утром.

8. **Ошибка:** ставить Zabbix на ту же машину, что и критичный сервис, без запаса по диску. **К чему приводит:** БД Zabbix растёт, диск забивается, падает и сервис, и мониторинг. **Как правильно:** отдельная ВМ под мониторинг (у нас так и есть — UBU01 отдельно от DC01).

### Безопасность

- Пароль `Lab#2026-vektor` — только для стенда. В боевой среде пароли БД, веб-интерфейса и агентов разные, хранятся в менеджере секретов, а не в конфиге в открытом виде.
- Не открывай веб-интерфейс Zabbix в интернет напрямую. В бою — за VPN или reverse-proxy с HTTPS.
- Агент Zabbix имеет доступ к метрикам системы; не давай ему лишних прав (не запускай от `SYSTEM` без необходимости, если хватает отдельного пользователя) `[ПРОВЕРИТЬ в твоей версии]`.
- Мониторинг — это ещё и данные о нагрузке и доступности; по 152-ФЗ это не персональные данные, но по внутренним политикам доступ к нему ограничивают.

## 7. Вопросы на собеседовании

**Вопрос 1. «Что такое Zabbix и зачем он нужен в компании?»**

Ответ: «Zabbix — система мониторинга с открытым кодом. Ставится на Linux, состоит из сервера, агентов на машинах и веб-интерфейса. Сервер по расписанию опрашивает агентов по порту 10050, собирает метрики — CPU, память, диски, службы — и по триггерам поднимает проблемы. Нужен, чтобы узнавать о сбое раньше пользователя и видеть историю: когда началось, что менялось. На стенде я ставил его на Ubuntu Server, агенты — на Windows Server и Windows 11, шаблон `Windows by Zabbix agent`».

**Что хочет услышать интервьюер:** что ты понимаешь архитектуру (сервер/агент/frontend) и роль мониторинга в поддержке, а не просто «ну такая штука».

**Красный флаг:** «Zabbix — это антивирус» или «не знаю, но слышал».

**Вопрос 2. «Пользователь пишет, что сервер недоступен. Как мониторинг помогает в диагностике?»**

Ответ: «Первым делом смотрю в Zabbix на этот хост: зелёный он или серый. Если серый — проблема на стороне машины или сети, а не приложения. Дальше смотрю метрики: не забит ли диск, не упёрся ли CPU, живы ли нужные службы. Если хост зелёный, а пользователь жалуется — проблема в приложении или в самом пользователе, и это уже другой сценарий. Так я экономлю время: не бегаю по серверам, а сразу вижу картину».

**Что хочет услышать интервьюер:** что ты используешь мониторинг как инструмент диагностики, а не как «красивую картинку».

**Красный флаг:** «Сразу иду на сервер и смотрю логи» — без упоминания мониторинга.

**Вопрос 3. «Хост в Zabbix серый, что проверишь?»**

Ответ: «По порядку: пингую машину с сервера Zabbix — если пинг не идёт, проблема в сети или машина выключена. Если пинг идёт — проверяю на клиенте службу агента (`Get-Service 'Zabbix Agent'` на Windows, `systemctl status zabbix-agent` на Linux). Если служба стоит — проверяю брандмауэр: открыт ли 10050/TCP. Дальше — `zabbix_get -s <ip> -k agent.ping` с сервера: если возвращает `1`, агент жив, проблема в конфигурации хоста в Zabbix (неверный IP, порт, шаблон). Если пусто — смотрю логи агента».

**Что хочет услышать интервьюер:** чёткий порядок «сеть → служба → порт → конфиг → логи», а не «перезагружу всё».

**Красный флаг:** «Перезапущу сервер Zabbix» — это не диагностика.

**Вопрос 4. «Чем отличается item от trigger?»**

Ответ: «Item — это метрика, конкретное значение, которое сервер собирает: например, "свободно байт на диске C:". Trigger — правило, которое смотрит на item и решает, проблема это или нет: "свободно меньше 10% — проблема". Item собирает данные всегда, trigger реагирует только когда условие выполнено. Проблема открывается, когда trigger сработал, и закрывается, когда метрика вернулась в норму».

**Что хочет услышать интервьюер:** что ты понимаешь разделение «данные» и «правила».

**Красный флаг:** путаница «trigger — это метрика».

**Вопрос 5. «Какие порты использует Zabbix?»**

Ответ: «10050/TCP — агент, к нему стучится сервер. 10051/TCP — сам сервер, для активных проверок и обмена с прокси. 80/TCP (или 443) — веб-интерфейс. На стенде я открывал 10050 на Windows-клиентах и 80 на UBU01 для доступа к frontend».

**Что хочет услышать интервьюер:** что ты помнишь порты и понимаешь, кто к кому ходит.

**Красный флаг:** «Не помню» без попытки рассуждать.

## 8. Источники (официальная документация)

- **Zabbix.** Официальная документация: домен `zabbix.com`, раздел Documentation → Zabbix 7.0 (или твоя версия) → Installation → «Installation from packages» (Ubuntu/Debian) и «Windows agent». Поисковая фраза: `zabbix install ubuntu server mysql apache`.

- **Zabbix.** Там же: «Zabbix agent» — параметры конфигурации, порт 10050. Поисковая фраза: `zabbix agent configuration file Server ListenPort`.
- **Ubuntu.** Официальная документация: домен `ubuntu.com`, раздел Server → «Package management» (apt). Поисковая фраза: `ubuntu server apt install package`.
- **MariaDB.** Официальная документация: домен `mariadb.com`, раздел «CREATE USER» и «GRANT». Поисковая фраза: `mariadb create user grant privileges`.
- **Microsoft.** Документация по PowerShell: домен `learn.microsoft.com`, разделы `New-NetFirewallRule`, `Get-Service`, `Set-Service`. Поисковая фраза: `powershell New-NetFirewallRule inbound port`.
- **Zabbix.** Форум и база знаний: домен `zabbix.com`, раздел Community → «Zabbix forums». Поисковая фраза: `zabbix agent windows service not starting` `[ПРОВЕРИТЬ актуальность разделов для твоей версии]`.
