# Обновления Windows: Windows Update, WSUS, откат, типовые ошибки

## 1. Введение (зачем это нужно в реальной работе)

Утро понедельника. В тикете — Иван Иванов, бухгалтерия, рабочая станция WIN11-CL01:

> «Добрый день! Включил компьютер — 20 минут висит «Настройка Windows. Не выключайте компьютер, 35%». Я опоздал на планёрку. Почему компьютер вообще что-то ставил ночью без моего разрешения? И можно ли это выключить навсегда?»

Дальше в течение дня прилетят ещё три похожих: у petrova (WIN10-CL02) обновление не ставится с кодом 0x80073712, у кладовщика «после обновления перестал открываться файл на `\\FS01\Obshchee`», а на сервере FS01 ночная перезагрузка оборвала печать.

Обновления — это тема, которая в L1 занимает больше времени, чем кажется. Причины две. Первая: обновления — единственный процесс в Windows, который **сам решает перезагрузить машину**, поэтому именно они регулярно «ломают людям работу». Вторая: обновления ломаются сами — кэш повреждается, места не хватает, политика указывает на недоступный сервер, хранилище компонентов бьётся.

После этой главы ты должен уметь: назвать причину и код ошибки, быстро понять, откуда машина вообще берёт обновления (из интернета или из локального WSUS), найти установленное обновление, откатить его, почистить кэш без убивания системы и — главное — спокойно объяснить пользователю, что происходит, чтобы он не отключил службу обновлений сам.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Windows Update — это не одно приложение, а набор служб, работающих в фоне.

**Слои обновления (сверху вниз):**

```text
Пользователь (Параметры / центр обновления)
      |
      v
USO — Update Orchestrator (служба UsoSvc). Решает КОГДА ставить,
      следит за "часами активности", планирует перезагрузку
      |
      v
Агент Windows Update (служба wuauserv). Сканирует, что нужно,
      формирует список обновлений под эту конкретную сборку
      |
      v
BITS (служба bits) + Delivery Optimization (dosvc) — качают файлы
      |
      v
Источник: Microsoft Update (интернет) ИЛИ локальный WSUS
      |
      v
CBS — Component Based Servicing. Ставит обновление по-настоящему:
      распаковывает в хранилище компонентов WinSxS, меняет файлы
      |
      v
Требуется перезагрузка. В момент выключения применяются "отложенные"
      операции. Именно тут появляется экран "Настройка Windows"
```

Три вещи, которые важно понять сразу:

1. **Обновление ставится в два этапа.** Сначала файлы распаковываются в системное хранилище (это можно делать на работающей машине), потом при перезагрузке применяются изменения. Экран «Настройка Windows 35%» — это второй этап. Если он висит долго — это нормально; если больше часа-двух — уже нет.
2. **Служб несколько, и они связаны.** Остановил wuauserv, но не остановил bits — кэш нормально не почистишь. Есть ещё защищённая служба **WaaSMedicSvc** (Windows Update Medic Service) — её нельзя выключить через `services.msc`, она автоматически «лечит» отключённый Windows Update. Это сделано специально, чтобы админы и «оптимизаторы» не могли навсегда убить обновления.
3. **Есть политика, которая сильнее настроек.** Если в реестре задана политика «использовать сервер обновлений в интрасети», Windows перестаёт ходить в интернет и идёт только туда, куда указано. Именно на этом ломаются 90% «а у меня обновления не ищутся».

**Windows Update против WSUS.**

```text
                        [ internet ]
                             |
                   HTTPS 443 | *.windowsupdate.com
                             |
        +--------------------+---------------------+
        |                                          |
  (домашний ПК)                          [ WSUS на Windows Server ]
   Windows Update сам                     качает обновления у Microsoft
   ходит в Microsoft                      один раз, хранит у себя,
                                          админ ОДОБРЯЕТ (approve),
                                          что и кому раздавать
                                                   |
                                     HTTP 8530 / HTTPS 8531
                                                   |
                                    +--------------+--------------+
                                    |                             |
                              [WIN11-CL01]                 [WIN10-CL02]
                                    |                             |
                                    +--- Delivery Optimization ---+
                                        (7680/TCP, 3544/UDP — раздача
                                         уже скачанного внутри LAN)
```

WSUS (Windows Server Update Services) — роль Windows Server. Смысл: 50 машин не тянут один и тот же файл на 800 МБ из интернета каждая, а скачивают его один раз на сервер и раздают по локальной сети. Плюс админ контролирует, что и когда установится: обновление сначала попадает в WSUS, потом «одобряется» для группы компьютеров.

Клиент узнаёт про WSUS **через групповую политику** (в домене — GPO с контроллера, на одиночной машине — локальная политика `gpedit.msc`). Ключи политики лежат в ветке:

```text
HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate
    WUServer        = http://10.10.10.10:8530
    WUStatusServer  = http://10.10.10.10:8530
HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU
    UseWUServer     = 1
```

Если там пусто — машина ходит в Microsoft напрямую.

**Важно про РФ и 2026 год.** Официальные поставки Microsoft в Россию приостановлены с 2022 года. Это не отменяет работу уже приобретённых лицензий и evaluation-стендов, но скачивание обновлений и дистрибутивов из РФ бывает нестабильным. Поэтому в компаниях чаще держат **локальный WSUS** или офлайн-репозиторий обновлений, собранный из официальных источников. Отдельно помни: **Windows 10 вышла из поддержки 14 октября 2025 года** — машины на WIN10-CL02 в реальной работе либо переводят на Windows 11, либо покупают ESU (Extended Security Updates) `[ПРОВЕРИТЬ условия ESU для РФ]`.

**Типы обновлений, которые ты встретишь:**

| Тип | Что это | Как часто |
|-----|---------|-----------|
| Quality update (качественное) | Ежемесячный кумулятивный пакет безопасности и исправлений | Раз в месяц, второй вторник («Patch Tuesday») |
| Feature update (функциональное) | Новая версия Windows (например, 23H2 → 24H2) | 1–2 раза в год |
| .NET / Visual C++ / Defender | Отдельные компоненты | По мере выхода |
| Драйверы | Через Windows Update приходят «рекомендованные» драйверы | Нерегулярно, часто ломают — см. урок 21 |

**Порты, которые нужны для диагностики:** 443/TCP (Microsoft Update), 80/TCP (проверка отзыва сертификатов), 8530/TCP и 8531/TCP (WSUS по HTTP и HTTPS), 7680/TCP и 3544/UDP (Delivery Optimization).

## 3. Аналогия из жизни

Представь автопарк компании. У каждой машины есть регламентное ТО: замена масла, колодок, прошивки блока управления. Есть два способа это организовать.

Первый — каждый водитель сам едет в любой сервис, когда загорелась лампочка, и сам решает, что делать. Быстро для одного, но 50 водителей едут в 50 разных сервисов, платят по-разному, а один вчера поставил «улучшенную прошивку» от знакомого и теперь машина не заводится.

Второй — начальник автопарка (WSUS) раз в месяц закупает одну партию деталей на всех, проверяет на одной тестовой машине, и потом выдаёт со склада по списку: «этой группе — можно, вот этой — пока нет». Водитель не выбирает, он приезжает на плановое ТО в назначенное окно. Дороже по организации, зато предсказуемо.

Ещё деталь: у водителя есть «часы, когда машина нужна для работы» (Active hours), и в это время гараж её не забирает. А если деталь поставили и она оказалась бракованной — есть N дней, чтобы вернуть старую (окно отката).

Аналогия перестаёт работать в одном месте: снятую с машины деталь можно вернуть на склад, а вот неудачно установленное обновление Windows иногда откатить нельзя — и тогда систему лечат в WinRE или переустанавливают.

## 4. Практика и команды

Все команды — на WIN11-CL01 или WIN10-CL02, из PowerShell **от имени администратора** (если не указано иное).

**1. Понять, какая версия Windows и сборка.** Номер сборки критичен: обновление подбирается под сборку.

```powershell
winver
# или
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber, OsArchitecture
```

```text
WindowsProductName WindowsVersion OsBuildNumber
------------------ -------------- -------------
Windows 11 Enterprise 2009         22631
```

Что смотреть: `OsBuildNumber`. Два одинаковых «Windows 11» с разными сборками — это разные наборы обновлений.

**2. Список установленных обновлений.**

```powershell
Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 10
```

```text
Source  Description      HotFixID   InstalledOn
------  -----------      --------   -----------
WIN11   Update           KB5041585  15.08.2026 0:00:00
WIN11   Security Update  KB5040442  16.07.2026 0:00:00
```

`Get-HotFix` (алиас `gh`) быстрый, но иногда неполный — не показывает обновления, поставленные через WSUS-пакеты. Более честный источник:

```powershell
Get-CimInstance -ClassName Win32_QuickFixEngineering | Select-Object HotFixID, InstalledOn
```

> Старый `wmic qfe list brief` в новых сборках Windows 11 может отсутствовать — WMIC объявлен deprecated и постепенно удаляется `[ПРОВЕРИТЬ на своей сборке]`.

**3. Полный список пакетов в хранилище компонентов (DISM).**

```cmd
dism /online /get-packages /format:table | findstr /i "rollup"
```

```text
Package Identity                                             State
----------------                                             -----
Package_for_RollupFix~31bf3856ad364e35~amd64~~22621.4169.1.11  Installed
```

`/online` — работать с текущей системой, `/format:table` — читаемый вывод, `findstr /i "rollup"` — оставить только кумулятивные пакеты. Смотри столбец `State`: `Installed`, `Install Pending`, `Uninstall Pending`. Именно `Pending` объясняет, почему «обновление поставилось, но не поставилось» — нужна перезагрузка (`dism /online /cleanup-image /revertpendingactions` отменяет зависшие отложенные операции, применять осторожно).

**4. Удалить конкретное обновление по номеру KB.**

```cmd
wusa.exe /uninstall /kb:5041585 /quiet /norestart
```

`/uninstall /kb:` — удалить пакет с этим KB, `/quiet` — без окон, `/norestart` — не перезагружаться (перезагрузку планируем сами через `shutdown /r /t 60`). После удаления обязательна перезагрузка.

**GUI-путь (так чаще делает L1):** Параметры → Центр обновления Windows → Журнал обновлений → «Удалить обновления» → выбрать KB → Удалить.

**5. Проверить состояние служб обновления.**

```powershell
Get-Service wuauserv, bits, dosvc, UsoSvc, WaaSMedicSvc | Format-Table Name, Status, StartType
```

```text
Name           Status  StartType
----           ------  ---------
bits           Running Automatic
dosvc          Running Manual
UsoSvc         Running Automatic
WaaSMedicSvc   Running Manual
wuauserv       Running Manual
```

`wuauserv` в состоянии `Stopped`/`Disabled` — почти всегда следствие «оптимизатора». `WaaSMedicSvc` не останавливается штатно — это норма, не пугайся.

**6. Почистить кэш обновлений (главный приём при «застряло на 0%»).**

```cmd
net stop wuauserv
net stop bits
ren C:\Windows\SoftwareDistribution SoftwareDistribution.old
ren C:\Windows\System32\catroot2 catroot2.old
net start wuauserv
net start bits
```

Переименовываем, а **не удаляем**: `SoftwareDistribution` — папка с уже скачанными обновлениями и базой данных; Windows создаст её заново при следующем сканировании. `catroot2` — хранилище подписей обновлений. Если `ren` пишет «Отказано в доступе» — какая-то служба ещё держит файлы; проверь `dosvc` и `UsoSvc`.

**7. Запустить проверку обновлений из командной строки.**

```cmd
usoclient StartScan
```

Запускает сканирование без кликов по меню. Другие глаголы: `StartDownload`, `StartInstall`, `RefreshSettings` `[ПРОВЕРИТЬ актуальный набор в своей сборке — утилита официально не документирована]`. Старая команда `wuauclt /detectnow` в Windows 10/11 фактически не работает — не трать на неё время.

**8. Прочитать лог обновлений.**

```powershell
Get-WindowsUpdateLog -LogPath C:\Temp\WU.log
```

Собирает разрозненные ETL-логи в один текстовый файл. Дальше:

```powershell
Select-String -Path C:\Temp\WU.log -Pattern "error|0x80" | Select-Object -Last 30
```

Ищем код ошибки и имя обновления. Файл большой, читать целиком бессмысленно.

**9. События журнала «Система» по компоненту обновлений.**

```powershell
Get-WinEvent -LogName System -MaxEvents 300 |
  Where-Object { $_.ProviderName -eq 'WindowsUpdateClient' } |
  Select-Object TimeCreated, Id, LevelDisplayName, Message -First 10
```

Ходовые Event ID: **19** — обновление успешно установлено, **20** — ошибка установки, **43/44** — этапы скачивания и установки. Быстрее, чем разбирать полный лог.

**10. Проверить, куда смотрит машина и доступен ли WSUS.**

```powershell
Get-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' -ErrorAction SilentlyContinue
Get-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU' -ErrorAction SilentlyContinue
Test-NetConnection -ComputerName 10.10.10.10 -Port 8530
gpupdate /force
gpresult /r
```

`Test-NetConnection` (алиас `tnc`) покажет `TcpTestSucceeded : True/False` — доходит ли клиент до WSUS. `gpresult /r` — применились ли политики к компьютеру (смотреть раздел «Объекты групповой политики», применённые к компьютеру).

**11. Открыть нужный экран Параметров одной командой.**

```powershell
Start-Process "ms-settings:windowsupdate"
```

Удобно при удалённой поддержке: не объясняешь пользователю, куда кликать, а сразу кидаешь ему ссылку/скрипт.

**12. Управление окном отката на прошлую версию Windows.**

```cmd
DISM /Online /Set-OSUninstallWindow /Value:30
```

Задаёт, сколько дней (по умолчанию 10) доступна кнопка «Вернуться назад» после функционального обновления. GUI-путь: Параметры → Система → Восстановление → «Вернуться назад».

## 5. Лабораторная работа (пошаговый сценарий на виртуалке)

### Предусловия

- **WIN11-CL01** — Windows 11 Enterprise (Evaluation), локальная учётная запись с правами администратора, сеть VMnet8 (NAT), интернет есть.
- **WIN10-CL02** — Windows 10 Enterprise LTSC (Evaluation), аналогично.
- **DC01** — может быть уже поднят как сервер с DNS/DHCP, но **роль WSUS на нём НЕ установлена** — и это принципиально для сценария ниже. Если DC01 у тебя ещё не создан (сетевой модуль не пройден) — лабораторная всё равно выполняется, просто вместо адреса `10.10.10.10` считай, что «сервер обновлений в компании не настроен». Домен AD на этом уроке ещё не развёрнут (это отдельный модуль), поэтому работаем с локальными политиками через `gpedit.msc`.
- Ты уже прошёл уроки 15, 18, 19 — умеешь читать журнал событий, работать в PowerShell и знать, что делают `sfc` и `dism`.

### Снапшот

В VMware Workstation для каждой ВМ: правый клик по вкладке машины → **Snapshot → Take Snapshot**, имя:

```text
before-l1-020
```

Сделать на **WIN11-CL01** и **WIN10-CL02** (DC01 не трогаем). Если ты ведёшь журнал — сразу добавь строку в `stand-log.md`: «before-l1-020 — снапшоты WIN11-CL01, WIN10-CL02 перед темой обновлений».

### Шаги

1. **WIN11-CL01.** Зафиксируй исходное состояние. Выполни `winver` (запиши сборку в блокнот) и `Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 10`. **Ожидаемо:** список KB с датами; самая свежая — дата установки образа Evaluation.

2. **WIN11-CL01.** Открой Параметры → Центр обновления Windows. Найди и запиши: дату последней проверки, статус («Все обновления установлены» / «Доступны обновления»), ссылку «Приостановить обновления», «Журнал обновлений», «Дополнительные параметры». **Ожидаемо:** видишь реальную картину машины. Скриншот — в папку `C:\Lab\`.

3. **WIN11-CL01.** В «Дополнительные параметры» → «Часы активности» выставь окно, например 08:00–19:00. **Ожидаемо:** в этом интервале Windows не будет перезагружаться сама.

4. **WIN11-CL01.** Запусти сканирование из консоли: `usoclient StartScan`. Затем сразу проверь события:
```powershell
Get-WinEvent -LogName System -MaxEvents 500 | Where-Object ProviderName -eq 'WindowsUpdateClient' | Select-Object TimeCreated,Id,Message -First 5
```
**Ожидаемо:** появились записи с ID 43/44 (начало сканирования/скачивания) или 19, если ставить нечего.

5. **WIN11-CL01.** Посмотри пакеты: `dism /online /get-packages /format:table | findstr /i "rollup"`. **Ожидаемо:** одна-две строки `Package_for_RollupFix...` со `State: Installed`. Запиши номер сборки из имени пакета.

6. **WIN11-CL01.** Собери лог: `Get-WindowsUpdateLog -LogPath C:\Temp\WU.log` (папку `C:\Temp` создай заранее). Проверь, что файл появился и его размер не нулевой. **Ожидаемо:** файл на несколько мегабайт; в нём есть строки с датами последних проверок.

7. **WIN11-CL01.** Удали одно кумулятивное обновление из списка шага 1 через Параметры → Журнал обновлений → «Удалить обновления» (или `wusa /uninstall /kb:<номер> /quiet /norestart`). Перезагрузись. **Ожидаемо:** после перезагрузки `Get-HotFix` больше не показывает этот KB, сборка ОС откатилась назад. *Если удалять нечего или удаление блокируется — зафиксируй это как результат и переходи дальше: сам факт попытки и сообщение системы уже учебные.*

8. **WIN11-CL01.** Почисти кэш обновлений по командам из раздела 4, пункт 6. Проверь, что появились папки `SoftwareDistribution.old` и `catroot2.old`, а `C:\Windows\SoftwareDistribution` создалась заново и почти пустая. **Ожидаемо:** `Get-Service wuauserv` — `Running`.

9. **WIN11-CL01.** Запусти `usoclient StartScan` и убедись, что сканирование снова работает (события в журнале появились, ошибок нет). **Ожидаемо:** обновления ищутся, `SoftwareDistribution` начинает наполняться.

10. **WIN11-CL01.** Сымитируй корпоративную политику: `Win+R` → `gpedit.msc` → Конфигурация компьютера → Административные шаблоны → Компоненты Windows → Центр обновления Windows → включи «Указать расположение службы обновлений Microsoft в интрасети», адрес сервера обновлений и сервера статистики: `http://10.10.10.10:8530`. Выполни `gpupdate /force`, затем проверь реестр (раздел 4, пункт 10). **Ожидаемо:** в ветке `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` появились `WUServer` и `WUStatusServer`, в подветке `AU` — `UseWUServer = 1`.

11. **WIN11-CL01.** Перезапусти `wuauserv` и нажми «Проверить наличие обновлений». **Ожидаемо:** ошибка вида «Не удалось подключиться к службе обновлений» с кодом `0x8024401C` / `0x80244022` / `0x80072EFD` — WSUS на 10.10.10.10 нет, порт 8530 закрыт. Проверь: `Test-NetConnection -ComputerName 10.10.10.10 -Port 8530` → `TcpTestSucceeded: False`.

```text

Мне до пятницы надо поставить обновления, у нас проверка документов».

```

**Как воспроизвести поломку.** Ты сам вчера тестировал политику на WIN11-CL01 и по привычке применил её и на WIN10-CL02, а откатить забыл.

1. На **WIN10-CL02** открой `gpedit.msc` → Конфигурация компьютера → Административные шаблоны → Компоненты Windows → Центр обновления Windows → «Указать расположение службы обновлений Microsoft в интрасети» → Включить → `http://10.10.10.10:8530` для обоих полей.
2. `gpupdate /force`, затем `Restart-Service wuauserv`.
3. В Параметрах нажми «Проверить наличие обновлений» — появится ошибка с кодом (конкретный код может быть `0x8024401C`, `0x80244022` или `0x80072EFD` — это нормально, смысл один: клиент не достучался до сервера).

**Диагностика по шагам (именно в этом порядке):**

1. **Уточни у пользователя, что менялось.** Один вопрос «вы что-то настраивали или устанавливали вчера?» экономит полчаса. В нашем случае — «ничего не трогала».
2. **Проверь, есть ли вообще политика.** `Get-ItemProperty 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' -ErrorAction SilentlyContinue`. Видишь `WUServer = http://10.10.10.10:8530` — вот и причина. Пусто — политики нет, копаем в сторону сети.
3. **Проверь, применена ли политика к компьютеру.** `gpresult /r` — раздел «Объекты групповой политики, применённые к компьютеру». Иногда ключ в реестре есть, а политика «зависла» — тогда `gpupdate /force`.
4. **Проверь доступность сервера обновлений.** `Test-NetConnection -ComputerName 10.10.10.10 -Port 8530`. `False` — сервер недоступен или порт закрыт.
5. **Проверь службы.** `Get-Service wuauserv, bits, UsoSvc` — все должны быть `Running`. Если `wuauserv` отключена, её сначала включают: `Set-Service wuauserv -StartupType Manual; Start-Service wuauserv`.
6. **Посмотри лог и события.** `Get-WindowsUpdateLog`, затем `Get-WinEvent` по `WindowsUpdateClient` — ищем код и адрес, к которому шла попытка подключения. Убедись, что в логе фигурирует именно `10.10.10.10`.
7. **Сделай вывод и озвучь его до исправления.** «Машина настроена брать обновления с внутреннего сервера, а он недоступен — поэтому и ошибка».

**Решение.** Политика была настроена ошибочно и указывает на несуществующий WSUS. Возвращаем «Не задано» в `gpedit.msc` → `gpupdate /force` → `Restart-Service wuauserv` → «Проверить наличие обновлений». Если в компании WSUS действительно планируется — это отдельная задача на L2, и до её запуска клиенты должны ходить в Microsoft напрямую.

## 6. Ошибки новичков и безопасность

**1. Удалять папку `SoftwareDistribution` целиком.** → Windows не может восстановить базу обновлений, сканирование падает с разными кодами, иногда требуется `dism /restorehealth`. → Правильно: **останавливать службы и переименовывать**, а не удалять.

**2. Отключать `wuauserv` «чтобы не мешало».** → Через сутки WaaSMedicSvc включит службу обратно, а в журнале появятся ошибки; зато пользователь, привыкнув к «обновления отключены», пропустит патч безопасности. → Правильно: настраивать часы активности и окно установки, а не рубить службу.

**3. Удалять обновление без записи номера KB и без согласования.** → Через месяц никто не помнит, что откатывали, и почему у одной машины дырка в безопасности. → Правильно: фиксировать KB, причину и дату в заявке и `stand-log.md`.

**4. Ставить функциональное обновление (24H2 и подобные) в разгар рабочего дня.** → Откат занимает часы, а если что-то пойдёт не так — рабочий день пользователя потерян. → Правильно: функциональные обновления — планово, по кольцам (сначала тестовая машина, потом все), вечером или в выходные, предупредив пользователя.

**5. Ставить «оптимизаторы реестра» и «активаторы», которые лезут в Windows Update.** → Ломают подписи, отключают службы, меняют политики — потом ловишь 0x80070005 и 0x8024402C. → Правильно: не ставить; на учебном стенде — только официальные evaluation-образы.

**6. Игнорировать «Ожидается перезагрузка».** → Обновления копятся в состоянии `Install Pending`, новые не ставятся, `dism` показывает кашу. → Правильно: после установки планировать перезагрузку сразу, а не «когда-нибудь».

**7. Не проверять свободное место перед установкой.** → Код `0x800F0922`: система не смогла дописать компоненты. → Правильно: до установки смотреть свободное место на `C:` (нужно хотя бы 15–20 ГБ) и на служебном разделе.

**8. Считать, что «обновление виновато» всегда.** → Часто «после обновления не работает» = другое обновление, драйвер, политика или совпадение. → Правильно: сначала выяснить точное время поломки и что реально изменилось, а не удалять всё подряд.

### Безопасность

- **Не отключать проверку подписи драйверов и не ставить обновления из торрентов/«сборников».** Ставь только официальные пакеты из Windows Update, WSUS или Microsoft Update Catalog. Пиратские «офлайн-паки» — прямой путь к майнеру в системе.
- **WSUS по HTTP (8530) — незашифрованный трафик.** В бою поднимают HTTPS (8531) с внутренним сертификатом, иначе обновления можно подменить внутри сети.
- **Тестовое кольцо обязательно.** В нормальной компании обновления сначала идут на пилотную группу (2–3 машины), потом на всех. Ставить всё сразу на 50 машин — это как раз тот случай, когда один битый патч останавливает работу офиса.
- **Учебный пароль `Lab#2026-vektor` — только для стенда.** В реальной работе он бы не пережил и дня.

## 7. Вопросы на собеседовании (3–5 вопросов с ответами)

**Вопрос 1. Пользователь жалуется: «Windows перезагрузилась ночью, я потерял несохранённый отчёт». Твои действия?**

Ответ: сначала спокойно объясняю причину — установка обновлений требует перезагрузки, и она была запланирована вне часов активности. Дальше проверяю: Параметры → Центр обновления Windows → Журнал обновлений (какое обновление и когда), часы активности, не стоит ли политика принудительной перезагрузки с коротким дедлайном. Предлагаю решение: расширяю часы активности под график пользователя, настраиваю напоминания о перезагрузке, объясняю, что нажатие «Обновить и выключить» переносит установку на конец дня. Дополнительно напоминаю про автосохранение в 1С/Office.

*Что хочет услышать интервьюер:* что ты не оправдываешься и не советуешь «отключить обновления», а ищешь настройку и работаешь с пользователем.
*Красный флаг:* «Сейчас отключу вам обновления, и всё будет хорошо».

**Вопрос 2. Чем Windows Update отличается от WSUS и как понять, откуда конкретная машина берёт обновления?**

Ответ: Windows Update — облачный сервис Microsoft, куда клиент ходит сам по HTTPS/443. WSUS — локальная роль Windows Server, которая скачивает обновления один раз и раздаёт внутри сети по HTTP/8530 или HTTPS/8531, с одобрением (approve) по группам. Клиент переключается на WSUS через групповую политику. Проверить просто: смотрю ветку `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` — если есть `WUServer` и `UseWUServer = 1`, машина управляется WSUS; если ветки нет — ходит в Microsoft. Дополнительно `gpresult /r` показывает применённые политики, а `Test-NetConnection -Port 8530` — доступность сервера.

*Что хочет услышать интервьюер:* понимание, что «обновления не работают» часто означает «политика указывает на недоступный WSUS».
*Красный флаг:* «WSUS — это то же самое, только от другого вендора».

**Вопрос 3. Обновление не устанавливается, код 0x80073712. Что делаешь по шагам?**

Ответ: `0x80073712` — повреждено хранилище компонентов (WinSxS). Порядок: 1) проверить свободное место на `C:`; 2) `dism /online /cleanup-image /scanhealth`, затем `/restorehealth` (нужен интернет или источник с install.wim); 3) `sfc /scannow`; 4) перезагрузка и повторная попытка установки; 5) если не помогло — `dism /online /cleanup-image /startcomponentcleanup`, перезапуск служб `wuauserv`/`bits`, очистка `SoftwareDistribution` (с переименованием, не удалением); 6) в крайнем случае — ручная установка MSU из Microsoft Update Catalog. Всё фиксирую в заявке.

*Что хочет услышать интервьюер:* знание связки DISM + SFC и понимание, что это не «удалить и забить».
*Красный флаг:* «Переустановлю Windows» как первое действие.

**Вопрос 4. Как откатить неудачное обновление и что делать, если после перезагрузки система не загружается?**

Ответ: если система грузится — Параметры → Центр обновления Windows → Журнал обновлений → «Удалить обновления», либо `wusa /uninstall /kb:<номер> /quiet /norestart` с последующей перезагрузкой; для функционального обновления — Параметры → Система → Восстановление → «Вернуться назад» (окно по умолчанию 10 дней, настраивается через `DISM /Online /Set-OSUninstallWindow`); пакеты видны в `dism /online /get-packages`. Если не грузится — WinRE: «Устранение неполадок» → «Дополнительные параметры» → «Удалить последнее обновление качества» (и отдельный пункт для функционального). Если и это не помогло — восстановление из образа/точки восстановления.

*Что хочет услышать интервьюер:* что ты знаешь три уровня отката — GUI, командная строка, WinRE.
*Красный флаг:* «Откатить нельзя, только переустановка».

**Вопрос 5. Что такое часы активности и зачем они нужны?**

Ответ: это настраиваемое окно времени, в котором Windows не перезагружается автоматически для установки обновлений. Настраивается в Параметры → Центр обновления Windows → Дополнительные параметры → Часы активности, в домене — политикой. Нужны, чтобы обновления не прерывали работу пользователя. Это компромисс: полностью отключать обновления нельзя, поэтому мы не убираем их, а сдвигаем во времени.

*Что хочет услышать интервьюер:* понимание баланса «безопасность против удобства» и знание, что это настраивается централизованно.
*Красный флаг:* «Часы активности — это чтобы вообще никогда не обновлялось».
