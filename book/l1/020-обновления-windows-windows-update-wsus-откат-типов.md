## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Windows Update — это не одно приложение, а связка из нескольких служб, папок и сетевых компонентов. Разберём по слоям.

**Службы.** На любой Windows 10/11 работают как минимум две ключевые службы:

- `wuauserv` (Windows Update) — сам движок: скачивает, проверяет, устанавливает.
- `UsoSvc` (Update Orchestrator Service) — «дирижёр»: решает, когда ставить, когда перезагружать, следит за активными часами.
- `BITS` (Background Intelligent Transfer Service) — фоновая передача файлов, качает пакеты обновлений, не забивая канал.
- `CryptSvc` (Cryptographic Services) — проверяет цифровые подписи пакетов. Если он «лежит», обновления не встанут.
- `msiserver` (Windows Installer) — нужен для установки MSI-патчей.

Если хотя бы одна из них в состоянии Stopped или Disabled — обновления не работают, и в интерфейсе вы увидите ошибку вроде `0x80070422`.

**Папки.** Скачанные пакеты лежат в `C:\Windows\SoftwareDistribution\Download`. Это кэш: его можно безопасно удалить (при остановленных службах), Windows перекачает заново. История установленных обновлений — в `C:\Windows\WinSxS` (это хранилище компонентов, туда руками не лезем никогда) и в реестре `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing`.

**Сеть.** Клиент Windows Update обращается к серверам Microsoft по HTTPS (443) на адреса вида `*.update.microsoft.com`, `*.windowsupdate.com`, `*.delivery.mp.microsoft.com`. В корпоративной сети эти адреса часто закрыты, и тогда работает WSUS — внутренний сервер, который сам скачивает патчи из интернета и раздаёт их клиентам по HTTP (8530) или HTTPS (8531). Клиент узнаёт про WSUS из групповой политики (ключ реестра `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`).

**Схема (домашний стенд сейчас и корпоративная сеть в будущем):**

```text
ДОМАШНИЙ СТЕНД (сейчас, до L1 №33 и №42):
  WIN11-CL01 (10.10.10.51) ──┐
                             ├──► интернет (NAT через VMnet8) ──► серверы Microsoft
  WIN10-CL02 (10.10.10.52) ──┘

КОРПОРАТИВНАЯ СЕТЬ (теория, WSUS):
  WIN11-CL01 ──┐
               ├──► WSUS-сервер (внутри сети) ──► Microsoft (раз в сутки)
  WIN10-CL02 ──┘        ▲
                        └── политика: "адрес сервера обновлений"
```

**Типы обновлений.** Важно различать:

- **Quality Update** (ежемесячный «патч-вторник», второй вторник месяца) — исправления безопасности и багов. Ставится быстро, откатывается через «Удалить обновление».
- **Feature Update** (обновление версии Windows, например 23H2 → 24H2) — крупное, ставится 30–60 минут, откатывается только через «Вернуться к предыдущей версии» в течение 10 дней.
- **Driver Update** — драйверы через Windows Update. Часто ломают периферию, поэтому в корпоративной среде их обычно отключают политикой.
- **Definition Update** — обновления баз Defender, приходят несколько раз в день.

**Точки отката.** Windows хранит предыдущие версии системных файлов в `WinSxS`, поэтому «Удалить обновление» работает. Для Feature Update — отдельный механизм `Windows.old` (папка `C:\Windows.old`), живёт 10 дней.

**Активные часы.** По умолчанию Windows не перезагружается в рабочее время (обычно 8:00–17:00). Если пользователь жалуется «перезагрузился ночью и потерял несохранённое» — это как раз оно.

## 3. Аналогия из жизни

Представьте, что Windows Update — это курьерская служба, которая привозит вам посылки (патчи). У неё есть:

- **Склад** (`SoftwareDistribution\Download`) — куда складывают коробки, пока вы не заберёте.
- **Диспетчер** (`UsoSvc`) — решает, в какое время вам звонить в дверь, чтобы не разбудить.
- **Курьер** (`wuauserv`) — собственно привозит.
- **Охрана на входе** (`CryptSvc`) — проверяет пломбы на коробках, не подменили ли.
- **Список доставки** (WSUS в офисе) — если вы в бизнес-центре, курьер не ходит к вам лично, а оставляет всё на ресепшене, а вы забираете оттуда.

Если склад забит старыми коробками (кэш `SoftwareDistribution` раздулся) — новые не помещаются, доставка «залипает». Если диспетчер уволился (служба `UsoSvc` отключена) — никто не звонит, обновления не ставятся. Если охрана нашла подозрительную пломбу (сбой подписи) — посылку не принимают, вы видите ошибку `0x800b0109`.

Где аналогия ломается: курьер не может «откатить» уже доставленную посылку, а Windows может — через «Удалить обновление» или «Вернуться к предыдущей версии».

## 4. Практика и команды

Все команды ниже выполняются **от имени администратора** (правый клик по PowerShell или CMD → «Запуск от имени администратора»). На стенде это учётка `adm.student`.

### 4.1. Посмотреть состояние служб обновления

```powershell
Get-Service wuauserv, UsoSvc, BITS, CryptSvc | Format-Table Name, Status, StartType
```

`Get-Service` — список служб; `Format-Table` — вывод таблицей. Смотрим: `Status` должен быть `Running`, `StartType` — `Automatic` (у `wuauserv` бывает `Manual (Trigger Start)` — это нормально). Если `Stopped` или `Disabled` — вот и причина.

Пример вывода (примерный):

```text
Name       Status  StartType
----       ------  ---------
BITS       Running Automatic
CryptSvc   Running Automatic
UsoSvc     Running Automatic
wuauserv   Running Manual
```

### 4.2. Запустить/перезапустить службы

```powershell
Restart-Service wuauserv, UsoSvc, BITS -Force
```

`-Force` — перезапустить, даже если служба занята. Если служба `Disabled`, сначала `Set-Service wuauserv -StartupType Manual`, потом `Start-Service wuauserv`.

### 4.3. Проверить, откуда клиент берёт обновления

```powershell
Get-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate' -ErrorAction SilentlyContinue
```

Если ключ есть и в нём `WUServer` — клиент смотрит на WSUS. Если ключа нет — идёт в интернет к Microsoft. На домашнем стенде ключа быть не должно (политик нет).

### 4.4. Запустить проверку обновлений из PowerShell

```powershell
UsoClient StartScan
```

`UsoClient` — утилита-обёртка над `UsoSvc`. Команды: `StartScan` (проверить), `StartDownload` (скачать), `StartInstall` (установить), `RefreshSettings` (перечитать политики). Вывод в консоль обычно пустой — это нормально, смотрим результат в интерфейсе или журнале.

### 4.5. Посмотреть историю установленных обновлений

```powershell
Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 10
```

`Get-HotFix` — список установленных патчей (KB-номера). `Sort-Object InstalledOn -Descending` — свежие сверху. `Select-Object -First 10` — только 10 строк. Важно: `Get-HotFix` показывает **не все** обновления, а только те, что зарегистрированы как hotfix. Полная история — в GUI (см. 4.6).

Пример вывода (примерный):

```text
Source        Description      HotFixID   InstalledOn
------        -----------      --------   -----------
WIN11-CL01    Update           KB5041585  15.09.2025 0:00:00
WIN11-CL01    Security Update  KB5040442  13.08.2025 0:00:00
```

### 4.6. GUI: история обновлений

Меню: **Пуск → Параметры → Центр обновления Windows → Журнал обновлений**. Там видно: что установлено, что не удалось, коды ошибок. Это первое, что вы открываете по заявке «не ставится обновление».

### 4.7. Удалить конкретное обновление

PowerShell (для hotfix):

```powershell
wusa /uninstall /kb:5041585 /quiet /norestart
```

`wusa` — Windows Update Standalone Installer. `/uninstall /kb:<номер>` — удалить патч по KB. `/quiet` — без окон. `/norestart` — не перезагружать. После — перезагрузка вручную.

GUI-путь: **Параметры → Центр обновления Windows → Журнал обновлений → Удалить обновления** (откроется список «Программы и компоненты»).

### 4.8. Очистить кэш обновлений (если «залипло»)

```powershell
Stop-Service wuauserv, UsoSvc, BITS -Force
Rename-Item -Path 'C:\Windows\SoftwareDistribution' -NewName 'SoftwareDistribution.old'
Start-Service wuauserv, UsoSvc, BITS
UsoClient StartScan
```

`Rename-Item` — переименовать папку (не удалить сразу — на случай, если понадобится вернуть). Windows создаст новую пустую `SoftwareDistribution` при старте службы. Старую можно удалить через пару дней, если всё работает.

### 4.9. Посмотреть журнал событий обновлений

```powershell
Get-WinEvent -LogName 'System' -MaxEvents 50 | Where-Object { $_.ProviderName -match 'WindowsUpdate|Servicing' } | Format-Table TimeCreated, Id, LevelDisplayName, Message -AutoSize
```

`Get-WinEvent` — чтение журнала. `-LogName 'System'` — системный журнал. `Where-Object` — фильтр по источнику. `-AutoSize` — подогнать ширину колонок. Смотрим события с `LevelDisplayName = Error` — там будут коды ошибок.

### 4.10. Проверить свободное место (частая причина сбоев)

```powershell
Get-PSDrive C | Select-Object Used, Free
```

Для установки Feature Update нужно минимум 20–30 ГБ свободно. Если меньше — обновление не встанет, ошибка будет невнятная (`0x80070070`).

### 4.11. Откатить Feature Update (в течение 10 дней)

GUI: **Параметры → Система → Восстановление → Вернуться к предыдущей версии Windows**. Кнопка доступна только 10 дней после обновления. Через PowerShell это делается сложнее и не всегда работает — на L1 используем GUI.

### 4.12. Приостановить обновления (временно)

GUI: **Параметры → Центр обновления Windows → Приостановить обновления на 1 неделю** (до 5 недель). В корпоративной среде это делается политикой, а не руками.

1. Остановите службы обновлений:
    ```powershell

    icacls 'C:\Windows\SoftwareDistribution'
    ```
    Ожидаемо: в выводе **нет** строки `NT AUTHORITY\SYSTEM:(OI)(CI)(F)`. Вот и причина.
4. Проверяем, что это именно наша поломка, а не что-то ещё: `Get-PSDrive C | Select-Object Free` — места хватает, значит не `0x80070070`.

**Решение:**

1. Остановите службы:
    ```powershell
    Stop-Service wuauserv, UsoSvc, BITS -Force
    ```
2. Верните права `SYSTEM` на папку:
    ```powershell
    icacls 'C:\Windows\SoftwareDistribution' /grant 'NT AUTHORITY\SYSTEM:(OI)(CI)F' /T
    ```
    `(OI)(CI)F` — наследование на файлы и папки, полный доступ.
3. Запустите службы:
    ```powershell
    Start-Service wuauserv, UsoSvc, BITS
    ```
4. Запустите проверку: `UsoClient StartScan`. Через 1–2 минуты в интерфейсе ошибка должна исчезнуть, пойдёт нормальная проверка.

**Ответ пользователю:**

> Мария, добрый день! Проблема была в правах доступа к служебной папке обновлений — система не могла записать туда скачанные файлы, поэтому выдавала ошибку 0x80070005. Права восстановили, проверка обновлений пошла нормально. Пожалуйста, не выключайте компьютер сегодня вечером — обновления доустановятся. Если завтра утром ошибка появится снова, напишите, разберёмся дальше.

**Закрытие заявки:** категория «Windows / Обновления», решение «Восстановлены права NTFS на C:\Windows\SoftwareDistribution», время — 25 минут.

## 6. Ошибки новичков и безопасность

1. **Удалять `C:\Windows\SoftwareDistribution` целиком, не останавливая службы.** → Файлы заняты, удаление падает с ошибкой, кэш остаётся битым. → Сначала `Stop-Service wuauserv, UsoSvc, BITS -Force`, потом переименовать/удалить.

2. **Отключать `wuauserv` «чтобы не мешала».** → Через месяц машина без патчей безопасности, при аудите — замечание, при инциденте — виноват L1. → Не отключать. Если мешает — использовать «Активные часы» или приостановку на неделю.

3. **Ставить Feature Update в рабочее время.** → 30–60 минут без компьютера, пользователь злится. → Согласовать время, поставить на вечер/выходные, предупредить.

4. **Удалять патч безопасности «потому что после него что-то сломалось», не разобравшись.** → Дыра в защите, а проблема может быть не в патче. → Сначала диагностика (журнал, `Get-HotFix`, история), удаление — только если подтверждено, и с записью в тикете.

5. **Игнорировать свободное место.** → Feature Update падает с `0x80070070`, пользователь думает, что «Windows сломался». → Проверять `Get-PSDrive C` перед крупным обновлением, нужно 20–30 ГБ.

6. **Не перезагружать после установки.** → Патч «висит» в состоянии pending, приложения работают со старыми файлами, баги не уходят. → Перезагрузка — часть установки, согласовать с пользователем.

7. **Путать «Удалить обновление» и «Вернуться к предыдущей версии».** → Первое — для quality update (KB), второе — для feature update (версия Windows). → Смотреть, что именно сломалось: если после KB — удалить KB, если после смены версии — «Вернуться».

8. **Не проверять, откуда клиент берёт обновления.** → В корпоративной сети клиент может смотреть на WSUS, а вы проверяете интернет и не понимаете, почему «нет обновлений». → `Get-ItemProperty HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`.

### Безопасность

- **Не отключайте Windows Update на боевых машинах.** Это нарушение политики ИБ, при инциденте — первый вопрос «почему без патчей».
- **Не ставьте патчи с непроверенных источников** («вот тут на форуме выложили KB»). Только Microsoft Update Catalog или WSUS.
- **Не удаляйте `C:\Windows\WinSxS`** — это хранилище компонентов, сломаете систему.
- **Пароли и учётки в тикетах не пишите.** Если пользователь прислал пароль — попросите сменить.
- **На стенде** пароль `Lab#2026-vektor` — учебный. В реальной работе так нельзя: пароли уникальные, хранятся в менеджере паролей.

## 7. Вопросы на собеседовании

**Вопрос 1. «Пользователь пишет: не ставятся обновления, ошибка 0x80070005. Что делаете?»**

Ответ: «0x80070005 — это Access Denied. Первым делом смотрю службы `wuauserv`, `UsoSvc`, `BITS` — запущены ли. Потом журнал System через `Get-WinEvent` — там будет текст ошибки с путём. Чаще всего это права на `C:\Windows\SoftwareDistribution` или антивирус блокирует. Проверяю `icacls` на папку, при необходимости останавливаю службы, чиню права или переименовываю папку, запускаю службы и `UsoClient StartScan`. На стенде я это делал: убрал права у SYSTEM, получил ту же ошибку, восстановил — заработало».

*Что хочет услышать интервьюер:* что вы знаете про службы, умеете читать журнал и не тыкаете наугад.
*Красный флаг:* «Переустановлю Windows» или «Отключу обновления».

**Вопрос 2. «Чем WSUS отличается от Windows Update?»**

Ответ: «Windows Update — это облачный сервис Microsoft, клиент ходит в интернет. WSUS — это сервер внутри корпоративной сети, который сам скачивает патчи из Microsoft и раздаёт клиентам. Клиент узнаёт про WSUS из групповой политики, ключ `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate`, параметр `WUServer`. Плюсы WSUS: экономия канала (патч скачивается один раз), контроль (админ одобряет, какие патчи ставить), отчётность. Минусы: нужно обслуживать сервер, чистить базу. На стенде WSUS пока нет, но я знаю, как проверить, настроен ли клиент на WSUS — через реестр».

*Что хочет услышать:* понимание разницы «облако vs внутренний сервер» и что вы знаете про политики.
*Красный флаг:* «WSUS — это то же самое, что Windows Update».

**Вопрос 3. «После обновления у пользователя пропал звук. Ваши действия?»**

Ответ: «Сначала уточняю: после какого именно обновления, когда это было. Смотрю историю через `Get-HotFix` или в GUI. Если это quality update (KB) и после него пропал звук — предлагаю удалить этот KB через `wusa /uninstall /kb:<номер>`, перезагрузить, проверить. Если помогло — фиксирую в тикете, эскалирую на L2 для анализа, сообщаю пользователю, что временно откатили. Если это feature update — пробую "Вернуться к предыдущей версии" в течение 10 дней. Параллельно проверяю драйверы звука в Диспетчере устройств — может, обновление заменило драйвер».

*Что хочет услышать:* что вы различаете типы обновлений и умеете откатывать.
*Красный флаг:* «Сразу переустановлю драйвер» без диагностики.

**Вопрос 4. «Можно ли отключить Windows Update на компьютере сотрудника?»**

Ответ: «Технически можно — отключить службу `wuauserv` или политикой. Но в корпоративной среде это нарушение политики ИБ: машина без патчей — это дыра. Если обновления мешают работе — правильное решение: настроить активные часы, приостановить на неделю, согласовать с пользователем время установки. Отключение — только по письменному согласованию с ИБ и с записью в тикете, и то временно».

*Что хочет услышать:* что вы понимаете риски и не идёте на поводу у пользователя.
*Красный флаг:* «Конечно, отключу, если просит».

**Вопрос 5. «Что такое активные часы и зачем они нужны?»**

Ответ: «Это настройка Windows Update, которая говорит системе: "в это время не перезагружайся". По умолчанию 8:00–17:00. Если пользователь жалуется, что компьютер перезагрузился ночью и он потерял работу — это как раз про активные часы: они не покрывали ночное время. Решение: расширить активные часы или настроить политику "No auto-restart with logged on users" — тогда перезагрузка только когда пользователь сам закроет сеанс».

*Что хочет услышать:* что вы знаете про поведение системы и умеете объяснить пользователю.
*Красный флаг:* «Не знаю, что это».
