## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Собеседование L1/L2 — это не один экзамен, а слоёная проверка. Понимай структуру:

```text
┌─────────────────────────────────────────────────────────┐
│ 1. Железо и ОС   (ПК, BIOS/UEFI, диски, Windows, Linux) │
├─────────────────────────────────────────────────────────┤
│ 2. Сеть          (OSI/TCP-IP, IP, DHCP, DNS, NAT, VPN)  │
├─────────────────────────────────────────────────────────┤
│ 3. Инфраструктура(AD, GPO, файлы, печать, бэкап)        │
├─────────────────────────────────────────────────────────┤
│ 4. Прикладное ПО (Office, 1С, КриптоПро, браузеры)      │
├─────────────────────────────────────────────────────────┤
│ 5. ИБ            (пароли, MFA, фишинг, 152-ФЗ, инцидент)│
├─────────────────────────────────────────────────────────┤
│ 6. Процессы      (ITIL, тикеты, эскалация, общение)     │
├─────────────────────────────────────────────────────────┤
│ 7. Скрипты/автоматизация (PowerShell, Bash, Python,     │
│                          Ansible, Docker, CI/CD, IaC)   │
└─────────────────────────────────────────────────────────┘
```

На L1 спрашивают в основном слои 1–3 и 6, на L2 добавляются 4–5 и 7. Ключевой принцип ответа — «сверху вниз по слоям»: сначала проверяем, что проблема вообще в том слое, о котором говорит пользователь. Пользователь говорит «интернет не работает», а на деле у него DNS не отвечает — это слой 2, а не «провайдер».

Второй принцип — модель «симптом → гипотеза → проверка → вывод». На собеседовании это ценят больше, чем знание конкретной команды. Третий — «я не знаю, но знаю, как узнать»: интервьюер специально задаёт вопрос за пределами твоего уровня, чтобы проверить, не начнёшь ли ты выдумывать.

## 3. Аналогия из жизни

Собеседование — это техосмотр автомобиля перед покупкой. Механик не спрашивает «расскажите теорию двигателя внутреннего сгорания» — он открывает капот, слушает, проверяет по чек-листу: масло, ремень, тормоза, электрика. Если чего-то не знает — честно говорит «это надо на диагностику». Покупатель ценит не всезнайку, а того, кто не пропустит проблему и не соврёт. На собеседовании L1 ты — механик, интервьюер — покупатель, а твои ответы — чек-лист. Аналогия ломается в одном: на техосмотре можно молча тыкать пальцем, а на собеседовании надо ещё и объяснять словами.

## 4. Практика и команды

Этот урок — про ответы, но каждый ответ должен опираться на команду, которую ты реально выполнял. Ниже — 10 «якорных» команд, которые чаще всего всплывают на собеседовании. Прогоняй их на стенде, чтобы говорить «я это делал», а не «я это читал».

**1. Проверка сети и DNS на Windows (WIN11-CL01):**
```powershell
ipconfig /all
nslookup dc01.corp.vektor.lab
```
`ipconfig /all` — полная конфигурация: IP, маска, шлюз, DNS-серверы, DHCP-сервер, lease. `nslookup <имя>` — запрос к DNS. Смотрим: правильный ли DNS-сервер (должен быть 10.10.10.10), отвечает ли зона `corp.vektor.lab`. Вывод примерный: `Server: dc01.corp.vektor.lab`, `Address: 10.10.10.10`, затем `Name: dc01.corp.vektor.lab`, `Address: 10.10.10.10`.

**2. Трассировка маршрута (Windows):**
```cmd
tracert 10.10.10.10
```
`tracert` показывает хопы до цели. На стенде до DC01 будет один хоп (та же подсеть). Если видишь `* * *` — маршрут не строится или ICMP блокируется. На собеседовании: «tracert показывает, где обрывается путь».

**3. Проверка службы и её состояния (Windows):**
```powershell
Get-Service -Name Dnscache
Get-Service -DisplayName 'VMware*'
```
`Get-Service` — состояние службы. `-DisplayName` ищет по отображаемому имени (важно: `VMAuthdService` не начинается с «VMware», поэтому ищем по DisplayName). Смотрим `Status: Running` и `StartType`.

**4. Журнал событий Windows:**
```powershell
Get-WinEvent -LogName System -MaxEvents 20
```
`-LogName System` — системный журнал, `-MaxEvents 20` — последние 20. Смотрим `LevelDisplayName` (Error/Warning) и `Message`. На собеседовании: «сначала смотрю журнал, а не перезагружаю».

**5. Проверка прав NTFS и доступа к шаре:**
```powershell
Get-Acl \\FS01\HR
icacls \\FS01\HR
```
`Get-Acl` — ACL объекта, `icacls` — компактный список разрешений. Смотрим, есть ли `GG-HR` с `Read`/`Modify`. На собеседовании: «права проверяю и на шаре, и на NTFS — доступ считается по пересечению».

**6. Проверка членства в группах AD (на DC01):**
```powershell
Get-ADUser petrova -Properties MemberOf | Select-Object Name, MemberOf
```
`Get-ADUser` с `-Properties MemberOf` — членство пользователя. Смотрим, есть ли `GG-HR`. Если нет — вот и причина «отказано в доступе».

**7. Проверка GPO на клиенте:**
```cmd
gpupdate /force
gpresult /r
```
`gpupdate /force` — принудительное применение политик, `gpresult /r` — какие политики применились. Смотрим раздел «Applied Group Policy Objects» и «The following GPOs were not applied».

**8. Linux: проверка службы и порта (UBU01):**
```bash
sudo systemctl status ssh
sudo ss -tlnp | grep :22
```
`systemctl status` — состояние юнита, `ss -tlnp` — слушающие TCP-порты с процессами. Смотрим `active (running)` и `LISTEN ... :22`.

**9. Linux: проверка диска и памяти:**
```bash
df -h
free -h
```
`df -h` — занятость файловых систем, `free -h` — память. На собеседовании: «первое, что смотрю при "тормозит" — диск и память».

**10. PowerShell: поиск процесса и его пути:**
```powershell
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5
Get-Process -Name explorer | Select-Object Path
```
`Get-Process` — процессы, `Sort-Object CPU -Descending` — по нагрузке, `Select-Object Path` — откуда запущен. На собеседовании: «подозрительный процесс проверяю по пути и подписи».

## 100 вопросов с ответами

### Блок 1. Железо и ОС (1–12)

**1. Что происходит при включении ПК?** Питание → BIOS/UEFI → POST (проверка железа) → поиск загрузчика → загрузка ОС. На собеседовании: «понимаю порядок, поэтому при "не включается" сначала смотрю питание и POST-коды».

**2. Чем BIOS отличается от UEFI?** UEFI современнее: поддержка GPT-дисков >2 ТБ, Secure Boot, быстрее загрузка. BIOS — legacy. Windows 11 требует UEFI + Secure Boot + TPM 2.0.

**3. Что такое TPM 2.0 и зачем он?** Чип (или виртуальный модуль) для хранения ключей шифрования. Нужен для BitLocker и требования Windows 11. На стенде WIN11-CL01 создана с vTPM.

**4. SSD vs HDD — что выбрать и почему?** SSD быстрее (нет механики), тише, надёжнее к тряске. HDD — дешевле за объём, для архивов. В офис — SSD под систему.

**5. Что такое S.M.A.R.T.?** Самодиагностика диска. Смотрим через `Get-PhysicalDisk` или CrystalDiskInfo. «Reallocated Sectors» растёт — диск умирает.

**6. Пользователь говорит «компьютер тормозит». С чего начать?** Диспетчер задач: CPU, память, диск. Потом `Get-Process | Sort-Object CPU -Descending`. Часто — 100% диск из-за обновлений или антивируса.

**7. Что такое драйвер и зачем он?** Программа, которая объясняет ОС, как работать с устройством. Без драйвера — «Неизвестное устройство» в Диспетчере устройств.

**8. Как откатить драйвер?** Диспетчер устройств → устройство → Свойства → Драйвер → «Откатить». Работает, если предыдущий драйвер сохранён.

**9. Что такое реестр Windows?** База настроек ОС и программ. `regedit`. Правка реестра — только с бэкапом (`reg export`).

**10. Где смотреть журналы Windows?** `eventvwr.msc` или `Get-WinEvent`. Основные: System, Application, Security.

**11. Что такое безопасный режим и когда его использовать?** Загрузка с минимумом драйверов и служб. Для диагностики: если в безопасном режиме работает, а в обычном нет — виноват драйвер или автозагрузка.

**12. Как восстановить Windows, если не грузится?** WinRE (Win + R → `reagentc /info`), точки восстановления, `sfc /scannow`, `DISM /Online /Cleanup-Image /RestoreHealth`, сброс/переустановка.

### Блок 2. Windows: учётки, права, файлы (13–24)

**13. Чем локальная учётка отличается от доменной?** Локальная — только на этой машине. Доменная — в AD, работает на всех машинах домена, централизованно управляется.

**14. Что такое UAC?** Контроль учётных записей: повышение прав требует подтверждения. Даже админ работает с обычными правами, повышает по запросу.

**15. Что такое NTFS-разрешения?** Права на файлы/папки: Read, Write, Modify, Full Control. Складываются по группам, запрет (`Deny`) приоритетнее разрешения.

**16. Чем шара (share) отличается от NTFS?** Шара — сетевой доступ, NTFS — локальный. Итоговый доступ — пересечение: если на шаре Read, а на NTFS Full — получишь Read.

**17. Пользователь не может зайти в папку. Как диагностировать?** 1) `whoami /groups` — есть ли группа; 2) `icacls` на шаре; 3) `Get-Acl` на NTFS; 4) проверить, не `Deny` ли; 5) перелогиниться (группы обновляются при входе).

**18. Что такое наследование разрешений?** Дочерние объекты наследуют права родителя. Можно отключить («Disable inheritance») и задать свои.

**19. Что такое «эффективные разрешения»?** Итоговые права пользователя с учётом всех групп. Смотреть: Свойства → Безопасность → Дополнительно → Эффективный доступ.

**20. Как дать пользователю доступ к папке правильно?** Через группу (`GG-Buh`, `GG-HR`), а не персонально. Так проще управлять и аудитить.

**21. Что такое «Take ownership»?** Взятие владения объектом. Нужно, когда владелец уволен и никто не имеет прав. Делать осторожно — это аудируется.

**22. Что такое «скрытая шара»?** Шара с `$` в конце (`C$`, `ADMIN$`). Не видна в «Сети», но доступна по имени. `C$` — админская.

**23. Как посмотреть открытые шары на сервере?** `net share` или `Get-SmbShare`. На FS01 увидишь `Obshchee`, `Buh`, `HR`.

**24. Что такое «оффлайн-файлы»?** Кэш сетевых папок на локальном диске. Позволяет работать без сети. Настраивается через GPO.

### Блок 3. PowerShell и CMD (25–34)

**25. Чем PowerShell отличается от CMD?** PowerShell работает с объектами, а не текстом. Есть конвейер (`|`), командлеты (`Get-*`, `Set-*`), модули. CMD — legacy, текст.

**26. Как найти команду в PowerShell?** `Get-Command *service*`, `Get-Help Get-Service -Examples`. `Get-Help` — твой лучший друг.

**27. Что такое конвейер?** Передача объектов от команды к команде: `Get-Process | Where-Object CPU -gt 100 | Sort-Object CPU -Descending`.

**28. Как в PowerShell проверить службу?** `Get-Service -Name Dnscache`. Смотрим `Status` и `StartType`.

**29. Как перезапустить службу?** `Restart-Service -Name Spooler`. Требует прав администратора.

**30. Как найти процесс по имени?** `Get-Process -Name explorer`. `-Id` — по PID.

**31. Как в CMD посмотреть IP?** `ipconfig /all`. `/release` и `/renew` — для DHCP.

**32. Как в CMD проверить связь?** `ping 10.10.10.10`, `tracert 10.10.10.10`, `pathping` — комбинация.

**33. Что такое `net use`?** Подключение сетевого диска: `net use Z: \\FS01\Obshchee`. `net use * /delete` — отключить все.

**34. Как в PowerShell посмотреть события?** `Get-WinEvent -LogName System -MaxEvents 20`. `-FilterXPath` — точный фильтр.

### Блок 4. Linux (35–44)

**35. Чем Linux отличается от Windows?** Открытый код, другая файловая система (`/` вместо `C:\`), права через `rwx`, пакеты через `apt`/`yum`, конфиги в текстовых файлах.

**36. Что такое `sudo`?** Выполнение команды с правами root. На стенде `adm.student` — sudo-пользователь.

**37. Как посмотреть процессы в Linux?** `ps aux`, `top`, `htop`. `ps aux | grep ssh` — найти конкретный.

**38. Как управлять службами?** `systemctl status ssh`, `systemctl restart ssh`, `systemctl enable ssh`. Юниты в `/etc/systemd/system/`.

**39. Как посмотреть логи?** `journalctl -u ssh`, `tail -f /var/log/syslog`. `-f` — следить в реальном времени.

**40. Как проверить диск и память?** `df -h`, `free -h`, `du -sh /var/log`. `df` — файловые системы, `du` — размер папки.

**41. Как настроить сеть в Ubuntu Server 24.04?** Через netplan: `/etc/netplan/*.yaml`, потом `sudo netplan apply`. `dhclient` не используем.

**42. Как настроить SSH-ключи?** `ssh-keygen -t ed25519`, `ssh-copy-id adm.student@10.10.10.30`. Потом вход без пароля.

**43. Что такое права `rwxr-xr-x`?** Владелец: чтение/запись/выполнение; группа: чтение/выполнение; остальные: чтение/выполнение. `chmod 755`.

**44. Как найти файл в Linux?** `find / -name "*.log"`, `locate`, `grep -r "error" /var/log`.

### Блок 5. Сеть (45–58)

**45. Что такое модель OSI?** 7 уровней: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. Помогает локализовать проблему.

**46. Что такое TCP/IP?** Практическая модель: 4 уровня (канальный, интернет, транспорт, прикладной). TCP — надёжный, UDP — быстрый.

**47. Что такое IP-адрес и маска?** IP — адрес в сети, маска — какие биты адрес, какие хост. `10.10.10.51/24` — сеть 10.10.10.0, хост .51.

**48. Что такое шлюз?** Адрес, куда отправлять пакеты за пределы своей подсети. На стенде 10.10.10.2.

**49. Что такое DHCP?** Автоматическая выдача IP, маски, шлюза, DNS. На стенде DC01, пул 10.10.10.100–150.

**50. Что такое DNS?** Превращает имена в IP. На стенде DC01, зона `corp.vektor.lab`, форвардер 77.88.8.8.

**51. Пользователь не открывает сайт. Как диагностировать?** 1) `ping 8.8.8.8` — есть ли сеть; 2) `nslookup ya.ru` — работает ли DNS; 3) `ping ya.ru` — резолвится ли; 4) браузер/прокси; 5) `tracert`.

**52. Что такое NAT?** Подмена адресов при выходе в интернет. На стенде VMnet8 — NAT-устройство VMware, шлюз 10.10.10.2.

**53. Что такое VPN?** Шифрованный туннель в корпоративную сеть. Пользователь дома подключается и работает как в офисе.

**54. Что такое прокси?** Посредник между клиентом и интернетом. Может кэшировать, фильтровать, логировать.

**55. Что такое Wi-Fi и чем 2.4 ГГц отличается от 5 ГГц?** 2.4 — дальше, но медленнее и зашумлённее; 5 — быстрее, но меньше радиус. Корпоративный Wi-Fi — через 802.1X.

**56. Что такое VLAN?** Логическое разделение сети на одном коммутаторе. Разные VLAN — разные подсети, изоляция трафика.

**57. Что такое MTU и когда он мешает?** Максимальный размер пакета. Если MTU не совпадает (VPN, туннели) — большие пакеты теряются, сайты «висят». `ping -f -l 1472`.

**58. Что такое `tracert` и что он показывает?** Маршрут до цели по хопам. `* * *` — хоп не отвечает на ICMP (не всегда проблема).

### Блок 6. Active Directory и GPO (59–70)

**59. Что такое Active Directory?** Служба каталогов: пользователи, группы, компьютеры, политики. Централизованное управление доменом.

**60. Что такое домен, лес, дерево?** Домен — логическая группа (corp.vektor.lab). Лес — совокупность доменов с общей схемой. Дерево — иерархия доменов.

**61. Что такое OU?** Organizational Unit — контейнер для группировки объектов и применения GPO. На стенде: `Company` → `Бухгалтерия`, `HR`, `Склад`, `IT`.

**62. Что такое группа безопасности?** Набор учёток для выдачи прав. На стенде: `GG-Buh`, `GG-HR`, `GG-Sklad`, `GG-IT`.

**63. Чем глобальная группа отличается от доменной локальной?** Глобальная — для группировки пользователей, доменная локальная — для выдачи прав на ресурсы. Правило AGDLP.

**64. Что такое GPO?** Group Policy Object — набор политик. Применяется к сайту, домену, OU. Порядок: LSDOU (Local, Site, Domain, OU).

**65. Как проверить, применилась ли GPO?** `gpupdate /force`, `gpresult /r`. Смотрим «Applied Group Policy Objects».

**66. Что такое «наследование GPO»?** Политики родительского OU применяются к дочерним. Можно блокировать (Block Inheritance) или принудительно (Enforced).

**67. Что такое «доверие домена»?** Отношение между доменами, позволяющее пользователям одного входить в другой. Ломается при смене пароля машины.

**68. Пользователь не может войти в домен. Что проверить?** 1) Сеть до DC01 (`ping 10.10.10.10`); 2) DNS (должен быть 10.10.10.10); 3) время (рассинхрон >5 мин ломает Kerberos); 4) `nltest /sc_verify:corp.vektor.lab`; 5) переприсоединить к домену.

**69. Что такое Kerberos?** Протокол аутентификации в AD. Билеты (TGT, TGS), время критично.

**70. Что такое «сброс пароля» и «разблокировка» в AD?** Сброс — новый пароль (`Set-ADAccountPassword`). Разблокировка — снятие блокировки после неудачных попыток (`Unlock-ADAccount`).

### Блок 7. Файлы, печать, бэкап (71–78)

**71. Как устроен файловый сервер?** Шары + NTFS-права + группы. На стенде FS01: `Obshchee` (все), `Buh` (GG-Buh), `HR` (GG-HR).

**72. Пользователь не видит принтер. Что делать?** 1) `Get-Service Spooler` — запущен ли; 2) `\\FS01` — виден ли сервер; 3) GPO принтера (`gpresult /r`); 4) переустановить драйвер; 5) `printmanagement.msc`.

**73. Принтер печатает «кракозябры». Причина?** Неверный драйвер (PCL vs PostScript) или кодировка. Переустановить драйвер под модель.

**74. Что такое print-сервер?** Машина, через которую идут задания печати. На стенде FS01, принтер развёрнут через GPO.

**75. Что такое «очередь печати» и как её очистить?** Список заданий. Остановить Spooler, удалить файлы в `C:\Windows\System32\spool\PRINTERS`, запустить Spooler.

**76. Зачем бэкап и что бэкапить?** Восстановление после сбоя/шифровальщика. Бэкапить: данные, конфиги, AD (System State). На стенде — Windows Server Backup на DC01 и FS01.

**77. Что такое «правило 3-2-1»?** 3 копии, 2 носителя, 1 вне офиса. Защита от шифровальщика и пожара.

**78. Как проверить, что бэкап рабочий?** Периодически восстанавливать на тестовую среду. Бэкап без проверки — не бэкап.

### Блок 8. Прикладное ПО и РФ-специфика (79–86)

**79. Пользователь не открывает 1С. Что проверить?** 1) Сервер 1С доступен (`ping`); 2) служба 1С на сервере; 3) лицензия; 4) база не заблокирована; 5) логи 1С.

**80. Что такое КриптоПро CSP?** Криптопровайдер для ЭП и ГОСТ-шифрования. Нужен для госуслуг, ЭДО, банков.

**81. Пользователь не может подписать документ. Что делать?** 1) Токен вставлен (`certmgr.msc` — виден ли сертификат); 2) КриптоПро запущен; 3) сертификат не истёк; 4) плагин в браузере; 5) переустановить КриптоПро.

**82. Что такое ЭДО?** Электронный документооборот. Документы подписываются ЭП, обмен через оператора (Диадок, СБИС).

**83. Что такое импортозамещение в ИТ?** Замена иностранного ПО на российское: Astra Linux, РЕД ОС, ALT, МойОфис, Р7-Офис. В госсекторе — требование.

**84. Чем Astra Linux отличается от Ubuntu?** Российская ОС на базе Debian, сертифицирована для госсектора. Пакеты `apt`, но свои репозитории.

**85. Что такое МойОфис / Р7-Офис?** Российские офисные пакеты (аналоги MS Office). Совместимы с docx/xlsx.

**86. Что такое ЕСИА и Госуслуги для бизнеса?** Портал госуслуг, вход через ЕСИА. Для организаций — личный кабинет, ЭП.

### Блок 9. Информационная безопасность (87–94)

**87. Что такое фишинг и как его распознать?** Поддельное письмо/сайт для кражи данных. Признаки: странный адрес, срочность, просьба ввести пароль, вложения.

**88. Пользователь кликнул на фишинговую ссылку. Что делать?** 1) Отключить от сети; 2) сменить пароли; 3) проверить логи входов; 4) запустить антивирус/EDR; 5) эскалировать в ИБ; 6) задокументировать инцидент.

**89. Что такое MFA?** Многофакторная аутентификация: пароль + что-то ещё (код, токен). Защита от кражи пароля.

**90. Что такое 152-ФЗ?** Закон о персональных данных. Требует защиты ПДн, согласия, уведомления Роскомнадзора.

**91. Что такое 187-ФЗ?** Закон о КИИ (критической информационной инфраструктуре). Требует категорирования и защиты значимых объектов.

**92. Что такое EDR?** Endpoint Detection and Response — антивирус нового поколения с поведенческим анализом и реагированием.

**93. Что такое BitLocker?** Шифрование диска Windows. Требует TPM. На стенде WIN11-CL01 с vTPM.

**94. Что делать при подозрении на шифровальщика?** 1) Отключить от сети; 2) не выключать (сохранить память); 3) эскалировать в ИБ; 4) восстановить из бэкапа; 5) проверить, как проник.

### Блок 10. Процессы, ITIL, общение (95–100)

**95. Что такое ITIL?** Библиотека лучших практик ИТ-сервисов. Ключевое: инцидент (сломалось), запрос (нужно новое), проблема (причина инцидентов), изменение.

**96. Чем инцидент отличается от запроса?** Инцидент — нарушение работы (не открывается почта). Запрос — штатная потребность (нужен доступ, новый сотрудник).

**97. Что такое SLA?** Соглашение об уровне сервиса: время реакции и решения. На L1 важно соблюдать приоритеты.

**98. Когда эскалировать на L2?** Когда исчерпал свой чек-лист, проблема требует прав/знаний выше, или SLA под угрозой. Эскалация — не провал, а процесс.

**99. Пользователь злится. Как общаться?** 1) Выслушать, не перебивать; 2) признать проблему; 3) сказать, что делаешь; 4) дать срок; 5) держать в курсе. Не спорить и не обвинять.

**100. Что делать, если не знаешь ответа на вопрос?** Честно сказать: «Я с этим не сталкивался, но знаю, как выяснить — посмотрю документацию/спрошу коллегу». Врать хуже, чем признать границу.

## 6. Ошибки новичков и безопасность

1. **Заучивать ответы дословно.** → На уточняющем вопросе рассыпаешься. → Понимай логику, а не текст.
2. **Отвечать «не знаю» и замолкать.** → Интервьюер не видит хода мысли. → Добавляй «но я бы проверил так…».
3. **Выдумывать опыт.** → Ловишься на деталях. → Говори про стенд «Вектор» честно: «на учебном стенде я это делал».
4. **Сыпать терминами без понимания.** → Первый уточняющий вопрос — провал. → Объясняй простыми словами.
5. **Игнорировать поведенческие вопросы.** → «Расскажите про конфликт» — и тишина. → Готовь 3–4 истории по STAR (ситуация, задача, действие, результат).
6. **Не спрашивать про компанию.** → Выглядит как «мне всё равно». → Готовь 2–3 вопроса про процессы, стек, обучение.
7. **Спорить с интервьюером.** → Даже если прав, выглядишь токсичным. → «Интересно, я знал иначе — расскажите, как у вас».

**Безопасность.** На собеседовании не рассказывай про реальные пароли, адреса продакшена, данные клиентов. Не показывай скриншоты боевых систем. Не предлагай «отключить файрвол, чтобы проверить» — это красный флаг для ИБ. В резюме и на GitHub не выкладывай конфиги с секретами.

## 7. Вопросы на собеседовании (3–5 вопросов с ответами)

**Вопрос 1. «Пользователь не может зайти в папку — ваши действия?»**
Ответ: «Сначала уточню, что именно он видит: "Отказано в доступе" или папка не открывается. Если отказ — проверю `whoami /groups`, есть ли нужная группа. Потом `icacls` на шаре и `Get-Acl` на NTFS. Если группа есть, а доступа нет — проверю `Deny` и попрошу перелогиниться. На стенде я так разбирал заявку от petrova — оказалось, её убрали из `GG-HR`».
*Что хочет услышать:* структурный подход, знание шары vs NTFS, групп.
*Красный флаг:* «перезагружу сервер» или «дам Full Control всем».

**Вопрос 2. «Интернет не работает — как диагностируете?»**
Ответ: «По слоям. Сначала `ipconfig /all` — есть ли IP, шлюз, DNS. Потом `ping 10.10.10.2` — шлюз. Потом `ping 8.8.8.8` — внешний IP. Потом `nslookup ya.ru` — DNS. Если IP пингуется, а имя нет — DNS. Если шлюз не пингуется — локальная сеть. Дальше `tracert`».
*Что хочет услышать:* порядок, понимание DNS vs маршрут.
*Красный флаг:* «позвоню провайдеру» сразу.

**Вопрос 3. «Что такое GPO и как проверить, что она применилась?»**
Ответ: «Group Policy Object — набор политик, применяется к сайту, домену, OU в порядке LSDOU. На клиенте `gpupdate /force`, потом `gpresult /r` — смотрю "Applied Group Policy Objects". Если политики нет — проверю, в каком OU объект, и не блокирует ли наследование».
*Что хочет услышать:* порядок применения, `gpresult`.
*Красный флаг:* «GPO — это что-то про группы».

**Вопрос 4. «Чем Linux отличается от Windows в администрировании?»**
Ответ: «В Linux конфиги — текстовые файлы, права через `rwx`, службы через `systemctl`, пакеты через `apt`. В Windows — реестр, GUI, `Get-Service`. Логика похожа: проверить службу, порт, логи. На стенде я настраивал SSH-ключи с WIN11-CL01 на UBU01».
*Что хочет услышать:* понимание обеих систем, не «Linux лучше».
*Красный флаг:* «Linux — для гиков, Windows — для работы».

**Вопрос 5. «Расскажите про случай, когда вы не знали, что делать».**
Ответ: «На стенде у меня не поднимался SSH на UBU01. Я не знал, что `ss` не установлен по умолчанию. Начал с `systemctl status ssh` — служба работает. Потом `ss` — команда не найдена. Поставил через `apt`, проверил порт. Вывод: сначала проверяю, есть ли инструмент, потом делаю выводы».
*Что хочет услышать:* честность, ход мысли, доведение до результата.
*Красный флаг:* «такого не было» или выдуманная героическая история.
