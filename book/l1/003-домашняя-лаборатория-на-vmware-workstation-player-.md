## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Гипервизор 1-го и 2-го типа.** Гипервизор — это программа, которая запускает виртуальные машины. Тип 1 (ESXi, Hyper-V, Proxmox) ставится прямо на железо и сам является «ОС». Тип 2 (VMware Workstation, VirtualBox) — обычное приложение поверх Windows, как Word. Ваш стенд — тип 2: VMware Workstation на Windows-хосте.

**Как ВМ общается с миром.** У каждой ВМ есть виртуальные устройства: виртуальный диск (файл `.vmdk` на хосте), виртуальная сетевая карта (обычно эмулируется как Intel E1000e или VMXNET3), виртуальный CD/DVD. Виртуальная сетевая карта ВМ подключается к «виртуальному коммутатору» VMware — это программный аналог обычного свитча. Таких коммутаторов несколько, они называются VMnet0, VMnet1, VMnet8 и т.д.

**Три режима сети VMware:**

```text
┌─────────────────────── ХОСТ (ваш Windows-ПК) ───────────────────────┐
│                                                                     │
│  VMware Workstation                                                 │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────────┐   │
│  │ VMnet0       │  │ VMnet1       │  │ VMnet8 (NAT)             │   │
│  │ Bridged      │  │ Host-only    │  │ 10.10.10.0/24            │   │
│  │ = мост в     │  │ = только     │  │ шлюз 10.10.10.2          │   │
│  │ физ. сеть    │  │ хост+ВМ      │  │ хост 10.10.10.1          │   │
│  └──────┬───────┘  └──────┬───────┘  └────────────┬─────────────┘   │
│         │                 │                       │                 │
│  ┌──────┴───────┐  ┌──────┴───────┐  ┌────────────┴─────────────┐   │
│  │ физ. NIC     │  │ вирт. адаптер│  │ вирт. адаптер VMware8    │   │
│  │ хоста        │  │ VMware1      │  │ + NAT-служба + DHCP      │   │
│  └──────┬───────┘  └──────────────┘  └────────────┬─────────────┘   │
└─────────┼──────────────────────────────────────────┼────────────────┘
          │                                          │
     роутер/интернет                            ВМ стенда
     (192.168.1.1)                              (10.10.10.x)
```

- **Bridged (VMnet0)** — ВМ выглядит как отдельный ПК в вашей домашней сети. Получает адрес от домашнего роутера (например, `192.168.1.55`), видна соседям по Wi-Fi. Удобно, но небезопасно: ваши виртуалки торчат в домашнюю сеть.
- **Host-only (VMnet1 по умолчанию)** — изолированная сеть только между хостом и ВМ. Наружу — никак. Идеально для «внутренних» сервисов.
- **NAT (VMnet8)** — ВМ в отдельной подсети, но через NAT-службу VMware может выходить в интернет через хост. Хост видит ВМ, ВМ видит хост, наружу — только через NAT. Это самый удобный режим для лаборатории: изолированно, но с интернетом.

**DHCP VMware.** У каждой VMnet есть встроенный DHCP-сервер VMware. На стенде «Вектора» он **выключен** для VMnet8 — потому что в уроке 33 DHCP будет поднимать DC01, и два DHCP в одной подсети устроят хаос. Пока (до урока 33) у клиентов статические адреса.

**Снапшот.** Это не «копия диска», а зафиксированное состояние: содержимое диска + содержимое ОЗУ + настройки ВМ. При откате VMware возвращает всё это. Снапшоты хранятся как дельта-файлы рядом с основным `.vmdk`, поэтому занимают место на хосте. Снапшот ≠ резервная копия: если удалить папку ВМ, снапшоты уйдут вместе с ней.

**Ресурсы.** У ВМ есть виртуальные CPU, RAM, диск. VMware не резервирует RAM жёстко, но при запуске ВМ хост выделяет ей память. Если запустить 3 ВМ по 8 ГБ на хосте с 16 ГБ — хост начнёт свопить и всё встанет. Правило: сумма RAM запущенных ВМ ≤ 60–70% RAM хоста.

## 3. Аналогия из жизни

Представьте, что ваш ПК — это большая квартира, а VMware Workstation — это арендодатель, который сдаёт в ней комнаты. Каждая ВМ — жилец в отдельной комнате со своей мебелью (диск), своим санузлом (ОЗУ) и своим входом. Bridged — это когда у жильца есть ключ от подъезда и он ходит по общей лестнице вместе с вашими соседями. Host-only — жилец может ходить только по вашей квартире, к нему никто с улицы не зайдёт. NAT — у жильца есть домофон, через который он звонит консьержу (хосту), а тот уже передаёт его просьбы наружу. Снапшот — это фотография комнаты: если жилец устроил потоп, вы достаёте фотографию, «щёлкаете» — и комната снова как была.

Аналогия ломается в одном: жильцы в квартире могут подслушивать друг друга через стену, а ВМ в NAT-сети друг друга видят только если они в одной VMnet — разные VMnet полностью изолированы.

## 4. Практика и команды

Всё делаем на хосте (ваш Windows-ПК). ВМ пока нет — только настройка.

**1. Проверить, что VMware Workstation установлен и службы работают.**

```powershell
Get-Service -DisplayName 'VMware*' | Format-Table Name, DisplayName, Status
```

Ключ `-DisplayName` ищет по отображаемому имени (имена вроде `VMAuthdService` не начинаются с «VMware», поэтому `-Name 'VMware*'` их не найдёт). В выводе должны быть `VMware Authorization Service`, `VMware NAT Service`, `VMware DHCP Service`, `VMware Hostd` — все `Running`. Если что-то `Stopped` — `Start-Service` от имени администратора.

**2. Посмотреть версию VMware и путь к `vmrun`.**

```powershell
& 'C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe' -T ws list
```

`-T ws` — тип хоста «Workstation». Без него `vmrun` может ругаться. `list` покажет запущенные ВМ (пока пусто). Путь `[ПРОВЕРИТЬ]` в вашей версии — может быть `C:\Program Files\VMware\...` без `(x86)`.

**3. Открыть Virtual Network Editor (редактор виртуальных сетей).**

GUI: меню `Edit` → `Virtual Network Editor` (в Workstation Pro). В Player редактора нет — только предустановленные VMnet. В редакторе нажмите `Change Settings` (нужны права администратора).

**4. Настроить VMnet8 (NAT) под стенд.**

В Virtual Network Editor выберите `VMnet8`, поставьте:
- `Type: NAT`
- `Subnet IP: 10.10.10.0`, `Mask: 255.255.255.0`
- Снимите галочку `Use local DHCP service to distribute IP address to VMs` (DHCP выключен по условиям стенда)
- `NAT Settings` → шлюз `10.10.10.2` (VMware подставит сам при смене подсети)

**5. Проверить, что хост получил адрес в VMnet8.**

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object InterfaceAlias -like 'VMware Network Adapter VMnet8'
```

Ожидаемо: `IPAddress 10.10.10.1`, `PrefixLength 24`. Если адрес другой — перезапустите службу `VMware NAT Service` или пересоздайте VMnet8 в редакторе.

**6. Создать рабочие папки на хосте.**

```powershell
New-Item -ItemType Directory -Force -Path 'C:\Lab\vektor','C:\Lab\vektor\docs','C:\Lab\vektor\VMs','C:\Support\Tickets'
```

`-Force` не ругается, если папка уже есть. `C:\Lab\vektor\VMs` — сюда VMware будет складывать файлы ВМ; `C:\Support\Tickets` — учебные заявки.

**7. Инициализировать Git и журнал.**

```powershell
Set-Location 'C:\Lab\vektor'
git init
New-Item -ItemType File -Path 'stand-log.md'
git add .
git commit -m 'init: lab vektor skeleton'
```

Git здесь — просто локальный репозиторий для истории журнала. Подробнее в уроке 77.

**8. Проверить свободное место и RAM хоста.**

```powershell
Get-PSDrive C | Select-Object Used,Free
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory
```

Свободно на C: нужно минимум 60–80 ГБ (Windows 11 ~25 ГБ, Windows Server ~20 ГБ, Linux ~10 ГБ, плюс снапшоты). RAM: 16 ГБ — комфортный минимум для 2–3 ВМ одновременно.

**9. Создать ВМ WIN11-CL01 без ОС (через GUI).**

`File` → `New Virtual Machine` → `Custom (advanced)` → `I will install the operating system later` → `Microsoft Windows` / `Windows 11 x64` → имя `WIN11-CL01`, путь `C:\Lab\vektor\VMs\WIN11-CL01` → firmware `UEFI`, `Secure Boot` включён, `TPM` включён (VMware зашифрует ВМ, пароль шифрования — `Lab#2026-vektor`) [ПРОВЕРИТЬ в вашей версии VMware] → CPU 2, RAM 4096 МБ → сеть `NAT (VMnet8)` → диск SCSI 60 ГБ, `Store virtual disk as a single file`.

**10. Сделать снапшот через `vmrun`.**

```powershell
& 'C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe' -T ws -vp "Lab#2026-vektor" snapshot "C:\Lab\vektor\VMs\WIN11-CL01\WIN11-CL01.vmx" "before-l1-003"
```

`-vp` — пароль шифрования (нужен, потому что ВМ зашифрована из-за vTPM). `snapshot <vmx> <имя>` создаёт снапшот. Проверить: `vmrun -T ws -vp "Lab#2026-vektor" listSnapshots "C:\Lab\vektor\VMs\WIN11-CL01\WIN11-CL01.vmx"`.

### Снапшот

Снапшот `before-l1-003` делаем **после** создания ВМ WIN11-CL01 (шаг 9), потому что до этого снапшотить нечего. На других ВМ снапшот не нужен — их ещё нет.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** запустить 4 ВМ по 8 ГБ на хосте с 16 ГБ RAM. **К чему приводит:** хост свопит, ВМ «висят», VMware выдаёт ошибку о нехватке памяти. **Как правильно:** сумма RAM запущенных ВМ ≤ 60–70% RAM хоста; для стенда «Вектора» одновременно держите 2–3 ВМ.

2. **Ошибка:** оставить DHCP VMware включённым на VMnet8. **К чему приводит:** в уроке 33, когда DC01 поднимет DHCP, в подсети `10.10.10.0/24` окажется два DHCP-сервера — клиенты будут получать адреса случайно, диагностика станет невозможной. **Как правильно:** DHCP VMware на VMnet8 выключен с самого начала.

3. **Ошибка:** использовать Bridged для всех ВМ. **К чему приводит:** ваши учебные ВМ видны в домашней сети, сосед по Wi-Fi может зайти на них; кроме того, адреса из домашней подсети (`192.168.1.x`) не совпадут с планом стенда (`10.10.10.x`). **Как правильно:** NAT для офисной сети, Host-only для DMZ (VMnet10 появится в L2 №30).

4. **Ошибка:** считать снапшот резервной копией. **К чему приводит:** удалили папку ВМ — снапшоты ушли вместе с ней. **Как правильно:** снапшот — для быстрого отката в процессе работы; резервные копии — отдельная тема (урок 48).

5. **Ошибка:** делать снапшот «на всякий случай» каждые 5 минут. **К чему приводит:** дельта-файлы растут, диск хоста заполняется, ВМ тормозит. **Как правильно:** снапшот перед рискованным действием (установка, смена сети, эксперимент), после успеха — удалить старый.

6. **Ошибка:** забыть пароль шифрования ВМ с vTPM. **К чему приводит:** ВМ не запускается, восстановить доступ без пароля нельзя. **Как правильно:** пароль стенда `Lab#2026-vektor` записан в `stand-log.md` (в реальной работе — в менеджере паролей, не в открытом файле).

7. **Ошибка:** ставить пиратскую сборку Windows 11 «для лаборатории». **К чему приводит:** проблемы с законом и с обновлениями, непредсказуемое поведение. **Как правильно:** только evaluation-версии с сайта Microsoft (Windows 11 Enterprise Evaluation, 90 дней, продлевается `slmgr /rearm` [ПРОВЕРИТЬ лимит переармов в вашей редакции]).

### Безопасность

- **Не выключайте брандмауэр Windows на хосте** ради «чтобы работало». На стенде брандмауэр включён, правило ICMP разрешено — этого достаточно.
- **Bridged-режим в кафе/отеле** — ваши ВМ окажутся в чужой сети. В поездках используйте только NAT/Host-only.
- **Пароль `Lab#2026-vektor` — только для стенда.** В рабочей среде такой пароль на всех машинах — грубейшее нарушение; там пароли уникальные, в менеджере паролей, с ротацией.
- **Не храните в Git реальные пароли и ключи.** В `stand-log.md` пишите «пароль стенда», а не сам пароль, если репозиторий когда-нибудь станет публичным.

## 7. Вопросы на собеседовании

**Вопрос 1. Чем VMware Workstation отличается от VMware Player?**
Как спросят: «Работали с VMware? В чём разница между Workstation и Player?»
Ответ: «Workstation — платная полная версия: есть Virtual Network Editor, снапшоты, клонирование, команды `vmrun`, тонкая настройка железа ВМ. Player — бесплатная урезанная: запускает готовые ВМ, но не даёт создавать сложные конфигурации и менять сети. В лаборатории я использую Workstation, потому что мне нужны снапшоты и настройка VMnet8».
Что хочет услышать интервьюер: понимание, что вы работали с реальным инструментом, а не только читали.
Красный флаг: «Не знаю, я только VirtualBox видел».

**Вопрос 2. Чем NAT отличается от Bridged и Host-only?**
Как спросят: «Объясните разницу сетевых режимов в VMware».
Ответ: «Bridged — ВМ как отдельный ПК в физической сети, получает адрес от домашнего роутера. Host-only — изолированная сеть только между хостом и ВМ, наружу никак. NAT — ВМ в отдельной подсети, но через NAT-службу VMware выходит в интернет через хост. Для лаборатории удобнее NAT: изолированно и с интернетом».
Что хочет услышать: понимание изоляции и маршрутизации.
Красный флаг: «Bridged — это когда всё видно» без деталей.

**Вопрос 3. Зачем нужны снапшоты и чем они отличаются от бэкапа?**
Как спросят: «Как вы откатываете лабораторию после неудачного эксперимента?»
Ответ: «Снапшот фиксирует состояние ВМ — диск, ОЗУ, настройки — и позволяет вернуться к нему за секунды. Это не бэкап: снапшоты лежат в папке ВМ и удаляются вместе с ней, они не защищают от потери диска хоста. Бэкап — отдельная копия на другом носителе. В лаборатории я делаю снапшот `before-l1-003` перед каждым рискованным шагом».
Что хочет услышать: что вы не путаете снапшот и резервную копию.
Красный флаг: «Снапшот — это и есть бэкап».

**Вопрос 4. Сколько ресурсов выделять ВМ на домашнем ПК?**
Как спросят: «У меня 16 ГБ RAM, сколько ВМ я могу запустить?»
Ответ: «Правило — сумма RAM запущенных ВМ не больше 60–70% RAM хоста. На 16 ГБ это примерно 10–11 ГБ на ВМ, то есть 2–3 ВМ по 4 ГБ. Плюс запас по диску: Windows 11 ~25 ГБ, Windows Server ~20 ГБ, Linux ~10 ГБ, плюс снапшоты. Если запустить больше — хост начнёт свопить и всё встанет».
Что хочет услышать: практическое чувство ресурсов.
Красный флаг: «Запущу 10 ВМ по 8 ГБ, нормально».

**Вопрос 5. Что делать, если ВМ не видит хост после смены настроек сети?**
Как спросят: «Пользователь поменял настройки в Virtual Network Editor, ВМ перестала пинговаться. Ваши действия?»
Ответ: «Сначала смотрю адрес хоста в VMnet8 через `Get-NetIPAddress` — совпадает ли с планом. Потом открываю Virtual Network Editor и сверяю подсеть, тип, состояние DHCP. Сверяю с журналом стенда. Если подсеть уехала — возвращаю исходную, проверяю связь пингом. В рабочей среде — фиксирую в заявке, что настройки менялись, и предупреждаю пользователя».
Что хочет услышать: алгоритм диагностики, а не «перезагрузите».
Красный флаг: «Сразу переустановлю VMware».
