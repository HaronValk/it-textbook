## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Что такое ISO.** ISO — это образ оптического диска: один файл, внутри которого лежит файловая система (обычно ISO 9660 или UDF). VMware Workstation умеет подключать ISO как виртуальный CD/DVD — для гостевой ОС это выглядит как настоящий диск в приводе. Windows Setup загружается с него так же, как с флешки на реальном ПК.

**Что происходит при установке Windows (упрощённо):**

```text
[ISO Windows 11/12] --(виртуальный DVD)--> [WIN11-CL01]
       |                                        |
       | 1. Загрузчик (bootmgr) читает boot.wim |
       | 2. WinPE: разметка диска, копирование   |
       |    install.wim на диск C:               |
       | 3. Первая загрузка: OOBE (регион, язык, |
       |    учётка), установка драйверов         |
       | 4. Рабочий стол                          |
       v                                        v
   VMware Tools (vmware-tools.iso) --> драйверы + агент
```

**Ключевые понятия, которые встретятся:**

- **WinPE** — минимальная среда, в которой работает установщик. Именно она показывает окно выбора диска.
- **install.wim / install.esd** — образ самой Windows, который копируется на диск.
- **OOBE (Out-of-Box Experience)** — мастер первой настройки: регион, раскладка, имя пользователя, пароль, вопросы приватности.
- **VMware Tools** — набор драйверов и служб для гостевой ОС: видеодрайвер (без него разрешение экрана «прыгает»), драйвер мыши (без него курсор «залипает»), синхронизация времени с хостом, общие папки, корректное выключение. Без Tools виртуалка работает, но неудобно.
- **Статический IP** — адрес, прописанный вручную. На нашем стенде до L1 №33 DHCP нет, поэтому клиенты получают адреса вручную: WIN11-CL01 → `10.10.10.51`, WIN10-CL02 → `10.10.10.52`, шлюз `10.10.10.2`, DNS пока не нужен (его не будет до L1 №34).
- **vTPM** — виртуальный TPM-модуль. Windows 11 требует TPM 2.0, поэтому VMware шифрует ВМ с vTPM. Пароль шифрования на стенде — `Lab#2026-vektor` [ПРОВЕРИТЬ в твоей версии VMware].

**Порты и протоколы, которые пригодятся позже:** RDP (3389) — удалённый рабочий стол, SMB (445) — общие папки, DNS (53) — имена. Сейчас они не нужны, но именно их ты будешь проверять, когда пользователь скажет «не открывается папка».

**Место темы в общей картине.** Установка ОС — это фундамент. Дальше по хронологии: L1 №5 — Linux на UBU01, L1 №6 — Windows Server на DC01, L1 №13–23 — работа внутри Windows, L1 №33–34 — DHCP и DNS, L1 №42–44 — домен. Если сейчас что-то сделать неправильно (например, забыть имя машины или адрес), позже придётся переделывать.

## 3. Аналогия из жизни

Установка Windows на виртуалку — это как заселение в новую квартиру. ISO — это коробки с мебелью, которые привезли к подъезду. VMware Workstation — грузчик, который заносит их внутрь. Установщик — сборщик мебели: он раскладывает детали по комнатам (копирует файлы на диск). OOBE — это момент, когда ты впервые заходишь и решаешь: где будет кровать, какой будет замок на двери (пароль), какие обои (тема). VMware Tools — это сантехник и электрик, которые приходят после сборки и подключают воду и свет: без них мебель стоит, но жить неудобно. Статический IP — это номер квартиры на двери: без него почтальон (сеть) не найдёт тебя.

Аналогия перестаёт работать в одном месте: в реальной квартире нельзя «откатиться к снапшоту» и заселиться заново за две минуты — а в виртуалке это обычная практика.

## 4. Практика и команды

### 4.1. Проверить, что ISO на месте и целое (на хосте, PowerShell)

```powershell
Get-Item 'C:\Lab\vektor\ISO\Win11_24H2_Russian_x64.iso' | Select-Object Name, Length
Get-FileHash 'C:\Lab\vektor\ISO\Win11_24H2_Russian_x64.iso' -Algorithm SHA256
```

`Get-FileHash` считает SHA-256 — сравни с хешем на странице загрузки Microsoft. Если не совпало — ISO битое, установка упадёт на середине. Имя файла — пример; подставь своё.

### 4.2. Список ВМ и их состояние (на хосте, PowerShell через vmrun)

```powershell
& 'C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe' -T ws list
```

Вывод примерно такой:

```text
Total running VMs: 1
C:\Lab\vektor\VMs\WIN11-CL01\WIN11-CL01.vmx
```

`-T ws` — тип хоста (Workstation). Без него `vmrun` иногда ругается на неоднозначность.

### 4.3. Запустить ВМ и подключить ISO (на хосте)

```powershell
& 'C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe' -T ws -vp "Lab#2026-vektor" start 'C:\Lab\vektor\VMs\WIN11-CL01\WIN11-CL01.vmx'
```

`-vp` — пароль шифрования (нужен для WIN11-CL01 из-за vTPM). Для WIN10-CL02 `-vp` не требуется. [ПРОВЕРИТЬ синтаксис `-vp` в твоей версии VMware.]

### 4.4. Посмотреть IP-конфигурацию (в гостевой Windows, CMD)

```cmd
ipconfig /all
```

Смотрим: `IPv4 Address`, `Default Gateway`, `DNS Servers`, `Physical Address` (MAC). Если адрес `169.254.x.x` — DHCP не нашёл сервер (у нас его и нет, поэтому статический адрес обязателен).

### 4.5. Задать статический IP (в гостевой Windows, PowerShell от админа)

```powershell
New-NetIPAddress -InterfaceAlias 'Ethernet0' -IPAddress 10.10.10.51 -PrefixLength 24 -DefaultGateway 10.10.10.2
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet0' -ServerAddresses 10.10.10.10
```

`-PrefixLength 24` — маска `255.255.255.0`. DNS `10.10.10.10` пока не отвечает (DC01 без ролей), но прописать можно — заработает после L1 №34. Имя интерфейса проверь через `Get-NetAdapter`.

### 4.6. Проверить связь с хостом (в гостевой Windows, CMD)

```cmd
ping 10.10.10.1
ping 10.10.10.2
```

Первый — хост (VMnet8), второй — NAT-шлюз VMware. Оба должны отвечать. Если первый не отвечает — проверь, что в настройках VMnet8 выключен DHCP самого VMware и что адаптер ВМ подключён к VMnet8.

### 4.7. Переименовать машину (в гостевой Windows, PowerShell от админа)

```powershell
Rename-Computer -NewName 'WIN11-CL01' -Restart
```

`-Restart` сразу перезагрузит. Имя должно совпадать с таблицей стенда — иначе позже (L1 №44) не введёшь в домен без путаницы.

### 4.8. Проверить, что VMware Tools работает (в гостевой Windows, PowerShell)

```powershell
Get-Service -Name 'VMTools' | Select-Object Status, StartType
Get-ItemProperty 'HKLM:\SOFTWARE\VMware, Inc.\VMware Tools' | Select-Object ProductVersion
```

Служба `VMTools` должна быть `Running`, `StartType = Automatic`. Версия — примерно `12.x` [ПРОВЕРИТЬ в твоей версии]. Если службы нет — Tools не установлены.

### 4.9. Создать локальную учётку (в гостевой Windows, PowerShell от админа)

```powershell
New-LocalUser -Name 'ivanov' -FullName 'Иван Иванов' -Password (Read-Host -AsSecureString 'Пароль')
Add-LocalGroupMember -Group 'Пользователи' -Member 'ivanov'
```

`Read-Host -AsSecureString` не показывает пароль на экране. На стенде пароль `Lab#2026-vektor`; в реальной работе — только по политике.

### 4.10. Через GUI (если PowerShell ещё не прошёл)

- Сеть: **Параметры → Сеть и Интернет → Ethernet → Изменить параметры адаптера → Свойства → IP версии 4 (TCP/IPv4)**.
- Имя: **Параметры → Система → О системе → Переименовать этот компьютер**.
- Учётки: **Управление компьютером → Локальные пользователи и группы → Пользователи → Создать пользователя**.
- VMware Tools: меню ВМ → **VM → Install VMware Tools**, затем в гостевой ОС запустить установщик с виртуального привода.

**Как воспроизвести поломку.** На WIN10-CL02 открой PowerShell от админа и удали шлюз у адаптера:

```powershell
Remove-NetRoute -InterfaceAlias 'Ethernet0' -DestinationPrefix '0.0.0.0/0' -Confirm:$false
```

Теперь у машины есть IP `10.10.10.52`, но нет маршрута по умолчанию — в интернет (и к NAT-шлюзу `10.10.10.2`) пакеты не уходят. Локальная сеть `10.10.10.0/24` при этом работает.

**Диагностика по шагам:**

1. Спроси пользователя: что менялось? Перезагружалась ли машина, ставилось ли что-то? (Петрова скажет: «просто перезагрузила».)
2. На WIN10-CL02: `ipconfig /all`. Смотрим — адрес есть, шлюз **пустой**. Это уже подозрительно.
3. `ping 10.10.10.51` — отвечает (локальная сеть жива). `ping 10.10.10.2` — не отвечает (шлюз недоступен).
4. `route print` — в таблице маршрутизации нет строки `0.0.0.0 0.0.0.0 ... 10.10.10.2`. Подтверждает: маршрута по умолчанию нет.
5. Причина: кто-то (или сбой) удалил шлюз. На стенде это учебная поломка; в реальной работе так бывает после кривого скрипта или ручной правки.

**Решение.** Вернуть шлюз:

```powershell
New-NetRoute -InterfaceAlias 'Ethernet0' -DestinationPrefix '0.0.0.0/0' -NextHop 10.10.10.2
```

Проверить: `ping 10.10.10.2` отвечает, `route print` показывает маршрут, браузер открывает внешний сайт (если NAT работает).

**Ответ пользователю:** «Мария, добрый день. Причина найдена: у сетевого адаптера пропал шлюз по умолчанию, поэтому компьютер не видел интернет. Шлюз восстановлен, соединение проверено. Пожалуйста, перезагрузите браузер и попробуйте снова. Если повторится — напишите, разберёмся глубже.»

**Закрытие заявки.** Категория: «Сеть / Конфигурация». Решение: восстановлен маршрут по умолчанию. Время: 10 минут. Запись в `stand-log.md`: «WIN10-CL02 — восстановлен default gateway 10.10.10.2 после учебной поломки».

## 6. Ошибки новичков и безопасность

1. **Забыл отключить ISO после установки.** Машина при каждой перезагрузке снова грузится с установщика. → Правильно: после первой перезагрузки **VM → Removable Devices → CD/DVD → Disconnect**.
2. **Не установил VMware Tools.** Экран «прыгает», мышь залипает, время расходится с хостом. → Правильно: Tools ставить сразу после установки ОС, до любых других настроек.
3. **Оставил адрес `169.254.x.x`.** DHCP на стенде нет, машина не видит сеть. → Правильно: статический IP из таблицы стенда, шлюз `10.10.10.2`.
4. **Забыл переименовать машину.** Позже при вводе в домен (L1 №44) имя не совпадёт с таблицей, придётся переделывать. → Правильно: `Rename-Computer` сразу после установки Tools.
5. **Создал учётку с правами администратора «на всякий случай».** Пользователь `ivanov` не должен быть админом — иначе любая ошибка пользователя ломает систему. → Правильно: `ivanov` и `petrova` — обычные пользователи, `adm.student` — админ.
6. **Поставил Windows 11 без vTPM.** Установщик откажется: «This PC can't run Windows 11». → Правильно: vTPM включён при создании ВМ (это сделано в L1 №3), пароль шифрования `Lab#2026-vektor`.
7. **Скачал ISO с торрента или «сборку».** Пиратская сборка = потенциальный бэкдор и нарушение лицензии. → Правильно: только официальный Evaluation с сайта Microsoft (или учебный образ через Azure for Students / Microsoft Learn).
8. **Не записал в `stand-log.md`.** Через неделю не вспомнишь, какой адрес куда. → Правильно: запись после каждой лабораторной.

### Безопасность

- **Пароль `Lab#2026-vektor` — только для стенда.** В рабочей среде такой пароль = мгновенный взлом. Реальные пароли — по политике компании, минимум 12 символов, разные для разных систем.
- **Не отключай брандмауэр «чтобы проверить».** На стенде правило ICMP уже разрешено — этого достаточно для ping. Отключение брандмауэра на рабочей машине — грубое нарушение.
- **Не давай пользователю права администратора** «чтобы он сам ставил программы». Это классическая причина инцидентов ИБ. Установка ПО — через заявку в поддержку.
- **Не подключай к ВМ общие папки хоста с реальными документами.** На стенде — только `C:\Lab\vektor` и `C:\Support`.

## 7. Вопросы на собеседовании

**Вопрос 1. «Как вы установите Windows 11 на новую машину?»**

Ответ: «Сначала проверю требования: 64-битный CPU, 4 ГБ RAM, 64 ГБ диск, UEFI + Secure Boot, TPM 2.0. Подготовлю официальный ISO, создам загрузочную флешку (Rufus или Media Creation Tool) или подключу ISO к виртуалке. Загружусь с носителя, выберу язык, тип установки "Выборочная", размечу диск, дождусь копирования. После OOBE — установлю драйверы (на виртуалке — VMware Tools), настрою сеть, имя машины, учётки. Запишу в журнал.»

*Что хочет услышать интервьюер:* что ты знаешь требования Windows 11 и не забудешь про TPM/Secure Boot; что установка — это не только «нажать Далее», но и настройка после.

*Красный флаг:* «Скачаю сборку с торрента, там всё уже настроено».

**Вопрос 2. «Зачем нужны VMware Tools и что будет, если их не ставить?»**

Ответ: «VMware Tools — это набор драйверов и служб для гостевой ОС: видеодрайвер (нормальное разрешение), драйвер мыши (нет залипания), синхронизация времени с хостом, корректное выключение, общие папки. Без них виртуалка работает, но неудобно: экран маленький, мышь дёргается, время уплывает. На стенде я проверяю службу `VMTools` через `Get-Service` — она должна быть Running.»

*Что хочет услышать:* понимание, что Tools — это не «украшение», а рабочий инструмент; что ты умеешь проверить их состояние.

*Красный флаг:* «Не знаю, никогда не ставил».

**Вопрос 3. «Пользователь говорит, что нет интернета. Ваши действия?»**

Ответ: «Начинаю с простого: `ipconfig /all` — есть ли адрес, шлюз, DNS. Если адрес `169.254.x.x` — не работает DHCP или адрес не задан. Проверяю `ping` шлюза и внешнего адреса. Смотрю `route print` — есть ли маршрут по умолчанию. Если локальная сеть работает, а внешняя нет — проблема в шлюзе или NAT. Если не работает ничего — проверяю кабель/адаптер. Дальше по обстоятельствам: DNS, прокси, брандмауэр.»

*Что хочет услышать:* что ты идёшь от простого к сложному, а не сразу лезешь в реестр; что знаешь `ipconfig`, `ping`, `route`.

*Красный флаг:* «Переустановлю Windows».

**Вопрос 4. «Как задать статический IP в Windows?»**

Ответ: «Через GUI: Параметры → Сеть → Ethernet → Изменить параметры адаптера → Свойства → IPv4 → Свойства → "Использовать следующий IP-адрес". Через PowerShell: `New-NetIPAddress -InterfaceAlias 'Ethernet0' -IPAddress 10.10.10.51 -PrefixLength 24 -DefaultGateway 10.10.10.2`. DNS — `Set-DnsClientServerAddress`. Проверяю `ipconfig /all` и `ping` шлюза.»

*Что хочет услышать:* что ты знаешь оба способа и умеешь проверить результат.

*Красный флаг:* «Только через GUI, PowerShell не знаю».

**Вопрос 5. «Что такое OOBE и какие шаги там важны?»**

Ответ: «OOBE — Out-of-Box Experience, мастер первой настройки после установки. Важные шаги: регион и раскладка (иначе пользователь будет мучиться), выбор между локальной учёткой и Microsoft-аккаунтом (в корпоративной среде — локальная или доменная, не личная), имя пользователя и пароль, вопросы приватности (все "Нет"), настройка сети. Пропускать шаги нельзя — потом сложнее исправлять.»

*Что хочет услышать:* что ты понимаешь разницу между локальной и Microsoft-учёткой и почему в компании выбирают локальную/доменную.

*Красный флаг:* «Жму Далее везде, потом разберусь».
