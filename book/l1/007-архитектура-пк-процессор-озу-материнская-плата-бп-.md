## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Компьютер — это несколько устройств, которые общаются по шинам (bus — канал передачи данных). Главные узлы:

```text
                +-------------------------------+
                |      Материнская плата        |
                |                               |
  +---------+   |   +---------+    +---------+  |
  |  CPU    |<--+-->|  Chipset|<-->|  RAM    |  |
  | (ядро,  |   |   | (PCH)   |   | (DDR)   |  |
  | кэш)    |   |   +----+----+    +---------+  |
  +----+----+   |        |                      |
       |        |        | PCIe                 |
       |        |   +----v----+   +----------+  |
       |        |   |  GPU    |   |  NVMe/   |  |
       |        |   | (видео) |   |  SATA    |  |
       |        |   +---------+   +----------+  |
       |        |                               |
       |        +-------------------------------+
       |                       ^
       |                       |
       |              +--------+--------+
       +------------->|  Блок питания   |
                      | (12V, 5V, 3.3V) |
                      +-----------------+
```

**Процессор (CPU).** Выполняет инструкции. Состоит из ядер (cores), кэша (L1/L2/L3) и контроллера памяти. У современных Intel и AMD контроллер памяти встроен в CPU, поэтому память подключается напрямую к процессору, а не к чипсету. Ключевые характеристики для L1: количество ядер/потоков, базовая и турбо-частота, сокет (разъём на материнке), TDP (сколько тепла выделяет — важно для «греется» и «шумит»).

**ОЗУ (RAM).** Оперативная память, в которой лежат запущенные программы и данные. Быстрая, но энергозависимая — при выключении всё пропадает. Типы: DDR4, DDR5 (DDR3 уже редкость). Важные параметры: объём (ГБ), частота (МГц), форм-фактор (DIMM для ПК, SO-DIMM для ноутбуков), количество каналов (одноканал/двухканал — заметно влияет на производительность). Если ОЗУ не хватает, Windows уходит в файл подкачки на диске — отсюда «тормозит и шуршит диском».

**Материнская плата.** Связывает всё. На ней: сокет CPU, слоты памяти, слоты PCIe (для видеокарты и других плат), разъёмы SATA и M.2 (для дисков), чипсет (PCH — Platform Controller Hub), разъёмы питания 24-pin и 4/8-pin CPU, порты USB, видео, сеть, аудио. Ключевые параметры: форм-фактор (ATX, microATX, mini-ITX), сокет, чипсет (например, B660, B550 — определяет, что поддерживается), версия BIOS/UEFI.

**Блок питания (БП, PSU).** Преобразует 220 В переменного тока в 12 В, 5 В и 3,3 В постоянного. Характеристики: мощность (Вт), стандарт (ATX 2.x, ATX 3.x), сертификат эффективности (80 PLUS Bronze/Gold/Platinum), разъёмы (24-pin, 8-pin CPU, 6+2-pin PCIe для видеокарты). Плохой или слабый БП — частая причина «выключается под нагрузкой», «не стартует», «перезагружается».

**Видеокарта (GPU).** Отвечает за вывод изображения. Бывает встроенная (в CPU или чипсете) и дискретная (отдельная плата в слоте PCIe). У дискретной свои видеопамять (VRAM), охлаждение и питание. Для офисных задач хватает встроенной; для 1С с тяжёлыми отчётами, CAD, монтажа — нужна дискретная. Симптомы проблем: артефакты на экране, «чёрный экран», драйвер отваливается.

**Как это работает вместе.** При включении БП подаёт питание → материнская плата запускает BIOS/UEFI → тот инициализирует CPU, память, находит диск → загружает ОС. В работе CPU читает инструкции и данные из ОЗУ, ОЗУ подгружает их с диска, GPU рисует картинку, всё это питается от БП и охлаждается кулерами. Если одно звено слабое или сбоит — страдает вся система.

## 3. Аналогия из жизни

Представь кухню ресторана. **Процессор** — повар: чем больше рук (ядер) и чем он быстрее, тем больше блюд в минуту. **ОЗУ** — разделочный стол: чем он больше, тем больше заготовок помещается рядом, и повару не надо бегать в холодильник. **Диск** — холодильник: там всё хранится, но доставать долго. **Материнская плата** — сама кухня: расположение плит, столов и розеток; если розеток мало или они не там — хоть какого повара зови, работать неудобно. **Блок питания** — подводка газа и электричества: слабая — и плита не раскаляется, а то и всё вырубается при включении духовки. **Видеокарта** — официант, который красиво подаёт блюда: если он медленный, гости видят, как еда остывает, хотя на кухне всё готово.

Аналогия ломается в одном: на кухне повар может сам сходить в холодильник, а процессор без ОЗУ не работает вообще — ему негде держать даже одну инструкцию.

## 4. Практика и команды

Все команды ниже — на существующих ВМ стенда. На WIN11-CL01 и WIN10-CL02 — PowerShell или CMD от имени `adm.student` (или локального пользователя, если он админ). На DC01 — тоже PowerShell. На UBU01 — bash через SSH под `adm.student`.

**1. Сводка о системе (Windows).**
```powershell
systeminfo
```
Показывает версию ОС, производителя, модель, объём ОЗУ, версию BIOS, процессор. Вывод длинный, но нам важны строки «OS Name», «System Manufacturer», «Total Physical Memory», «Processor(s)». Примерно так:
```text
OS Name:                   Microsoft Windows 11 Enterprise
System Manufacturer:       VMware, Inc.
System Model:              VMware Virtual Platform
Total Physical Memory:     4,096 MB
Processor(s):              1 processor(s) installed.
```
Смотрим: сколько ОЗУ выделено ВМ, какой процессор «видит» гость.

**2. Процессор и ОЗУ через WMI/CIM (PowerShell).**
```powershell
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors, MaxClockSpeed
Get-CimInstance Win32_PhysicalMemory | Select-Object Capacity, Speed, Manufacturer, PartNumber
```
Первая команда — модель CPU, число ядер и потоков, частота. Вторая — каждая планка ОЗУ: объём, частота, производитель. На ВМ VMware увидишь виртуальные планки — это нормально.

**3. Материнская плата и BIOS.**
```powershell
Get-CimInstance Win32_BaseBoard | Select-Object Manufacturer, Product, Version
Get-CimInstance Win32_BIOS | Select-Object Manufacturer, SMBIOSBIOSVersion, ReleaseDate
```
На ВМ производитель будет «VMware, Inc.» — это ожидаемо. На реальном ПК здесь будет ASUS/Gigabyte/MSI и модель платы — эти данные нужны при заказе запчастей и поиске драйверов.

**4. Видеокарта.**
```powershell
Get-CimInstance Win32_VideoController | Select-Object Name, DriverVersion, AdapterRAM, VideoModeDescription
```
Показывает адаптер (на ВМ — «VMware SVGA II» или подобное), версию драйвера, объём видеопамяти, текущее разрешение. Если пользователь жалуется на «артефакты» — первым делом смотрим сюда и обновляем драйвер.

**5. Блок питания и температура — только через датчики.**
```powershell
Get-CimInstance -Namespace root/wmi -ClassName MSAcpi_ThermalZoneTemperature -ErrorAction SilentlyContinue
```
На большинстве ВМ и многих ПК этот класс пуст — нормально. На реальном железе температуру и напряжение БП надёжнее смотреть через BIOS/UEFI или фирменную утилиту производителя (ASUS AI Suite, MSI Center и т.п.). Мощность БП из Windows не узнать — только глазами по наклейке на корпусе.

**6. Загрузка CPU и памяти в реальном времени.**
```powershell
Get-Counter '\Processor(_Total)\% Processor Time' -SampleInterval 1 -MaxSamples 5
Get-Counter '\Memory\Available MBytes' -SampleInterval 1 -MaxSamples 5
```
Пять замеров с интервалом в секунду. Если `% Processor Time` стабильно 90–100% — что-то грузит CPU. Если `Available MBytes` падает ниже 500 — памяти мало, система уходит в подкачку.

**7. Linux: сводка о железе на UBU01.**
```bash
lscpu
free -h
sudo dmidecode -t system -t baseboard -t memory | head -n 60
```
`lscpu` — модель CPU, ядра, потоки, частоты. `free -h` — сколько ОЗУ всего/занято/свободно в человекочитаемом виде. `dmidecode` (нужен sudo) — производитель и модель системы, материнской платы, планок памяти. На UBU01 (виртуалка VMware) увидишь «VMware Virtual Platform» — это норма.

**8. Linux: видеокарта и PCI-устройства.**
```bash
lspci | grep -Ei 'vga|3d|display'
```
Показывает видеоадаптер. На UBU01 — что-то вроде «VMware SVGA II Adapter». На реальном сервере — Matrox/ASPEED (встроенный серверный видеочип) или дискретная карта.

**9. Linux: температура и питание (если датчики есть).**
```bash
sudo apt install lm-sensors -y
sudo sensors-detect --auto
sensors
```
На ВМ VMware датчиков обычно нет — вывод будет пустой или «No sensors found». На физическом сервере покажет температуры CPU и обороты кулеров. Пакет `lm-sensors` в стандартных репозиториях Ubuntu 24.04 есть.

**10. GUI-путь для L1 (Windows).**
- `Win + R` → `msinfo32` → «Сведения о системе»: процессор, ОЗУ, модель платы, версия BIOS — всё на одном экране.
- `Win + R` → `dxdiag` → вкладки «Система» и «Экран»: CPU, ОЗУ, видеокарта, версия драйвера.
- `Ctrl + Shift + Esc` → «Диспетчер задач» → «Производительность»: графики CPU, памяти, диска, GPU в реальном времени.

Эти три инструмента — то, что ты будешь открывать пользователю по удалёнке или просить открыть и прислать скриншот.

### Сломай и почини

**Заявка:**
> **Пользователь:** Мария Петрова (HR), ВМ WIN10-CL02
> **Что написала:** «После обеда компьютер стал жутко тормозить: Word открывается по 20 секунд, вкладки в браузере висят. Вчера было нормально. Перезагружала — не помогло. Срочно, у меня отчёт к 17:00».
> **Срочность:** Высокая.

**Как воспроизвести поломку.** На WIN10-CL02 под `petrova` (или `adm.student`) запусти «пожиратель» памяти — например, открой PowerShell и выполни:
```powershell
$hog = @()
1..200 | ForEach-Object { $hog += ('x' * 1MB) }
```
Это создаст массив из 200 строк по 1 МБ — примерно 200 МБ «мусора» в памяти процесса. Если ОЗУ у ВМ небольшое (например, 2 ГБ), этого достаточно, чтобы `Available MBytes` просело и система начала активно использовать файл подкачки. Для более выраженного эффекта можно увеличить до 500–800 итераций — но следи, чтобы ВМ не «упала» в своп полностью. Альтернатива: запустить несколько копий тяжёлого приложения (например, несколько окон браузера с десятком вкладок). Не забудь потом закрыть PowerShell — иначе «поломка» останется.

**Диагностика по шагам.**
1. Подключись к WIN10-CL02, открой PowerShell. Проверь `Get-Counter '\Memory\Available MBytes' -SampleInterval 1 -MaxSamples 5`. Если значения низкие (сотни МБ и меньше) — памяти не хватает.
2. Открой «Диспетчер задач» (`Ctrl + Shift + Esc`) → «Производительность» → «Память». Смотри, кто ест память: вкладка «Процессы» отсортирована по памяти.
3. Проверь `Get-CimInstance Win32_PhysicalMemory | Format-Table Capacity` — сколько физически выделено ВМ. Сравни с тем, что записано в `stand-log.md` по уроку 7.
4. Проверь `Get-Counter '\Processor(_Total)\% Processor Time'` — если CPU тоже 90–100%, возможно, дело не только в памяти.
5. Проверь диск: `Get-Counter '\PhysicalDisk(_Total)\% Disk Time'` — при активной подкачке диск будет загружен на 100%.

**Решение.** Закрой процесс-«пожиратель» (в нашем случае — PowerShell с массивом `$hog`). Если проблема повторяется у пользователя — предложи увеличить ОЗУ ВМ в настройках VMware (VM → Settings → Memory) или закрыть лишние приложения. В реальной работе — согласовать апгрейд ОЗУ с руководителем.

## 6. Ошибки новичков и безопасность

1. **Путать объём ОЗУ с объёмом диска.** «У меня 256 ГБ» — это про SSD, а не про память. → Пользователь думает, что у него много памяти, а на самом деле 8 ГБ и всё тормозит. → Всегда уточняй: «оперативная память» vs «диск».
2. **Смотреть только на CPU при «тормозит».** Часто виновата память или диск, а не процессор. → Меняешь CPU, а проблема остаётся. → Смотри все три графика в диспетчере задач одновременно.
3. **Игнорировать блок питания.** «Выключается под нагрузкой» — классика слабого БП. → Меняешь материнку, а проблема возвращается. → Спрашивай мощность БП и что подключено.
4. **Верить надписи на корпусе.** «У меня 500 Вт» — а на наклейке БП написано «450 Вт peak». → Заказываешь видеокарту, которая не запустится. → Смотри наклейку на самом БП, а не на корпусе.
5. **Ставить память разных частот и типов.** DDR4 и DDR5 несовместимы, разные частоты работают на минимальной. → Система не стартует или работает медленнее. → Проверяй тип и частоту перед покупкой.
6. **Забывать про охлаждение.** «Шумит» — часто забитый пылью кулер или высохшая термопаста. → Перегрев, троттлинг, внезапные выключения. → Чистка и замена термопасты раз в 1–2 года.
7. **Путать встроенную и дискретную видеокарту.** На ВМ и офисных ПК часто только встроенная — и это нормально. → Пользователь жалуется, что «игры не идут», а у него офисная машина. → Уточняй задачу.

**Безопасность.**
- Не открывай корпус включённого ПК и не трогай платы под напряжением — только после полного отключения от сети и снятия статики.
- Не выдёргивай шнур питания во время работы — риск потерять данные и повредить диск.
- Не устанавливай «ускорители» и «оптимизаторы» из интернета — часто это майнеры и рекламное ПО. В рабочей среде установка ПО — только через согласование с ИБ.
- Пароли на стенде (`Lab#2026-vektor`) — учебные. В реальной работе так нельзя: пароли не пишут в журналах и не передают в открытом виде.

## 7. Вопросы на собеседовании

**Вопрос 1. «Пользователь говорит, что компьютер тормозит. С чего начнёте?»**
Ответ: «Открою диспетчер задач и посмотрю три графика: CPU, память, диск. Если CPU 100% — ищу процесс, если память в нуле — смотрю, кто ест ОЗУ, если диск 100% — проверяю, не идёт ли обновление или индексация. Параллельно уточню у пользователя, что именно тормозит: всё или конкретная программа, когда началось, что менялось. Дальше сужаю круг: железо, софт или сеть».
Что хочет услышать интервьюер: системный подход, а не «перезагрузите».
Красный флаг: «Сразу переустановлю Windows».

**Вопрос 2. «Чем отличается ОЗУ от диска?»**
Ответ: «ОЗУ — оперативная память, быстрая, но энергозависимая: при выключении всё пропадает. Диск — долговременное хранение, медленнее, но данные сохраняются. Когда ОЗУ не хватает, система использует файл подкачки на диске — это медленно, отсюда „тормоза“».
Что хочет услышать: понимание разницы и связи с производительностью.
Красный флаг: «Это одно и то же, просто разного размера».

**Вопрос 3. «Как узнать модель материнской платы и версию BIOS?»**
Ответ: «Через `msinfo32` или PowerShell: `Get-CimInstance Win32_BaseBoard` и `Get-CimInstance Win32_BIOS`. На Linux — `sudo dmidecode -t baseboard`. Эти данные нужны для поиска драйверов и заказа запчастей».
Что хочет услышать: знание штатных инструментов, а не «посмотрю на коробке».
Красный флаг: «Не знаю, это же не моя работа».

**Вопрос 4. «Компьютер выключается под нагрузкой. Что проверите?»**
Ответ: «Первым делом блок питания: мощность, возраст, что подключено. Дальше — охлаждение: пыль, кулеры, термопаста. Потом — температуру CPU через BIOS или утилиту производителя. Если БП слабый или старый — замена. Если перегрев — чистка».
Что хочет услышать: связь симптома с железом, а не с Windows.
Красный флаг: «Переустановлю драйвер видеокарты».

**Вопрос 5. «Зачем L1 знать архитектуру ПК, если он работает с заявками?»**
Ответ: «Чтобы по симптому быстро понять, куда смотреть, и не гонять пользователя по кругу. И чтобы говорить с закупкой и подрядчиком на одном языке: „нужна планка DDR4 3200 8 ГБ“ звучит понятнее, чем „нужна память“».
Что хочет услышать: понимание, что архитектура — инструмент диагностики, а не самоцель.
Красный флаг: «Мне это не нужно, я только тикеты закрываю».
