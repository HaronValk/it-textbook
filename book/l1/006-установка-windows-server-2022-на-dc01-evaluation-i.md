## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Windows Server — это та же Windows, что и на клиенте, но с другим набором ролей и служб. Для L1 важно понимать три вещи.

**Первое — редакции и режимы установки.** Evaluation-образ Windows Server 2022 существует в двух вариантах установки: **Server Core** (без графической оболочки, только консоль и PowerShell) и **Desktop Experience** (с привычным рабочим столом). Для учебного стенда и для L1-практики берём Desktop Experience — так проще смотреть «глазами», а не гадать по выводу команд. В реальной работе серверы часто ставят Core, но это осознанное решение админа, а не выбор новичка.

**Второе — сеть.** У сервера адрес должен быть **статическим**. DHCP-сервера на стенде пока нет (он появится в L1 №33), а главное — сервер, который сам будет раздавать адреса и отвечать за DNS, не может зависеть от чужого DHCP. Поэтому `10.10.10.10` прописывается руками, шлюз `10.10.10.2` (NAT-устройство VMware), DNS на этом этапе — тоже `10.10.10.10` (пока просто «на будущее», реально заработает в L1 №34).

**Третье — имя.** Имя компьютера в Windows ограничено 15 символами, регистр не важен, дефисы допустимы. `DC01` — короткое, читаемое, стандартное для контроллера домена.

Схема того, что у нас есть на стенде к началу урока:

```text
        Хост (Windows, VMware Workstation)
        ├── VMnet8 (NAT) 10.10.10.0/24, шлюз 10.10.10.2, хост 10.10.10.1
        │
        ├── WIN11-CL01  10.10.10.51  (Windows 11, локальная ivanov)
        ├── WIN10-CL02  10.10.10.52  (Windows 10 LTSC, локальная petrova)
        ├── UBU01       10.10.10.30  (Ubuntu Server 24.04, SSH)
        └── DC01        10.10.10.10  ← создаём сегодня (Windows Server 2022)
```

Порты и протоколы, которые нам сегодня нужны: **ICMP** (ping — проверка связности), **RDP 3389** (удалённый рабочий стол, если захотите подключиться с хоста), **SMB 445** (проверим позже, когда появятся общие папки). Пока достаточно ICMP.

## 3. Аналогия из жизни

Представьте, что вы открываете новый офис. Сначала завозят мебель и ставят её в нужное место (это установка ОС). Потом на дверь вешают табличку с номером и названием организации (это имя компьютера). Потом в почтовый ящик кладут бумажку с точным адресом — не «где-то на Ленинском», а «Ленинский, 10, офис 10» (это статический IP). И только после этого курьер сможет найти вас без звонков и объяснений. Снапшот — это фотография офиса в первый день: если завтра вы разобьёте окно, можно вернуться к состоянию «всё новое и чистое».

Аналогия перестаёт работать в одном месте: в реальном офисе адрес не меняется сам по себе, а IP-адрес в сети может «уплыть», если его выдаёт DHCP — поэтому мы и прописываем его руками.

## 4. Практика и команды

Все команды ниже выполняются либо на DC01 (после установки), либо на хосте. Где именно — указано.

**1. Проверить, что ISO скачан и его контрольная сумма совпадает с сайтом Microsoft.** На хосте, в PowerShell:

```powershell
Get-FileHash -Path 'C:\Lab\vektor\ISO\WindowsServer2022.iso' -Algorithm SHA256
```

`Get-FileHash` считает хеш файла. Сравните с SHA256 на странице загрузки Microsoft — если не совпадает, образ битый, установка может упасть на середине. Вывод примерно такой:

```text
Algorithm       Hash                                                                   Path
---------       ----                                                                   ----
SHA256          A1B2C3D4E5F6...                                                        C:\Lab\vektor\ISO\WindowsServer2022.iso
```

**2. Создать ВМ через GUI VMware Workstation.** Меню `File → New Virtual Machine → Typical`. Указать ISO, выбрать «Microsoft Windows» → «Windows Server 2022», задать имя `DC01`, папку `C:\Lab\vektor\VMs\DC01`, диск 60 ГБ, память 4 ГБ, 2 CPU, сеть — `VMnet8 (NAT)`.

**3. Проверить, что ВМ создана и её параметры корректны.** На хосте:

```powershell
vmrun -T ws list
```

`vmrun` — утилита управления ВМ из командной строки (ставится вместе с Workstation). `-T ws` — тип хоста Workstation. `list` — список запущенных ВМ. Вывод примерно:

```text
Total running VMs: 0
```

Пока DC01 не запущена — пусто. Это нормально.

**4. Запустить ВМ и пройти установку.** В окне VMware: `Power on`. В установщике Windows Server: язык → `Next` → `Install now` → «Windows Server 2022 Standard Evaluation (Desktop Experience)» → принять лицензию → «Custom: Install Windows only» → выбрать диск → установка (10–20 минут).

**5. Задать пароль администратора при первом входе.** После установки Windows попросит пароль для встроенной учётной записи `Administrator`. Введите `Lab#2026-vektor`. Это учебный пароль, в реальной среде так нельзя — см. раздел 6.

**6. Открыть PowerShell от администратора и переименовать компьютер.** На DC01, в меню `Start → Windows PowerShell (Admin)`:

```powershell
Rename-Computer -NewName 'DC01' -Restart
```

`Rename-Computer` меняет имя. `-NewName` — новое имя. `-Restart` — сразу перезагрузиться. После перезагрузки имя применится. Проверить:

```powershell
hostname
```

Вывод:

```text
DC01
```

**7. Задать статический IP.** GUI: `Server Manager → Local Server → Ethernet → Properties → Internet Protocol Version 4 (TCP/IPv4) → Properties`. Или PowerShell:

```powershell
New-NetIPAddress -InterfaceAlias 'Ethernet0' -IPAddress 10.10.10.10 -PrefixLength 24 -DefaultGateway 10.10.10.2
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet0' -ServerAddresses 10.10.10.10
```

`New-NetIPAddress` создаёт адрес. `-PrefixLength 24` — маска `255.255.255.0`. `-DefaultGateway` — шлюз. `Set-DnsClientServerAddress` задаёт DNS-сервер (пока сам на себя — заработает в L1 №34). Имя интерфейса `Ethernet0` — типичное для VMware, но проверьте через `Get-NetAdapter`, если не совпадает.

**8. Проверить IP и шлюз.**

```powershell
ipconfig /all
```

Смотрите строки `IPv4 Address`, `Subnet Mask`, `Default Gateway`, `DNS Servers`. Должно быть `10.10.10.10`, `255.255.255.0`, `10.10.10.2`, `10.10.10.10`.

**9. Проверить связность с другими ВМ.** На DC01:

```powershell
Test-Connection -ComputerName 10.10.10.51 -Count 4
Test-Connection -ComputerName 10.10.10.30 -Count 4
```

`Test-Connection` — аналог `ping`. `-Count 4` — четыре пакета. WIN11-CL01 и UBU01 должны ответить (правило ICMP на стенде разрешено). Если WIN11-CL01 не отвечает — проверьте, что она запущена и в той же сети VMnet8.

**10. Проверить, что DC01 видна с других машин.** На WIN11-CL01 (в CMD):

```cmd
ping 10.10.10.10
```

Должно быть 4 ответа `Reply from 10.10.10.10: bytes=32 time<1ms TTL=128`. TTL=128 — признак Windows-хоста.

**11. Сделать снапшот.** В окне VMware: `VM → Snapshot → Take Snapshot`, имя `before-l1-006`. Или через `vmrun`:

```powershell
vmrun -T ws snapshot "C:\Lab\vektor\VMs\DC01\DC01.vmx" before-l1-006
```

`snapshot` — создать снапшот. Первый аргумент — путь к `.vmx`-файлу ВМ, второй — имя снапшота. Проверить список:

```powershell
vmrun -T ws listSnapshots "C:\Lab\vektor\VMs\DC01\DC01.vmx"
```

**12. Записать в журнал.** Откройте `C:\Lab\vektor\stand-log.md` и добавьте строку: дата, «DC01 создана, Windows Server 2022, 10.10.10.10, снапшот before-l1-006».

**Как воспроизвести поломку.** На DC01 (или через консоль VMware) откройте PowerShell и выполните:

```powershell
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True
New-NetFirewallRule -DisplayName 'Block ICMP from 10.10.10.52' -Direction Inbound -Protocol ICMPv4 -RemoteAddress 10.10.10.52 -Action Block
```

Это добавит правило, блокирующее ICMP именно с адреса WIN10-CL02. На стенде правило «ICMPv4 Echo Request In» разрешено, но конкретное блокирующее правило имеет приоритет над общим разрешающим — так работает Windows Firewall (block сильнее allow).

**Диагностика по шагам.**

1. На WIN10-CL02: `ping 10.10.10.10` — таймауты. `ping 10.10.10.51` — ответы есть. Значит, сеть работает, проблема в конкретном адресе.
2. На WIN10-CL02: `ipconfig` — адрес `10.10.10.52`, маска `255.255.255.0`, шлюз `10.10.10.2`. Всё в порядке.
3. На DC01: `Test-Connection 10.10.10.52` — ответы есть (исходящий ping с DC01 работает). Значит, проблема во входящем трафике на DC01.
4. На DC01: `Get-NetFirewallRule -DisplayName '*ICMP*' | Select-Object DisplayName, Enabled, Action, Direction` — видим два правила: разрешающее (общее) и блокирующее (наше). Смотрим `RemoteAddress`:

    ```powershell
    Get-NetFirewallRule -DisplayName 'Block ICMP from 10.10.10.52' | Get-NetFirewallAddressFilter
    ```

    Видим `RemoteAddress: 10.10.10.52`. Вот и причина.

**Решение.** Удалить блокирующее правило:

```powershell
Remove-NetFirewallRule -DisplayName 'Block ICMP from 10.10.10.52'
```

Проверить с WIN10-CL02: `ping 10.10.10.10` — ответы пошли.

**Ответ пользователю.** «Мария, добрый день. Проблема была в правиле брандмауэра на сервере, которое блокировало запросы именно с вашего компьютера. Правило удалено, сейчас всё работает. Проверьте, пожалуйста, и напишите, если что-то ещё не так.»

**Закрытие заявки.** Категория: «Сеть / Брандмауэр». Решение: «Удалено ошибочное блокирующее правило ICMP на DC01». Время: 15 минут. Запись в `stand-log.md`: «DC01: удалено правило Block ICMP from 10.10.10.52».

## 6. Ошибки новичков и безопасность

1. **Ошибка:** оставить сеть в режиме DHCP и удивиться, что адрес «плавает».
   **К чему приводит:** сервер получает адрес от VMware (если бы DHCP был включён) или остаётся без адреса; DNS и другие службы ломаются.
   **Как правильно:** всегда статический IP для серверов, проверка через `ipconfig /all`.

2. **Ошибка:** назвать сервер `SRV-1`, `SERVER`, `TEST`.
   **К чему приводит:** через месяц никто не помнит, что это за машина; в документации путаница.
   **Как правильно:** осмысленные имена по схеме компании (`DC01`, `FS01`, `WEB01`).

3. **Ошибка:** выбрать Server Core «потому что быстрее», а потом искать, где «Мой компьютер».
   **К чему приводит:** новичок не может выполнить даже простые задачи, тратит часы.
   **Как правильно:** для учебного стенда и L1 — Desktop Experience; Core — осознанный выбор админа.

4. **Ошибка:** не проверить SHA256 ISO.
   **К чему приводит:** установка падает на середине, ошибки «Windows cannot read the product key» или повреждённые файлы.
   **Как правильно:** `Get-FileHash` и сверка с сайтом Microsoft.

5. **Ошибка:** сделать снапшот «потом», после настройки.
   **К чему приводит:** если что-то сломается, откатываться некуда.
   **Как правильно:** снапшот сразу после чистой установки и первичной настройки, до установки ролей.

6. **Ошибка:** забыть пароль администратора.
   **К чему приводит:** переустановка ВМ с нуля.
   **Как правильно:** записать пароль в `stand-log.md` (на стенде это допустимо; в реальной среде — в защищённом хранилище).

7. **Ошибка:** отключить брандмауэр «чтобы пинговалось».
   **К чему приводит:** сервер открыт для всех, в реальной среде — инцидент ИБ.
   **Как правильно:** разрешить конкретное правило (ICMP), а не отключать профиль.

### Безопасность

- **Пароль `Lab#2026-vektor` — только для стенда.** В реальной среде такой пароль (общий на все машины, лежит в открытом файле) — грубейшее нарушение. На работе пароли уникальные, хранятся в менеджере паролей (KeePass, Bitwarden, встроенный в компанию), меняются по политике.
- **Не отключайте брандмауэр «для проверки».** В рабочей среде это инцидент. Правильное действие — добавить узкое правило.
- **Не используйте пиратские ISO и «активаторы».** Только evaluation, официальные образы, легальные лицензии. Пиратская сборка может содержать бэкдор.
- **Не оставляйте RDP открытым в интернет.** На стенде RDP доступен только внутри VMnet8 — это нормально. В реальной среде RDP за VPN или через шлюз.

## 7. Вопросы на собеседовании

**Вопрос 1. «Как вы поставите Windows Server с нуля?»**

Ответ: «Скачиваю официальный evaluation-ISO с сайта Microsoft, проверяю SHA256. Создаю ВМ в гипервизоре: 2 CPU, 4 ГБ RAM, 60 ГБ диск, сеть — во внутреннюю подсеть. Ставлю Desktop Experience, задаю пароль администратора. После установки переименовываю компьютер по схеме компании, задаю статический IP, маску, шлюз, DNS. Проверяю `ipconfig /all` и `ping` до соседних машин. Делаю снапшот и записываю в журнал.»

*Что хочет услышать интервьюер:* что вы знаете порядок действий и не забудете про статический IP и снапшот.
*Красный флаг:* «ставлю пиратскую сборку», «IP получаю по DHCP», «снапшот не делаю».

**Вопрос 2. «Почему серверу нужен статический IP, а клиенту — можно DHCP?»**

Ответ: «Сервер предоставляет службы (DNS, DHCP, файлы, печать). Если его адрес поменяется, клиенты потеряют к нему доступ. DHCP удобен для клиентов, потому что их много и они меняются. Сервер — точка опоры, его адрес должен быть предсказуем.»

*Что хочет услышать:* понимание разницы между сервером и клиентом.
*Красный флаг:* «всем DHCP», «не знаю».

**Вопрос 3. «Пользователь не пингует сервер, а с другой машины пингуется. Что проверите?»**

Ответ: «Сначала `ipconfig` на клиенте — адрес, маска, шлюз. Потом `ping` до шлюза и до другого адреса — работает ли сеть вообще. Потом на сервере `Get-NetFirewallRule` — нет ли блокирующего правила для этого адреса. Потом `Test-Connection` с сервера до клиента — работает ли обратное направление. Так локализую проблему: клиент, сеть или сервер.»

*Что хочет услышать:* системный подход, а не «перезагрузите».
*Красный флаг:* «отключу брандмауэр».

**Вопрос 4. «Зачем снапшот и когда его делать?»**

Ответ: «Снапшот — это точка возврата. Делаю после чистой установки и первичной настройки, до установки ролей и сложных изменений. Если что-то сломается — откатываюсь за минуту, а не переустанавливаю. В реальной среде снапшоты на боевых серверах делают осторожно: они не заменяют резервное копирование.»

*Что хочет услышать:* понимание, что снапшот ≠ бэкап.
*Красный флаг:* «снапшот — это и есть бэкап».

**Вопрос 5. «Что такое evaluation-версия Windows Server?»**

Ответ: «Бесплатная версия для оценки, работает 180 дней, потом требует активации. Полнофункциональная, но с ограничениями по лицензии. Для учебного стенда и тестов — идеально. Для продакшена нужна купленная лицензия.»

*Что хочет услышать:* что вы не путаете evaluation с пираткой.
*Красный флаг:* «нашёл ключ в интернете».
