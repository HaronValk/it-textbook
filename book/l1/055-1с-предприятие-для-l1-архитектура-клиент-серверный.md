## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

1С:Предприятие — это **платформа** (движок) + **конфигурация** (прикладное решение: «Бухгалтерия», «Зарплата и управление персоналом», «Управление торговлей», «Документооборот» и т.д.). Платформа одна, конфигураций много. Пользователь работает в конфигурации, но «падает» чаще всего платформа или связка «клиент ↔ сервер».

### Два режима работы

**Файловый режим.** Вся база — это один файл `1Cv8.1CD` (плюс служебные `*.lgd`, `*.lgf`, `*.cdn` и папка `*.cfl`). Лежит на диске или в сетевой папке. Клиент открывает файл напрямую. Подходит для 1–5 пользователей. Просто, дёшево, но: нет нормальной блокировки при параллельной работе, нет резервного копирования «на лету», при обрыве сети файл можно повредить.

**Клиент-серверный режим.** Есть три звена:

```
[Тонкий/толстый клиент]  --tcp/1540-1541-->  [Сервер 1С:Предприятия (rphost)]  --tcp/1433-->  [СУБД: MS SQL / PostgreSQL]
        WIN11-CL01                              SRV1C01 (в будущем)                          SRV1C01
```

- **Клиент** (тонкий `1cv8c.exe`, толстый `1cv8.exe`, веб-клиент в браузере) — то, что видит пользователь.
- **Сервер 1С** (служба `1C:Enterprise 8.3 Server`, процесс `rphost.exe`, менеджер `rmngr.exe`, агент `ragent.exe`) — держит соединения, кэш, блокировки, фоновые задания.
- **СУБД** — где реально лежат данные. Чаще всего MS SQL Server или PostgreSQL.

Клиент **никогда** не ходит в СУБД напрямую — только через сервер 1С. Это ключевой факт для диагностики: если «висит соединение с сервером», проблема между клиентом и сервером 1С, а не в базе.

### Порты и протоколы

| Что | Порт | Протокол |
|-----|------|----------|
| Клиент → сервер 1С (основной) | 1540 | TCP |
| Клиент → сервер 1С (диапазон) | 1541, 1560–1591 | TCP |
| Сервер 1С → MS SQL | 1433 | TCP |
| Сервер 1С → PostgreSQL | 5432 | TCP |
| Веб-клиент | 80/443 | HTTP/HTTPS |
| Кластер (менеджер ↔ рабочие процессы) | 1540, 1541 | TCP |

Точные диапазоны зависят от версии платформы — при настройке брандмауэра всегда сверяйся с документацией `[ПРОВЕРИТЬ]`.

### Строка соединения

Когда пользователь запускает ярлык 1С, клиент читает **строку соединения** — она хранится в файле `%APPDATA%\1C\1CEStart\ibases.v8i` (общий список баз) или в самом ярлыке. Формат:

```
File="C:\Bases\Buh";
Srvr="srv1c01.corp.vektor.lab";
Ref="buh_prod";
```

- `File=` — файловый режим, путь к папке с базой.
- `Srvr=` — адрес сервера 1С (имя или IP).
- `Ref=` — имя информационной базы на сервере (регистр важен!).
- `Usr=` — имя пользователя 1С (не путать с доменной учёткой).

Если в строке соединения опечатка в `Srvr` или `Ref` — пользователь получает «Не найден сервер» или «База не найдена», хотя сеть и сервер в порядке.

### Где что лежит на клиенте

- `%APPDATA%\1C\1CEStart\ibases.v8i` — список баз.
- `%LOCALAPPDATA%\1C\1Cv8\` — кэш клиента (можно чистить при «глюках» интерфейса).
- `%PROGRAMFILES%\1cv8\` — установленная платформа (может быть несколько версий).
- `%PROGRAMFILES%\1cv8\conf\` — конфигурация (шаблоны).

### Что типично ломается (и где искать)

```
Симптом                          | Где искать
---------------------------------|------------------------------------------
"Не найден файл базы"            | путь в File=, права на папку, диск
"Соединение с сервером"          | сеть, порт 1540, служба сервера 1С
"Недостаточно прав"              | роли пользователя в 1С, не Windows
"База занята другим сеансом"     | файловый режим, .1CD открыт другим
"Ошибка СУБД"                    | сервер 1С ↔ SQL/PostgreSQL
Медленно / зависает              | кэш клиента, сеть, нагрузка на сервер
```

## 3. Аналогия из жизни

1С — это как офисное здание с проходной. **Клиент** — это ты, сотрудник, который пришёл на работу. **Строка соединения** — это адрес здания и номер кабинета в пропуске. **Сервер 1С** — это проходная с охраной: она проверяет пропуск, ведёт журнал, решает, кого пустить. **СУБД** — это архив в подвале, куда ходит только охрана, а не ты лично. Если ты стоишь у проходной и говоришь «не пускают» — проблема либо в пропуске (строка соединения), либо в охране (служба сервера), либо в дороге до здания (сеть). Аналогия перестаёт работать, когда мы вспоминаем про **файловый режим**: там нет проходной, ты сам заходишь в архив и берёшь папку с полки — и если двое одновременно схватят одну папку, оба порвут документы.

## 4. Практика и команды

### 4.1. Посмотреть установленные версии платформы 1С

```powershell
Get-ChildItem 'C:\Program Files\1cv8' -Directory | Select-Object Name
```

Смотрим список папок вида `8.3.24.1548`, `8.3.25.1257`. Если версий несколько — это нормально, у каждой базы своя. Что смотреть: **какая версия нужна базе** (спроси у сопровождающего или посмотри в `ibases.v8i`).

### 4.2. Открыть список баз пользователя

```powershell
Get-Content "$env:APPDATA\1C\1CEStart\ibases.v8i"
```

Вывод примерно такой:

```text
[Бухгалтерия Вектор]
Connect=File="C:\Bases\Buh";
```

Что смотреть: путь в `File=` или `Srvr=`/`Ref=`. Если путь указывает на сетевую папку — проверь доступность (см. 4.4).

### 4.3. Проверить, что служба сервера 1С запущена (на будущем SRV1C01)

```powershell
Get-Service -Name '1C:Enterprise 8.3 Server Agent*'
```

Имя службы зависит от версии — ищи по маске `1C*`. Статус должен быть `Running`. Если `Stopped` — сервер 1С не работает, все пользователи получат «Соединение с сервером». На нашем стенде этой службы пока нет (сервера нет), но команду запомни — она пригодится в L2.

### 4.4. Проверить доступность сервера 1С по порту

```powershell
Test-NetConnection -ComputerName 10.10.10.25 -Port 1540
```

`10.10.10.25` — это будущий SRV1C01. На стенде сейчас его нет, поэтому `TcpTestSucceeded` будет `False` — это нормально, мы проверяем саму команду. В рабочей среде `True` = порт открыт, `False` = либо сервер лежит, либо брандмауэр, либо неверный адрес.

### 4.5. Проверить доступность сетевой папки с базой (файловый режим)

```powershell
Test-Path '\\FS01\Buh\1C'
```

`FS01` у нас уже есть (появился в L1 №46). Если база лежит в `\\FS01\Buh\1C` — `Test-Path` вернёт `True`/`False`. `False` = либо нет прав, либо папка переехала, либо FS01 недоступен. Проверь `ping 10.10.10.20` и `net use`.

### 4.6. Посмотреть, кто держит файл базы (файловый режим)

```powershell
Get-SmbOpenFile | Where-Object Path -like '*1Cv8.1CD*'
```

Показывает, какие пользователи открыли файл базы по SMB. Если видишь «зависший» сеанс — можно попросить пользователя закрыть 1С, а в крайнем случае закрыть сеанс через `Close-SmbOpenFile` (осторожно, только с согласия пользователя и с записью в заявку).

### 4.7. Очистить кэш клиента 1С

```powershell
Remove-Item "$env:LOCALAPPDATA\1C\1Cv8\*" -Recurse -Force
```

Делать **только при закрытой 1С**. Лечит «глюки интерфейса», «не открывается форма», «пропали кнопки». Не лечит «не найден файл базы» и «соединение с сервером».

### 4.8. Посмотреть журнал регистрации 1С (файловый режим)

В самой 1С: меню **Администрирование → Журнал регистрации**. Или файл `1Cv8.lgd` рядом с базой. Что смотреть: время, пользователь, событие (`_$Session$_.Start`, `_$Session$_.Finish`, ошибки). На L1 достаточно открыть и глазами найти последнюю ошибку по времени заявки.

### 4.9. Проверить, что клиент видит сервер по имени (DNS)

```powershell
Resolve-DnsName srv1c01.corp.vektor.lab
```

Если не резолвится — клиент не найдёт сервер, даже если сеть работает. На стенде зона `corp.vektor.lab` есть с L1 №34, но записи `srv1c01` пока нет — она появится вместе с сервером.

### 4.10. Посмотреть, какие процессы 1С запущены у пользователя

```powershell
Get-Process -Name '1cv8*' -ErrorAction SilentlyContinue | Select-Object Name, Id, StartTime
```

Помогает понять: клиент вообще запустился или упал на старте. Если процесса нет — проблема до запуска (ярлык, права, антивирус).

### Сломай и почини

**Заявка:**

> **Пользователь:** Иванов, бухгалтерия (WIN11-CL01)
> **Что написал:** «1С не открывается, пишет "Не найден файл базы данных". Вчера всё работало.»
> **Срочность:** Высокая.

**Как воспроизвести поломку.** На FS01 переименуй папку базы:

```powershell
Rename-Item -Path '\\FS01\Buh\1C\BuhDemo' -NewName 'BuhDemo_old'
```

Теперь путь в `ibases.v8i` указывает на несуществующую папку — ровно то, что видит пользователь.

**Диагностика по шагам.**

1. Спроси пользователя: что именно написано? С какого момента? Что менялось (обновление, переезд, отпуск)?
2. На WIN11-CL01 под `ivanov`:
    ```powershell
    Get-Content "$env:APPDATA\1C\1CEStart\ibases.v8i"
    ```
    Смотрим путь: `\\FS01\Buh\1C\BuhDemo`.
3. Проверяем доступность:
    ```powershell
    Test-Path '\\FS01\Buh\1C\BuhDemo'
    ```
    Ожидаемо: `False`.
4. Проверяем, что FS01 вообще доступен:
    ```powershell
    Test-Path '\\FS01\Buh'
    ```
    Ожидаемо: `True`. Значит, сеть и права в порядке, проблема в конкретной папке.
5. Смотрим содержимое:
    ```powershell
    Get-ChildItem '\\FS01\Buh\1C'
    ```
    Видим `BuhDemo_old` — папку переименовали.

**Решение.** Вернуть имя обратно:

```powershell
Rename-Item -Path '\\FS01\Buh\1C\BuhDemo_old' -NewName 'BuhDemo'
```

Проверить `Test-Path '\\FS01\Buh\1C\BuhDemo'` → `True`. Попросить пользователя перезапустить 1С.

**Ответ пользователю:** «Иван, разобрались: папка базы на файловом сервере была переименована (видимо, при обслуживании). Вернули имя, база снова открывается. Проверьте, пожалуйста, что ваши документы на месте, и напишите, если что-то не так.»

**Закрытие заявки.** Категория: «1С / файловая база / путь». Решение: восстановлено имя папки. Профилактика: договориться с тем, кто обслуживает FS01, что переименование папок с базами 1С — только через заявку и с уведомлением.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** лезть в файл `1Cv8.1CD` «посмотреть, что внутри» (архиватором, редактором).
   **К чему приводит:** повреждение базы, потеря данных за день.
   **Как правильно:** файл базы не открывать ничем, кроме 1С. Резервные копии — только через выгрузку `*.dt` или штатное резервное копирование.

2. **Ошибка:** чистить кэш `%LOCALAPPDATA%\1C\1Cv8\` при работающей 1С.
   **К чему приводит:** «битый» профиль клиента, ошибки при следующем запуске.
   **Как правильно:** сначала закрыть 1С, потом чистить.

3. **Ошибка:** «перезапустить сервер 1С» без согласования.
   **К чему приводит:** обрыв всех сеансов, потеря несохранённых документов у всех пользователей.
   **Как правильно:** перезапуск сервера 1С — только через L2/администратора 1С, в окно обслуживания, с предупреждением.

4. **Ошибка:** править `ibases.v8i` вручную «наугад».
   **К чему приводит:** пользователь теряет все базы из списка.
   **Как правильно:** сначала сохранить копию файла, потом править; лучше — через «Добавить/Изменить» в самой 1С.

5. **Ошибка:** считать, что «не открывается 1С» = «сломался сервер».
   **К чему приводит:** эскалация не туда, потеря времени.
   **Как правильно:** сначала выясни, у одного или у всех; файловый или клиент-серверный режим; что именно в ошибке.

6. **Ошибка:** давать пользователю права администратора «чтобы 1С работала».
   **К чему приводит:** дыра в безопасности, 1С всё равно не заработает, если проблема в базе.
   **Как правильно:** 1С работает под обычным пользователем; права администратора нужны только для установки/обновления платформы.

7. **Ошибка:** устанавливать платформу 1С «какую нашёл» без учёта версии базы.
   **К чему приводит:** база не открывается («несовместимая версия»), приходится переустанавливать.
   **Как правильно:** версия платформы должна совпадать с той, что указана в требованиях к базе (спроси у сопровождающего 1С).

8. **Ошибка:** хранить файловую базу 1С на сетевой папке для 10+ пользователей.
   **К чему приводит:** повреждение базы при параллельной записи.
   **Как правильно:** больше 5 пользователей — только клиент-серверный режим.

### Безопасность

- **Не запускай 1С от имени администратора** без необходимости — это маскирует проблемы с правами и создаёт риск.
- **Не отключай антивирус** «чтобы 1С быстрее работала» — в рабочей среде это нарушение политики ИБ; если антивирус мешает, добавь папку базы в исключения через заявку в ИБ.
- **Не передавай файлы баз (`*.dt`, `1Cv8.1CD`) по почте и в мессенджерах** — там персональные данные сотрудников (152-ФЗ, подробнее в уроке 67).
- **Пароли 1С** — не те же, что доменные; на стенде у нас учебный `Lab#2026-vektor`, в бою так нельзя.
- **Учётка `adm.student`** — только для установки и настройки; повседневная работа пользователя — под `ivanov`.

## 7. Вопросы на собеседовании

**Вопрос 1. Чем отличается файловый режим 1С от клиент-серверного?**
*Как спросят:* «У нас 1С в файловом режиме, пользователей 15, всё тормозит — что скажете?»
*Ответ:* В файловом режиме вся база — один файл `1Cv8.1CD`, клиент открывает его напрямую, нет нормальной блокировки при параллельной работе. Для 1–5 пользователей это ок, для 15 — нет: будут конфликты, повреждения, медленно. Клиент-серверный режим — это три звена: клиент, сервер 1С (служба, порт 1540) и СУБД (MS SQL или PostgreSQL). Клиент ходит только на сервер 1С, сервер — в СУБД. Для 15 пользователей нужен клиент-серверный, это задача администратора 1С и L2, а на L1 — зафиксировать факт и эскалировать.
*Что хочет услышать интервьюер:* что ты понимаешь разницу и не полезешь «оптимизировать» файловую базу сам.
*Красный флаг:* «Файловый режим всегда лучше, потому что проще».

**Вопрос 2. Пользователь пишет «1С не открывается, не найден файл базы». Твои действия?**
*Как спросят:* «Вот заявка, что делаешь по шагам?»
*Ответ:* Сначала уточняю: у одного или у всех, что именно в ошибке, что менялось. Потом на машине пользователя смотрю строку соединения в `%APPDATA%\1C\1CEStart\ibases.v8i` — путь в `File=` или `Srvr=`/`Ref=`. Проверяю `Test-Path` для файлового режима или `Test-NetConnection -Port 1540` для клиент-серверного. Если путь битый — ищу, куда переехала папка, или восстанавливаю имя. Если сеть — проверяю доступность сервера/FS01. Если всё в порядке, а ошибка остаётся — смотрю журнал регистрации 1С и эскалирую на L2/администратора 1С с собранной информацией.
*Что хочет услышать интервьюер:* чёткий алгоритм, а не «перезагрузите».
*Красный флаг:* «Сразу переустанавливаю 1С».

**Вопрос 3. Какие порты использует 1С и зачем их знать L1?**
*Как спросят:* «Если пользователь не подключается к серверу 1С, что проверишь?»
*Ответ:* Клиент ходит на сервер 1С по TCP 1540 (и диапазон 1541, 1560–1591 — точный набор зависит от версии `[ПРОВЕРИТЬ]`). Сервер 1С ходит в СУБД: MS SQL — 1433, PostgreSQL — 5432. Веб-клиент — 80/443. L1 это нужно, чтобы быстро проверить `Test-NetConnection` на 1540 и отличить «сервер лежит / брандмауэр» от «неверная строка соединения». Если порт закрыт — эскалировать сетевому администратору или администратору 1С.
*Что хочет услышать интервьюер:* что ты знаешь про 1540 и не путаешь клиент 1С с СУБД.
*Красный флаг:* «1С работает по 3389» (это RDP, не 1С).

**Вопрос 4. Можно ли чистить кэш 1С и когда это помогает?**
*Как спросят:* «Пользователь жалуется, что 1С "глючит", кнопки пропали — что сделаешь?»
*Ответ:* Кэш клиента лежит в `%LOCALAPPDATA%\1C\1Cv8\`. Чистить можно, но только при закрытой 1С. Помогает при «глюках» интерфейса, пропавших формах, странном поведении кнопок. Не помогает при «не найден файл базы» или «соединение с сервером» — там другие причины. Перед чисткой предупреждаю пользователя, что первый запуск будет дольше.
*Что хочет услышать интервьюер:* что ты понимаешь границы применимости и не чистишь кэш «на всякий случай».
*Красный флаг:* «Удаляю всю папку 1C в AppData» (там же `ibases.v8i` — потеряешь список баз).

**Вопрос 5. Что нельзя делать с базой 1С на L1?**
*Как спросят:* «Какие действия с 1С ты себе не позволяешь?»
*Ответ:* Не открываю `1Cv8.1CD` ничем, кроме 1С. Не перезапускаю службу сервера 1С без согласования. Не правлю `ibases.v8i` без резервной копии. Не даю пользователю права администратора «чтобы заработало». Не передаю файлы баз по почте и мессенджерам. Не устанавливаю платформу версии, отличной от требуемой базой. Всё, что касается данных и сервера, — через L2/администратора 1С.
*Что хочет услышать интервьюер:* что ты знаешь границы своей ответственности и не навредишь.
*Красный флаг:* «Я сам всё могу, мне лишь бы доступ дали».
