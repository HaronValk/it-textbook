## 2. Теория «под капотом»

### Зачем вообще модель
Сеть — это стек из задач, которые решаются независимо. Модель OSI (**Open Systems Interconnection**, эталонная модель взаимодействия открытых систем) — это способ договориться, кто за что отвечает. Раньше каждый вендор делал свою сеть (IBM — свою, DEC — свою) и совместимости не было. OSI разложила передачу данных на семь уровней — и появилось общее понимание, где именно «сломалось».

Практически весь реальный интернет и корпоративные сети работают не по OSI, а по модели **TCP/IP** (4–5 уровней). Но в работе и на собеседованиях говорят на языке OSI: «это проблема второго уровня», «у нас L3 недоступен», «на седьмом уровне отваливается». Сопоставление:

```text
   OSI (7 уровней)                          TCP/IP (4 уровня)
   ─────────────────                        ─────────────────
7  Application   (HTTP, DNS, SMB, RDP)  ┐
6  Presentation  (TLS, кодировки)       ├─► Application
5  Session       (сессии)               ┘
4  Transport     (TCP, UDP, порты)      ──► Transport
3  Network       (IP, ICMP, ARP*)       ──► Internet
2  Data Link     (Ethernet, MAC, ARP*)  ┐
1  Physical      (кабель, Wi-Fi, PoE)   ┘──► Network Access (Link)
```

`*` ARP формально живёт между L2 и L3. На практике его относят к L2.

### Инкапсуляция
Когда ты открываешь `http://10.10.10.30:8080/`, данные опускаются по стеку, каждый уровень добавляет свой «заголовок»:

```text
[HTTP-запрос]                                              ← L7
   └─[TCP-сегмент: порт 8080 → 34512, флаги]
         └─[IP-пакет: 10.10.10.x → 10.10.10.30]
               └─[Ethernet-кадр: MAC WIN11-CL01 → MAC UBU01]
                     └─[биты в кабеле / Wi-Fi]              ← L1
```

На приёмной стороне каждый уровень снимает свой заголовок и передаёт выше следующему. Это и есть инкапсуляция (и декапсуляция). Wireshark показывает все эти слои одновременно в окне «детали пакета» — потому он и незаменим.

### Что важно для L1
Тебе не нужно учить наизусть номера уровней и все протоколы. Нужны «рабочие» знания:

| Уровень (OSI) | Что проверяем | Инструменты |
|---------------|---------------|-------------|
| 1 Физический | Кабель, линк, порт, Wi-Fi | глаза, `ip link`, индикатор на коммутаторе |
| 2 Канал | MAC, ARP, VLAN | `arp -a`, `getmac /v`, Wireshark (`arp`) |
| 3 Сеть | IP-адрес, шлюз, маршрут | `ipconfig`, `ip route`, `ping`, `tracert` |
| 4 Транспорт | Порты TCP/UDP, соединение | `netstat -an`, `ss -tulpn`, `Test-NetConnection` |
| 5–7 Прикладной | Приложение, DNS, HTTP, SMB | `nslookup`, сам клиент, Wireshark (`http`, `dns`) |

Некоторые протоколы и порты, которые встречаются ежедневно:

| Протокол | Порт | Уровень | Что это |
|----------|------|---------|---------|
| SSH | 22 TCP | 7 | удалённый доступ к Linux |
| DNS | 53 UDP/TCP | 7 | имена → IP |
| HTTP | 80 TCP | 7 | веб без шифрования |
| HTTPS | 443 TCP | 7 | веб с TLS |
| SMB | 445 TCP | 7 | общие папки Windows |
| RDP | 3389 TCP | 7 | удалённый рабочий стол |
| ICMP | — | 3 | ping, tracert |
| ARP | — | 2 | MAC ↔ IP в локальной сети |

### Что Wireshark может и не может
Wireshark — **анализатор трафика**, бесплатный и с открытым исходным кодом, легальная лицензия GPL. Он перехватывает пакеты с сетевой карты и показывает их «в разрезе». Что важно понимать:
- На коммутаторе он видит в основном **свой** трафик + broadcast/multicast. Чтобы видеть чужой, нужен SPAN-порт (зеркалирование) — это уже L2-админская задача.
- HTTPS он **не расшифрует** без ключей, — увидит только TCP-хендшейк и шифротекст.
- Wireshark — не «хакерский» инструмент, но использовать его на чужой сети без разрешения нельзя (см. раздел «Безопасность»).

## 3. Аналогия из жизни

Представь, что ты отправляешь посылку через Почту России. Внутри — вещь, которую нужно доставить (**данные, L7**). Ты кладёшь её в коробку и подписываешь — «это кроссовки, хрупкое» (**заголовок приложения**). Затем на коробку клеишь адресный лист: «Москва, ул. Тверская, 1, кв. 5, Петрову И.И.» (**IP-адрес, L3**). Служба доставки оборачивает всё это в мешок и маркирует «сортировочный центр №3 → машина 12» (**MAC-адрес, L2**). И наконец, машина физически едет по дорогам (**кабель/Wi-Fi, L1**).

Если посылка не пришла, — надо искать на каком этапе. Курьер не забрал (L1)? Мешок уехал не туда (L2)? Адрес написан неверно (L3)? Или получатель не открыл дверь (L7)? Методика одна и та же: **проверяем по шагам**, а не кричим «посылка сломана».

Где аналогия перестаёт работать: на почте ты видишь один мешок и один адрес, а по сети одновременно летят миллионы пакетов, которые могут перепутаться, потеряться и прийти не по порядку — TCP это исправляет, почта в реальности так не умеет.

## 4. Практика и команды

Дальше — рабочий минимум, который ты будешь использовать почти в каждой сетевой заявке. Windows — в PowerShell или CMD (команды идентичны), Linux — в bash на UBU01.

**1. `ipconfig /all` (Windows)** — все сетевые параметры интерфейса. Уровень 3.
```powershell
ipconfig /all
```
Смотрим: `IPv4 Address` (твой адрес), `Default Gateway` (шлюз), `DNS Servers`. Если здесь пусто или `169.254.x.x` — L3 не работает (DHCP не ответил или кабель).

**2. `ip a` (Linux)** — то же самое, что `ipconfig`, но в Linux.
```bash
ip a
```
Смотрим `inet 10.10.10.30/24` — это адрес, `state UP` — линк поднят (L1).

**3. `getmac /v` (Windows) / `ip link` (Linux)** — MAC-адреса. Уровень 2.
```powershell
getmac /v
```
```bash
ip link show
```
MAC (например `00:0c:29:aa:bb:cc`) нужен, чтобы понять, на каком коммутаторе искать устройство.

**4. `arp -a` (Windows) / `ip neigh` (Linux)** — ARP-кэш: кто из соседей по подсети какой MAC имеет. Уровень 2/3.
```powershell
arp -a
```
```bash
ip neigh
```
Типичный вывод:
```text
  10.10.10.10          00-0c-29-aa-11-22     dynamic
  10.10.10.30          00-0c-29-bb-33-44     dynamic
```
Если адрес нужного хоста есть — L2 работает. Если нет — либо ARP не прошёл, либо хост выключен.

**5. `ping`** — самый быстрый тест L3 (ICMP).
```powershell
ping 10.10.10.10
```
```bash
ping -c 4 10.10.10.10
```
Ожидаемый вывод (сокращённо): `Ответ от 10.10.10.10: число байт=32 время<1мс TTL=128`. Если `Превышен интервал ожидания для запроса` — L3 не работает (или ICMP зарезан файрволом).

**6. `tracert` (Windows) / `traceroute` или `mtr` (Linux)** — маршрут до цели, где обрывается.
```powershell
tracert 10.10.10.10
```
```bash
mtr -rw 10.10.10.30
```
Каждая строка — узел. Если до второго узла доходит, а до третьего нет — проблема за этим узлом.

**7. `route print` (Windows) / `ip route` (Linux)** — таблица маршрутов. Уровень 3.
```powershell
route print
```
```bash
ip route
```
Смотрим строку `0.0.0.0/0 via 10.10.10.2` — это маршрут по умолчанию (всё «наружу» через шлюз). Нет строки — «интернета» не будет даже при живом пинге.

**8. `netstat -an` (Windows) / `ss -tulpn` (Linux)** — открытые порты и активные соединения. Уровень 4.
```powershell
netstat -an | findstr :445
```
```bash
sudo ss -tulpn
```
Ищем, слушает ли нужный сервис ожидаемый порт (`LISTEN`) и куда идут соединения (`ESTABLISHED`).

**9. `Test-NetConnection` (PowerShell)** — проверка конкретного порта. Очень частая задача.
```powershell
Test-NetConnection -ComputerName 10.10.10.30 -Port 22
```
Смотрим `TcpTestSucceeded : True`. Если `False` — порт недоступен (сервис не запущен или файрвол блокирует).

**10. `nslookup`** — L7, DNS.
```powershell
nslookup dc01.corp.vektor.lab
```
Смотрим, на какой DNS ушёл запрос и что вернулось. Пустой `Non-existent domain` — запись не резолвится.

**11. Фильтры Wireshark** — их «язык». Это не команды ОС, но ими пользуешься постоянно:

```text
ip.addr == 10.10.10.10        — любой пакет с этим IP (в обе стороны)
icmp                          — только ping/tracert
arp                           — только ARP
dns                           — только DNS
tcp.port == 8080              — TCP с портом 8080
tcp.flags.syn == 1 && tcp.flags.ack == 0   — только SYN (начало соединения)
http.request                  — только HTTP-запросы
```

**12. `tshark` (Linux)** — консольный Wireshark, удобен на серверах без GUI.
```bash
sudo apt install tshark
sudo tshark -i any -f "port 8080" -c 20
```
`-i any` — все интерфейсы, `-f "port 8080"` — фильтр захвата (BPF), `-c 20` — остановиться после 20 пакетов.

### Шаги

1. **WIN11-CL01.** Скачай Wireshark с официального сайта wireshark.org (бесплатно). При установке оставь галочку **Install Npcap** — без него захват не пойдёт. После установки перезагрузка не требуется.
   *Ожидаемо:* ярлык Wireshark на рабочем столе, при запуске видишь список интерфейсов (`Ethernet0`, `Loopback` и т.п.).

2. **WIN11-CL01.** Узнай свой IP:
   ```powershell
   ipconfig
   ```
   *Ожидаемо:* `IPv4 Address : 10.10.10.xxx` (например 10.10.10.101), `Default Gateway : 10.10.10.10` — если DC01 уже раздаёт адреса. Запиши адрес — он понадобится при фильтрации.

3. **WIN11-CL01.** Запусти Wireshark, выбери свой основной интерфейс (Ethernet0), нажми **Start** (синяя акула). Идёт захват.

4. **WIN11-CL01.** В отдельном окне выполни:
   ```powershell
   arp -d *
   ping 10.10.10.10
   ```
   `arp -d *` чистит ARP-кэш, чтобы Wireshark поймал свежий ARP-обмен (если команда не сработает — нужны права администратора; тогда пропусти очистку или запусти PowerShell от админа).
   *Ожидаемо:* `ping` выдаёт 4 ответа, в Wireshark летят пакеты.

5. **WIN11-CL01.** Останови захват (красный квадрат). В строке фильтра введи `arp`. Увидишь два кадра: `Who has 10.10.10.10? Tell 10.10.10.xxx` (запрос) и `10.10.10.10 is at 00:0c:29:xx:xx:xx` (ответ).
   *Что смотреть:* это **L2** — до того, как пинг уйдёт, машина должна узнать MAC шлюза/цели.

6. **WIN11-CL01.** Смени фильтр на `icmp`. Увидишь 8 пакетов: 4 `Echo (ping) request` и 4 `Echo (ping) reply`. Разверни любой — в окне деталей видны Ethernet → IP → ICMP (три вложенных уровня — та самая инкапсуляция).
   *Ожидаемо:* `TTL: 128` в ответе (у Windows), размер пакета ~74 байта.

7. **UBU01.** Подними тестовый HTTP-сервер:
   ```bash
   cd /tmp && echo "vektor lab" > index.html
   python3 -m http.server 8080
   ```
   *Ожидаемо:* `Serving HTTP on 0.0.0.0 port 8080`. Оставь SSH-сессию открытой.

8. **WIN11-CL01.** Начни новый захват Wireshark. Затем в браузере открой `http://10.10.10.30:8080/` (по IP, не по имени — мы не хотим сейчас зависеть от DNS).
   *Ожидаемо:* страница с текстом `vektor lab`. Останови захват.

9. **WIN11-CL01.** Фильтр: `tcp.port == 8080`. Найди три первых пакета — **трёхстороннее рукопожатие TCP** (3-way handshake):
   ```text
   SYN       →  (клиент говорит: хочу соединиться)
   SYN, ACK  ←  (сервер: согласен)
   ACK       →  (клиент: ок, начинаем)
   ```
   Отфильтруй только начала соединений: `tcp.flags.syn == 1 && tcp.flags.ack == 0`. Именно этот пакет ты будешь искать, когда «порт не отвечает».
   Затем отфильтруй `http` — увидишь текстом `GET / HTTP/1.1` и ответ `HTTP/1.0 200 OK`. Это **L7**.

10. **WIN11-CL01.** Сохрани дамп: **File → Save As** → `C:\Lab\osi-l1-031.pcapng`. Запиши в `stand-log.md`, где он лежит.

### Сломай и почини

> **Пользователь:** Иванов Иван (бухгалтерия), ВМ WIN11-CL01  
> **Что написал:** «Иван, открываю `http://10.10.10.30:8080/` — страница крутится и не открывается. Вчера всё работало. Срочно, у меня платёжка.»  
> **Срочность:** Высокая (финансовая).

**Как воспроизвести поломку:** на UBU01 останови сервер — `Ctrl+C` в окне с `python3 -m http.server`.

**Диагностика по шагам (снизу вверх — надёжнее):**

1. `ping 10.10.10.30` с WIN11-CL01. **Отвечает** → L1/L2/L3 в порядке. Проблема выше.
2. `Test-NetConnection -ComputerName 10.10.10.30 -Port 8080`. Результат `TcpTestSucceeded : False` → **L4**: порт закрыт. При этом `ping 10.10.10.30` работает — значит машина жива, но конкретный сервис не слушает.
3. Проверь захват Wireshark в момент попытки: видно `SYN` от клиента, ответа `SYN, ACK` нет (или приходит `RST`). Это чёткая картина «порт закрыт».
4. На UBU01 проверь, слушает ли кто-то порт:
   ```bash
   sudo ss -tulpn | grep 8080
   ```
   Вывод пустой → сервиса нет.
5. **Решение:** на UBU01 снова запусти `python3 -m http.server 8080` из `/tmp` (где лежит `index.html`).
6. Повтори проверку с WIN11-CL01: `Test-NetConnection … -Port 8080` → `True`, страница открывается.

> Альтернативная причина отказа, которую ты тоже теперь умеешь ловить: на UBU01 включён UFW с политикой deny — тогда `ss` показывает `LISTEN`, а порт всё равно закрыт снаружи. Лечится `sudo ufw allow 8080/tcp`. Но это уже про firewall (урок 39).

## 6. Ошибки новичков и безопасность

- **Ошибка:** «У пользователя не работает сайт — переустановим браузер».  
  **К чему приводит:** теряешь время, проблема на L3/L4 остаётся.  
  **Правильно:** сначала `ping` и `Test-NetConnection`, потом лезем в приложение.

- **Ошибка:** путать уровни и называть ping «проверкой интернета».  
  **К чему приводит:** «пинг идёт, а сайты не открываются» ставит в тупик — а это классика (DNS или шлюз).  
  **Правильно:** ping проверяет только L3 (достижимость IP), DNS нужен отдельно (урок 34).

- **Ошибка:** запускать Wireshark без фильтра и ловить весь трафик.  
  **К чему приводит:** десятки тысяч пакетов, в них ничего не найти.  
  **Правильно:** сначала фильтр захвата (BPF, `-f "port 8080"`), потом уже смотри.

- **Ошибка:** захват «вслепую» без понимания, что ищем.  
  **К чему приводит:** набирается огромный дамп, разбираться в нём дольше, чем чинить.  
  **Правильно:** сформулировал гипотезу → воспроизвёл проблему под захватом → нашёл пакет.

- **Ошибка:** считать, что Wireshark покажет пароль в HTTPS.  
  **К чему приводит:** тратишь время и делаешь неверные выводы.  
  **Правильно:** видно только TLS-хендшейк и шифротекст. Расшифровка — отдельная история с ключами.

- **Ошибка:** снимать трафик на чужом Wi-Fi или в чужой корпоративной сети «просто посмотреть».  
  **К чему приводит:** от дисциплинарки до статьи — трафик содержит персональные данные.  
  **Правильно:** только на своей ВМ, на учебном стенде или по письменному согласованию.

- **Ошибка:** «Я не знаю порт — значит, порт не важен».  
  **К чему приводит:** проверяешь не тот сервис.  
  **Правильно:** держи головой минимум: 22 SSH, 53 DNS, 80 HTTP, 443 HTTPS, 445 SMB, 3389 RDP.

### Безопасность
Wireshark перехватывает всё, что летит через интерфейс, — включая учётки, токены, персональные данные сотрудников. В боевой среде:
- не запускай захват без заявки и согласования с ИБ; фиксируй, что и зачем снимал;
- хранить дампы с ПДн — это обработка персональных данных по 152-ФЗ, со всеми требованиями (место, срок, доступ);
- не оставляй Wireshark с включённым захватом «на весь день» — это утечка;
- на учебном стенде — только учебные пароли (`Lab#2026-vektor`) и только локальная сеть.

## 7. Вопросы на собеседовании

**Вопрос 1. Что такое модель OSI и зачем она нужна? Сколько в ней уровней?**  
**Ответ:** OSI — эталонная семиуровневая модель сетевого взаимодействия: Physical, Data Link, Network, Transport, Session, Presentation, Application. Нужна, чтобы разделить зоны ответственности и договориться о совместимости оборудования. В реальности используется TCP/IP (4–5 уровней), но язык OSI удобен для диагностики: «проблема на L2», «порт закрыт на L4».  
**Что хочет услышать интервьюер:** что ты не путаешь модель с протоколом и умеешь ими пользоваться в диагностике.  
**Красный флаг:** «7 уровней: физический, канальный, сетевой, транспортный, сеансовый, представления, приложения — всё, я выучил» — без понимания, зачем.

**Вопрос 2. На каком уровне работают ping, ARP, DNS, HTTP?**  
**Ответ:** ping — ICMP, уровень 3 (сеть). ARP — между L2 и L3, на практике L2. DNS — прикладной уровень, L7 (обычно UDP/53). HTTP — прикладной L7, поверх TCP/80.  
**Что хочет услышать:** понимание, что «уровень» — это не номер для галочки, а место в стеке.  
**Красный флаг:** путает ping и HTTP, называет DNS «сетевым протоколом».

**Вопрос 3. В чём разница между TCP и UDP?**  
**Ответ:** TCP — с установлением соединения, подтверждениями, пересылкой потерянных пакетов, порядком (используется в HTTP, SSH, RDP, SMB). UDP — без соединения, без гарантий (DNS-запросы, NTP, VoIP, видео). TCP медленнее и «тяжелее», но надёжнее; UDP проще и быстрее, но приложения сами разбираются с потерями.  
**Что хочет услышать:** конкретное понимание, а не «TCP надёжный».  
**Красный флаг:** «UDP — это старый TCP».

**Вопрос 4. Что такое инкапсуляция? Приведи пример.**  
**Ответ:** это последовательное «оборачивание» данных заголовками на каждом уровне при отправке и снятие их при приёме. Пример: HTTP-запрос → TCP-сегмент с портами → IP-пакет с адресами → Ethernet-кадр с MAC → биты в кабеле. В Wireshark видно все уровни одновременно при выборе пакета.  
**Что хочет услышать:** понимание, зачем в Wireshark три окна и как читать «дерево» пакета.  
**Красный флаг:** путает инкапсуляцию с шифрованием.

**Вопрос 5. Пользователь говорит «сайт не открывается». Ping до сервера идёт. Как будешь разбираться?**  
**Ответ:** пинг прошёл — значит L3 в порядке, проблема выше. Проверю `Test-NetConnection -Port 80/443` — это L4. Если порт открыт, но страница не грузится — смотрю Wireshark: 3-way handshake прошёл, значит сервер принял соединение; тогда смотрю HTTP-ответ (код ошибки) — возможно, 500 или 404. Заодно проверю DNS: если сайт открывался по имени — `nslookup`. Так последовательно закрываю уровни 3 → 4 → 7.  
**Что хочет услышать:** методичность, умение сузить круг, а не «давай переустановим браузер».  
**Красный флаг:** «Ну раз пинг идёт — значит всё работает у меня, пусть пользователь сам разбирается».
