## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

### Что такое «уровни» и зачем они нужны

Когда ты открываешь сайт, происходит примерно 20 разных вещей одновременно: браузер формирует HTTP-запрос, ОС упаковывает его в TCP-сегмент, добавляет IP-заголовок, драйвер сетевой карты превращает это в кадр Ethernet и отправляет в кабель (в нашем случае — в виртуальный коммутатор VMware). Каждый шаг — отдельный «уровень». Идея модели: **каждый уровень знает только про свой кусок и не лезет в чужие**. Браузеру не надо знать, какой у тебя MAC-адрес. Сетевой карте не надо знать, что внутри HTTP.

Модель **OSI** (Open Systems Interconnection) — эталонная, 7 уровней, придумана для обучения и описания. Модель **TCP/IP** — практическая, 4 уровня, по ней реально работает интернет. Соотношение:

```text
   OSI (7 уровней)              TCP/IP (4 уровня)         Примеры
   ─────────────────            ─────────────────         ────────────────────────
 7 Прикладной   ┐
 6 Представления├──────────►    Прикладной          ────  HTTP, HTTPS, DNS, SSH
 5 Сеансовый    ┘

 4 Транспортный ──────────►     Транспортный        ────  TCP, UDP (порты)

 3 Сетевой      ──────────►     Межсетевой (IP)     ────  IP, ICMP (адреса)

 2 Канальный    ┐
 1 Физический   ┴─────────►     Доступ к сети       ────  Ethernet, Wi-Fi, MAC
```

Запомни главное для L1: **диагностика идёт по уровням**. Снизу вверх: есть ли линк (уровень 1–2), есть ли IP и маршрут (3), открыт ли порт (4), отвечает ли приложение (7). Если «сайт не открывается», а пинг до шлюза идёт — проблема выше уровня 3.

### Что такое «пакет», «кадр», «сегмент»

Это одно и то же сообщение на разных уровнях, с разными «обёртками»:

```text
┌──────────────────────────────────────────────────────────────┐
│ Ethernet-кадр (уровень 2)                                    │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ MAC-заголовок │ IP-пакет (уровень 3)                     │ │
│ │               │ ┌──────────────────────────────────────┐ │ │
│ │               │ │ IP-заголовок │ TCP-сегмент (ур. 4)  │ │ │
│ │               │ │              │ ┌──────────────────┐ │ │ │
│ │               │ │              │ │ TCP-заголовок    │ │ │ │
│ │               │ │              │ │ + данные HTTP    │ │ │ │
│ │               │ │              │ └──────────────────┘ │ │ │
│ │               │ └──────────────────────────────────────┘ │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- **Кадр (frame)** — то, что реально летит по проводу, с MAC-адресами.
- **Пакет (packet)** — IP-уровень, с IP-адресами.
- **Сегмент (segment)** — TCP, с портами. У UDP — «датаграмма».

Wireshark показывает всё это сразу, и ты можешь раскрыть любой уровень.

### Порты и протоколы, которые надо знать наизусть

Порт — это «дверь» на компьютере, за которой сидит конкретная служба. Стандартные:

| Порт | Протокол | Что это |
|------|----------|---------|
| 53 | DNS (UDP и TCP) | превращение имени в IP |
| 80 | HTTP | веб без шифрования |
| 443 | HTTPS | веб с TLS |
| 22 | SSH | удалённый доступ к Linux |
| 3389 | RDP | удалённый рабочий стол Windows |
| 445 | SMB | общие папки Windows |
| 67/68 | DHCP | выдача IP (сервер/клиент) |

ICMP — отдельный протокол без портов, на нём работает `ping`.

### Что такое Wireshark и как он «видит» трафик

Wireshark — бесплатный анализатор трафика. Он ставит сетевой адаптер в **promiscuous mode** (режим «слушаю всё, что пролетает мимо») и записывает каждый кадр. На реальном коммутаторе ты увидишь только свой трафик и broadcast, если не настроено зеркалирование порта. На нашем стенде WIN11-CL01 в VMware — это отдельная виртуалка со своим виртуальным адаптером, и Wireshark увидит ровно то, что идёт через этот адаптер. Этого достаточно для учёбы.

Важно: **Wireshark на стенде — только для учебного трафика**. В рабочей среде запускать захват на чужом трафике без письменного разрешения — это нарушение, вплоть до увольнения (подробнее в уроке 62).

## 3. Аналогия из жизни

Представь, что ты отправляешь посылку из Москвы в Казань.

- **Уровень 7 (прикладной)** — это ты сам: написал записку «поздравляю с днём рождения», положил в конверт. Содержимое — твоё дело, почте всё равно.
- **Уровень 6–5 (представление/сеанс)** — ты выбрал язык записки и договорился, что получатель её откроет.
- **Уровень 4 (транспортный)** — почта разбила посылку на части и пронумеровала: «часть 1 из 3», «часть 2 из 3». Если одна потеряется — попросишь переслать только её (это TCP). Если тебе всё равно (UDP) — не просишь.
- **Уровень 3 (сетевой)** — на каждой коробке написан адрес: «Москва, ул. Тверская, 1 → Казань, ул. Баумана, 5». Это IP-адреса. Сортировочный центр смотрит только на адрес и решает, в какой поезд грузить.
- **Уровень 2 (канальный)** — конкретный почтальон, который несёт коробку от твоего подъезда до отделения. Он знает только «от подъезда до отделения», а не весь маршрут. Это MAC-адреса.
- **Уровень 1 (физический)** — сам грузовик, дорога, бензин.

Где аналогия ломается: в реальной сети «почтальон» (MAC) меняется на каждом участке пути, а «адрес на коробке» (IP) остаётся тем же. В почте так не бывает — там адрес один на всё путешествие.

## 4. Практика и команды

Все команды ниже выполняются на WIN11-CL01 (Windows 11, локальная учётка `ivanov`, адрес 10.10.10.51) или на UBU01 (Ubuntu, 10.10.10.30, sudo-пользователь `adm.student`). Wireshark ставится на WIN11-CL01.

### 1. Установить Wireshark на WIN11-CL01

Скачай установщик с официального сайта wireshark.org (Windows x64 Installer). При установке оставь галочку **Install Npcap** — это драйвер захвата, без него Wireshark не увидит адаптер. Npcap ставится в режиме «WinPcap API-compatible Mode» — оставь по умолчанию.

### 2. Посмотреть, какие адаптеры есть и какой из них «наш»

```powershell
Get-NetAdapter | Format-Table Name, InterfaceDescription, Status, LinkSpeed
```

Пример вывода (примерный):

```text
Name          InterfaceDescription                    Status  LinkSpeed
----          --------------------                    ------  ---------
Ethernet0     Intel(R) 82574L Gigabit Network Conn…  Up      1 Gbps
```

Смотри: `Status = Up` — линк есть. Это уровень 1. Если Down — проблема на физическом уровне (в VMware — «Connect at power on» не стоит или сеть не подключена).

### 3. Посмотреть IP-конфигурацию

```powershell
ipconfig /all
```

Смотри: `IPv4 Address` = 10.10.10.51, `Subnet Mask` = 255.255.255.0, `Default Gateway` = 10.10.10.2, `DNS Servers` = пока пусто или 10.10.10.10 (DNS-сервер появится только в уроке 34, до него — что настроено вручную). Это уровень 3.

### 4. Проверить связность до шлюза и до другой ВМ

```powershell
ping 10.10.10.2
ping 10.10.10.52
```

`ping` работает на ICMP (уровень 3). Если до шлюза идёт, а до 10.10.10.52 — нет, проблема либо на WIN10-CL02, либо в её брандмауэре (но у нас правило ICMP разрешено на всех ВМ стенда — значит, скорее всего, ВМ выключена или сеть отключена).

### 5. Запустить Wireshark и выбрать адаптер

GUI: **Пуск → Wireshark**. В списке интерфейсов выбери `Ethernet0` (или тот, что с трафиком — рядом будут бегущие полоски). Двойной клик — захват пошёл.

Если хочешь через командную строку (удобно для скриптов):

```cmd
"C:\Program Files\Wireshark\tshark.exe" -D
```

`-D` — список интерфейсов. Примерный вывод:

```text
1. \Device\NPF_{...} (Ethernet0)
2. \Device\NPF_{...} (Loopback)
```

### 6. Снять простой захват и отфильтровать по ICMP

В Wireshark в строке фильтра вверху набери:

```text
icmp
```

и нажми Enter. Пока захват идёт, в другом окне выполни `ping 10.10.10.2`. В списке появятся пары: `Echo (ping) request` и `Echo (ping) reply`. Кликни на любой пакет — внизу откроется разбор по уровням:

```text
Frame 12: 98 bytes on wire
Ethernet II, Src: 00:0c:29:xx:xx:xx, Dst: 00:50:56:xx:xx:xx
Internet Protocol Version 4, Src: 10.10.10.51, Dst: 10.10.10.2
Internet Control Message Protocol, Type: 8 (Echo request)
```

Видишь три уровня: канальный (Ethernet II), сетевой (IPv4), и ICMP как «прикладной» для пинга. Это и есть модель OSI вживую.

### 7. Отфильтровать по IP-адресу

```text
ip.addr == 10.10.10.52
```

Покажет весь трафик между WIN11-CL01 и WIN10-CL02 в обе стороны. Полезно, когда пользователь говорит «не работает с этим сервером» — сразу видно, идут ли пакеты вообще.

### 8. Отфильтровать по порту

```text
tcp.port == 445
```

Покажет весь SMB-трафик (общие папки). Пока на стенде общих папок нет (FS01 появится в уроке 46), но фильтр пригодится позже. А вот `tcp.port == 22` уже сейчас покажет SSH-трафик, если ты с WIN11-CL01 подключишься к UBU01.

### 9. Посмотреть DNS-запрос (пока вручную)

```text
dns
```

DNS-сервера на стенде ещё нет (появится в уроке 34), но если в браузере на WIN11-CL01 открыть любой сайт — уйдут DNS-запросы к внешнему серверу (через NAT VMnet8). В фильтре увидишь `Standard query A example.com` и `Standard query response A ...`. Это уровень 7 (прикладной) — но работает поверх UDP/53 (уровень 4) и IP (уровень 3).

### 10. На Linux — то же самое через tcpdump

На UBU01 (через SSH с WIN11-CL01):

```bash
sudo apt update
sudo apt install -y tcpdump
sudo tcpdump -i any -n icmp
```

`-i any` — слушать все интерфейсы, `-n` — не резолвить имена (быстрее и понятнее). Пока идёт захват, с WIN11-CL01 пингани UBU01 (`ping 10.10.10.30`). Увидишь строки вида:

```text
IP 10.10.10.51 > 10.10.10.30: ICMP echo request, id 1, seq 1, length 64
IP 10.10.10.30 > 10.10.10.51: ICMP echo reply, id 1, seq 1, length 64
```

Остановить — `Ctrl+C`.

### 11. Сохранить захват в файл

В Wireshark: **File → Save As**, формат `.pcapng`. Файл потом можно приложить к заявке (в рабочей среде — только с разрешения, см. раздел 6). Через tshark:

```cmd
"C:\Program Files\Wireshark\tshark.exe" -i 1 -w C:\Lab\vektor\docs\capture-31.pcapng -a duration:30
```

`-i 1` — интерфейс №1 из `-D`, `-w` — куда писать, `-a duration:30` — остановиться через 30 секунд.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** сразу лезть в Wireshark, не проверив `ipconfig` и `ping`.
   **К чему приводит:** тонны трафика, в которых новичок тонет, и потерянные 20 минут.
   **Как правильно:** сначала уровни 1–3 (`Get-NetAdapter`, `ipconfig`, `ping` шлюза и цели), только потом захват.

2. **Ошибка:** запускать Wireshark «на всё» без фильтра.
   **К чему приводит:** файл на гигабайты, Wireshark тормозит, нужный пакет не найти.
   **Как правильно:** ставь фильтр захвата (`-f` в tshark/dumpcap) или хотя бы фильтр отображения сразу.

3. **Ошибка:** путать MAC- и IP-адреса.
   **К чему приводит:** неверные выводы («у него другой адрес, значит, не тот компьютер»).
   **Как правильно:** MAC — уровень 2, меняется на каждом участке; IP — уровень 3, сквозной.

4. **Ошибка:** думать, что «пинг не идёт = сеть не работает».
   **К чему приводит:** ложная диагностика: ICMP могут блокировать, а сервис при этом работает.
   **Как правильно:** проверяй конкретный порт (`Test-NetConnection` в PowerShell — но это уже урок 35; пока — через Wireshark и `tcp.port`).

5. **Ошибка:** менять настройки на «сломанной» ВМ, не сделав снапшот.
   **К чему приводит:** не можешь вернуться к рабочему состоянию.
   **Как правильно:** снапшот `before-l1-031` до любых экспериментов.

6. **Ошибка:** сохранять захваты с реальным трафиком пользователей в личные папки.
   **К чему приводит:** утечка персональных данных, разбор у безопасников.
   **Как правильно:** в рабочей среде — только с письменного разрешения, файлы хранить в согласованном месте и удалять после разбора.

7. **Ошибка:** считать, что «Wireshark видит весь трафик сети».
   **К чему приводит:** удивление, что не видно чужого трафика.
   **Как правильно:** на коммутаторе видно только свой трафик + broadcast, если не настроено зеркалирование порта (SPAN).

### Безопасность

- **Нельзя** запускать захват трафика на рабочем компьютере без разрешения — это нарушение 152-ФЗ (персональные данные) и внутренних политик. В нашем стенде всё учебное, но привычку формируй сразу.
- **Нельзя** ставить Wireshark на машины, где обрабатываются реальные платежи или ПДн, без согласования с ИБ.
- **Нельзя** отключать брандмауэр «чтобы пинг прошёл» — на стенде правило ICMP уже разрешено, а в бою это дыра.
- Пароль стенда `Lab#2026-vektor` — только для лаборатории. В реальной работе такие пароли недопустимы.

## 7. Вопросы на собеседовании

**Вопрос 1. «Расскажите, что такое модель OSI и зачем она нужна?»**

Ответ: OSI — это эталонная семиуровневая модель, которая описывает, как данные проходят от приложения до провода. Уровни: физический, канальный, сетевой, транспортный, сеансовый, представления, прикладной. Нужна для диагностики: когда «не работает», мы идём по уровням и находим, где обрыв. На практике используется четырёхуровневый стек TCP/IP, но названия уровней OSI прижились в обиходе.

*Что хочет услышать интервьюер:* что ты понимаешь уровни не как заклинание, а как инструмент диагностики.

*Красный флаг:* «OSI — это протокол» или путаница в порядке уровней.

**Вопрос 2. «Чем отличается MAC-адрес от IP-адреса?»**

Ответ: MAC — адрес на канальном уровне, «прошит» в сетевой адаптер (в виртуалке — назначается VMware), уникален в пределах сегмента, меняется на каждом участке пути. IP — адрес на сетевом уровне, логический, назначается администратором или DHCP, сквозной на всём маршруте. В одном кадре Wireshark видно и то, и другое: в `Ethernet II` — MAC, в `IPv4` — IP.

*Что хочет услышать интервьюер:* что ты понимаешь «сквозной» vs «локальный» адрес.

*Красный флаг:* «это одно и то же» или «MAC — это для Wi-Fi».

**Вопрос 3. «Пользователь говорит, что у него не открывается сайт. Ваши действия?»**

Ответ: сначала уточняю, что именно не открывается (один сайт или все), что пишет. Дальше по уровням: `ipconfig` — есть ли IP, шлюз, DNS; `ping` шлюза — есть ли связность; `ping` внешнего адреса (например, 77.88.8.8) — работает ли маршрут; если IP пингуется, а сайт по имени нет — проблема в DNS. Если нужно — снимаю трафик в Wireshark с фильтром по IP пользователя, смотрю, уходят ли пакеты и приходят ли ответы.

*Что хочет услышать интервьюер:* системный подход, а не «перезагрузите».

*Красный флаг:* «сразу переустанавливаю Windows» или «не знаю, зову старшего».

**Вопрос 4. «Что такое порт и какие порты вы знаете?»**

Ответ: порт — числовой идентификатор службы на компьютере, чтобы ОС понимала, какому приложению отдать пакет. Знаю: 22 — SSH, 53 — DNS, 80 — HTTP, 443 — HTTPS, 445 — SMB, 3389 — RDP, 67/68 — DHCP. В Wireshark фильтр `tcp.port == 443` покажет HTTPS-трафик.

*Что хочет услышать интервьюер:* что ты помнишь основные порты и понимаешь, зачем они.

*Красный флаг:* «порт — это разъём на компьютере».

**Вопрос 5. «Зачем нужен Wireshark и когда вы его используете?»**

Ответ: Wireshark — анализатор трафика, показывает пакеты по уровням. Использую, когда нужно понять, уходит ли трафик вообще, приходит ли ответ, на каком уровне обрыв. Например, при «сайт не открывается»: видно, ушёл ли DNS-запрос, пришёл ли ответ, установилось ли TCP-соединение. В рабочей среде — только с разрешения, потому что там могут быть персональные данные.

*Что хочет услышать интервьюер:* что ты понимаешь и пользу, и ограничения.

*Красный флаг:* «Wireshark показывает пароли» (это про незашифрованные протоколы, и говорить так на собеседовании — плохо).
