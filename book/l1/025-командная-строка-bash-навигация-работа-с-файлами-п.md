## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Что такое Bash.** Bash (Bourne Again SHell) — программа-посредник между вами и ядром Linux. Вы печатаете строку — Bash разбирает её, подставляет переменные и шаблоны, находит программу (`ls`, `cp`) и запускает её. Bash не «делает файлы» сам: он просит ядро. Ядро проверяет права и либо выполняет операцию, либо возвращает `Permission denied`.

**Где это в модели OSI.** Bash — не сетевой протокол, он живёт выше: прикладной уровень и уровень ОС. Сеть появляется только когда вы подключаетесь к серверу по SSH (TCP-порт 22) — это тема урока 29. Здесь мы работаем в консоли виртуальной машины (окно VMware), то есть вообще без сети.

```text
Вы → терминал (виртуальная консоль TTY / окно VMware)
        ↓ ввод строки
      bash  ── разбор строки, glob (*.txt), переменные, пайпы | > <
        ↓ запуск утилиты (/usr/bin/ls, /usr/bin/cp)
      системный вызов ядра (open, readdir, unlink, chmod)
        ↓ проверка прав по UID/GID процесса
      файловая система (ext4) на виртуальном диске
```

**Пользователи и идентификаторы.** Ядро не знает слова «ivanov» — оно знает числа. У каждого процесса есть UID (идентификатор пользователя) и GID (идентификатор группы). `root` — это UID 0, у него проверка прав фактически отключена. На Ubuntu обычные пользователи начинаются с UID 1000, служебные (systemd, www-data и т.п.) занимают 1–999.

**Где что лежит:**

| Файл | Что внутри |
|------|-----------|
| `/etc/passwd` | учётные записи: `имя:x:UID:GID:описание:домашний каталог:оболочка` |
| `/etc/shadow` | хэши паролей и сроки действия (читает только root) |
| `/etc/group` | группы: `имя:x:GID:список участников` |
| `/etc/sudoers`, `/etc/sudoers.d/*` | кому разрешено выполнять команды от root |

Пароля в `/etc/passwd` нет — там стоит `x`, сам хэш уехал в `/etc/shadow`. Если в `/etc/shadow` перед хэшем стоит `!`, учётка заблокирована по паролю (так по умолчанию у `root` в Ubuntu).

**Модель прав.** У каждого файла есть владелец (owner), группа (group) и «все остальные» (others). Для каждой из трёх категорий заданы три бита: `r` (читать), `w` (писать), `x` (для файла — выполнять, для каталога — входить в него и обращаться к содержимому). Плюс четыре спецбита, из которых L1 реально нужны три: `setuid`, `setgid` и `sticky`.

```text
-rwxr-x---  1 ivanov gg-buh 4096 окт 12 10:30 report.sh
│└┬┘└┬┘└┬┘  │   │      │      │        │       └ имя
│ │  │  └── others: r-x  → прочитать и запустить можно, изменить нельзя
│ │  └───── группа gg-buh: r-x
│ └──────── владелец ivanov: rwx
└────────── тип: - файл, d каталог, l символическая ссылка
```

Восьмеричная запись: `r=4`, `w=2`, `x=1`, сумма по тройке. `rwxr-x---` = 750. `rw-r--r--` = 644.

**Каталог — это тоже файл**, но его «содержимое» — список имён. Поэтому `r` на каталоге = «увидеть список имён», `x` = «пройти внутрь и открыть файл, если знаешь имя», `w` = «создавать и удалять файлы». Отсюда классический прикол: каталог с правами `--x` — войти можно, а `ls` покажет `Permission denied`.

**umask** — маска, которая вычитается из «полных» прав при создании файла. Файл создаётся как `666 & ~umask`, каталог как `777 & ~umask`. При `umask 022` файл получит 644, каталог 755. Исполняемый бит файлу по умолчанию не даётся никогда.

## 3. Аналогия из жизни

Представьте бизнес-центр. Каталоги — это этажи и кабинеты, файлы — документы в них. `bash` — администратор на ресепшене: он выполняет поручения буквально и без фантазии. Скажете «убери кабинет» — уберёт вместе с людьми, если не уточнили. `cd` — вы вошли в лифт и нажали этаж, `pwd` — табличка «вы находитесь здесь». Права — пропускная система: `r` — «посмотреть на документ через стекло», `w` — «взять и исправить», `x` — «открыть дверь ключом». Владелец, группа и остальные — три категории пропусков: хозяин кабинета, его отдел и все прочие посетители. Группы — это отделы: один пропуск `GG-Buh` открывает все кабинеты бухгалтерии. `sudo` — временный пропуск начальника: выдаётся на одну операцию, и каждый вход записывается в журнал.

Аналогия ломается в одном: пропуска в офисе выдаёт человек и может «закрыть глаза», а в Linux права проверяет ядро при каждом открытии файла — договориться с ним нельзя.

## 4. Практика и команды

Ниже — `admstudent@ubu01` — локальный администратор UBU01 (UID 1000, состоит в группе `sudo`), `$` — приглашение обычного пользователя, `#` — root. `~` означает домашний каталог.

**1) Кто я и где я: `pwd`, `whoami`, `id`**

```bash
pwd
whoami
id
id ivanov
hostname
```

```text
admstudent@ubu01:~$ id
uid=1000(admstudent) gid=1000(admstudent) группы=1000(admstudent),27(sudo)
```

`pwd` — полный путь текущего каталога. `whoami` — имя текущей учётки (важно, если вы «перепрыгнули» под другого пользователя). `id` — UID, основной GID и **все** группы, включая дополнительные. `id <пользователь>` — то же про другого человека, не переключаясь. Смотреть: входит ли пользователь в `sudo` и в нужную группу доступа.

**2) Просмотр каталога: `ls`**

```bash
ls
ls -l /srv/vektor
ls -la ~
ls -lh /var/log
ls -ld /srv/vektor/buh
```

| Ключ | Смысл |
|------|-------|
| `-l` | длинный формат: права, владелец, группа, размер, дата |
| `-a` | показать скрытые файлы (начинаются с точки: `.bashrc`, `.bash_history`) |
| `-h` | размеры в К/М/Г |
| `-d` | показать сам каталог, а не его содержимое |
| `-t`, `-r` | сортировка по времени, в обратном порядке |

```text
admstudent@ubu01:~$ ls -la
итого 32
drwxr-x--- 5 admstudent admstudent 4096 окт 12 09:14 .
drwxr-xr-x 3 root       root       4096 окт 10 18:02 ..
-rw------- 1 admstudent admstudent  512 окт 12 09:10 .bash_history
-rw-r--r-- 1 admstudent admstudent  220 окт 10 18:02 .bashrc
drwxr-xr-x 2 admstudent admstudent 4096 окт 12 09:14 vektor
```

`.` — текущий каталог, `..` — родительский. Смотреть: `d` в начале строки = каталог; кто владелец; нет ли подозрительного `rwxrwxrwx`.

**3) Навигация: `cd`**

```bash
cd /var/log
cd ~
cd ..
cd -
cd /srv/vektor/buh
```

`cd` без аргумента = домой. `cd -` возвращает в предыдущий каталог (удобно прыгать туда-обратно). `cd ..` — на уровень выше. Абсолютный путь начинается с `/`, относительный — с имени каталога.

**4) Создание: `mkdir`, `touch`, перенаправление вывода**

```bash
mkdir -p ~/vektor/{docs,tmp}
touch ~/vektor/docs/readme.txt
echo "Тестовый файл стенда Вектор" > ~/vektor/docs/readme.txt
echo "вторая строка" >> ~/vektor/docs/readme.txt
```

`mkdir -p` создаёт всю цепочку каталогов и не ругается, если каталог уже есть. `{docs,tmp}` — «раскрытие фигурных скобок» Bash: получится `mkdir -p ~/vektor/docs ~/vektor/tmp`. `touch` создаёт пустой файл или обновляет дату изменения. `>` перезаписывает файл, `>>` дописывает в конец.

**5) Копирование, перемещение, удаление: `cp`, `mv`, `rm`, `rmdir`**

```bash
cp ~/vektor/docs/readme.txt ~/vektor/docs/readme.bak
cp -r ~/vektor/docs ~/vektor/docs-copy
cp -a ~/vektor/docs/readme.txt /tmp/
mv ~/vektor/docs/readme.bak ~/vektor/tmp/
mv ~/vektor/tmp/readme.bak ~/vektor/tmp/readme-old.txt
rm ~/vektor/tmp/readme-old.txt
rm -r ~/vektor/docs-copy
rmdir ~/vektor/tmp
```

`-r` (recursive) — рекурсивно, обязателен для каталогов. `-a` (archive) — копировать с сохранением прав, владельца и дат. `mv` тем же синтаксисом переименовывает и переносит. `rmdir` удаляет **только пустой** каталог — это защита от случайности. `rm -rf` — рекурсивно и без вопросов; в реальной работе применять только с явным путём и после `ls` того же пути.

**6) Чтение файлов и метаданные: `cat`, `less`, `head`, `tail`, `file`, `stat`**

```bash
cat ~/vektor/docs/readme.txt
less /var/log/syslog
head -n 5 /var/log/syslog
tail -n 20 /var/log/syslog
file /bin/ls
stat ~/vektor/docs/readme.txt
stat -c '%a %U %G %n' ~/vektor/docs/readme.txt
```

`less` — постраничный просмотр (`q` — выход, `/слово` — поиск). `head`/`tail` — первые/последние строки; `tail -f` «следит» за файлом в реальном времени (это уже про логи, подробнее — урок 28). `file` показывает реальный тип содержимого, даже если расширение врёт. `stat -c` — быстрый способ увидеть права в восьмеричном виде, владельца и группу одной строкой.

```text
admstudent@ubu01:~$ stat -c '%a %U %G %n' ~/vektor/docs/readme.txt
644 admstudent admstudent /home/admstudent/vektor/docs/readme.txt
```

**7) Поиск файлов: `find`**

```bash
find /srv/vektor -type d
find /home -name "readme*"
find /srv -user ivanov 2>/dev/null
find / -size +100M -type f 2>/dev/null
sudo find / -perm -4000 -type f 2>/dev/null
```

`-type d` — только каталоги (`-type f` — файлы). `-name` — по имени (шаблоны в кавычках). `-user` — по владельцу. `2>/dev/null` прячет поток ошибок «нет доступа» — без него `find /` выдаст километры `Permission denied`. Последняя команда ищет файлы с битом `setuid` — типовой шаг проверки «а не завёлся ли на сервере чужой root-бинарник».

**8) Права: `chmod`, `chown`, `chgrp`, `umask`**

```bash
chmod 640 ~/vektor/docs/readme.txt
chmod u+x ~/vektor/docs/readme.txt
chmod g+r,o-r ~/vektor/docs/readme.txt
sudo chown ivanov:gg-buh /srv/vektor/buh/report.txt
sudo chgrp gg-hr /srv/vektor/hr
sudo chmod 2770 /srv/vektor/buh
sudo chmod 1777 /srv/vektor/obshchee
umask
```

- Числовая запись `640` = `rw- r-- ---`.
- Символьная: `u`/`g`/`o`/`a` + `+`/`-`/`=` + `r`/`w`/`x`. Читается почти по-английски: «владельцу добавить выполнение».
- `chown владелец:группа файл` меняет и владельца, и группу; `chgrp` — только группу. Только root может «отдать» файл другому человеку.
- `2770` — это `setgid` на каталоге: любой новый файл внутри унаследует группу каталога, а не личную группу создателя. Для общих папок это стандарт.
- `1777` — `sticky`-бит: писать могут все, удалять — только владелец файла (именно так устроен `/tmp`).
- `-R` (recursive) в `chmod`/`chown` применяется ко всему дереву — самая частая причина аварий. Сначала проверьте `ls -lR` или `find`.

```text
admstudent@ubu01:~$ umask
0022
```

**9) Пользователи и группы: `adduser`, `usermod`, `passwd`, `chage`, `groups`**

```bash
sudo adduser ivanov
sudo adduser ivanov gg-buh
sudo usermod -aG gg-sklad sidorov
sudo gpasswd -d ivanov gg-buh
groups ivanov
sudo passwd -S ivanov
sudo chage -l ivanov
sudo deluser --remove-home petrova
```

- `adduser` (Debian/Ubuntu) — интерактивная обёртка: спрашивает пароль, создаёт домашний каталог и одноимённую группу. `useradd` — низкоуровневая утилита, без ключей не создаёт ни дом, ни пароль; новичку лучше `adduser`.
- `adduser ivanov gg-buh` — добавить пользователя в группу (то же, что `usermod -aG gg-buh ivanov`).
- **`-a` в `usermod -G` обязателен.** Без `-a` список дополнительных групп *заменяется* на указанный — человек молча теряет все остальные доступы.
- `gpasswd -d` / `deluser user group` — убрать из группы.
- `passwd -S` — статус пароля (`P` — задан, `L` — заблокирован, `NP` — пустой). `chage -l` — когда пароль истекает, когда последний раз менялся, заблокирована ли учётка.
- Изменения групп применяются к новой сессии: уже открытый сеанс сохраняет старые права, пока пользователь не перелогинится.

```text
admstudent@ubu01:~$ sudo chage -l ivanov
Последняя смена пароля                                 : окт 12, 2026
Срок действия пароля                                   : никогда
Пароль неактивен                                      : никогда
Срок действия учётной записи                           : никогда
```

**10) `sudo` и `su`**

```bash
sudo ls /root
sudo -l
sudo -i
sudo -i -u ivanov
exit
```

`sudo` выполняет одну команду от root, спрашивая **ваш** пароль (и запоминая его на 15 минут). `sudo -l` — что именно вам разрешено (полезно в первый день на новом сервере). `sudo -i` — полноценная root-оболочка. `sudo -i -u ivanov` — войти под другим пользователем, не зная его пароля (нужно для проверки прав). `su - ivanov` требует пароль самого `ivanov`, поэтому для диагностики чаще удобнее `sudo`.

**11) Проверка через базу пользователей: `getent`**

```bash
getent passwd ivanov
getent group gg-buh
getent passwd | tail -n 5
```

```text
ivanov:x:1001:1001:Иван Иванов,,,:/home/ivanov:/bin/bash
gg-buh:x:1004:ivanov
```

`getent` читает то же, что и `cat /etc/passwd`, но **правильным способом**: если сервер когда-нибудь подключат к Active Directory или LDAP, `getent` покажет и доменных пользователей, а `cat /etc/passwd` — нет. Привыкайте к `getent`.

**GUI.** На Ubuntu Server графики нет. На Ubuntu Desktop то же самое лежит в «Файлы → Свойства → Права». В Astra Linux (урок 30) есть «Свойства → Права доступа» в файловом менеджере — но права на общие каталоги там всё равно принято ставить командами.

## 6. Ошибки новичков и безопасность

1. **`rm -rf` с неверным путём или лишним пробелом.** `rm -rf / tmp/foo` (пробел) — это два аргумента: `/` и `tmp/foo`. Итог — снесённая система. → Всегда сначала `ls` по тому же пути, потом `rm`. Для больших деревьев — `rm -ri` (с подтверждением).
2. **`usermod -G` без `-a`.** Заменяет все дополнительные группы одной. Человек молча теряет доступ к половине ресурсов. → Только `usermod -aG`.
3. **`chmod -R 777` «чтобы точно заработало».** Любой пользователь и любой процесс может изменить или удалить что угодно. → Разбирайтесь, какого бита не хватает: чаще всего нужна группа + `2770` или `1777`.
4. **`chown -R` на каталог, где лежат системные файлы.** Ломает запуск служб (`/etc`, `/var/lib`, `/usr`). → Сначала `ls -lR | head`, при сомнении — снапшот.
5. **Правка `/etc/passwd` и `/etc/shadow` вручную в редакторе.** Одна опечатка — и вход в систему невозможен ни для кого. → Только `adduser`/`usermod`/`passwd`; группы и sudoers — через `visudo`.
6. **`cp` без `-a` для бэкапа.** Копия получает владельца-копировавшего и права по umask, а не оригинальные. → Для «сохранить как было» — `cp -a`, для каталогов — `cp -a` или `rsync -a`.
7. **Забыть про перелогин после смены групп.** «Я же добавил, почему не работает?» — работает, но не в открытой сессии. → Проверять через `sudo -i -u <user>` и просить пользователя перезайти.
8. **Не смотреть скрытые файлы.** `ls` без `-a` не покажет `.bashrc`, `.ssh`, конфиги и мусор — картина каталога будет неполной. → `ls -la` как привычка.

### Безопасность

- Не выдавайте `sudo` «на всякий случай»: полный `sudo` = полный root. Минимум — конкретные команды в `/etc/sudoers.d`, правка только через `visudo` (он проверяет синтаксис и не даст сохранить сломанный файл).
- Пароли на стенде (`Lab#2026-vektor`) — **только учебные**. В реальной среде такие пароли и их передача в чате недопустимы; там используют индивидуальные пароли, срок действия (`chage`) и централизованную аутентификацию (AD/LDAP/FreeIPA).
- Не работайте постоянно в root-оболочке (`sudo -i`) — под root не срабатывают обычные предохранители (`rm` не спросит, `>` перезапишет системный файл). Правило: root-сессию открыл — сделал — закрыл.
- Не читайте и не копируйте `/etc/shadow` без задачи: это хэши паролей всех учёток. Файл и должен быть `640 root:shadow` — не «чините» это.
- `1777` на общей папке — компромисс: писать могут все. Для боевых общих папок правильнее группа + `2770`, а «всем» — только на чтение (`2775` там, где это осознанно).
- Всё, что вы делаете через `sudo`, попадает в `/var/log/auth.log`. Это не «слежка», это нормальная практика разбора инцидентов.

## 7. Вопросы на собеседовании

**Вопрос 1. Пользователь пишет: «Не могу сохранить файл в папку, пишет Permission denied». Ваши действия?**

Ответ: сначала уточняю точный путь и что именно он делает (создаёт новый файл / перезаписывает существующий). Дальше проверяю по порядку: `id <пользователь>` — в каких он группах; `ls -ld <каталог>` — владелец, группа, права; `ls -l <файл>` — если файл существует, важны права на сам файл, а не только на каталог; `getent group <нужная группа>` — есть ли он в ней; была ли смена групп в этой сессии (нужен перелогин); `findmnt` — не смонтирован ли раздел только для чтения; `getfacl` — если используются ACL, обычный `ls` их не покажет. Решение — добавить в группу (`usermod -aG`) или выдать корректные права (`chmod`/`chown`), без `777`.

*Что хочет услышать интервьюер:* что вы идёте от «кто пользователь» к «какие права», а не сразу стучите `chmod 777`.
*Красный флаг:* «сделаю `chmod -R 777` и попрошу перезайти».

**Вопрос 2. Что означает запись `drwxr-x---` и как это в цифрах?**

Ответ: `d` — каталог. Владелец: `rwx` (4+2+1=7) — читать, создавать/удалять, входить. Группа: `r-x` (5) — читать список и входить, но не создавать. Остальные: `---` (0) — доступа нет. Итого 750. Права проверяются ядром при каждом обращении по UID/GID процесса.

*Что хочет услышать интервьюер:* уверенное чтение `ls -l` и перевод в восьмеричную запись.
*Красный флаг:* путаница «r на каталоге = можно удалять файлы» (удаление требует `w` на каталоге).

**Вопрос 3. Чем `usermod -G` отличается от `usermod -aG`?**

Ответ: `-G` **задаёт** полный список дополнительных групп, заменяя прежний; всё, чего нет в новом списке, отваливается. `-aG` **добавляет** к существующим. Практически всегда нужен `-aG`; `-G` без `-a` — типовая причина «доступ пропал сам». Проверка — `id <user>` или `groups <user>`, изменения действуют для новых сессий.

*Что хочет услышать интервьюер:* понимание, что это самая частая ошибка при управлении доступом.
*Красный флаг:* «разницы нет».

**Вопрос 4. Чем `su` отличается от `sudo`? Почему в Ubuntu root «не пускает»?**

Ответ: `su` переключает вас в другого пользователя (по умолчанию root) и требует пароль **целевой** учётки. `sudo` выполняет одну команду от root, требуя **ваш** пароль и сверяясь с `/etc/sudoers`; каждое использование попадает в лог. В Ubuntu учётка `root` по умолчанию заблокирована по паролю (в `/etc/shadow` стоит `!`) — административные задачи делаются через `sudo` от пользователя из группы `sudo`. Это осознанное решение: нет общего root-пароля, есть персональная ответственность и аудит.

*Что хочет услышать интервьюер:* понимание модели `sudo` и того, что это не «баг Ubuntu».
*Красный флаг:* «надо разблокировать root и работать под ним, так проще».

**Вопрос 5. Что такое `umask 022` и какие права получат новый файл и новый каталог?**

Ответ: umask — маска, которая вычитается из максимальных прав при создании. Новый файл: `666` минус `022` = `644` (`rw-r--r--`); новый каталог: `777` минус `022` = `755` (`drwxr-xr-x`). Исполняемый бит новому файлу не выдаётся никогда, даже если маска его «разрешает». Проверить текущую маску — `umask`; поменять на сессию — `umask 077`.

*Что хочет услышать интервьюер:* формулу и понимание, что маска — про умолчания, а не про уже существующие файлы.
*Красный флаг:* «umask 022 даёт 777».
