## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Bash** (Bourne Again SHell) — это программа-оболочка (shell), которая читает ваши команды, разбирает их и передаёт ядру Linux на исполнение. Когда вы подключаетесь к UBU01 по SSH (это будет в уроке 29, а пока — через консоль VMware), вы попадаете в Bash-сессию под своим пользователем.

**Файловая система Linux** — единое дерево, начинающееся с `/` (корень). Никаких дисков `C:` и `D:` нет: диски и разделы «монтируются» в точки дерева (`/home`, `/srv`, `/var` и т.д.).

Схема ключевых каталогов, которые вам нужны на L1:

```text
/
├── etc/        конфиги системы и служб
├── home/       домашние папки пользователей (/home/adm.student)
├── root/       домашняя папка root (суперпользователя)
├── srv/        данные сервисов (сюда положим /srv/vektor/reports)
├── tmp/        временные файлы (чистится при перезагрузке)
├── var/        изменяемые данные: /var/log — журналы
└── usr/        программы и библиотеки
```

**Права доступа.** У каждого файла и папки в Linux есть:
- **владелец (owner)** — обычно один пользователь;
- **группа (group)** — одна группа;
- **три набора прав**: для владельца (u), для группы (g), для остальных (o).

Каждый набор — три бита: **r** (read, читать), **w** (write, писать), **x** (execute, выполнять; для папки — «зайти в неё»). В числовом виде: r=4, w=2, x=1. Например, `rwxr-x---` = 750 = владелец всё, группа читает и заходит, остальные — ничего.

**Пользователи и группы.** Каждый пользователь имеет числовой **UID**, каждая группа — **GID**. Суперпользователь `root` — UID 0, у него все права. Обычный пользователь может менять права только на свои файлы; менять владельца и создавать пользователей может только root (или через `sudo`). На стенде `adm.student` — sudo-пользователь, то есть может выполнять команды от root через `sudo`.

**Где хранится учётка:** `/etc/passwd` (список пользователей), `/etc/group` (список групп), `/etc/shadow` (хэши паролей, читать может только root).

## 3. Аналогия из жизни

Представьте офисный шкаф с документами. У шкафа есть **владелец** (кто его купил и поставил) и **отдел**, за которым он закреплён. На каждой полке — свой набор разрешений: владелец может всё, сотрудники отдела — читать и брать копии, остальные — только смотреть через стекло. Чтобы положить документ в шкаф, нужно право «писать» на эту полку. Чтобы вообще открыть дверцу шкафа — право «заходить» (x на папку). Администратор здания (root) может открыть любой шкаф и переставить ярлык владельца. Аналогия перестаёт работать в одном: в Linux «права» — это не физический замок, а запись в метаданных файла, и её можно поменять одной командой, не трогая сам файл.

## 4. Практика и команды

Все команды выполняются на **UBU01** (Ubuntu Server 24.04, IP 10.10.10.30, пользователь `adm.student`). Подключение — через консоль VMware (SSH будет в уроке 29).

### 4.1. Где я и кто я

```bash
pwd
whoami
id
hostname
```

- `pwd` — print working directory, показывает текущий каталог. Пример вывода: `/home/adm.student`.
- `whoami` — под кем я сейчас. Пример: `adm.student`.
- `id` — UID, GID и все группы пользователя. Пример: `uid=1000(adm.student) gid=1000(adm.student) groups=1000(adm.student),27(sudo)`.
- `hostname` — имя машины. Пример: `ubu01`.

**Что смотреть:** если `id` не показывает `sudo` в группах — вы не сможете выполнять административные команды.

### 4.2. Навигация

```bash
ls -la
cd /srv
cd ..
cd ~
cd -
```

- `ls -la` — список файлов с подробностями (`-l` — длинный формат, `-a` — включая скрытые, начинающиеся с точки).
- `cd /srv` — перейти в `/srv` (абсолютный путь).
- `cd ..` — на уровень выше.
- `cd ~` — в домашнюю папку.
- `cd -` — вернуться в предыдущий каталог.

Пример вывода `ls -la` (примерно):

```text
drwxr-xr-x 2 adm.student adm.student 4096 Jan 10 10:00 .
drwxr-xr-x 3 root        root        4096 Jan 10 09:55 ..
-rw-r--r-- 1 adm.student adm.student  220 Jan 10 09:55 .bash_logout
```

**Что смотреть:** первая колонка — тип и права (`d` — папка, `-` — файл), третья — владелец, четвёртая — группа.

### 4.3. Создание, копирование, перемещение, удаление

```bash
mkdir -p /srv/vektor/reports
touch /srv/vektor/reports/report-2026-01.txt
cp /srv/vektor/reports/report-2026-01.txt /srv/vektor/reports/report-2026-01.bak
mv /srv/vektor/reports/report-2026-01.bak /srv/vektor/reports/archive-2026-01.txt
rm /srv/vektor/reports/archive-2026-01.txt
```

- `mkdir -p` — создать папку и все родительские, если их нет.
- `touch` — создать пустой файл (или обновить время изменения).
- `cp` — копировать.
- `mv` — переместить или переименовать.
- `rm` — удалить файл. **Без корзины.** Для папки — `rm -r`, для «не спрашивать» — `rm -rf` (опасно, см. раздел 6).

### 4.4. Просмотр содержимого

```bash
cat /etc/hostname
less /etc/passwd
head -5 /etc/passwd
tail -5 /etc/passwd
```

- `cat` — вывести файл целиком (для маленьких).
- `less` — постраничный просмотр (выход — `q`).
- `head -5` / `tail -5` — первые/последние 5 строк.

### 4.5. Права: смотреть и менять

```bash
ls -l /srv/vektor/reports
chmod 750 /srv/vektor/reports
chmod u+rwx,g+rx,o-rwx /srv/vektor/reports
chown adm.student:adm.student /srv/vektor/reports
```

- `chmod 750` — числовой режим: владелец rwx, группа r-x, остальные — ничего.
- `chmod u+rwx,g+rx,o-rwx` — то же самое буквами (u/g/o — владелец/группа/остальные, +/- — добавить/убрать).
- `chown user:group` — сменить владельца и группу. Только root или через `sudo`.

### 4.6. Пользователи и группы

```bash
sudo useradd -m -s /bin/bash sidorov
sudo passwd sidorov
sudo groupadd GG-Sklad
sudo usermod -aG GG-Sklad sidorov
id sidorov
```

- `useradd -m -s /bin/bash` — создать пользователя с домашней папкой и Bash как оболочкой.
- `passwd` — задать пароль.
- `groupadd` — создать группу.
- `usermod -aG` — добавить в группу (важно: **с `-a`**, иначе пользователь будет исключён из всех остальных групп).
- `id sidorov` — проверить.

**Важно:** на стенде `sidorov` — это персонаж заявок, а не пользователь Linux. Здесь мы создаём **локального** пользователя Linux с тем же именем для учебной задачи. Доменная учётка `sidorov` появится только в уроке 43, это другое.

### 4.7. Кто в системе

```bash
who
w
last -n 5
```

- `who` — кто сейчас залогинен.
- `w` — то же плюс чем занят.
- `last -n 5` — последние 5 входов.

### 4.8. Поиск файлов и справка

```bash
find /srv -name "*.txt"
man ls
ls --help | head -20
```

- `find /srv -name "*.txt"` — найти все `.txt` в `/srv`.
- `man ls` — встроенная справка (выход — `q`).
- `--help` — краткая справка.

## 6. Ошибки новичков и безопасность

1. **`rm -rf /` или `rm -rf *` не в той папке.** → Уничтожает всё, до чего дотянется, без корзины и подтверждения. → Всегда сначала `pwd` и `ls`, потом `rm`. Для папок — `rm -r` без `-f`, чтобы система спрашивала.
2. **`chmod 777` «чтобы работало».** → Любой пользователь может читать, менять и удалять файл. → Разбирайтесь, кому именно нужен доступ: владельцу, группе или остальным. 750/640 — рабочий минимум.
3. **`usermod -G` без `-a`.** → Пользователь выпадает из всех групп, кроме указанной. → Всегда `usermod -aG`.
4. **`chown` без `-R` на папку с вложениями.** → Меняется владелец только самой папки, файлы внутри остаются чужими. → Если нужна рекурсия — `chown -R`, но осознанно.
5. **Работа от `root` без необходимости.** → Одна опечатка — и сломана система. → Используйте `sudo` только для конкретной команды.
6. **`>` вместо `>>`.** → `>` перезаписывает файл, `>>` дописывает. → Проверяйте, что нужно.
7. **Правка системных файлов «наугад».** → Сломанный `/etc/passwd` = никто не войдёт. → Перед правкой — копия: `sudo cp /etc/passwd /etc/passwd.bak`.

**Безопасность.** В боевой среде нельзя: давать `sudo` всем подряд, ставить `777` на общие папки, хранить пароли в открытом виде в скриптах, запускать `rm -rf` без проверки пути. На стенде пароль `Lab#2026-vektor` — учебный; в реальной работе такой пароль недопустим, и его нельзя переиспользовать между серверами.

## 7. Вопросы на собеседовании

**Вопрос 1. «Пользователь говорит, что не может открыть папку на Linux-сервере. Что будете смотреть?»**
Ответ: «Сначала `id` пользователя — существует ли он и в каких группах. Потом `ls -ld` на папку — кто владелец, какая группа, какие права. Дальше проверю, входит ли пользователь в группу папки. Если да — смотрю права: нужен `x` на папку, чтобы зайти, и `r`, чтобы увидеть содержимое. Если нет — либо добавляю в группу через `usermod -aG`, либо меняю права через `chmod`, в зависимости от того, что правильно по политике.»
*Что хочет услышать интервьюер:* системный подход, а не «сделаю 777».
*Красный флаг:* «сразу поставлю 777, чтобы работало».

**Вопрос 2. «Чем отличаются права 644 и 755?»**
Ответ: «644 — владелец читает и пишет, группа и остальные только читают. Обычно для файлов. 755 — владелец читает, пишет и выполняет, группа и остальные читают и выполняют. Обычно для папок и исполняемых файлов. Для папки `x` означает право зайти в неё.»
*Что хочет услышать:* понимание r/w/x и числовой записи.
*Красный флаг:* путаница между `r` и `x` для папок.

**Вопрос 3. «Как добавить пользователя в группу, не потеряв остальные?»**
Ответ: «`usermod -aG имя_группы пользователь`. Ключ `-a` — append, без него `-G` перезапишет список групп. Проверить — `id пользователь`.»
*Что хочет услышать:* знание подводного камня `-a`.
*Красный флаг:* «`usermod -G`».

**Вопрос 4. «Что такое `sudo` и зачем он нужен?»**
Ответ: «`sudo` позволяет обычному пользователю выполнить конкретную команду от root, не заходя под root целиком. Настройки — в `/etc/sudoers`, править через `visudo`. На стенде `adm.student` в группе `sudo`, поэтому может выполнять административные команды.»
*Что хочет услышать:* понимание принципа минимальных привилегий.
*Красный флаг:* «работаю всегда под root, так проще».

**Вопрос 5. «Как безопасно удалить папку с файлами?»**
Ответ: «Сначала `pwd` и `ls` — убедиться, что я в нужном месте. Потом `rm -r имя_папки` без `-f`, чтобы система спросила подтверждение на каждый файл. Если файлов много и уверен — `rm -rf`, но только после проверки пути. В боевой среде перед удалением — бэкап или перемещение в `/tmp` на пару дней.»
*Что хочет услышать:* осторожность и понимание, что корзины нет.
*Красный флаг:* «`rm -rf` — это быстро и удобно».
