# Установка, переустановка и активация Windows: MBR/GPT, загрузочные флешки, образы, лицензирование в корпоративной среде

## 1. Введение (зачем это нужно в реальной работе)

Понедельник, 9:20. В тикете — заявка от Марии Петровой (HR, ВМ WIN10-CL02):

> «Добрый день! Компьютер вчера вечером выключился во время обновления. Теперь при включении чёрный экран и надпись: "An operating system wasn't found. Try disconnecting any drives that don't contain an operating system". Мне срочно, у меня собеседования с 11:00».

Через двадцать минут вторая: Иван Иванов (бухгалтерия, WIN11-CL01) пишет, что ему «привезли новый системный блок, надо всё поставить, как было». И третья, от Сидорова: «Windows пишет, что срок действия лицензии истекает».

Вот это и есть три кита урока: установка с нуля, восстановление/переустановка после поломки и активация. На L1 вы будете делать это постоянно — новые сотрудники, списанные и заменённые машины, «упавшая» система, подготовка ПК к передаче в отдел. После этой главы вы должны уметь: определить, в каком режиме загружается система (UEFI или Legacy) и какая на диске разметка (GPT или MBR); собрать загрузочную флешку из официального ISO; поставить Windows 11 с нуля и не потерять данные; проверить и при необходимости выполнить активацию штатными средствами; и главное — понимать, что переустановка это **последний** шаг, а не первый.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

### Путь от кнопки питания до рабочего стола

```text
   BIOS / Legacy                         UEFI
   -------------                         ----
   Прошивка BIOS (16-бит)                Прошивка UEFI (32/64-бит, драйверы, сеть)
        |                                     |
   MBR: сектор 0, 512 байт               GPT: защитный MBR (LBA0) + заголовок (LBA1)
   (446 байт код + таблица 4x16 + 0x55AA)     + таблица разделов (LBA2..33)
        |                                     + РЕЗЕРВНАЯ копия в конце диска
   bootmgr -> winload.exe                ESP (FAT32, ~100 МБ) -> \EFI\Microsoft\Boot\bootmgfw.efi
        |                                     -> winload.efi (+ проверка подписи Secure Boot)
   ntoskrnl.exe (ядро Windows)           ntoskrnl.exe (ядро Windows)
```

**MBR (Master Boot Record)** — старая схема разметки. Вся таблица разделов живёт в одном 512-байтном секторе: 446 байт под загрузочный код, 64 байта под 4 записи по 16 байт. Отсюда ограничения: максимум 4 первичных раздела (пятый и далее — «логические» внутри расширенного) и максимум ~2 ТБ на диск при секторах 512 байт. Резервной копии таблицы нет: убил первый сектор — потерял разметку.

**GPT (GUID Partition Table)** — современная схема. Таблица на 128 разделов по умолчанию, 64-битная адресация (ограничение по объёму астрономическое), защитный MBR на случай, если диск сунут в старую систему, контрольные суммы CRC32 и **резервная копия заголовка и таблицы в конце диска**. Windows умеет загружаться с GPT только в режиме UEFI — это важно помнить.

**ESP (EFI System Partition)** — маленький раздел FAT32, где лежат загрузчики. Плюс служебный **MSR** (Microsoft Reserved, 16 МБ, без файловой системы), раздел Windows (NTFS) и раздел восстановления (WinRE). Windows Setup на чистом диске в UEFI создаёт их сам — обычно четыре штуки.

**Загрузочная флешка.** Установочный ISO Windows — это, по сути, FAT32-образ с файлами `\sources\install.wim` (или `.esd`), `\boot`, `\efi` и загрузочной записью El Torito. Флешка должна быть размечена так, чтобы прошивка её увидела: для UEFI достаточно FAT32 и файла `\EFI\Boot\bootx64.efi`.

**Что происходит при установке.** Загружается **Windows PE** (мини-система из ISO) → `setup.exe` → выбор редакции → разметка диска → разворачивание образа WIM на раздел → этап `specialize` (драйверы, имя, настройки) → **OOBE** (первичная настройка: язык, учётная запись, сеть). Все действия пишутся в логи `C:\Windows\Panther\setupact.log` и `setuperr.log` — по ним разбирают 90% провалов установки.

**Лицензирование.** Ключевое различие: *лицензия* — это право использования (договор, закупка), *активация* — техническая привязка к железу. Каналы:

| Канал | Что это | Нюанс для L1 |
|---|---|---|
| OEM | предустановлена на ПК, ключ в прошивке (SLIC/MSDM) | привязана к материнской плате, при замене платы «умирает» |
| Retail | куплена в коробке/онлайн | переносится на другое железо, но снимается со старого |
| Volume: MAK | корпоративный ключ с ограниченным числом активаций | каждая переустановка съедает активацию, счёт не бесконечен |
| Volume: KMS | внутренний сервер активации, TCP **1688**, DNS-запись `_vlmcs._tcp` | активация на 180 дней, клиент продлевает каждые 7 дней; серверу нужно набрать минимум 25 клиентов Windows / 5 серверов |
| AD-based activation | активация через домен (Windows Server 2012+) | «просто работает» для доменных ПК |
| Evaluation | бесплатные 90 дней | **только для тестов**, не для боевых ПК |

Ключи **GVLK** (generic volume license key) — публичные ключи Microsoft для KMS-клиентов, они есть в открытой документации. Сами по себе они ничего не активируют, это лишь «адрес», куда идти за активацией.

## 3. Аналогия из жизни

Диск — это дом. **Разметка (MBR/GPT)** — план дома. MBR — старый бумажный план: не больше четырёх комнат, дом не больше 2 «терабайт», и единственный экземпляр плана лежит в прихожей на тумбочке. Пролил чай — дом стоит, а комнат больше нет. GPT — электронный план: комнат сколько угодно, копия плана хранится в сейфе у консьержа, и на каждой странице подпись архитектора, чтобы никто не подрисовал лишнюю дверь.

**Загрузочная флешка** — грузовик с мебелью, прорабом и чертежами (Windows PE). **Установка** — заезд: сначала прораб размечает комнаты, потом заносит мебель по списку (WIM), потом выдаёт вам ключи (OOBE). **Активация** — договор с управляющей компанией: либо именной ключ на одну квартиру (Retail/OEM), либо домовой пропуск, который надо раз в полгода подтверждать у консьержа (KMS).

Ломается аналогия в одном месте: план дома можно перерисовать на ходу, не вынося мебель, а вот `convert gpt` на живом диске без потери данных — так себе затея.

## 4. Практика и команды

**1. `msinfo32` — первый взгляд на систему.** GUI: `Win+R` → `msinfo32` → «Сведения о системе». PowerShell-аналог:

```powershell
Get-ComputerInfo | Select-Object BiosFirmwareType, WindowsProductName, OsVersion, CsName
```

```text
BiosFirmwareType    : Uefi
WindowsProductName  : Windows 11 Enterprise
OsVersion           : 10.0.22631
CsName              : WIN11-CL01
```

Смотрим: `BiosFirmwareType` = Uefi/Bios. В GUI то же самое — строки «Режим BIOS» (BIOS Mode) и «Состояние безопасной загрузки» (Secure Boot State).

**2. `Confirm-SecureBootUEFI` — работает ли Secure Boot.**

```powershell
Confirm-SecureBootUEFI
# True
```

Возвращает `True`/`False`; на Legacy-BIOS выдаёт ошибку «командлет не поддерживается на этой платформе» — это тоже ответ.

**3. `Get-Disk` / `Get-Partition` — стиль разметки и разделы.**

```powershell
Get-Disk | Format-Table Number,FriendlyName,PartitionStyle,Size,BusType -AutoSize
Get-Partition -DiskNumber 0 | Format-Table PartitionNumber,DriveLetter,Type,Size -AutoSize
```

```text
Number FriendlyName      PartitionStyle          Size BusType
------ ------------      --------------          ---- -------
     0 VMware Virtual…   GPT            64424509440 SCSI

PartitionNumber DriveLetter Type        Size
--------------- ----------- ----        ----
              1             System     100 MB   <- ESP
              2             Reserved    16 MB   <- MSR
              3 C           Basic       58 GB
              4             Recovery   750 MB
```

GUI: `Win+X` → «Управление дисками» (`diskmgmt.msc`), правый клик по надписи «Диск 0» → Свойства → вкладка «Тома» → «Стиль раздела».

**4. `diskpart` — ручная разметка (WinPE, Shift+F10 в установщике).** *Деструктивно: `clean` стирает ВСЁ.*

```cmd
diskpart
list disk
select disk 0
detail disk
list partition
clean
convert gpt
create partition efi size=300
format quick fs=fat32 label="System"
assign letter=S
create partition msr size=16
create partition primary
format quick fs=ntfs label="Windows"
assign letter=C
exit
```

`detail disk` печатает строку «Тип разделов диска» (Partition Style) — GPT или MBR. `clean` затирает первые и последние сектора, `convert gpt` переводит пустой диск в GPT.

**5. `slmgr.vbs` — состояние лицензии.** Только из-под администратора; `cscript` нужен, чтобы вывод шёл в консоль, а не в окошко.

```cmd
cscript //nologo %windir%\System32\slmgr.vbs /dli
cscript //nologo %windir%\System32\slmgr.vbs /dlv
cscript //nologo %windir%\System32\slmgr.vbs /xpr
```

```text
Name: Windows(R), Enterprise edition
Description: Windows(R) Operating System, VOLUME_KMSCLIENT channel
License Status: Licensed
Remaining Windows rearm count: 1001
```

Ключи: `/dli` — кратко, `/dlv` — подробно (канал, оставшиеся переактивации, KMS-сервер и порт), `/xpr` — когда истекает. Точные формулировки строк зависят от редакции и канала `[ПРОВЕРИТЬ под свою редакцию]`. Ещё: `/ato` — активировать сейчас, `/ipk <ключ>` — ввести ключ, `/skms <сервер:1688>` — задать KMS, `/ckms` — сбросить, `/rearm` — сбросить счётчик активации.

**6. `DISM` — что за редакции внутри образа и какая стоит сейчас.**

```cmd
DISM /Online /Get-CurrentEdition
DISM /Get-WimInfo /WimFile:D:\sources\install.wim
DISM /Online /Get-TargetEditions
```

`/Get-WimInfo` показывает список редакций в ISO (Home/Pro/Enterprise) — это отвечает на вопрос «а Enterprise в образе вообще есть?». Если в ISO лежит `install.esd`, команда тоже работает.

**7. `bcdedit` — чем реально грузится система.**

```cmd
bcdedit /enum {current}
bcdedit /enum firmware
```

```text
path                    \WINDOWS\system32\winload.efi
```

`winload.efi` — UEFI, `winload.exe` — Legacy. Второй взгляд — `device partition=C:` и наличие `{bootmgr}`.

**8. Логи установки.**

```powershell
Get-WinEvent -LogName Setup -MaxEvents 20 | Format-Table TimeCreated,Id,LevelDisplayName,Message -Wrap
Get-Content C:\Windows\Panther\setupact.log -Tail 40
Select-String -Path C:\Windows\Panther\setuperr.log -Pattern "error" -SimpleMatch
```

`Setuperr.log` маленький и злой — там только ошибки. Если его нет, значит установка прошла без явных сбоев.

**9. Linux: проверка ISO и запись флешки.** На UBU01 (если он уже стоит) или на любом Linux.

```bash
sha256sum ~/ISO/Win11_Enterprise.iso
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
sudo dd if=~/ISO/Win11_Enterprise.iso of=/dev/sdb bs=4M status=progress oflag=sync
```

`sha256sum` сверяем с хешем на странице загрузки. `lsblk` — критично: `/dev/sdb` должен быть **флешкой**, а не вашим диском с данными. `dd` пишет побайтово и не спрашивает подтверждений. Для UEFI такой флешки обычно достаточно; для Legacy-BIOS запись через `dd` может не загрузиться — тогда нужен Rufus/WoeUSB `[ПРОВЕРИТЬ под ваш образ]`.

**10. Контрольная сумма на Windows.**

```powershell
Get-FileHash .\Win11_Enterprise.iso -Algorithm SHA256 | Format-List
```

**11. `mbr2gpt` — конвертация MBR → GPT без потери данных** (Windows 10 1703+, диск с ≤3 разделами, UEFI-прошивка).

```cmd
mbr2gpt /validate /disk:0 /allowFullOS
mbr2gpt /convert  /disk:0 /allowFullOS
```

Сначала **всегда** `validate` и полный бэкап. После конвертации нужно переключить прошивку в UEFI-режим, иначе система не загрузится.

## 5. Лабораторная работа

### Предусловия

- **WIN11-CL01** — в этой лабораторной мы её и создаём (это модуль установки ОС). Если у вас она уже стоит — лабораторная превращается в тренировку переустановки: снапшот, установка с форматированием, проверка, откат.
- **UBU01** — опционально, если уже установлен: пригодится для `sha256sum`/`dd`. Если его нет — пропускаем шаги с Linux, они не обязательны.
- **DC01 не нужен.** Сеть и DHCP появятся в сетевых темах позже; на этом уроке сетевой адаптер ВМ можно держать отключённым.
- ISO: **Windows 11 Enterprise Evaluation** (90 дней, Evaluation Center Microsoft). Только официальный образ. Если скачивание из РФ недоступно `[ПРОВЕРИТЬ актуальный статус]` — легальный вариант: использовать образ, выданный работодателем/учебным центром, а разметку и Linux-часть тренировать на Ubuntu/Astra.
- VMware Workstation с поддержкой виртуального TPM (16.2+) `[ПРОВЕРИТЬ версию у себя]`.

### Снапшот

ВМ WIN11-CL01 ещё нет — снимаем снапшот **сразу после создания ВМ с пустым диском**, это и будет точка «до».

```text
VMware Workstation -> правый клик по ВМ -> Snapshot -> Take Snapshot
Имя: before-l1-014
```

Или из командной строки хоста:

```cmd
"C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe" snapshot "C:\VMs\WIN11-CL01\WIN11-CL01.vmx" before-l1-014
```

### Шаги

1. **Хост, проводник.** Скачать ISO Windows 11 Enterprise Evaluation. Проверить SHA256: `Get-FileHash .\Win11_Enterprise.iso -Algorithm SHA256` (или `sha256sum` на UBU01). **Ожидаемо:** хеш совпал с сайтом.
2. **VMware → File → New Virtual Machine → Custom.** «I will install the operating system later» → Guest OS: Microsoft Windows, Windows 11 x64 → имя `WIN11-CL01`, путь `C:\VMs\WIN11-CL01` → Firmware type: **UEFI**, галочка **Secure Boot** → 2 vCPU, 4 ГБ RAM, 60 ГБ диск (NVMe или SCSI), сеть **NAT (VMnet8)**.
3. **VM Settings → Hardware → Add → Trusted Platform Module.** Без vTPM установщик Win11 откажется ставиться. **Ожидаемо:** в списке устройств появился TPM 2.0.
4. **CD/DVD → Use ISO image file** → указать ISO, галочка «Connect at power on».
5. **Снапшот `before-l1-014`** (см. выше). **Ожидаемо:** в Snapshot Manager одна запись.
6. **Power On.** Появляется «Press any key to boot from CD or DVD» — успеть нажать клавишу. **Ожидаемо:** синий экран установщика, выбор языка.
7. **«Установить сейчас» → «У меня нет ключа продукта»** (для Evaluation ключ обычно не спрашивают) → выбрать редакцию **Windows 11 Enterprise (Evaluation)** → принять лицензию → **«Выборочная установка»**.
8. **На экране выбора диска — `Shift+F10`**, в чёрном окне:

```cmd
diskpart
list disk
select disk 0
detail disk
list partition
exit
exit
```

**Ожидаемо:** один диск 60 ГБ, строки о разделах отсутствуют, «Тип разделов диска» пустой/RAW. Закрываем два окна и возвращаемся в установщик.
9. **Выбрать «Незанятое пространство» → «Далее».** Setup сам создаст ESP, MSR, раздел Windows и раздел восстановления. **Ожидаемо:** копирование файлов, несколько перезагрузок (ISO при перезагрузке не нажимаем — грузимся с диска).
10. **OOBE.** Регион «Россия» → раскладка → при запросе сети выбираем **«У меня нет Интернета»** → **«Продолжить с ограниченной настройкой»** (в Enterprise доступно; в свежих сборках путь может отличаться `[ПРОВЕРИТЬ под свою сборку]`).
11. **Создать локальную учётную запись** `ivanov`, пароль `Lab#2026-vektor`. Контрольные вопросы — любые осмысленные ответы, **обязательно записать их в `stand-log.md`** (иначе пароль не восстановить). Отключить все «рекламные» галочки приватности.
12. **Первый вход.** Задать имя компьютера: `Rename-Computer -NewName WIN11-CL01 -Restart` (или Параметры → Система → О системе → «Переименовать этот компьютер»). **Ожидаемо:** после перезагрузки имя WIN11-CL01.
13. **Проверить режим и разметку:** `Get-ComputerInfo | Select BiosFirmwareType`, `Confirm-SecureBootUEFI`, `Get-Disk | ft Number,PartitionStyle`. **Ожидаемо:** Uefi, True, GPT.
14. **Проверить активацию:** Параметры → Система → **Активация**; в консоли `cscript //nologo %windir%\System32\slmgr.vbs /dlv`. **Ожидаемо:** редакция Enterprise, Evaluation, виден оставшийся срок (около 90 дней).
15. **Установить VMware Tools** (VM → Install VMware Tools): аналог «пакета драйверов производителя» на реальном железе. Перезагрузка.
16. **Записать изменения в `stand-log.md`** и поставить снапшот `after-l1-014`.

> **Срочность:** Высокая (блокирует работу), данные не под угрозой — машина новая.

**Как воспроизвести поломку.** Загрузиться с ISO → `Shift+F10` → `diskpart` → `select disk 0` → `clean` → `exit` → перезагрузиться с диска. Получаем ровно ту надпись, что в тикете.

**Диагностика по шагам.**

1. **Не верить формулировке, проверить самому.** В VMware: VM → Power → **Power On to Firmware** → в UEFI-меню Boot посмотреть, виден ли диск и в каком порядке загрузка. Если первым стоит CD/DVD — это не «поломка диска», а порядок загрузки.
2. **Проверить настройки ВМ.** Firmware type = UEFI (не переключился ли на BIOS), ISO подключён и «Connect at power on» снят? Тип диска SCSI/NVMe не менялся?
3. **Загрузиться с ISO → `Shift+F10` → `diskpart` → `list disk` → `select disk 0` → `detail disk` → `list partition`.** Ожидаемо: диск есть, но разделов нет (`clean` всё убрал). Вывод: загрузчику не с чего стартовать.
4. **Если разделы есть, но нет ESP** (`list partition` показывает Basic + Recovery, но не System) — загрузчик стоит в Legacy-режиме либо ESP повреждён. Лечится восстановлением, не переустановкой: `bcdboot C:\Windows /s S: /f UEFI` (букву S предварительно назначить ESP через `diskpart`).
5. **Если есть разделы и Windows, но загрузка падает** — проверить `bcdedit /enum` из WinRE. Осторожно: `bootrec /fixboot` на UEFI часто отвечает «Отказано в доступе» — это нормально, для UEFI правильный инструмент `bcdboot` `[ПРОВЕРИТЬ под свою сборку WinRE]`.
6. **Наш случай (диск пуст, данных нет) → штатная переустановка.** Шаги 6–13 лабораторной заново. Это не «костыль»: на новом ПК без данных переустановка — самое быстрое и предсказуемое решение.

**Решение.** Переустановка с нуля по шагам 6–15, затем проверка активации и имени компьютера.

**Ответ пользователю:**

> «Иван, добрый день. Машину посмотрел: железо целое, данные не пострадали — она новая, просто установка не завершилась из-за отключения питания. Переустанавливаю систему, займёт около часа. Как только закончу — напишу и вместе проверим, что всё открывается. Если что-то нужно срочно — скажите, подберём, где поработать.»

**Закрытие заявки.** Категория: «ОС / установка и восстановление». Причина: прерывание питания во время установки. В комментарий — что сделано и что проверено. Профилактика: подключить ПК через ИБП (см. урок 10) и не выключать питание во время установки и обновлений.

## 6. Ошибки новичков и безопасность

1. **`dd`/Rufus не на ту флешку** → затёртый внешний диск или, хуже, диск с данными. → Всегда `lsblk` / «Проверить устройство» перед запуском, отключать лишние накопители.
2. **`clean` на диске с данными** → потеря всего раздела за секунду, восстановление только через восстановление данных. → Перед `clean` смотреть `list disk` и `detail disk`, физически отключать рабочие диски.
3. **Переустановка «в лоб» при проблемах с загрузкой** → теряются данные пользователя, которые можно было спасти. → Сначала загрузиться с Live-среды и снять данные, потом ставить.
4. **Игнорирование режима прошивки** → создали ВМ в BIOS-режиме, установщик ругается на TPM/Secure Boot, либо система ставится в Legacy и потом «не видит» GPT-диски. → Проверять `BiosFirmwareType` до и после установки.
5. **Активация «ключом из интернета» или KMS-эмулятором** → нарушение лицензии, отсутствие обновлений, риск трояна в «активаторе», а в компании — дисциплинарка и претензии. → Только официальные каналы: OEM/Retail/MAK/KMS, Evaluation для тестов.
6. **Не проверить активацию после установки** → через 90 дней (Evaluation) или 180 (KMS) ПК начинает регулярно напоминать об истечении, а после истечения — ограничивать работу. → `slmgr /dlv` в чек-лист приёмки ПК.
7. **Клонирование без подготовки (sysprep)** → одинаковые имена и настройки в сети, конфликты в домене. → Использовать `sysprep /generalize /oobe /shutdown` перед снятием эталонного образа.
8. **Переустановка без учёта BitLocker** → данные на диске не читаются без ключа восстановления, а ключ был в AD. → Перед любыми работами проверять `manage-bde -status` и сохранять ключ.

**Безопасность.** Не отключайте Secure Boot и не переводите ПК в Legacy «чтобы ставилось» — это снижает защиту от подмены загрузчика. Не оставляйте пользователю локального администратора и не пишите пароль на стикере под клавиатурой. Не используйте сборки «Windows 11 от Василия» — там нет обновлений и часто есть сюрпризы. И помните: при переустановке вы уничтожаете всё, что было на системном разделе, включая чужие файлы, — согласование с пользователем и бэкап обязательны.

## 7. Вопросы на собеседовании

**1. «Чем GPT отличается от MBR и что вы выберете для Windows 11?»**
Ответ: MBR — 4 первичных раздела и ~2 ТБ, таблица в одном секторе без резерва; GPT — до 128 разделов, огромные объёмы, резервная копия таблицы и CRC-проверка, работает с UEFI. Windows 11 требует UEFI + Secure Boot + TPM 2.0, значит GPT. Проверяется через `Get-Disk`/`msinfo32`.
*Что хочет услышать:* что кандидат связывает разметку с режимом прошивки, а не просто заучил цифры.
*Красный флаг:* «GPT быстрее» или «GPT — это файловая система».

**2. «Пользователь после переустановки жалуется, что Windows просит активацию. Ваши действия?»**
Ответ: `slmgr /dlv` — смотрю редакцию, канал, статус. Если OEM — ключ в прошивке, проверяю, что редакция совпадает с той, что была (частая ошибка — поставили Pro вместо Home). Если корпоративный ПК — проверяю, доменный ли он, доступен ли KMS (`nslookup -type=SRV _vlmcs._tcp`), открыт ли TCP 1688, затем `slmgr /ato`. Ключи из интернета не ввожу.
*Что хочет услышать:* порядок «сначала выяснить канал и статус, потом действовать», знание `/dlv` и KMS.
*Красный флаг:* «Скачаю активатор» или «введу любой ключ из сети».

**3. «Как определить, в каком режиме загрузилась система — UEFI или Legacy?»**
Ответ: `msinfo32` → «Режим BIOS»; `Confirm-SecureBootUEFI`; `bcdedit /enum {current}` → `winload.efi` против `winload.exe`; наличие ESP (`Get-Partition`, тип System, FAT32); `Get-Disk` → PartitionStyle.
*Что хочет услышать:* несколько независимых способов, а не один.
*Красный флаг:* «По логотипу при загрузке».

**4. «Клиент приносит ноутбук: "не грузится, был синий экран". Ваши первые шаги?»**
Ответ: уточняю, что менялось (обновление, драйвер, новое ПО), есть ли бэкап; проверяю, читается ли диск (SMART — урок 8), пробую WinRE / безопасный режим / точку восстановления (урок 22); при необходимости снимаю данные с Live-среды. Переустановка — крайняя мера и только после согласования.
*Что хочет услышать:* «сначала данные и диагностика, потом установка» — это главный навык L1.
*Красный флаг:* «Сразу переставлю Windows».

**5. «Что такое KMS и почему нельзя активировать Windows "ключом из интернета"?»**
Ответ: KMS — внутренний сервер активации, к которому клиенты обращаются по DNS-записи `_vlmcs._tcp` через TCP 1688; активация живёт 180 дней, клиент продлевает каждые 7 дней; серверу нужно набрать минимум 25 клиентов Windows. Ключи из интернета — это либо чужие MAK (исчерпают чужой лимит и нарушают договор), либо GVLK, которые без своего KMS ничего не дают, либо пиратские активаторы с вредоносным кодом.
*Что хочет услышать:* разницу между лицензией и активацией и понимание, что «бесплатная активация» = нарушение.
*Красный флаг:* «KMS — это взлом» или «GVLK активирует сам».
