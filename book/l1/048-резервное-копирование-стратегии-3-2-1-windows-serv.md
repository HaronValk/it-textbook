# Резервное копирование: стратегии 3-2-1, Windows Server Backup, Veeam, восстановление

## 1. Введение (зачем это нужно в реальной работе)

Понедельник, 9:12. В учебной заявке `C:\Support\Tickets` появляется сообщение от Марии Петровой (HR, WIN10-CL02): «Здравствуйте! В пятницу вечером пропал файл с расчётом отпусков — я его точно сохраняла на рабочий стол. В бухгалтерии сказали, что у вас есть бэкапы. Можно восстановить? Очень срочно, отчёт сдавать сегодня». Срочность: высокая.

В реальной работе L1 такая заявка — почти рутина. Кто-то удалил файл, кто-то перезаписал его нулевой версией, кто-то «нажал не туда» и снёс папку. Иногда диск умирает целиком, иногда сервер не поднимается после обновления. И тогда единственный вопрос, который имеет значение: **есть ли копия и можно ли её быстро вернуть**. Именно поэтому в любой компании с более-менее серьёзной инфраструктурой резервное копирование — не «когда-нибудь потом», а обязательный процесс с расписанием, проверками и ответственным.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Резервное копирование — это процесс создания и хранения копий данных, из которых можно восстановить исходное состояние системы или файлов. Ключевые понятия:

- **Полная копия (full)** — копия всех данных целиком. Долго, много места, но восстанавливается просто.
- **Инкрементная (incremental)** — копия только того, что изменилось с прошлого раза (полного или инкрементного). Быстро, но для восстановления нужна вся цепочка.
- **Дифференциальная (differential)** — копия всего, что изменилось с последней полной. Компромисс: восстанавливать проще, чем инкремент, но копия растёт.
- **Точка восстановления (recovery point)** — конкретный момент времени, к которому можно откатиться.
- **RPO (Recovery Point Objective)** — сколько данных допустимо потерять (например, «не больше суток»). Определяет частоту копий.
- **RTO (Recovery Time Objective)** — за сколько допустимо восстановиться. Определяет, насколько быстрым должен быть процесс.

**Стратегия 3-2-1** — золотое правило, которое придумал фотограф Питер Крон в 2009 году. Звучит так:

- **3** копии данных (одна рабочая + две резервные);
- **2** разных носителя (например, диск сервера и внешний диск или лента);
- **1** копия вне площадки (offsite — в другом здании, в облаке, на удалённом сервере).

Смысл: если сгорит сервер — есть копия на другом носителе; если сгорит здание — есть копия вне площадки. На нашем стенде мы сделаем упрощённый вариант: рабочая система + копия на отдельном виртуальном диске (это уже 2 копии на 2 носителях). Offsite на домашнем стенде — теория.

Схема того, как это выглядит в «Векторе»:

```text
   ┌──────────────────────┐         ┌──────────────────────┐
   │  DC01 (10.10.10.10)  │         │  FS01 (10.10.10.20)  │
   │  AD DS, DNS, DHCP    │         │  Файлы, печать       │
   │  системный диск C:   │         │  системный диск C:   │
   └──────────┬───────────┘         └──────────┬───────────┘
              │                                │
              │ Windows Server Backup          │ Windows Server Backup
              │ (полная копия раз в сутки)     │ (полная копия раз в сутки)
              ▼                                ▼
   ┌──────────────────────┐         ┌──────────────────────┐
   │  Доп. виртуальный    │         │  Доп. виртуальный    │
   │  диск (VHDX) на ВМ   │         │  диск (VHDX) на ВМ   │
   │  (не системный)      │         │  (не системный)      │
   └──────────────────────┘         └──────────────────────┘

   Offsite-копия (3-2-1): теория, в лаборатории не делаем
```

**Windows Server Backup (WSB)** — встроенная оснастка Windows Server. Умеет делать копии томов, папок, системного состояния (System State) и «голого железа» (Bare Metal Recovery). Работает через службу `wbengine`, хранит копии в формате VHD/VHDX (то есть копия — это виртуальный диск, который можно даже примонтировать и посмотреть). Настраивается через GUI (`wbadmin.msc`) или PowerShell-модуль `WindowsServerBackup`. Ключевая команда — `wbadmin`.

**Veeam Backup & Replication** — коммерческий продукт, стандарт де-факто в российских компаниях для виртуальных сред (VMware, Hyper-V). Умеет делать копии целых ВМ, репликацию, мгновенное восстановление, дедупликацию. На L1 тебе не нужно его настраивать — но нужно понимать, что «бэкап Veeam» — это отдельная инфраструктура, и заявки «восстановите файл из Veeam» идут через L2/сисадмина. На стенде Veeam — только теория (лицензия платная; для учебных целей есть бесплатная Veeam Backup & Replication Community Edition [ПРОВЕРИТЬ актуальные условия на сайте вендора]).

**Восстановление** — обратный процесс. Бывает трёх уровней:
1. **Файл/папка** — восстановить отдельный файл из копии (самый частый случай на L1).
2. **Системное состояние** — реестр, AD, SYSVOL, сертификаты (для контроллера домена — критично).
3. **Bare Metal Recovery** — восстановить сервер с нуля на чистое железо.

## 3. Аналогия из жизни

Представь, что ты пишешь книгу. Ты держишь рукопись на рабочем столе (рабочая копия). Раз в день ты фотографируешь все страницы и складываешь фотографии в сейф в соседней комнате (вторая копия на другом носителе). А ещё раз в неделю отвозишь копию фотографий родителям в другой город (offsite). Если ты случайно зальёшь рукопись кофе — достанешь вчерашнюю фотографию и восстановишь почти всё. Если сгорит квартира — поедешь к родителям. Если сгорит и квартира, и дом родителей — ну, тогда ты сам виноват, что не сделал третью копию. Аналогия перестаёт работать в одном месте: фотография — это снимок на конкретный момент, а инкрементные бэкапы — это цепочка, и если потерять одно звено, вся цепочка после него может стать бесполезной.

## 4. Практика и команды

### 4.1. Посмотреть текущее состояние резервного копирования (PowerShell)

```powershell
Get-WBSummary
```

Показывает последнюю копию, следующую по расписанию, статус. Вывод примерный:

```text
LastSuccessfulBackupTime : 15.03.2026 02:00:00
LastBackupTarget         : Backup Disk (E:)
NextBackupTime           : 16.03.2026 02:00:00
LastBackupResult         : Success
```

Смотреть: `LastBackupResult` (Success/Failed) и `LastSuccessfulBackupTime` — если последняя успешная копия старше суток, это тревога.

### 4.2. Список доступных копий (wbadmin)

```cmd
wbadmin get versions
```

Вывод примерный:

```text
Backup time: 15.03.2026 02:00
Backup location: Backup Disk (E:)
Version identifier: 03/15/2026-02:00
Can recover: Volume(s), File(s), Application(s), Bare Metal Recovery, System State
```

Смотреть: дату и `Version identifier` — он понадобится для восстановления.

### 4.3. Список элементов внутри копии

```cmd
wbadmin get items -version:03/15/2026-02:00
```

Показывает тома и компоненты, которые есть в этой копии. Полезно, когда не уверен, попал ли нужный том в бэкап.

### 4.4. Запустить копию вручную (GUI)

Путь: **Server Manager → Tools → Windows Server Backup → Local Backup → Backup Once…** Дальше мастер: тип (Full server / Custom / System state), куда (Backup Disk / Remote shared folder), подтверждение. На L1 чаще всего используется именно GUI — это быстрее и меньше шансов ошибиться в ключах.

### 4.5. Запустить копию вручную (PowerShell)

```powershell
$policy = New-WBPolicy
$target = New-WBBackupTarget -Disk (Get-WBDisk | Where-Object { $_.DiskNumber -eq 1 })
Add-WBBackupTarget -Policy $policy -Target $target
Add-WBSystemState -Policy $policy
Start-WBBackup -Policy $policy
```

`New-WBPolicy` создаёт политику, `New-WBBackupTarget` указывает, куда копировать, `Add-WBSystemState` добавляет системное состояние, `Start-WBBackup` запускает. Для полной копии вместо `Add-WBSystemState` используй `Add-WBVolume -Policy $policy -Volume (Get-WBVolume -AllVolumes)` [ПРОВЕРИТЬ синтаксис в твоей версии модуля].

### 4.6. Восстановить файл из копии (wbadmin)

```cmd
wbadmin start recovery -version:03/15/2026-02:00 -itemType:File -items:"C:\Users\petrova\Desktop\otpusk.xlsx" -recoveryTarget:"C:\Restore" -notRestoreAcl
```

Ключи: `-version` — из `get versions`, `-itemType:File` — восстанавливаем файл, `-items` — путь в копии, `-recoveryTarget` — куда положить (лучше в отдельную папку, не поверх оригинала), `-notRestoreAcl` — не восстанавливать NTFS-права (на L1 безопаснее). После восстановления файл появится в `C:\Restore\...` — его можно отдать пользователю.

### 4.7. Восстановить системное состояние (для DC01)

```cmd
wbadmin start systemstaterecovery -version:03/15/2026-02:00 -quiet
```

`-quiet` — без интерактивных подтверждений. **Осторожно:** восстановление System State на контроллере домена — операция уровня L2/сисадмина, на L1 её не делают без разрешения. Команда приведена для понимания.

### 4.8. Проверить, что копия читается (mount)

```cmd
wbadmin get versions -backupTarget:E:
```

Проверка, что диск с копиями доступен и копии на нём видны. Если команда не находит копий — проблема с диском или с правами.

### 4.9. Linux: посмотреть, что занимает место (для будущих серверов)

```bash
sudo du -sh /var/backups
sudo ls -la /var/backups
```

На UBU01 пока нет системы бэкапов, но привычка проверять размер и содержимое папки с копиями — полезная. `du -sh` — размер папки, `ls -la` — содержимое с правами.

### 4.10. События службы WSB

```powershell
Get-WinEvent -LogName 'Microsoft-Windows-Backup/Operational' -MaxEvents 20
```

Показывает последние события службы резервного копирования. Смотреть: ошибки (`Level 2`) и предупреждения (`Level 3`).

**Диагностика по шагам:**

1. **Уточни у пользователя:** что именно не открывается — папка целиком или конкретный файл; какая ошибка дословно; когда началось. Мария говорит: «папка целиком, вчера работало».

    ```powershell
    Get-ADGroupMember -Identity GG-HR
    ```
    Ожидаемо: в списке есть `petrova`. Значит, группа на месте, дело в правах на папку.
4. **Проверь NTFS-права на папке.** На FS01:

    Ожидаемо: в `Access` нет записи для `VEKTOR\GG-HR`. Это и есть причина.

**Решение:**

1. На FS01 верни разрешение для `GG-HR`:
    ```powershell

    $acl.AddAccessRule($rule)
    Set-Acl C:\Shares\HR $acl
    ```

## 6. Ошибки новичков и безопасность

1. **Ошибка:** делать бэкап на тот же диск, где лежат данные.
   **К чему приводит:** при отказе диска теряются и данные, и копии.
   **Как правильно:** отдельный физический или виртуальный диск, отдельный сервер, отдельное хранилище. На стенде — отдельный VHDX `E:`.

2. **Ошибка:** настроить расписание и ни разу не проверить восстановление.
   **К чему приводит:** в момент аварии выясняется, что копии битые или неполные.
   **Как правильно:** раз в месяц (или чаще) делать тестовое восстановление файла в отдельную папку. На стенде — шаги 8–10 лабораторной.

3. **Ошибка:** восстанавливать файл «поверх» оригинала.
   **К чему приводит:** если восстанавливаешь не тот файл или не ту версию — теряешь текущую рабочую копию.
   **Как правильно:** всегда восстанавливать в отдельную папку (`C:\Restore`), проверять содержимое, потом отдавать пользователю.

4. **Ошибка:** делать копию System State на контроллере домена без понимания последствий.
   **К чему приводит:** восстановление System State на DC откатывает AD, пароли, GPO — может «сломать» домен.
   **Как правильно:** на L1 — только по инструкции L2/сисадмина, с предварительным согласованием.

5. **Ошибка:** хранить пароль от хранилища бэкапов в текстовом файле рядом с бэкапом.
   **К чему приводит:** компрометация хранилища.
   **Как правильно:** пароли — в защищённом хранилище (на стенде — только учебные, в реальной работе — менеджер паролей или сейф).

6. **Ошибка:** считать, что «бэкап есть — значит, всё хорошо».
   **К чему приводит:** копия может быть старой (RPO не соблюдается), неполной (не тот том), недоступной (диск отключён).
   **Как правильно:** проверять `Get-WBSummary`, `wbadmin get versions`, журнал событий.

7. **Ошибка:** делать копию во время активной работы с файлами (например, 1С в файловом режиме).
   **К чему приводит:** копия может быть «грязной» — файл в момент копирования изменялся.
   **Как правильно:** для баз данных — специальные агенты или VSS-aware копии; для файлов — копия в нерабочее время.

### Безопасность

- **Нельзя** хранить резервные копии на том же сервере, где данные, в боевой среде — это не бэкап, а «вторая копия на том же диске».
- **Нельзя** давать пользователям доступ к хранилищу бэкапов — они могут случайно удалить копии.
- **Нельзя** восстанавливать System State на DC без согласования — это операция уровня L2/сисадмина.
- **Нельзя** использовать пиратские версии Veeam или «кряки» — только evaluation, Community Edition или легальная лицензия.
- **Нельзя** пренебрегать шифрованием бэкапов, если они уезжают offsite (в реальной работе — обязательно; на стенде — теория).

## 7. Вопросы на собеседовании

**Вопрос 1. Что такое стратегия 3-2-1 и зачем она нужна?**
*Как спросят:* «Расскажите про правило 3-2-1 в резервном копировании».
*Ответ:* «Три копии данных, две на разных носителях, одна вне площадки. Смысл — защититься от разных сценариев: отказ диска, отказ сервера, пожар в здании. На стенде я делал упрощённый вариант: рабочая система + копия на отдельном виртуальном диске, offsite — теория».
*Что хочет услышать интервьюер:* понимание, что бэкап — это не «одна копия на том же диске», а многоуровневая защита.
*Красный флаг:* «Делаю копию на тот же диск, чтобы быстрее».

**Вопрос 2. Чем отличается полная, инкрементная и дифференциальная копия?**
*Как спросят:* «Какие бывают типы резервных копий?»
*Ответ:* «Полная — все данные целиком, восстанавливается просто, но долго и много места. Инкрементная — только изменения с прошлого раза, быстро, но для восстановления нужна вся цепочка. Дифференциальная — всё, что изменилось с последней полной, компромисс: восстанавливать проще, чем инкремент, но копия растёт».
*Что хочет услышать интервьюер:* понимание компромисса между скоростью, местом и сложностью восстановления.
*Красный флаг:* путаница между инкрементной и дифференциальной.

**Вопрос 3. Как восстановить отдельный файл из копии Windows Server Backup?**
*Как спросят:* «Пользователь удалил файл, у вас есть бэкап. Ваши действия?»
*Ответ:* «Сначала `wbadmin get versions` — нахожу нужную версию. Потом `wbadmin start recovery` с `-itemType:File`, `-items` — путь к файлу в копии, `-recoveryTarget` — отдельная папка, например `C:\Restore`, `-notRestoreAcl` — чтобы не тащить старые права. Восстанавливаю в отдельную папку, проверяю содержимое, потом отдаю пользователю. Не восстанавливаю поверх оригинала».
*Что хочет услышать интервьюер:* аккуратность, понимание, что восстановление — не «нажал кнопку», а последовательность с проверкой.
*Красный флаг:* «Восстановлю сразу поверх, чтобы быстрее».

**Вопрос 4. Что такое Veeam и почему на L1 его не настраивают?**
*Как спросят:* «Знакомы с Veeam?»
*Ответ:* «Veeam Backup & Replication — коммерческий продукт для резервного копирования виртуальных сред, стандарт в российских компаниях. На L1 его не настраивают — это зона L2/сисадмина. Но L1 должен понимать, что заявки "восстановите файл из Veeam" идут через L2, и уметь правильно их эскалировать».
*Что хочет услышать интервьюер:* честность («не настраивал, но понимаю, что это») и понимание границ своей роли.
*Красный флаг:* «Да, я всё настрою» — без опыта.

**Вопрос 5. Как проверить, что резервное копирование работает?**
*Как спросят:* «Как вы убеждаетесь, что бэкапы в порядке?»
*Ответ:* «Смотрю `Get-WBSummary` — последняя успешная копия, следующая по расписанию, результат. Проверяю `wbadmin get versions` — есть ли свежие версии. Смотрю журнал `Microsoft-Windows-Backup/Operational` на ошибки. И раз в месяц делаю тестовое восстановление файла в отдельную папку — это единственный способ убедиться, что копия реально читается».
*Что хочет услышать интервьюер:* что ты не веришь «зелёной галочке», а проверяешь восстановление.
*Красный флаг:* «Если расписание настроено — значит, работает».
