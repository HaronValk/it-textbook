# Драйверы и устройства: диспетчер устройств, откат драйвера, диагностика BSOD

## 1. Введение (зачем это нужно в реальной работе)

В 9 случаях из 10 причина — драйвер (программа, которая объясняет Windows, как общаться с конкретным железом) или само железо. Твоя задача как L1: не переустанавливать Windows «на всякий случай», а за 10–15 минут выяснить, что именно упало, откатить или обновить драйвер, вернуть человека в работу и записать в заявку, что сделал.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**Что такое драйвер.** Драйвер — это файл (обычно `.sys` для ядра, `.inf` — файл установки с описанием устройства) плюс запись в реестре. Windows не умеет напрямую «разговаривать» с видеокартой, принтером или чипсетом — она загружает драйвер, который знает язык конкретного устройства. Драйверы работают в режиме ядра (kernel mode), то есть с полными правами. Поэтому кривой драйвер может уронить всю систему — в отличие от кривой программы, которая просто закроется.

**Откуда берутся драйверы.** Три источника:
1. Встроенные в Windows (inbox) — универсальные, работают «из коробки», но без фирменных фишек.
2. От производителя устройства (Intel, AMD, NVIDIA, Realtek, HP…) — обычно лучшие, но иногда с багами.
3. Из Центра обновления Windows (Windows Update) — Microsoft подписывает и раздаёт проверенные версии. В уроке 20 ты уже видел, что обновления могут приносить и драйверы.

**Как Windows понимает, что устройство есть.** При старте и при подключении нового железа работает PnP (Plug and Play, «включил и работает»). Windows опрашивает шины (PCIe, USB), получает от устройства идентификаторы (VENdor ID и DEVice ID), ищет подходящий драйвер в своей базе и в Windows Update, ставит и запускает. Если не нашла — устройство помечается как «неизвестное», в Диспетчере устройств появляется жёлтый треугольник.

**Что такое BSOD.** Когда драйвер в режиме ядра делает что-то недопустимое (обращается к чужой памяти, зацикливается, падает), ядро Windows не может просто «убить» его, как обычную программу — он же часть ядра. Поэтому система останавливается целиком, показывает синий экран с кодом остановки (Bug Check Code, например `IRQL_NOT_LESS_OR_EQUAL`, `PAGE_FAULT_IN_NONPAGED_AREA`, `SYSTEM_SERVICE_EXCEPTION`), пишет дамп памяти на диск и перезагружается (если настроено).

**Где искать следы.** Два места:
- `C:\Windows\Minidump\*.dmp` — маленькие дампы (обычно 256 КБ–2 МБ), создаются при каждом BSOD, если включён.
- Журнал событий Windows → «Система» → источник `BugCheck` (Event ID 1001) — там код остановки и параметры.
- `C:\Windows\MEMORY.DMP` — полный дамп, огромный, для L1 обычно не нужен.

**Схема пути драйвера:**

```text
[Железо]  <-- PCIe/USB -->  [Драйвер .sys]  <-- вызовы ядра -->  [Ядро Windows]
                                    |
                                    +--> запись в реестре
                                         HKLM\SYSTEM\CurrentControlSet\Services\<имя>
                                    |
                                    +--> файлы в C:\Windows\System32\drivers\
                                    |
                                    +--> .inf в C:\Windows\INF\ (описание установки)
```

**Порты и протоколы** здесь почти не при чём — драйверы работают внутри машины. Единственное сетевое, что встретится: Windows Update (порт 443, HTTPS) для скачивания драйверов. Всё остальное — локально.

**Три уровня диагностики, которые тебе нужны на L1:**
1. Устройство не работает вообще (нет звука, не видит флешку) → Диспетчер устройств, код ошибки.
2. Устройство работало, после обновления сломалось → откат драйвера.
3. Система падает с BSOD → журнал событий + дамп + анализ кода остановки.

## 3. Аналогия из жизни

Представь, что Windows — это начальник, а устройства — сотрудники из других стран. Начальник не знает ни одного иностранного языка, поэтому на каждого сотрудника держит переводчика — это драйвер. Если переводчик хороший, работа идёт. Если переводчика заменили на стажёра, который путает слова (кривой драйвер), сотрудник начинает делать глупости, и в какой-то момент начальник в панике останавливает весь офис — это BSOD. Откат драйвера — это вернуть старого проверенного переводчика. Диспетчер устройств — это доска, где видно, у кого из сотрудников нет переводчика (жёлтый треугольник). Аналогия перестаёт работать в одном: переводчика можно поменять на лету, а драйвер в режиме ядра иногда нельзя выгрузить без перезагрузки.

## 4. Практика и команды

Все команды ниже выполняются на **WIN10-CL02** (или WIN11-CL01) от локального администратора `adm.student`. Открывай PowerShell «от имени администратора».

**1. Открыть Диспетчер устройств (GUI).**
Путь: правый клик по «Пуск» → «Диспетчер устройств» (Device Manager). Или `Win+R` → `devmgmt.msc`. Смотри: жёлтые треугольники с восклицательным знаком — проблема; стрелка вниз — устройство отключено вручную; «Другие устройства» → «Неизвестное устройство» — нет драйвера.

**2. Список проблемных устройств через PowerShell.**
```powershell
Get-PnpDevice | Where-Object { $_.Status -ne 'OK' } | Format-Table Status, Class, FriendlyName, InstanceId -AutoSize
```
`Get-PnpDevice` — встроенный командлет (есть в Windows 10/11). `Status` бывает `OK`, `Error`, `Unknown`, `Disabled`. `Class` — категория (Display, Net, USB и т.д.). Если список пуст — проблемных устройств нет.

**3. Код ошибки устройства.**
```powershell
Get-PnpDevice -Status Error | Select-Object FriendlyName, Problem, ProblemDescription
```
`Problem` — числовой код (например, 10, 28, 43). Расшифровка: 10 — «устройство не может запуститься», 28 — «драйвер не установлен», 43 — «Windows остановила устройство из-за сбоя». В GUI то же самое: свойства устройства → вкладка «Общие» → «Состояние устройства».

**4. Информация о драйвере конкретного устройства.**
```powershell
Get-PnpDevice -Class Display | Get-PnpDeviceProperty -KeyName 'DEVPKEY_Device_DriverVersion','DEVPKEY_Device_DriverDate','DEVPKEY_Device_DriverProvider'
```
Выводит версию, дату и поставщика драйвера. В GUI: свойства устройства → вкладка «Драйвер» → там же кнопки «Обновить», «Откатить», «Отключить устройство», «Удалить устройство».

**5. Откат драйвера (GUI).**
Свойства устройства → вкладка «Драйвер» → кнопка **«Откатить»** (Roll Back Driver). Активна, только если Windows сохранила предыдущую версию. Если серая — предыдущей версии нет, откатывать нечего, нужно ставить драйвер вручную с сайта производителя.

**6. Откат драйвера через PowerShell (если GUI недоступен).**
```powershell
pnputil /enum-drivers
```
`pnputil` — встроенная утилита управления драйверами. Показывает все сторонние драйверы в хранилище с их `oemXX.inf`. Удалить конкретный: `pnputil /delete-driver oem12.inf /uninstall /force` (осторожно: `/force` снесёт даже используемый). `[ПРОВЕРИТЬ]` точный набор ключей в твоей сборке Windows 10 LTSC.

**7. Журнал событий: найти BSOD.**
```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WER-SystemErrorReporting'} -MaxEvents 5 | Format-List TimeCreated, Id, Message
```
Или проще: `eventvwr.msc` → «Журналы Windows» → «Система» → фильтр «Источник: BugCheck», Event ID 1001. В сообщении будет код остановки и четыре параметра — их полезно скопировать в заявку.

**8. Список дампов памяти.**
```powershell
Get-ChildItem C:\Windows\Minidump\*.dmp | Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, Length, LastWriteTime
```
Если папка пуста — либо BSOD не было, либо дампы отключены (см. п. 9).

**9. Проверить, включены ли дампы.**
```powershell
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CrashControl' | Select-Object CrashDumpEnabled, DumpFile, MiniDumpDir
```
`CrashDumpEnabled`: 0 — нет, 1 — полный, 2 — ядра, 3 — малый, 7 — автоматический. Для L1 достаточно 3 (малый) или 7. Меняется в GUI: «Система» → «Дополнительные параметры системы» → «Дополнительно» → «Запуск и восстановление».

**10. Прочитать дамп через WinDbg (бесплатно из Microsoft Store).**
```text
windbg -z C:\Windows\Minidump\112026-12345-01.dmp
```
Внутри: `!analyze -v`. В выводе смотри строки `BUGCHECK_CODE`, `MODULE_NAME`, `IMAGE_NAME` — там имя виновного драйвера (например, `nvlddmkm.sys`, `rt640x64.sys`). `[ПРОВЕРИТЬ]` синтаксис запуска в твоей версии WinDbg (Store-версия может требовать другой ключ).

**11. Проверить целостность системных файлов (частая причина «необъяснимых» BSOD).**
```powershell
sfc /scannow
```
В CMD от админа. Ищет и восстанавливает повреждённые системные файлы. Занимает 5–15 минут.

**12. Проверить диск на ошибки (тоже триггер BSOD).**
```powershell
chkdsk C: /scan
```
Только чтение, без перезагрузки. Если найдёт ошибки — `chkdsk C: /f` (потребует перезагрузки).

### Шаги

1. **На WIN10-CL02** войди под `adm.student`. Открой PowerShell от админа. Выполни `Get-PnpDevice | Where-Object { $_.Status -ne 'OK' }`. Ожидаемо: пусто или только устройства, которые VMware эмулирует без полного драйвера (например, «Базовое аудиоустройство»). Запиши, что видишь.

2. **Посмотри на видеодрайвер.** `Get-PnpDevice -Class Display | Get-PnpDeviceProperty -KeyName 'DEVPKEY_Device_DriverVersion','DEVPKEY_Device_DriverProvider'`. Ожидаемо: `VMware SVGA II` или `Microsoft Basic Display Adapter` — это драйвер виртуальной видеокарты VMware. Запомни версию.

3. **Смоделируй «проблемное устройство».** В Диспетчере устройств (`devmgmt.msc`) найди «Видеоадаптеры» → правый клик по адаптеру → «Отключить устройство» → «Да». Ожидаемо: экран мигнёт, разрешение может упасть, в Диспетчере появится стрелка вниз.

4. **Проверь через PowerShell.** `Get-PnpDevice -Class Display`. Ожидаемо: `Status = Disabled`. Это то, что ты увидишь в реальной заявке «пропал второй монитор» или «не работает проектор».

5. **Включи обратно.** Правый клик → «Включить устройство». Ожидаемо: разрешение вернётся, статус `OK`.

6. **Смоделируй «кривой драйвер» и откат.** В Диспетчере устройств → «Видеоадаптеры» → свойства адаптера → вкладка «Драйвер» → «Обновить драйвер» → «Выполнить поиск драйверов на этом компьютере» → «Выбрать драйвер из списка уже установленных». Если в списке есть две версии — выбери другую, установи. Ожидаемо: Windows поставит другую версию, кнопка «Откатить» станет активной. `[ПРОВЕРИТЬ]` — на чистой виртуалке VMware в списке может быть только одна версия; тогда откат недоступен, и это нормальный результат — зафиксируй его.

7. **Откати драйвер.** Свойства → «Драйвер» → «Откатить». Ожидаемо: подтверждение, версия возвращается к предыдущей. Проверь `Get-PnpDeviceProperty` — версия должна совпасть с шагом 2.

8. **Настрой дампы памяти.** `Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CrashControl' | Select-Object CrashDumpEnabled`. Если значение не 3 и не 7 — через GUI «Система» → «Дополнительные параметры системы» → «Дополнительно» → «Запуск и восстановление» → «Параметры» поставь «Малый дамп памяти» и путь `%SystemRoot%\Minidump`. Ожидаемо: `CrashDumpEnabled = 3`.

9. **Проверь журнал событий на прошлые BSOD.** `Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WER-SystemErrorReporting'} -MaxEvents 5`. Ожидаемо: пусто (на свежей виртуалке BSOD не было) или одна-две записи, если что-то падало при установке. Запиши результат.

10. **Проверь целостность системы.** `sfc /scannow` в CMD от админа. Ожидаемо: «Защита ресурсов Windows не обнаружила нарушений целостности» или восстановление. Займёт несколько минут.

11. **Проверь диск.** `chkdsk C: /scan`. Ожидаемо: «Windows проверила файловую систему и не обнаружила проблем».

12. **Запиши в `C:\Lab\vektor\stand-log.md`** строку: `2026-XX-XX L1-21: на WIN10-CL02 проверены Диспетчер устройств, откат драйвера (если был), дампы памяти включены (CrashDumpEnabled=3), sfc и chkdsk чисто. Снапшот before-l1-021 снят.`

6. Если кнопка «Откатить» активна — жми. Перезагрузи. Проверь.
7. Если откат недоступен — «Обновить драйвер» → «Автоматический поиск» (Windows Update). Если не помогло — скачай драйвер с сайта производителя (для VMware — VMware Tools, переустанови).

## 6. Ошибки новичков и безопасность

1. **«Переустановлю Windows — быстрее».** → Теряются данные пользователя, настройки, учётки; на реальной работе это часы простоя и разбор с руководителем. → Сначала диагностика: Диспетчер устройств, журнал, дамп. Переустановка — крайний случай и только с согласия пользователя и с бэкапом.
2. **«Откачу драйвер, даже если кнопка серая — нажму посильнее».** → Кнопка серая = предыдущей версии нет; нажатие ничего не даст, а время уйдёт. → Если откат недоступен, ставь драйвер с сайта производителя вручную или через Windows Update.
3. **«Удалю устройство из Диспетчера — вдруг поможет».** → Удаление драйвера без переустановки оставит устройство без драйвера вообще; на ноутбуке можно остаться без Wi-Fi и без возможности скачать драйвер. → Сначала откат, потом обновление, удаление — только с готовым установщиком драйвера под рукой.
4. **«Скопирую дамп в заявку целиком».** → Дампы весят мегабайты, в заявке они не нужны. → Копируй только код остановки, имя драйвера (`IMAGE_NAME`) и время.
5. **«BSOD — это всегда железо, пусть L2 меняет материнку».** → В 80% случаев виноват драйвер или обновление. → Сначала драйверы и `sfc`/`chkdsk`, потом эскалация.
6. **«Отключу проверку подписи драйверов, чтобы поставить старый».** → Это дыра в безопасности; в рабочей среде запрещено политикой. → Ставь только подписанные драйверы от производителя.
7. **«Не запишу в заявку, что делал».** → Следующий инженер начнёт с нуля, пользователь позвонит повторно. → Всегда фиксируй: симптом, действия, результат, время.

**Безопасность.** В боевой среде нельзя: скачивать драйверы с торрентов и «сборников драйверов» (там часто майнеры и бэкдоры); отключать проверку подписи драйверов; ставить драйверы от другой модели устройства «на удачу»; запускать `pnputil /delete-driver ... /force` на рабочей машине без бэкапа. Драйверы ставь только с сайта производителя устройства или из Windows Update. На стенде пароль `Lab#2026-vektor` — учебный; в реальной работе такие пароли недопустимы.

## 7. Вопросы на собеседовании

**Вопрос 1. «Пользователь говорит, что у него синий экран. Что вы сделаете?»**

Ответ: «Сначала уточню, когда это началось и что делали перед этим — обновление, установка программы, новое устройство. Потом посмотрю журнал событий Windows, источник BugCheck, Event ID 1001 — там код остановки. Если есть дамп в `C:\Windows\Minidump`, открою в WinDbg и посмотрю `IMAGE_NAME` — имя драйвера. Параллельно проверю Диспетчер устройств на проблемные устройства и запущу `sfc /scannow` и `chkdsk /scan`. Если виноват драйвер — откачу или обновлю. Если не помогло — эскалирую на L2 с кодом остановки и именем драйвера.»

Что хочет услышать интервьюер: что ты не переустанавливаешь Windows сразу, а идёшь по диагностике; знаешь, где искать код остановки и дамп.

Красный флаг: «Сразу переустановлю Windows» или «BSOD — это железо, пусть меняют».

**Вопрос 2. «Что такое Диспетчер устройств и что вы там смотрите в первую очередь?»**

Ответ: «Это оснастка Windows (`devmgmt.msc`), которая показывает все устройства и их драйверы. В первую очередь смотрю жёлтые треугольники — это проблемные устройства, и „Другие устройства“ — там устройства без драйвера. По каждому проблемному открываю свойства, вкладку „Общие“, и читаю код ошибки: 10 — не запускается, 28 — нет драйвера, 43 — Windows остановила из-за сбоя. Дальше вкладка „Драйвер“ — версия, дата, кнопки „Обновить“ и „Откатить“.»

Что хочет услышать: что ты знаешь коды ошибок и умеешь читать свойства устройства.

Красный флаг: «Просто смотрю, всё ли зелёное» — без конкретики.

**Вопрос 3. «Как откатить драйвер и что делать, если кнопка „Откатить“ неактивна?»**

Ответ: «Свойства устройства → вкладка „Драйвер“ → кнопка „Откатить“. Она активна, только если Windows сохранила предыдущую версию. Если серая — предыдущей версии нет: тогда ставлю драйвер вручную с сайта производителя или через Windows Update, либо переустанавливаю устройство. На стенде я это проверял: на чистой виртуалке VMware в списке часто только одна версия, и откат недоступен — это нормально.»

Что хочет услышать: понимание, что откат — не всегда возможен, и что делать дальше.

Красный флаг: «Всегда откатываю» — без понимания ограничения.

**Вопрос 4. «Где Windows хранит информацию о BSOD и как её прочитать?»**

Ответ: «Два места: журнал событий Windows → „Система“ → источник BugCheck (Event ID 1001) — там код остановки и параметры; и файлы дампов в `C:\Windows\Minidump\*.dmp` (малые) или `C:\Windows\MEMORY.DMP` (полный). Дампы должны быть включены — параметр `CrashDumpEnabled` в реестре, `HKLM\SYSTEM\CurrentControlSet\Control\CrashControl`. Читаю через WinDbg: открываю дамп, команда `!analyze -v`, смотрю `BUGCHECK_CODE` и `IMAGE_NAME`.»

Что хочет услышать: что ты знаешь оба места и умеешь открыть дамп.

Красный флаг: «Дампы — это для разработчиков, я их не трогаю».

**Вопрос 5. «Пользователь говорит, что после обновления Windows пропал звук. Ваши действия?»**

Ответ: «Открою Диспетчер устройств, посмотрю звуковые устройства — если жёлтый треугольник, прочитаю код ошибки. Скорее всего, обновление поставило новый драйвер аудио. Зайду в свойства → „Драйвер“ → посмотрю дату: если она совпадает с датой обновления — откачу. Если откат недоступен — обновлю драйвер через Windows Update или поставлю с сайта производителя. После — перезагрузка и проверка: звук есть. Запишу в заявку, что сделал.»

Что хочет услышать: связку «симптом → устройство → драйвер → откат → проверка → запись».

Красный флаг: «Скажу пользователю купить новую звуковую карту».
