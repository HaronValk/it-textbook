## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

**BIOS** (Basic Input/Output System) — старая прошивка на материнской плате. При включении компьютера процессор первым делом выполняет код из микросхемы прошивки: она проверяет железо, находит загрузочный диск и передаёт управление загрузчику ОС. BIOS работает в 16-битном режиме, имеет ограничения (диски больше 2 ТБ не грузятся в старом режиме, меню мышью не управляется, нет нормальной защиты).

**UEFI** (Unified Extensible Firmware Interface) — современная замена BIOS. Работает в 64-битном режиме, поддерживает большие диски (GPT-разметку), мышь и графическое меню, сетевую загрузку, безопасную загрузку. На всех современных ПК и на всех ВМ твоего стенда используется UEFI. Слово «BIOS» в быту до сих пор говорят про UEFI — привычка, но технически это разные вещи.

**Secure Boot** (безопасная загрузка) — механизм UEFI, который проверяет цифровую подпись загрузчика. Если загрузчик не подписан доверенным ключом (Microsoft, производитель), UEFI отказывается его запускать. Это защита от руткитов (rootkit — вредоносный код, загружающийся до ОС) и от подмены загрузчика. Windows 11 требует Secure Boot включённым.

**TPM** (Trusted Platform Module) — отдельная микросхема (или программный модуль) на материнской плате, которая умеет хранить криптографические ключи и измерять состояние системы. TPM 2.0 — вторая версия стандарта, обязательное требование Windows 11. TPM используется BitLocker (шифрование диска), Windows Hello (вход по PIN/отпечатку), защитой учётных данных. На физическом ПК TPM — это чип; в виртуалке VMware Workstation можно включить **виртуальный TPM** (vTPM), который эмулирует этот чип.

**Требования Windows 11** (упрощённо, для L1):
- 64-битный процессор, 2+ ядра, 1 ГГц+
- 4 ГБ ОЗУ, 64 ГБ диск
- UEFI + Secure Boot
- TPM 2.0
- DirectX 12 / WDDM 2.0 (для видеокарты)

Схема того, что происходит при включении:

```text
Питание → UEFI прошивка
            ├─ проверка железа (CPU, RAM, диски)
            ├─ Secure Boot: проверка подписи загрузчика
            ├─ TPM: измерение состояния (хэши компонентов)
            └─ передача управления загрузчику Windows
                  └─ Windows Boot Manager → ядро → драйверы → рабочий стол
```

Когда Windows 11 запускается, она спрашивает у UEFI: «Secure Boot включён? TPM 2.0 есть?» Если нет — установщик отказывается ставиться, а уже установленная система может ругаться на обновления. Поэтому при создании WIN11-CL01 в VMware Workstation ты включал виртуальный TPM и шифрование ВМ (пароль шифрования — учебный `Lab#2026-vektor`). WIN10-CL02 создавалась без TPM, потому что Windows 10 его не требует.

## 3. Аналогия из жизни

Представь пропускной пункт на заводе. **UEFI** — это современный КПП с турникетами, сканерами и охраной: проверяет документы, сверяет с базой, пускает только своих. **BIOS** — старый вахтёр с бумажным списком: пускает всех, кто назвал фамилию. **Secure Boot** — требование, чтобы у каждого входящего был заверенный пропуск с голограммой: без него не пустят, даже если человек свой. **TPM** — сейф на КПП, где хранятся ключи от важных дверей и журнал, кто когда входил. Windows 11 — это новый цех, куда пускают только через современный КПП, с проверкой пропусков и сейфом. Где аналогия ломается: на заводе охранник — человек и может ошибиться, а Secure Boot — это криптография, ошибиться она не может, но может отказать в запуске легитимному загрузчику, если его ключ не в списке доверенных.

## 4. Практика и команды

Все команды ниже выполняются на **WIN11-CL01** (Windows 11) и **WIN10-CL02** (Windows 10), где применимо. Linux-команды — на **UBU01** (Ubuntu Server 24.04), где это имеет смысл.

**1. Сведения о системе — `msinfo32`**

```powershell
msinfo32
```

Открывает окно «Сведения о системе». Смотри строки:
- `Режим BIOS` — должно быть `UEFI` (если `Legacy` — старый режим).
- `Состояние безопасной загрузки` — `Вкл` или `Выкл`.
- `Виртуализация: включена в прошивке` — влияет на Hyper-V и вложенную виртуализацию.

Вывод примерный, конкретные строки зависят от версии Windows.

**2. Проверка TPM через оснастку — `tpm.msc`**

```powershell
tpm.msc
```

Открывает «Управление доверенным платформенным модулем». Смотри: «Состояние TPM: Готов к использованию» и «Спецификация версии: 2.0». Если написано «TPM не найден» — либо чипа нет, либо он отключён в UEFI.

**3. Проверка TPM через PowerShell**

```powershell
Get-Tpm
```

Ключевые поля: `TpmPresent` (True/False), `TpmReady`, `TpmEnabled`, `ManufacturerIdTxt`. Если `TpmPresent : False` — TPM нет.

**4. Проверка Secure Boot через PowerShell**

```powershell
Confirm-SecureBootUEFI
```

Возвращает `True` или `False`. Если команда падает с ошибкой «командлет не поддерживается на этом компьютере» — система загружена в режиме Legacy BIOS, а не UEFI.

**5. Проверка версии UEFI и режима загрузки**

```powershell
$env:firmware_type
```

Возвращает `UEFI` или `BIOS`. Простой способ быстро понять, в каком режиме загружена система.

**6. Список разделов диска — проверка GPT**

```powershell
Get-Disk
```

Смотри колонку `Partition Style`: `GPT` — современная разметка (нужна для UEFI), `MBR` — старая (для Legacy BIOS). Windows 11 требует GPT.

**7. Проверка требований Windows 11 — `PC Health Check`**

Утилита Microsoft «Проверка работоспособности ПК» (PC Health Check) — отдельная программа, скачивается с сайта Microsoft. Запускается двойным кликом, показывает список требований и что не выполнено. На стенде её можно поставить на WIN11-CL01 для тренировки. [ПРОВЕРИТЬ актуальность ссылки на 2026 год]

**8. Просмотр журнала загрузки UEFI (Linux, UBU01)**

```bash
sudo efibootmgr -v
```

Показывает записи загрузки UEFI. На UBU01, установленной в UEFI-режиме, увидишь строку `BootCurrent: 0001` и запись `ubuntu`. Если команда не найдена — установи пакет `sudo apt install efibootmgr`. Вывод примерный.

**9. Проверка Secure Boot на Linux (UBU01)**

```bash
sudo mokutil --sb-state
```

Возвращает `SecureBoot enabled` или `SecureBoot disabled`. Пакет `mokutil` может быть не установлен — тогда `sudo apt install mokutil`. [ПРОВЕРИТЬ наличие пакета в стандартном репозитории Ubuntu 24.04]

**10. Вход в UEFI виртуальной машины VMware**

В VMware Workstation: выбери ВМ → `VM` → `Power` → `Power On to Firmware` (или удерживай `Esc`/`F2` при старте). Откроется меню UEFI виртуальной машины. Там можно посмотреть порядок загрузки, включить/выключить Secure Boot (в разделе `Boot` или `Security`). Точные пункты меню зависят от версии VMware [ПРОВЕРИТЬ в твоей версии].

## 6. Ошибки новичков и безопасность

1. **Путать BIOS и UEFI.** Говоришь «зайди в BIOS», пользователь ищет старый синий экран, а у него современное графическое меню UEFI. → Правильно: «зайди в настройки прошивки (UEFI), обычно клавиша Del или F2 при включении».
2. **Считать, что TPM — это программа.** TPM — это чип (или vTPM в виртуалке). Его нельзя «установить» драйвером, если чипа нет. → Правильно: проверять `Get-Tpm`, при отсутствии — смотреть UEFI.
3. **Отключать Secure Boot «чтобы заработало».** Это снижает защиту от руткитов и ломает BitLocker (при следующей загрузке система попросит ключ восстановления). → Правильно: выяснить, зачем отключают, искать подписанный загрузчик.
4. **Менять настройки UEFI без записи исходных значений.** Потом не вспомнить, что было. → Правильно: перед изменением сфотографировать экран или записать в `stand-log.md`.
5. **Считать, что раз Windows 10 работает — компьютер подходит для Windows 11.** Требования разные. → Правильно: проверять по списку (UEFI, Secure Boot, TPM 2.0, GPT, 4 ГБ ОЗУ, 64 ГБ диск).
6. **Использовать обходные пути установки Windows 11 (правка реестра, Rufus с обходом TPM).** Microsoft их не поддерживает, обновления могут не приходить, в корпоративной среде это нарушение политики. → Правильно: официальные требования или замена железа.
7. **Забывать, что WIN11-CL01 зашифрована.** `vmrun` без `-vp` для неё не сработает. → Правильно: всегда `vmrun -T ws -vp "Lab#2026-vektor" ...` для WIN11-CL01.

**Безопасность.** В боевой среде нельзя: отключать Secure Boot на рабочих машинах без согласования с ИБ; перепрошивать UEFI «на всякий случай» (риск окирпичить плату); сбрасывать TPM без предупреждения пользователя (потеря ключей BitLocker и Windows Hello); сообщать пользователю пароль шифрования ВМ или ключ восстановления BitLocker по открытым каналам. На стенде пароль `Lab#2026-vektor` — учебный, в реальной работе так нельзя: пароли шифрования и ключи восстановления хранятся в защищённом месте (сейф, менеджер секретов, AD).

## 7. Вопросы на собеседовании

**Вопрос 1. Чем UEFI отличается от BIOS?**
Как задают: «Объясните разницу между BIOS и UEFI, зачем перешли».
Ответ: BIOS — старая 16-битная прошивка с ограничениями (диски до 2 ТБ, нет мыши, нет Secure Boot). UEFI — современная замена: 64-битная, поддерживает GPT-разметку и большие диски, графическое меню, Secure Boot, сетевую загрузку. На всех современных ПК и на учебных ВМ используется UEFI.
Что хочет услышать интервьюер: понимание, что это не «одно и то же под разными названиями», и знание практических следствий (GPT, Secure Boot).
Красный флаг: «UEFI — это просто новое название BIOS, разницы нет».

**Вопрос 2. Что такое Secure Boot и зачем он нужен?**
Как задают: «Пользователь не может загрузиться после установки нестандартного загрузчика — что проверить?»
Ответ: Secure Boot — механизм UEFI, который проверяет цифровую подпись загрузчика. Если подпись не доверенная — загрузка блокируется. Защищает от руткитов и подмены загрузчика. Windows 11 требует его включённым. Если пользователь ставит нестандартный загрузчик (например, кастомную сборку Linux), Secure Boot может его заблокировать — тогда либо подписывать загрузчик, либо отключать Secure Boot (с пониманием рисков).
Что хочет услышать интервьюер: понимание, что Secure Boot — это защита, а не «помеха», и что отключение имеет последствия.
Красный флаг: «Secure Boot всегда надо отключать, он мешает».

**Вопрос 3. Что такое TPM 2.0 и почему Windows 11 его требует?**
Как задают: «Почему Windows 11 не ставится на старый компьютер, хотя Windows 10 работала?»
Ответ: TPM (Trusted Platform Module) — чип или программный модуль для хранения криптографических ключей и измерения состояния системы. TPM 2.0 — вторая версия стандарта. Windows 11 использует его для BitLocker, Windows Hello, защиты учётных данных. Windows 10 работала без TPM, поэтому «работает Windows 10» не значит «подходит для Windows 11». Проверить наличие TPM можно через `tpm.msc` или `Get-Tpm`.
Что хочет услышать интервьюер: понимание, что TPM — это про безопасность, а не «каприз Microsoft», и умение проверить его наличие.
Красный флаг: «TPM — это просто маркетинг, можно обойти».

**Вопрос 4. Как проверить, соответствует ли компьютер требованиям Windows 11?**
Как задают: «Пользователь хочет обновиться до Windows 11 — как быстро проверить, подходит ли его ПК?»
Ответ: Открыть `msinfo32` — посмотреть `Режим BIOS` (должно быть UEFI) и `Состояние безопасной загрузки` (Вкл). Выполнить `Get-Tpm` — `TpmPresent : True`, версия 2.0. `Get-Disk` — `Partition Style : GPT`. Плюс проверить ОЗУ (4 ГБ+) и диск (64 ГБ+). Можно использовать утилиту Microsoft PC Health Check для наглядного отчёта.
Что хочет услышать интервьюер: знание конкретных команд и параметров, а не «погуглить».
Красный флаг: «Надо просто попробовать установить — если не пойдёт, значит не подходит».

**Вопрос 5. Пользователь просит отключить Secure Boot, чтобы поставить программу. Что делать?**
Как задают: «Приходит заявка: отключите Secure Boot, у меня программа не запускается. Ваши действия?»
Ответ: Сначала выяснить, что за программа и почему она требует отключения Secure Boot. Если это легитимное ПО — искать подписанную версию или официальную инструкцию. Если это самодельный загрузчик или нестандартная сборка — согласовать с ИБ, объяснить пользователю риски (снижение защиты, возможная блокировка BitLocker). В корпоративной среде отключение Secure Boot на рабочей машине — это изменение политики безопасности, его нельзя делать по одной заявке без согласования.
Что хочет услышать интервьюер: что ты не бросаешься выполнять «отключите защиту», а сначала выясняешь причину и согласуешь.
Красный флаг: «Конечно, отключу, лишь бы работало».
