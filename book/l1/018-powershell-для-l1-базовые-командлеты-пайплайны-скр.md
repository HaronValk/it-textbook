# PowerShell для L1: базовые командлеты, пайплайны, скрипты автоматизации рутины

## 1. Введение (зачем это нужно в реальной работе)

Заявка в учебной очереди `C:\Support\Tickets`:

> **Пользователь:** Мария Петрова (HR), ВМ WIN10-CL02
> **Что написала:** «Каждое утро вручную проверяю, что на моём компьютере запущены службы печати и планировщика, и записываю в блокнот, сколько места осталось на диске C:. Это занимает минут десять, и я всё время путаюсь. Можно как-то автоматизировать?»
> **Срочность:** низкая, но повторяется каждый день.

Вот это «каждое утро вручную» — типичная рутина L1. Проверить службы, посмотреть свободное место, собрать список запущенных процессов, найти в журнале событий ошибки за сутки, посмотреть, кто из пользователей вошёл в систему. По отдельности — минута-две, но таких задач у одного сотрудника пять, у отдела — пятьдесят, и всё это съедает день.

PowerShell — это встроенная в Windows оболочка и язык сценариев, которая позволяет делать всё это одной строкой или одним маленьким скриптом, а потом запускать по расписанию. В отличие от обычной командной строки (CMD), PowerShell работает не с текстом, а с объектами: у каждой команды есть результат с полями, которые можно фильтровать, сортировать, передавать дальше. Это и есть его главная сила.

После этой главы ты будешь уметь: запускать базовые командлеты (это официальное название команд PowerShell), строить пайплайны (цепочки команд через `|`), фильтровать и сортировать результаты, сохранять их в файл, писать простой скрипт `.ps1` и запускать его. Этого достаточно, чтобы закрыть половину ежедневной рутины L1 и уверенно отвечать на вопросы про PowerShell на собеседовании.

## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

PowerShell — это не «CMD с другим синтаксисом». Это отдельная программа `powershell.exe` (Windows PowerShell 5.1, встроен в Windows 10/11) или `pwsh.exe` (PowerShell 7, ставится отдельно). На стенде у нас Windows 11 и Windows 10 «из коробки», значит работаем с Windows PowerShell 5.1 — он уже есть, ничего ставить не надо.

Как устроена работа команды:

```text
   Ты вводишь команду
          │
          ▼
   ┌──────────────────┐
   │  Парсер PowerShell│  разбирает строку: командлет, параметры, аргументы
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │  Командлет        │  Get-Service, Get-Process, Where-Object...
   │  (cmdlet)         │  это .NET-класс, а не отдельный .exe
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │  Объект(ы)        │  НЕ текст! У объекта есть свойства (Name, Status)
   │  в пайплайне      │  и методы (Start(), Stop())
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │  Форматтер        │  превращает объект в текст для экрана
   │  (Out-Default)    │  (или в CSV/JSON/файл)
   └──────────────────┘
```

Ключевая идея: `Get-Service` возвращает не строчки текста, а объекты служб. У каждого объекта есть свойства `Name`, `DisplayName`, `Status`, `StartType`. Поэтому можно написать `Get-Service | Where-Object Status -eq 'Stopped'` — и получить только остановленные службы, а не парсить текст глазами.

Три понятия, без которых дальше никак:

- **Командлет (cmdlet)** — команда вида `Глагол-Существительное`: `Get-Service`, `Stop-Process`, `Set-Location`. Глагол говорит, что делаем (Get — получить, Set — задать, Start/Stop — запустить/остановить, New — создать, Remove — удалить).
- **Пайплайн** — цепочка команд через `|`. Выход одной команды становится входом следующей. Это как конвейер на заводе: каждая команда берёт деталь, что-то с ней делает и передаёт дальше.
- **Провайдер** — способ, которым PowerShell смотрит на разные «хранилища». Файловая система, реестр, переменные среды — всё это доступно через одни и те же команды (`Get-ChildItem`, `Set-Location`). Поэтому `cd HKLM:\SOFTWARE` работает так же, как `cd C:\Windows`.

Порты и протоколы тут ни при чём — PowerShell работает локально внутри машины. Сеть появится в уроке 31, а удалённое выполнение команд — сильно позже.

## 3. Аналогия из жизни

Представь склад, где каждая коробка — это объект с наклейкой. На наклейке написано: «Служба», «Статус: работает», «Тип запуска: автоматически». Раньше (в CMD) тебе выдавали список коробок, переписанный от руки на бумажку, и ты глазами искал нужную. В PowerShell тебе выкатывают сами коробки, и ты можешь сказать: «оставь только те, где статус "остановлена"», «отсортируй по имени», «положи в файл». Ты работаешь с коробками, а не с их описанием на бумажке.

Аналогия ломается в одном месте: у настоящей коробки на складе нельзя нажать кнопку и запустить её содержимое, а у объекта-службы в PowerShell есть методы `Start()` и `Stop()` — то есть можно не только смотреть, но и действовать.

## 4. Практика и команды

Все команды ниже выполняй в PowerShell на **WIN11-CL01** (там локальная учётка `ivanov`) или на **WIN10-CL02** (там `petrova`). Открывать: правый клик по «Пуск» → **Windows PowerShell** (или **Терминал** → вкладка Windows PowerShell). Для команд, которые меняют систему (запуск/остановка служб), нужны права администратора — тогда «Windows PowerShell (администратор)».

### 4.1. `Get-Help` — как узнать, что делает команда

```powershell
Get-Help Get-Service
Get-Help Get-Service -Examples
Get-Help Get-Service -Full
```

`-Examples` показывает примеры, `-Full` — полное описание со всеми параметрами. Если справка не установлена, PowerShell предложит `Update-Help` (нужен интернет; на стенде он есть через NAT). Сокращённый вывод примерно:

```text
NAME
    Get-Service

SYNOPSIS
    Gets the services on a computer.
```

Смотреть: раздел SYNOPSIS (что делает) и EXAMPLES (как вызывать).

### 4.2. `Get-Command` — найти команду по имени

```powershell
Get-Command *Service*
Get-Command -Verb Get -Noun *Process*
```

Первая команда ищет все командлеты, в имени которых есть «Service». Вторая — все `Get-*Process*`. Сокращённый вывод примерно:

```text
CommandType     Name                Version    Source
-----------     ----                -------    ------
Cmdlet          Get-Service         3.1.0.0    Microsoft.PowerShell.Management
Cmdlet          Get-Process         3.1.0.0    Microsoft.PowerShell.Management
```

Смотреть: колонку `Name` — это и есть имя командлета, которое можно вводить.

### 4.3. `Get-Service` — состояние служб

```powershell
Get-Service
Get-Service -Name Spooler
Get-Service | Where-Object Status -eq 'Stopped'
Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' }
```

`-Name` фильтрует по имени. `Where-Object` — фильтр по свойству: `Status -eq 'Stopped'` значит «статус равен Stopped». В фигурных скобках `$_` — это текущий объект в пайплайне. Третья команда находит службы с автозапуском, которые при этом не работают — классический симптом «что-то не стартовало».

Сокращённый вывод примерно:

```text
Status   Name               DisplayName
------   ----               -----------
Running  Spooler            Print Spooler
Stopped  WSearch            Windows Search
```

Смотреть: `Status` (Running/Stopped) и `Name` (короткое имя, по нему потом запускать).

### 4.4. `Get-Process` — запущенные процессы

```powershell
Get-Process
Get-Process -Name explorer
Get-Process | Sort-Object -Property WS -Descending | Select-Object -First 5 Name, Id, WS
```

`Sort-Object -Property WS -Descending` сортирует по памяти (WS — working set, объём оперативной памяти в байтах), `Select-Object -First 5 Name, Id, WS` берёт первые пять и оставляет только три поля. Это «топ-5 процессов по памяти» — то, что пользователь обычно просит, когда говорит «компьютер тормозит».

Сокращённый вывод примерно:

```text
Name       Id     WS
----       --     --
chrome   4321   850000000
explorer 1234   120000000
```

Смотреть: `Name` (что за процесс) и `WS` (сколько памяти, в байтах; делить на 1 ГБ = 1073741824 для человеческих цифр).

### 4.5. `Get-ChildItem` — файлы и папки

```powershell
Get-ChildItem C:\Windows\System32 -Filter *.dll | Measure-Object
Get-ChildItem C:\Users -Directory
Get-ChildItem C:\Windows\Logs -Recurse -ErrorAction SilentlyContinue | Where-Object Length -gt 10MB
```

`-Filter` фильтрует по маске, `-Directory` только папки, `-Recurse` рекурсивно, `-ErrorAction SilentlyContinue` не выводит ошибки доступа (их будет много на системных папках). `Measure-Object` считает количество. Третья команда находит файлы больше 10 МБ — полезно, когда диск забит.

Смотреть: `Count` у `Measure-Object` (сколько файлов), `FullName` и `Length` у найденных файлов.

### 4.6. `Get-Content` — читать файлы и логи

```powershell
Get-Content C:\Windows\System32\drivers\etc\hosts
Get-Content C:\Windows\System32\drivers\etc\hosts -Tail 5
Get-Content C:\Windows\Logs\CBS\CBS.log -Tail 20
```

`-Tail N` показывает последние N строк — это то, что нужно 90% времени при чтении логов. `-Wait` (не показан) следит за файлом в реальном времени, как `tail -f` в Linux.

Смотреть: последние строки — там самое свежее событие.

### 4.7. `Select-Object` и `Format-Table` — что показать

```powershell
Get-Service | Select-Object Name, Status, StartType
Get-Service | Format-Table Name, Status -AutoSize
Get-Service | Format-List Name, Status, StartType
```

`Select-Object` оставляет только нужные свойства (и передаёт дальше объекты с этими свойствами). `Format-Table` и `Format-List` — только для отображения: они превращают объект в текст. Важно: после `Format-*` объект уже нельзя фильтровать, поэтому `Format-*` ставят в конце пайплайна.

Смотреть: `-AutoSize` подгоняет ширину колонок, `Format-List` удобен, когда свойств много.

### 4.8. `Export-Csv` и `Out-File` — сохранить результат

```powershell
Get-Service | Select-Object Name, Status, StartType | Export-Csv C:\Support\services.csv -NoTypeInformation -Encoding UTF8
Get-Process | Out-File C:\Support\processes.txt
```

`Export-Csv` пишет CSV с заголовками — открывается в Excel. `-NoTypeInformation` убирает служебную первую строку `#TYPE ...`. `-Encoding UTF8` важен для русских букв. `Out-File` пишет простой текст.

Смотреть: файл появился в `C:\Support`, открывается в Блокноте/Excel без «кракозябр».

### 4.9. `Get-EventLog` / `Get-WinEvent` — журналы событий

```powershell
Get-EventLog -LogName System -Newest 10
Get-WinEvent -LogName System -MaxEvents 20 | Where-Object LevelDisplayName -eq 'Error'
```

`Get-EventLog` — старый командлет, работает с классическими журналами (System, Application, Security). `Get-WinEvent` — новый, умеет и новые журналы. `-Newest 10` — последние 10 записей. Вторая команда фильтрует только ошибки.

Смотреть: `TimeGenerated` (когда), `Source` (кто), `Message` (что случилось).

### 4.10. `Get-Location`, `Set-Location`, `New-Item` — работа с папками

```powershell
Get-Location
Set-Location C:\Support
New-Item -ItemType Directory -Path C:\Support\Reports -Force
```

`Get-Location` — где я сейчас (аналог `pwd`), `Set-Location` — перейти (аналог `cd`), `New-Item -ItemType Directory` — создать папку. `-Force` не ругается, если папка уже есть.

Смотреть: после `Set-Location` приглашение показывает новый путь.

### 4.11. `Start-Service` / `Stop-Service` — управление службами

```powershell
Start-Service -Name Spooler
Stop-Service -Name Spooler -Force
Restart-Service -Name Spooler
```

Требуют прав администратора. `-Force` останавливает, даже если у службы есть зависимые. Это те команды, которые реально «чинят» — но применять их надо осознанно, а не наугад.

Смотреть: после `Start-Service` повторный `Get-Service -Name Spooler` показывает `Running`.

### 4.12. `Get-History` и `Invoke-History` — история команд

```powershell
Get-History
Invoke-History -Id 5
```

`Get-History` показывает, что ты вводил в этой сессии. `Invoke-History -Id N` повторяет команду с номером N. Быстрее, чем набирать заново.

Смотреть: `Id` и `CommandLine`.

## 5. Лабораторная работа (пошаговый сценарий на виртуалке)

### Предусловия

- **WIN11-CL01** — Windows 11, локальная учётка `ivanov`, адрес 10.10.10.51 статически, VMware Tools установлены.
- **WIN10-CL02** — Windows 10 LTSC, локальная учётка `petrova`, адрес 10.10.10.52 статически.
- **DC01** — Windows Server 2022, рабочая группа, 10.10.10.10, роли не установлены. Используем только для чтения журналов, ничего не настраиваем.
- Домена нет, AD нет, DHCP нет. Все учётки локальные.
- На хосте есть папки `C:\Lab\vektor` (журнал `stand-log.md`) и `C:\Support` (учебные заявки `C:\Support\Tickets`).

### Снапшот

В VMware Workstation на каждой затрагиваемой ВМ (WIN11-CL01, WIN10-CL02, DC01): правый клик по ВМ → **Snapshot** → **Take Snapshot** → имя `before-l1-018`. Если ВМ запущена — можно делать снапшот на ходу, но надёжнее выключить (гостевое выключение, не «Power Off»).

### Шаги

1. **WIN11-CL01, вход `ivanov`.** Открой PowerShell: правый клик по «Пуск» → **Windows PowerShell**. Проверь версию:

    ```powershell
    $PSVersionTable
    ```

    Ожидаемо: таблица, где `PSVersion` примерно `5.1.xxxxx`. Это Windows PowerShell 5.1 — встроенный, ставить ничего не надо.

2. **WIN11-CL01.** Посмотри справку по `Get-Service`:

    ```powershell
    Get-Help Get-Service -Examples
    ```

    Ожидаемо: список примеров с описанием. Если PowerShell предложит `Update-Help` — можно согласиться (интернет через NAT есть), но для лабораторной это не обязательно.

3. **WIN11-CL01.** Посмотри все службы и отфильтруй остановленные:

    ```powershell
    Get-Service | Where-Object Status -eq 'Stopped' | Select-Object Name, DisplayName
    ```

    Ожидаемо: список из нескольких десятков служб со статусом Stopped (на чистой Windows 11 их обычно 20–40). Запиши 2–3 имени — они пригодятся.

4. **WIN11-CL01.** Найди службы с автозапуском, которые не работают:

    ```powershell
    Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' } | Select-Object Name, Status, StartType
    ```

    Ожидаемо: пусто или 1–2 службы. На свежей системе обычно пусто — это нормально, значит всё стартует.

5. **WIN11-CL01.** Топ-5 процессов по памяти:

    ```powershell
    Get-Process | Sort-Object -Property WS -Descending | Select-Object -First 5 Name, Id, WS
    ```

    Ожидаемо: 5 строк, сверху обычно браузер или `explorer`. Значения `WS` в сотнях мегабайт-миллиардах байт.

6. **WIN11-CL01.** Собери отчёт по службам в CSV:

    ```powershell
    New-Item -ItemType Directory -Path C:\Support\Reports -Force
    Get-Service | Select-Object Name, Status, StartType | Export-Csv C:\Support\Reports\services.csv -NoTypeInformation -Encoding UTF8
    Get-Content C:\Support\Reports\services.csv -TotalCount 5
    ```

    Ожидаемо: папка `C:\Support\Reports` создана, файл `services.csv` существует, первые 5 строк — заголовок и 4 службы. Открой файл в Блокноте — русские буквы читаются.

7. **WIN11-CL01.** Посмотри последние ошибки в журнале System:

    ```powershell
    Get-WinEvent -LogName System -MaxEvents 50 | Where-Object LevelDisplayName -eq 'Error' | Select-Object TimeCreated, ProviderName, Id
    ```

    Ожидаемо: 0–5 строк (на свежей системе ошибок мало). Если пусто — это хорошо, не ошибка лабораторной.

8. **WIN11-CL01.** Напиши первый скрипт. Открой Блокнот, вставь:

    ```powershell
    # daily-check.ps1 — ежедневная проверка рабочей станции
    $report = "C:\Support\Reports\daily-$(Get-Date -Format 'yyyy-MM-dd').txt"
    "=== Отчёт от $(Get-Date) ===" | Out-File $report -Encoding UTF8
    "" | Out-File $report -Append -Encoding UTF8
    "--- Свободное место на C: ---" | Out-File $report -Append -Encoding UTF8
    Get-PSDrive C | Select-Object Used, Free | Format-List | Out-File $report -Append -Encoding UTF8
    "--- Остановленные службы с автозапуском ---" | Out-File $report -Append -Encoding UTF8
    Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' } | Select-Object Name, Status | Out-File $report -Append -Encoding UTF8
    "--- Топ-5 процессов по памяти ---" | Out-File $report -Append -Encoding UTF8
    Get-Process | Sort-Object WS -Descending | Select-Object -First 5 Name, WS | Out-File $report -Append -Encoding UTF8
    ```

    Сохрани как `C:\Support\daily-check.ps1`, тип файла — «Все файлы», кодировка — **UTF-8** (в Блокноте Windows 11 это пункт «Кодировка» в диалоге сохранения).

9. **WIN11-CL01.** Запусти скрипт. По умолчанию политика выполнения блокирует `.ps1`. Сначала посмотри её:

    ```powershell
    Get-ExecutionPolicy
    ```

    Ожидаемо: `Restricted` (на клиентской Windows по умолчанию). Разреши для текущего пользователя:

    ```powershell
    Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
    ```

    На вопрос ответь `Y`. `RemoteSigned` разрешает локальные скрипты без подписи, а скачанные из интернета — только подписанные. Это разумный компромисс для учебного стенда; в боевой среде политику задаёт администратор через GPO.

10. **WIN11-CL01.** Запусти скрипт:

    ```powershell

    ```

    Ожидаемо: без вывода в консоль (всё ушло в файл). Проверь:

    ```powershell

    Get-Content (Get-ChildItem C:\Support\Reports\daily-*.txt | Select-Object -Last 1).FullName
    ```

    Ожидаемо: файл `daily-2026-XX-XX.txt` с четырьмя разделами. Второй командой — его содержимое.

11. **WIN10-CL02, вход `petrova`.** Повтори шаги 3, 5, 6 (только чтение и экспорт в `C:\Support\Reports`). Убедись, что PowerShell ведёт себя одинаково на Windows 10 и 11. Скрипт `daily-check.ps1` копировать не нужно — просто проверь, что базовые командлеты работают.

12. **DC01, вход `adm.student`.** Открой PowerShell (можно без админа) и посмотри журнал System:

    ```powershell

    ```

    Ожидаемо: 20 записей. На сервере событий обычно больше, чем на клиенте. Ничего не меняем — только читаем.

13. **Хост, `C:\Lab\vektor\stand-log.md`.** Запиши, что сделал: на WIN11-CL01 создана папка `C:\Support\Reports`, файл `services.csv`, скрипт `daily-check.ps1`, изменена ExecutionPolicy для `ivanov` на `RemoteSigned`. На WIN10-CL02 создан `C:\Support\Reports` и `services.csv`. На DC01 ничего не менялось.

## 6. Ошибки новичков и безопасность

1. **Ошибка:** путать `Get-Service` и `Get-Process`.
   **К чему приводит:** пользователь говорит «служба не работает», а ты ищешь процесс, или наоборот. Время теряется.
   **Как правильно:** служба — это то, что видно в `services.msc` (Spooler, WSearch). Процесс — то, что видно в диспетчере задач (chrome.exe, explorer.exe). Служба может запускать процесс, но это разные сущности.

2. **Ошибка:** ставить `Format-Table` в середину пайплайна.
   **К чему приводит:** `Get-Service | Format-Table | Where-Object Status -eq 'Stopped'` не фильтрует — `Format-Table` уже превратил объекты в текст, у текста нет свойства `Status`.
   **Как правильно:** `Format-*` — только в самом конце. Фильтруй `Where-Object` до форматирования.

3. **Ошибка:** запускать `Stop-Service` или `Restart-Service` «на всякий случай».
   **К чему приводит:** остановка Spooler рвёт печать у всех, кто печатает; остановка сетевых служб — обрыв связи. На сервере — простой.
   **Как правильно:** сначала `Get-Service` и `Get-WinEvent`, чтобы понять причину. Менять состояние — только когда есть гипотеза и понимание последствий.

4. **Ошибка:** менять ExecutionPolicy на `Unrestricted` или `Bypass` «чтобы работало».
   **К чему приводит:** любой скачанный скрипт запускается без предупреждения. Это классический вектор атаки.
   **Как правильно:** `RemoteSigned` для `CurrentUser` — разумный минимум. В боевой среде политику задаёт администратор через GPO, а не пользователь.

5. **Ошибка:** сохранять скрипт в кодировке ANSI с русскими буквами.
   **К чему приводит:** в консоли «кракозябры», скрипт может не запуститься.
   **Как правильно:** сохранять `.ps1` в UTF-8 (в Блокноте Windows 11 — «UTF-8» в списке кодировок; в старом Блокноте — «UTF-8 с BOM»).

6. **Ошибка:** писать скрипт, который молча удаляет файлы или меняет систему, и запускать его без проверки.
   **К чему приводит:** `Remove-Item -Recurse -Force C:\Users\*` без `-WhatIf` — и данных нет.
   **Как правильно:** сначала прогони команду с `-WhatIf` (показывает, что было бы сделано) или `-Confirm` (спрашивает перед каждым действием). Для опасных скриптов — снапшот ВМ перед запуском.

7. **Ошибка:** считать, что `Get-Content` покажет весь большой лог.
   **К чему приводит:** консоль зависает на гигабайтном файле.
   **Как правильно:** `-Tail N` для последних строк, `Select-String` для поиска по шаблону, `Measure-Object -Line` для подсчёта.

8. **Ошибка:** запускать скрипт двойным кликом.
   **К чему приводит:** окно открывается и мгновенно закрывается, ошибку не видно.
   **Как правильно:** запускать из уже открытой консоли PowerShell через `& C:\путь\скрипт.ps1` или `.\скрипт.ps1` (если ты в его папке). Тогда ошибки остаются на экране.

### Безопасность

- **Не отключай ExecutionPolicy «навсегда» ради одного скрипта.** В боевой среде политику задаёт администратор домена через GPO, а пользователь не должен её менять. Если скрипт нужен регулярно — его подписывают сертификатом или кладут в доверенную папку.
- **Не запускай скрипты из интернета и из писем.** «Скрипт для ускорения Windows» из форума — классический способ получить шифровальщика. Скачивай только с официальных сайтов вендоров.
- **Не храни пароли в скриптах в открытом виде.** `$password = "Lab#2026-vektor"` в `.ps1` — это утечка. На стенде это допустимо только потому, что пароль учебный; в реальной работе — `Get-Credential`, менеджеры секретов, учётные записи служб.
- **`Remove-Item` без `-WhatIf` — зло.** Всегда проверяй, что удаляешь. Особенно с `-Recurse -Force`.
- **Логируй, что делает скрипт.** Хотя бы `Start-Transcript` в начале и `Stop-Transcript` в конце — потом легче разобраться, что пошло не так.

## 7. Вопросы на собеседовании

**Вопрос 1. Чем PowerShell отличается от командной строки CMD?**
Как задают: «Вот у вас Windows, вы пользуетесь CMD или PowerShell? В чём разница?»
Ответ: «CMD работает с текстом: команда выдаёт строки, и я их разбираю глазами или парсером. PowerShell работает с объектами: `Get-Service` возвращает объекты служб со свойствами `Name`, `Status`, `StartType`, и я могу фильтровать по этим свойствам через `Where-Object`, сортировать через `Sort-Object`, выбирать нужные поля через `Select-Object`. Плюс в PowerShell одинаковый синтаксис для файлов, реестра, переменных среды — через провайдеры. И есть полноценный язык сценариев: переменные, циклы, функции, обработка ошибок. На стенде я это проверял: `Get-Service | Where-Object Status -eq 'Stopped'` в CMD одной строкой не сделать.»
Что хочет услышать интервьюер: понимание «объекты vs текст» и что PowerShell — это язык, а не просто оболочка.
Красный флаг: «PowerShell — это то же самое, только синее».

**Вопрос 2. Что такое пайплайн и зачем он нужен?**
Как задают: «Объясните, что делает вертикальная черта в PowerShell.»
Ответ: «Пайплайн — это цепочка команд через `|`. Выход одной команды становится входом следующей. Каждая команда получает объекты, что-то с ними делает и передаёт дальше. Пример: `Get-Process | Sort-Object WS -Descending | Select-Object -First 5 Name, Id, WS` — берём все процессы, сортируем по памяти, оставляем первые пять и три поля. Это читается как конвейер: получить → отсортировать → выбрать. Важно, что `Format-Table` и `Format-List` ставят в конце — они превращают объекты в текст, и после них фильтровать уже нельзя.»
Что хочет услышать: понимание, что пайплайн передаёт объекты, а не текст, и что порядок команд важен.
Красный флаг: «Пайплайн — это просто чтобы в одну строку писать».

**Вопрос 3. Пользователь говорит, что скрипт `.ps1` не запускается, ошибка про «running scripts is disabled». Что делать?**
Как задают: «Приходит заявка: скрипт не работает, ошибка про политику выполнения. Ваши действия?»
Ответ: «Сначала уточню точный текст ошибки — по нему видно, что дело в ExecutionPolicy. Проверю `Get-ExecutionPolicy -List` — увижу, на каком уровне стоит `Restricted`. Спрошу, менял ли пользователь что-то, и проверю, что скрипт на месте и не пустой через `Get-Item`. Если это локальный скрипт пользователя и он ему нужен для работы — верну `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`. Это разрешает локальные скрипты без подписи, но скачанные из интернета — только подписанные. В боевой среде политику задаёт администратор через GPO, поэтому если увижу, что политика доменная, — эскалирую, а не меняю сам. В заявке запишу точный текст ошибки и что сделал.»
Что хочет услышать: понимание, что `RemoteSigned` — разумный компромисс, и что в домене политику не меняют вручную.
Красный флаг: «Поставлю `Bypass` и всё заработает».

**Вопрос 4. Как вы найдёте, какая служба с автозапуском не стартовала?**
Как задают: «Компьютер после перезагрузки работает странно. Как через PowerShell найти проблему со службами?»
Ответ: «Одной строкой: `Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' }`. Это отфильтрует службы, которые должны стартовать автоматически, но не работают. Дальше по каждой смотрю журнал: `Get-WinEvent -LogName System -MaxEvents 50 | Where-Object LevelDisplayName -eq 'Error'` — ищу ошибки, связанные с именем службы. Если служба упала из-за зависимости — видно в событиях. Запускаю через `Start-Service -Name <имя>` и проверяю, что она осталась в Running. Если падает снова — смотрю, что в журнале, и эскалирую, если причина не в моей зоне.»
Что хочет услышать: умение одной строкой найти проблему и не «тыкать наугад».
Красный флаг: «Перезапущу все службы подряд».

**Вопрос 5. Как автоматизировать ежедневную проверку рабочей станции?**
Как задают: «Пользователь просит каждое утро присылать отчёт о состоянии компьютера. Как сделаете?»
Ответ: «Напишу скрипт `.ps1`, который собирает нужное: свободное место через `Get-PSDrive C`, остановленные службы с автозапуском, топ-5 процессов по памяти, последние ошибки из журнала System. Всё складываю в файл через `Out-File` или `Export-Csv`. Запускать можно вручную через `& C:\Support\daily-check.ps1` или по расписанию — Планировщиком задач, но это уже отдельная тема. Важно: скрипт сохраняю в UTF-8, проверяю на тестовой машине, для опасных действий использую `-WhatIf`. На стенде я такой скрипт писал — он собирает отчёт за пару секунд вместо десяти минут ручной работы.»
Что хочет услышать: понимание, что автоматизация — это скрипт + расписание, и что скрипт надо проверять.
Красный флаг: «Напишу скрипт, который удалит всё лишнее, и всё будет быстро».
