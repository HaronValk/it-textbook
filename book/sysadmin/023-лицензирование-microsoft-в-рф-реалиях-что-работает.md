## 2. Теория «под капотом» (как это работает: архитектура, протоколы)

Главная мысль главы: **юридическая лицензия и техническая активация — это два независимых слоя**. Ключ, который «сработал», не даёт права использовать ПО; договор с дистрибьютором не отменяет того, что сервер нужно активировать технически.

```text
┌───────────────────── ЮРИДИЧЕСКИЙ СЛОЙ ──────────────────────┐
│ Договор / счёт / акт приёма-передачи / лицензионный сертификат│
│ Права: perpetual (бессрочно) или подписка (срок)             │
│ Единицы: сервер (ядро), User CAL, Device CAL, RDS CAL        │
└───────────────────────────┬─────────────────────────────────┘
                            │ связи НЕТ (это разные вещи)
┌───────────────────── ТЕХНИЧЕСКИЙ СЛОЙ ──────────────────────┐
│ slmgr.vbs / Get-CimInstance  ⇄  служба sppsvc                │
│ (Software Protection Platform)                               │
│   ├─ Product Key Channel: Retail / OEM:DM / Volume:MAK / GVLK│
│   ├─ KMS: свой сервер, клиент ищет SRV _vlmcs._tcp в DNS      │
│   ├─ ADBA: активация через AD (объекты в CN=Activation Objects)│
│   └─ Token store: C:\Windows\System32\spp\store\2.0\tokens.dat│
│                            ▲                                 │
│ Прошивка ACPI MSDM (OEM-ключ) ─┘ (только физическое железо)   │
└───────────────────────────────────────────────────────────────┘
```

**Каналы ключей.** `Retail` — куплен в рознице, переносится на другое железо (по правилам вендора). `OEM` — «вшит» в прошивку ноутбука, привязан к материнской плате, переносить нельзя. `Volume:MAK` — корпоративный многократный ключ, каждая активация «списывает» счётчик на серверах вендора. `Volume:GVLK` — публичный установочный ключ, сам по себе не активирует: он лишь говорит клиенту «ищи KMS-сервер». **KMS** (Key Management Service) — свой сервер внутри сети, который выдаёт активацию на 180 дней и продлевает её; требует корпоративного KMS-ключа из личного кабинета. **ADBA** (Active Directory-Based Activation) — то же, но объект активации хранится в AD, клиенты ничего не опрашивают.

**Редакции и единицы.** Windows Server Standard/Datacenter с 2016 года лицензируется **по физическим ядрам**: минимум 16 ядер на сервер (2 процессора × 8), дальнейшее — парами. Standard даёт права на 2 виртуальные ОС (OSE), Datacenter — на неограниченное количество на этом же физическом сервере. `OSE` (Operating System Environment) — экземпляр ОС в ВМ или на железе. CAL (Client Access License) — не «на сервер», а на пользователя (User CAL) или устройство (Device CAL) и покрывает доступ ко всем серверам парка; отдельно нужны RDS CAL для терминального сервера, отдельно — SQL/1С. Windows 11 в виртуалке на VMware Workstation — это отдельное право (VDA/E3/E5 или Windows 365), для учебы — только Evaluation.

**Порты и протоколы.** KMS-клиент ходит на TCP/1688. DNS-запись `_vlmcs._tcp` в зоне домена — то, по чему клиент находит KMS. `sppsvc` работает локально, сеть ей нужна только для связи с серверами активации/AD.

**Схема OSI тут почти не применима** — тема лежит выше: прикладной уровень (служба SPP) + организационный слой (договор). Именно поэтому сисадмины и путают активацию с лицензией.

**Реалии РФ.** С 2022 года Microsoft остановила новые продажи в России; в 2024-м ограничения затронули облачные сервисы (Azure, Microsoft 365) для российских организаций. Точные даты и формулировки уведомлений сверяй сам — `[ПРОВЕРИТЬ]` по релизам Microsoft и письмам дистрибьюторов. Практические следствия: (1) ранее купленные perpetual-лицензии продолжают действовать, их никто не отменял; (2) новый закуп и продление подписок — проблема; (3) обновления и техподдержка — вопрос договора, а не «совести»; (4) параллельный импорт — юридически серая зона, правообладатель такой ввоз не признаёт, и это риск, а не решение; (5) использование «активаторов» — прямое нарушение и, как правило, закладка в системе.

## 3. Аналогия из жизни

Лицензия — это **пропуск в бизнес-центр**, а активация — **замок на двери твоего офиса**. Замок можно вскрыть отмычкой (активатор), но пропуска у тебя от этого не появится: охрана на входе спросит документ. И наоборот: пропуск есть, а замок сломан — ты стоишь перед дверью и не работаешь (Evaluation истёк, ключ не применён). Отдельная история — корпоративный «мастер-ключ» от здания (Volume-лицензия): он открывает много дверей, но если ты передашь его соседу, здание перестанет быть безопасным — ключ заблокируют, а с ним встанут все твои двери.

Аналогия ломается в одном месте: сломанный замок можно починить самому и навсегда, а техническая активация всегда привязана к счётчику/сроку — её приходится подтверждать заново (KMS — каждые 180 дней), и без сервера активации она умрёт, даже если договор у тебя в сейфе.

## 4. Практика и команды

**1. Полная карточка лицензии на машине**

```powershell
cscript //nologo C:\Windows\System32\slmgr.vbs /dlv
```

Ключ `/dlv` — detail view: редакция, канал ключа, статус, остаток дней, сколько осталось переактиваций.

```text
Name: Windows(R), ServerStandard edition
Description: Windows(R) Operating System, RETAIL channel
Product Key Channel: Retail
License Status: Licensed
Remaining Windows rearm count: 3
Time remaining: 179 day(s)
```

Смотрим три строки: `Product Key Channel` (откуда ключ), `License Status` (Licensed / Notification / OOB Grace), `Time remaining` (для Evaluation — сколько жить).

**2. Краткий статус и срок**

```powershell
cscript //nologo C:\Windows\System32\slmgr.vbs /dli
cscript //nologo C:\Windows\System32\slmgr.vbs /xpr
```

`/dli` — базовая инфо, `/xpr` — дата окончания активации. На Evaluation `/xpr` покажет конкретную дату, после которой сервер начнёт перезагружаться каждый час.

**3. Инвентаризация через WMI/CIM (то, что нужно автоматизировать)**

```powershell
Get-CimInstance -ClassName SoftwareLicensingProduct -Filter "PartialProductKey IS NOT NULL" |
    Select-Object Name, Description, LicenseStatus, GracePeriodRemaining, PartialProductKey
```

`PartialProductKey` — последние 5 символов ключа (полный ключ в системе не показывается — так и надо). `LicenseStatus`: 0 — не активировано, 1 — активировано, 2/3 — льготный период, 5 — уведомление об активации. Именно эту команду кладут в основу скрипта инвентаризации.

**4. Служба лицензирования и OEM-ключ**

```powershell
Get-CimInstance -ClassName SoftwareLicensingService |
    Select-Object Version, OA3xOriginalProductKey
Get-Service sppsvc | Select-Object Name, Status, StartType
```

`OA3xOriginalProductKey` заполнен только на физическом железе с вшитым OEM-ключом — на виртуалках стенда будет пусто.

**5. Есть ли в сети KMS**

```powershell
nslookup -type=srv _vlmcs._tcp.corp.vektor.lab
```

Пустой ответ = KMS в домене нет, клиенты активируются MAK/цифровой лицензией/Evaluation. SRV-запись — единственное, что реально «настраивается» для KMS-клиентов.

**6. Сколько у нас пользователей (расчёт User CAL)**

```powershell
(Get-ADUser -Filter * -SearchBase "OU=Company,DC=corp,DC=vektor,DC=lab" -Properties Enabled |
    Where-Object Enabled).Count
```

CAL покупается на реальных людей, которым нужен доступ. Считаем включённые учётки, а не всех, кто когда-либо заводился.

**7. Сколько устройств (расчёт Device CAL)**

```powershell
(Get-ADComputer -Filter * -SearchBase "OU=Компьютеры,DC=corp,DC=vektor,DC=lab").Count
```

Device CAL выгоден, когда на одном ПК работают три смены, а с ноутбуками на каждого сотрудника — User CAL.

**8. Фактические обращения к файловому серверу (и почему это НЕ CAL)**

```powershell
# на FS01
Get-SmbSession | Select-Object ClientComputerName, ClientUserName, NumOpens
Get-SmbOpenFile | Measure-Object
```

Три одновременные сессии ≠ три CAL: лицензия нужна каждому, кто *имеет право* обращаться, даже если он сейчас в отпуске.

**9. События службы лицензирования**

```powershell
Get-WinEvent -LogName Application -MaxEvents 40 |
    Where-Object ProviderName -match 'Software Protection' |
    Select-Object TimeCreated, Id, Message
```

Провайдер и точные ID — `[ПРОВЕРИТЬ]` на своей сборке; фильтр по имени провайдера удобнее, чем по номерам. Ищем жалобы на активацию, отключение службы, ошибки 0x80070422 (служба выключена).

**10. Linux-парк: что лицензировать не надо**

```bash
lsb_release -a; cat /etc/os-release      # UBU01, ASTRA01
cat /etc/astra_version                   # только на Astra
dpkg-query -W -f='${Package}\n' | wc -l  # сколько пакетов
apt list --installed 2>/dev/null | tail -n 5
```

Ключевое: Astra Linux **Common Edition** — свободно распространяемая, Ubuntu — тем более. В реестре лицензий они фиксируются как «СПО, лицензия не требуется», но с пометкой «нет сертификации ФСТЭК» — для ГИС это важно.

**11. Оформление реестра в файл**

```powershell
$rows = foreach ($c in 'DC01','FS01','WIN10-CL02') {
    Invoke-Command -ComputerName $c -ScriptBlock {
        $p = Get-CimInstance SoftwareLicensingProduct -Filter "PartialProductKey IS NOT NULL" |
             Select-Object -First 1
        [pscustomobject]@{
            Host = $env:COMPUTERNAME
            Edition = (Get-CimInstance Win32_OperatingSystem).Caption
            Channel = $p.Description
            Status  = $p.LicenseStatus
            DaysLeft= [math]::Round($p.GracePeriodRemaining/1440)
        }
    }
}
$rows | Export-Csv -Path '\\FS01\Obshchee\licenses-vektor.csv' -NoTypeInformation -Encoding UTF8
```

Требует включённого WinRM (`Enable-PSRemoting -SkipNetworkProfileCheck`) — на стенде допустимо, в бою это отдельное правило файрвола и сервисная учётка.

**12. GUI, если привычнее**

Windows 11: `Параметры → Система → Активация`. Windows 10: `Параметры → Обновление и безопасность → Активация`. Windows Server: `Панель управления → Система`. Там же — ссылка «Изменить ключ продукта».

> **Срочность:** Высокая

**Как воспроизвести поломку** (только на учебном стенде, никакого реального пиратского софта — имитируем *признаки*):

```powershell
# WIN11-CL01, от админа
Add-Content C:\Windows\System32\drivers\etc\hosts "10.10.10.99 kms.corp.vektor.lab"
schtasks /create /tn "KMSAuto Lite" /tr "cmd /c echo activation" /sc onlogon /ru SYSTEM /f
sc.exe create KMSService binPath= "C:\Windows\System32\cmd.exe /c timeout /t 3600" start= auto
sc.exe config sppsvc start= disabled
Restart-Computer
```

Ожидаемо после перезагрузки: `Параметры → Система → Активация` показывает ошибку, в трее — уведомление об активации, `slmgr.vbs /dlv` возвращает `0x80070422` (служба отключена).

**Диагностика по порядку:**

1. `slmgr.vbs /dlv` → ошибка. Это не «ключ протух», это «служба не работает». Не начинай с переустановки ключа.
2. `Get-Service sppsvc` и `sc.exe qc sppsvc` → `START_TYPE: 4 DISABLED`. Причина найдена.
3. `Get-Content C:\Windows\System32\drivers\etc\hosts` → подозрительная запись `kms.corp.vektor.lab` на несуществующий адрес. Классика «активатора»: блокирует серверы активации вендора.
4. `Get-ScheduledTask | Where-Object TaskName -match 'KMS|Activat'` → задача `KMSAuto Lite`.
5. `Get-Service | Where-Object Name -like 'KMS*'` → служба `KMSService`.
6. `Get-WinEvent -LogName System -MaxEvents 100 | Where-Object Message -match 'sppsvc'` → когда и что отключали (время совпадёт с «приходом подрядчика»).

**Решение:**

```powershell
sc.exe config sppsvc start= demand
Start-Service sppsvc
schtasks /delete /tn "KMSAuto Lite" /f
sc.exe delete KMSService
# из hosts убрать строку 10.10.10.99 kms.corp.vektor.lab
cscript //nologo C:\Windows\System32\slmgr.vbs /ato
Restart-Computer
```

Если `sppsvc` не поднимается или статус остался «Notification» — откат ВМ на `before-sysadmin-023` (в бою в такой ситуации машину переустанавливают: доверять системе с подсунутым активатором нельзя, даже если «починилось»).

Я всё удалил, активация восстановлена, перезагрузите машину и проверьте отчёт. Никакие "активаторы" на рабочих машинах ставить нельзя — это не только нарушение лицензии, но и дыра в безопасности: такие программы обычно содержат вредоносный код. Если увидите подобное снова — сразу тикет.»

**Закрытие заявки:** категория «ИБ / нелегальное ПО», приоритет High, в решении — перечень удалённых объектов, ссылка на реестр лицензий, запись в журнал инцидентов. В «Векторе» — отдельная задача руководителю ИБ: проверить остальные 49 машин тем же скриптом.

## 6. Ошибки новичков и безопасность

1. **«Активировалось — значит лицензия есть»** → к проверке нет ни одного документа, компенсация по ст. 1301 ГК РФ (10 тыс. — 5 млн руб. либо двукратная стоимость) → правильно: активация и право использования живут в разных таблицах реестра.
2. **Перенос OEM-ключа с ноутбука на виртуалку** → технически может «сработать», юридически — нет, OEM привязан к железу → правильно: для ВМ нужна отдельная лицензия (подписка/VDA/E3/E5) или Evaluation для учебы.
3. **Считать CAL по одновременным сессиям** → недозакупка в разы → правильно: User/Device CAL на каждое лицо/устройство, имеющее доступ; RDS CAL — отдельно.
4. **Думать, что Standard покрывает все ВМ** → Standard = 2 OSE на сервер; далее либо ещё лицензии, либо Datacenter → правильно: считать ядра (минимум 16) и OSE до покупки.
5. **«Вендор ушёл, значит всё теперь бесплатно»** → произведение охраняется десятилетиями, «abandonware» юридически не существует → правильно: perpetual-права остаются, новое — либо альтернатива, либо официальный канал закупки.
6. **Хранить MAK/KMS-ключ в тикете, заметках или на флешке** → утечка ключа, блокировка активаций у всего парка → правильно: ключи в защищённом хранилище с ограниченным доступом, в реестре — только последние 5 символов.
7. **Забыть про Evaluation** → через 180 дней DC01 уходит в перезагрузку каждый час, а вместе с ним домен → правильно: дата в календаре + снапшот + план переустановки; `slmgr /rearm` продлевает ограниченное число раз `[ПРОВЕРИТЬ]` и не является решением.
8. **Ставить сервер «на будущее» без лицензии** → обнаруживается при первой же инвентаризации, изымается вместе с железом → правильно: реестр лицензий обновляется в момент ввода машины в эксплуатацию, а не после.

**Безопасность.** В боевой среде нельзя: запускать активаторы и «кряки» (это внедрение кода с правами SYSTEM, отключение Defender и защищённых служб), менять `sppsvc` и `tokens.dat` вручную как «способ починить активацию», покупать «серые» ключи у частников (перепроданные MSDN/корпоративные ключи блокируются, а сделка не даёт прав), использовать один корпоративный ключ на личные устройства сотрудников. Отдельно: право менять ключи продукта должно быть только у админов, а факт смены ключа — событие в журнале, которое кто-то читает.

## 7. Вопросы на собеседовании

**1. Чем техническая активация отличается от лицензии на ПО?**
Ответ: активация — техническая процедура подтверждения подлинности копии (ключ → служба SPP → токен в `spp/store`); лицензия — юридическое право использования по договору. Можно иметь активированную систему без прав (активатор, OEM с другого железа) и права без активации (куплен ключ, но KMS-сервер не настроен). Реестр лицензий и отчёт инвентаризации — разные документы.
*Что хочет услышать:* понимание, что «активировано» ≠ «легально», и что инвентаризация — регулярный процесс.
*Красный флаг:* «ну если активировалось, значит всё нормально».

**2. User CAL и Device CAL — в чём разница и как считать?**
Ответ: CAL даёт право доступа к серверным службам; User CAL закрепляется за человеком (он может работать с любого числа устройств), Device CAL — за устройством (на нём может работать сколько угодно людей посменно). Считать по числу включённых учёток AD либо по числу устройств — и брать вариант дешевле; CAL покрывает весь парк серверов, а не один, но RDS CAL покупаются отдельно. Считать «по одновременным сессиям» — ошибка.
*Что хочет услышать:* разницу сценариев (сменность vs «ноутбук каждому») и мысль про подсчёт из AD.
*Красный флаг:* «CAL на сервер» или «CAL по количеству подключений».

**3. Как узнать редакцию, канал и остаток активации сервера?**
Ответ: `slmgr.vbs /dlv` — редакция, `Product Key Channel` (Retail/OEM/Volume:MAK/GVLK), `License Status`, `Time remaining`, `rearm count`. Массово — `Get-CimInstance SoftwareLicensingProduct -Filter "PartialProductKey IS NOT NULL"`, состояние службы — `Get-Service sppsvc`, наличие KMS — `nslookup -type=srv _vlmcs._tcp`.
*Что хочет услышать:* конкретные команды и умение отдать это скриптом в CSV, а не руками по 50 машинам.
*Красный флаг:* «посмотреть в "Свойствах системы"» как единственный метод.

**4. Как лицензируется Windows Server Standard/Datacenter в виртуализации?**
Ответ: по физическим ядрам, минимум 16 на сервер, дальше парами; Standard — 2 OSE (ВМ) на лицензию, Datacenter — неограниченно на этом сервере, гипервизор роли не играет (VMware, Proxmox, Hyper-V — одинаково). Плюс CAL на доступ. Datacenter окупается при высокой плотности ВМ, при 2–4 ВМ почти всегда дешевле Standard.
*Что хочет услышать:* «ядра, минимум 16, 2 OSE vs unlimited», и что это не зависит от гипервизора.
*Красный флаг:* «одна лицензия на сервер = сколько хочешь ВМ».

**5. Вендор ушёл из РФ, а нам нужен новый сервер и ещё 20 CAL. Что делать?**
Ответ: сначала аудит — что уже куплено (perpetual живут, их не отзывают); затем варианты: (а) эксплуатировать имеющееся и не расширяться, (б) закупка через сохранившиеся каналы/параллельный импорт — с письменным согласованием рисков юристами (правообладатель такой ввоз не признаёт), (в) перенос части ролей на свободное и российское ПО: Samba AD DC / ALD Pro вместо AD, Postfix/Mailu вместо Exchange, PostgreSQL вместо MSSQL, Proxmox/zVirt вместо гипервизора, ОС Astra Linux / РЕД ОС / ALT, (г) облако РФ-провайдера, где лицензия Windows входит в услугу, (д) если заказчик — госструктура или КИИ, проверить требования реестра российского ПО и сертификации ФСТЭК. Итог — план миграции с приоритетами и бюджетом, согласованный с бизнесом, а не «поставим активатор».
*Что хочет услышать:* структурированный ответ: аудит → варианты → риски → план, с упоминанием реестра и сертификации.
*Красный флаг:* «поставим KMS-эмулятор» или «всё равно никто не проверяет».
